  - контракт ввода: стори обязана ответить (`handleMessage` без null); транспорт без `next()` — бот единственный обработчик; ввод без ожидания/адресата — реплика-подсказка транспорта;
  - временный проактив `invite(telegramId, { text, keyboard })` (ФР-6, до модуля tasks-system): кнопки штампуются seq диалога получателя, без диалога — текст с подсказкой /start.

Ключевые решения ревью (зафиксированы в spec.md / plan.md):
- ФР-5 переориентирован: слот `info` → `notify` (переименование), хелпер `errorNotify(err)` — реплика-ошибка без захвата экрана (валидация ввода — переспрос с сохранением контекста).
- Концепция адресации: кнопка — адресная (префикс), ввод — только активной (dialog.path), команда — активный первым, затем всем (pipe). Параметрический API адресации НЕ вводить.
- `app:main-menu` / `app:help` — системные маршруты uiApp (у них нет стори-адресата); menuPath `app/menu` — виртуальный якорь seq.
