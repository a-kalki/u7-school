# Модуль 5 «DOM» — план модуля

> **Источник видения:** `../m4-html-css/concept.md` (общая концепция модулей 4 и 5). Этот план самодостаточен, но при изменении видения обновляются оба файла. Перед генерацией шагов обязательно читать `conductor/guides/lesson-design.md`.

## 1. Мета

- **Курс:** Fullstack-js; **модуль 5** (после «HTML & CSS»)
- **Длительность:** 5 проектов, ~5–6 недель (проект = 3–10 дней, ориентир — неделя)
- **Формат:** теорию преподаём сами (уроки-конспекты + шаги). В спарсенном наборе w3-js по DOM всего 4 страницы + 1 мини-проект — мало для курса; используем их как доп. чтение (§9)
- **Связка:** продолжение работы над проектом модуля 4. М4 (вёрстка с жёсткими данными) + М5 (логика) = одна большая задача: приложение «Портал предприятия». Студент начинает со своего свёрстанного портала из М4

## 2. Цель и результат модуля

**Цель:** студент оживляет свёрстанный портал на чистом JS: навигация, расчёт из данных страницы, поочерёдный перевод разделов на ввод с сохранением; в финале получает теорию двухслойной архитектуры (домен + ui) и основы проектирования (путь пользователя ui → домен → ui) и пробует применить их самостоятельно.

**Результат модуля:** работающее приложение «Портал предприятия»: переключение разделов из сайдбара, «Результат» считает из данных страницы по выбранному месяцу и отделу (с итогами по отделам и предприятию), все разделы редактируемые через формы, правки сохраняются в localStorage и восстанавливаются при загрузке. Плюс — самостоятельная попытка перестроить приложение по двухслойной архитектуре (домен + ui).

## 3. Архитектурный принцип модуля: HTML — источник данных

- Все данные приложения вшиты в HTML (М4). JS **читает данные из DOM**, считает чистыми функциями и выводит; при вводе — **правит DOM** и сохраняет правки в localStorage.
- Логика вывода («Результат») не меняется от этапа к этапу: она всегда парсит данные из HTML и строит таблицу по выбору месяца и отдела.
- Схема намеренно примитивна («DOM как база данных») — даёт прямое понимание взаимодействия HTML/CSS/JS/DOM и знакомит с browser API. Её ограничения и правильная альтернатива (двухслойная архитектура домен + ui) — предмет финального этапа (проект 5).

## 4. Ограничения (важно для всех уроков)

- **Ванильный JS.** Никаких фреймворков, библиотек, сборщиков, npm.
- **Без ООП.** Классы, `this`, методы в объектах не используем. Объекты — только структуры данных. Всё на функциях. ООП — будущие модули.
- **Запуск в браузере.** Проверка через страницу + DevTools Console. ES-модули требуют локального сервера (Live Server) — инструкцию дать в первом уроке.
- **Функции расчёта — отдельно от DOM-кода:** файл расчётов (например `calc.js`) подключается import'ом и не трогает DOM — единственное обязательное структурное требование модуля.
- **События — персональные:** обработчики на конкретных элементах (кнопка, форма, поле) через `addEventListener`. Глобальные шины и CustomEvent не используются. Обновление результата после изменений — прямым вызовом функции перерасчёта.
- **localStorage:** с первого перевода раздела на ввод (проект 3): правка → сохранить; загрузка → восстановить; сброс к исходным.

## 5. Контракт и свобода

**Мы даём (контракт):**
- состав разделов и их функциональность (§7, чек-листы проектов)
- формулы расчёта и эталонные данные (`concept.md` §4–§5): результат JS-расчёта должен воспроизводить вшитую таблицу §5.3
- последовательность теории и мини-заданий

**Студент решает (свобода):**
- способ открытия формы ввода (модалка или inline-панель) и её устройство
- какие написать функции, как их назвать, как разложить по файлам (в рамках требования §4)
- способ создания элементов (createElement или innerHTML)
- порядок и способ правки DOM при вводе

Следствие: у студентов разные работающие решения — норма; на ревью обсуждаем вариативность. В проекте 3 ведём за руку, в проекте 4 — самостоятельная работа по аналогии, в проекте 5 — свободное плавание.

## 7. Домен и расчёт

Ставки и правила — как в М1 (ИПН 10%, ОПВ 2%, валюта ₸). Полные формулы и эталонные данные — `concept.md` §4–§5.

**Расчёт сотрудника за месяц:**
1. Окладная часть: `salary × workedDays / workingDays`
2. Премия за полный месяц: `workedDays >= workingDays` → +10% от окладной части (переработка тоже даёт премию)
3. Выслуга (полные годы от `hiredAt` до 1-го числа расчётного месяца): ≥3 лет → +5%, ≥5 лет → +10% (не суммируются, берётся большая)
4. gross = 1+2+3; ИПН = 10% gross; ОПВ = 2% gross; net = gross − ИПН − ОПВ
5. Итоги: суммы по отделу; итог по предприятию — с разбивкой по отделам

**Округление:** точный расчёт, округление до целого ₸ (`Math.round`) — только при выводе. JS-результат должен воспроизводить эталонные таблицы `concept.md` §5.3: октябрь — против вшитой, сентябрь — против эталона (расхождения ±1 ₸ из-за порядка округления — допустимы и разбираются).

**Функции расчёта** (файл отдельно, без DOM): `calcEmployee(employee, salary, workedDays, workingDays, seniorityYears)` → `{ gross, ipn, ops, net }`; `calcDepartment(...)` → итоги по отделу/предприятию. Входные структуры собирает парсер DOM (в т.ч. месяцы и табель по месяцам).

## 8. Проекты и уроки

Именование папок: `data/fullstack-js/m5-dom/p<N>-l<M>-<kebab-name>/`. По каждому уроку: сначала `lesson.md` + `summary.md`; `steps.md` — отдельный этап.

**Цель:** DOM как дерево; поиск и изменение элементов; события click. Секции перестают быть потоком: JS показывает ровно одну — выбранную в сайдбаре.

| 2 | `p1-l2-find-elements` | Поиск элементов: querySelector, querySelectorAll; навигация по дереву | своя + [js_htmldom_navigation](https://www.w3schools.com/js/js_htmldom_navigation.asp.html) |
| 3 | `p1-l3-change-elements` | Изменение: textContent, classList (add/remove/toggle), скрытие секций | своя |

| 5 | `p1-l5-project-navigation` | **Проект:** клик по сайдбару переключает разделы | — |

**Результат проекта:** клик по пункту сайдбара показывает соответствующую секцию и скрывает остальные (до проекта все секции были видимы потоком — теперь ровно одна); активный пункт подсвечен. Первый живой JS студента в браузере.

### Проект 2. «Результат из данных страницы» (~1–1,5 недели)

**Цель:** чтение данных из DOM, разбор дат, функции расчёта, вывод. «Результат» оживает.

| № | Папка | Тема урока |
|---|---|---|
| 1 | `p2-l1-read-dom-data` | Чтение данных из DOM: textContent, trim, Number; обход строк таблицы |
| 2 | `p2-l2-parse-dates` | Даты: разбор `2022-03-01`, Date, полные годы стажа до расчётного месяца |
| 3 | `p2-l3-calc-functions` | Функции расчёта: перенос `calcEmployee` из М1, расширение (премии, выслуга); файл `calc.js` без DOM; итоги `calcDepartment` |
| 4 | `p2-l4-render-result` | Вывод в DOM: createElement/append, перезапись секции «Результат», округление при выводе; фильтры «месяц + отдел» (select, событие change, персональный обработчик) и пересборка таблицы по выбору |
| 5 | `p2-l5-project-result` | **Проект:** «Результат» собирается из данных страницы |

**Результат проекта:** «Результат» строится парсингом HTML остальных разделов по выбранному месяцу и отделу: строки сотрудников, ИТОГО по отделам и предприятию. Октябрь совпадает с вшитой таблицей `concept.md` §5.3, сентябрь — с эталоном; выбор месяца/отдела в фильтрах пересобирает таблицу. Вшитые числа можно удалить — JS их воспроизводит.

### Проект 4. «Все разделы на вводе» (~1 неделя)

**Цель:** самостоятельно, по аналогии с проектом 3, перевести «Табель» и «Сотрудников» на ввод.

| № | Папка | Тема урока |
|---|---|---|
| 1 | `p4-l1-timesheet-input` | Табель на вводе: правка дней по сотруднику за конкретный месяц (выбор месяца); тонкость — табель ссылается на сотрудников и месяцы (зависимость разделов) |
| 2 | `p4-l2-employees-input` | Сотрудники на вводе: добавление нового (широкая форма), правка, удаление строки (кнопка у строки — опционально); синхронизация с «Табелем» |

### Проект 5. «Как правильно» (~1–1,5 недели)

**Цель:** теория двухслойной архитектуры (домен + ui) и основ проектирования (путь пользователя ui → домен → ui) — в рамках этого приложения; свободное плавание.

| № | Папка | Тема урока |
|---|---|---|
| 1 | `p5-l1-data-vs-dom` | Данные и DOM: где должны жить данные; данные приложения как единственный источник правды; что видел пользователь vs что есть на самом деле |
| 2 | `p5-l2-domain-and-ui` | Двухслойная архитектура: домен (данные + чистые функции: данные → данные) и ui (рендер: данные → DOM; события: DOM → данные); путь пользователя ui → домен → ui; правило зависимостей `ui → домен`; сравнение с пройденным путём: чем «DOM как база» была хрупка |
| 3 | `p5-l3-project-free-swimming` | **Проект:** свободное плавание — перестрой приложение по двухслойной архитектуре (или по своему варианту). Защита: объяснить свои решения и что изменилось |

**Результат проекта (итог модуля):** приложение в варианте «как правильно» (или осознанном собственном) + защищённое понимание: где данные, где логика, где ui, кто от кого зависит. Ошибки допустимы и обсуждаются — это первый самостоятельный опыт проектирования перед модулями об ООП и архитектуре.

## 11. Правила генерации уроков (кратко; полно — `concept.md` §9, `lesson-design.md`)

- `lesson.md` пишем сами (теория наша); w3-страницы — доп. чтение в первом шаге урока. `summary.md` — выжимка 10–15 строк.
- Теория без видео: структурированный материал даём **шагами-теориями** и **обязательно закрепляем дополнительными заданиями** (мини-задание сразу после теории). w3-страницы — как доп. чтение, не заменяют свою теорию.
- Мини-задания: короткие js-фрагменты + проверка в браузере/DevTools; одна концепция, 1–3 минуты.
- Минимум один шаг «напиши по текстовой задаче» в уроке.
- **Только изученное:** DOM/JS-концепции не опережают свои уроки (порядок §8); запрещены классы, this, промисы, fetch, компоненты, CustomEvent. Студент умеет из М1–М2: функции, массивы, объекты-структуры, import/export, Git.
- Данные в примерах и заданиях — только эталонный набор `concept.md` §5.
- **Не подрывать драматургию:** до проекта 5 не критиковать схему «данные в HTML» в шагах и конспектах.
- Проектные уроки — постановка естественным языком по чек-листу, без готового кода. В проекте 4 готовых решений не давать (по аналогии с проектом 3); в проекте 5 — только теория и свобода.
- Всё на русском; файлы студента в kebab-case (`calc.js`, `read-employees.js`, `render-result.js`).
- Формат сумм — без разделителей в данных; форматирование вывода (пробелы, ₸) — опциональная полировка проекта 5.
