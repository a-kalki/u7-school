# Переиспользуемые стили: базовый класс и модификатор

**Краткое содержание:**
Одни и те же элементы повторяются — таблицы, кнопки, карточки. Переиспользуемые компоненты позволяют описать стили один раз и применять ко многим местам. Приём «базовый класс + модификатор» и область видимости (scope). Служебные классы для портала: числа по правому краю, жирные строки итогов. Наполняем последние секции — «Табель» и таблицу «Результата».

### Подробный конспект

#### 1. Идея компонента

В портале одни и те же элементы повторяются: таблиц уже несколько, будет ещё больше. Если стилизовать каждый элемент отдельно, файл разрастётся, а правки придётся делать в десяти местах.

**Компонент** — кусочек интерфейса с готовым набором стилей: карточка, кнопка, таблица, бейдж. Компонент описывают один раз классом, а потом ставят этот класс на все похожие элементы. Ключевое слово — **область видимости (scope)**: правило компонента должно задевать только его элементы и не «протекать» на соседей. Поэтому селектор `.btn` точнее, чем свободный `button`.

#### 2. Базовый класс и модификатор

Разные кнопки похожи, но отличаются оттенком. Вместо двух независимых классов делают **базовый + модификатор**:

```css
.btn {
  padding: 8px 16px;
  border: 1px solid #2b5fd9;
  background: #2b5fd9;
  color: #fff;
}

.btn-ghost {
  background: transparent;
  color: #2b5fd9;
}
```

В разметке: `class="btn btn-ghost"` — базовый класс отвечает за форму и отступы, модификатор меняет только отличие.

**Сделай:** сделай две кнопки — главную и «прозрачную»; общие свойства в `.btn`, различия в модификаторах.

**Получишь:** две кнопки одинаковой формы, но разного веса. Правка общего свойства в одном месте меняет обе.

#### 3. Наш случай: классы для таблиц

В портале много таблиц, и у них есть повторяющиеся особенности:

- **числовые ячейки** выравнивают по правому краю — разряды выстраиваются, суммы сравниваются мгновенно (приём из p2-l3);
- **строки итогов** выделяют жирным;
- строку с названием компании (в «Календаре») — приглушённым цветом.

Для этого заведём **служебные (utility) классы** — маленькие классы «на одно свойство»:

| Класс | Что делает | Где применяем |
|---|---|---|
| `num` | числа по правому краю | все числовые ячейки и их заголовки |
| `total-row` | жирный текст строки | строки ИТОГО |
| `company` | приглушённый текст | название компании в «Календаре» |

**Сделай:** заведи классы в `styles.css`: `num` — на столбец «Оклад» в «Штате», `company` — на строку с названием предприятия, а в строке «Итого» **убери `<strong>`** и повесь `total-row` на `<tr>`.

**Почему класс, а не `<strong>`:** `<strong>` — смысловой тег «важно» и умеет только жирный, а строка итога — это роль: класс вешается на строку один раз и позволяет добавлять любые свойства через `.total-row td`.

**Получишь:** числа в «Штате» встали по правому краю, а строка «Итого» стала жирной через класс, а не `<strong>`.

### Термины урока

- **компонент** — от лат. `componentis` — «составляющий»: переиспользуемый кусок интерфейса со своим набором стилей
- **scope** — от греч. `skopos` — «цель, кругозор»: область видимости стилей: кого задевает правило
- **базовый класс** — общие стили компонента
- **модификатор** — от лат. `modificare` — «изменять»: класс, меняющий одно отличие компонента
- **utility-класс** — от англ. `utility` — «полезность»: служебный класс «на одно свойство»: `num`, `total-row`
- **BEM** — от `Block Element Modifier` — «блок, элемент, модификатор»: соглашение именовать классы по роли
- **`colspan`** — от англ. `column` — «колонка» + `span` — «охват»: объединение ячеек по горизонтали
