# Проект 2: оформленная визитка

**Краткое содержание:**
Финал проекта 2. Стили накапливались по ходу уроков: карточка, палитра, типографика, токены. Осталась одна зона без оформления — таблица. Доводим её по нормам, сверяем визитку с растром-образцом от ментора и отправляем проект на код-ревью через pull request.

### Что делаем

Визитка уже почти оформлена: карточка на сером фоне (p2-l2), палитра и типографика (p2-l3), токены (p2-l4). Единственная «голая» зона — таблица штатного расписания. В этом уроке оформляем её, сверяем результат с образцом и сдаём работу.

### Оформляем таблицу

Открой визитку и посмотри на таблицу: ячейки слиплись, шапка ничем не отличается от данных. У таблицы на твоей странице должно стать так:

- **границы** — у всех ячеек (и заголовочных, и обычных), толщиной 1px, цветом границ; соседние границы слиты в одну линию;
- **воздух в ячейках** — внутренний отступ 4px по вертикали и 8px по горизонтали;
- **текст ячеек** — по левому краю;
- **шапка таблицы** (`thead`) — фон как у страницы, чтобы зрительно отделиться от данных;
- строка «Итого» уже выделяется жирным — это сделал `<strong>` в HTML, стили ей не нужны.

Вот готовый код — добавь его в конец `styles.css` (все токены тебе знакомы из p2-l4):

```css
table {
  width: 100%;                              /* на всю ширину карточки */
  border-collapse: collapse;                /* соседние границы сливаются в одну линию (p2-l2) */
}

th, td {
  border: 1px solid var(--color-border);    /* сетка: тонкая рамка цветом границ */
  padding: var(--space-1) var(--space-2);   /* воздух в ячейках: 4px по вертикали, 8px по горизонтали */
  text-align: left;                         /* текст ячеек по левому краю */
}

thead th {
  background: var(--color-bg);              /* шапка на фоне страницы — зрительно отделяется */
}
```

**Сделай:** сохрани и обнови страницу.

**Получишь:** таблица с ровной сеткой границ, дышащими ячейками и выделенной шапкой. Страница выглядит законченной.

Хочешь понять, а не просто скопировать: в DevTools → Styles снимай галочки с правил по очереди — сразу видно, за что каждое отвечает.

**Сделай:** (проверка каскада) в DevTools → Styles выбери любую `td` и посмотри, какие правила на неё действуют.

**Получишь:** видишь свои правила из `styles.css` — и ничего инлайн. Если видишь перечёркнутые строки — где-то спор правил; разберись, кто победил и почему.

### Сверка с образцом

Открой рядом: свою визитку и растр `p2-visit-card-styled`, который ментор выдал в начале проекта. Сверяй зону за зоной.

**Сделай:** пройди по списку и по растру. Что-то отличается — найди правило, которое за это отвечает (DevTools → Styles в помощь), и поправь. Не обязательно делать как в образце, хочешь что то сделать по другому, делай, это твой проект.

**Получишь:** твоя страница визуально сопоставима с образцом: те же зоны, та же палитра, та же сетка. Мелкие отличия допустимы — они и интересны на ревью: сравним, кто как применил одни и те же нормы.

### Чек-лист самопроверки

- [ ] В `styles.css` первым правилом — `* { box-sizing: border-box }`, затем блок `:root` с токенами
- [ ] Ни одного сырого цвета или отступа вне `:root` — всё через `var()` (проверь поиском `#` и `px`)
- [ ] Карточка: белая, рамка, padding 24, max-width 680, по центру
- [ ] `h1` 24px; `h2` 18px акцентные; описание приглушённое; таблица с сеткой и выделенной шапкой
- [ ] Смена `--color-accent` перекрашивает оба `h2` (проверь и верни как было)
- [ ] В DevTools → Styles стили приходят только из `styles.css`
- [ ] Данные не менялись: все числа и тексты из проекта 1 на месте

### Термины урока

- **border-collapse** — от англ. `border` — «граница» + `collapse` — «схлопывать»: соседние границы ячеек сливаются в одну линию
- **инлайн** — от англ. `inline` — «в строке»: проверка каскада: в Styles видно, что стили не инлайн, а из styles.css (не путать с инлайн-элементами p1-l3)
- **токен** — от англ. `token` — «жетон, знак»: проверка: в файле ноль сырых значений вне `:root` — всё через токены
- **ревью** — от англ. `review` — «обзор, повторный просмотр»: работу смотрят другие студенты потока и оставляют замечания
- **апрув** — от англ. `approve` — «одобрять»: отметка в PR «код можно принять»; для мерджа нужно две

### Куда это растёт

Токены, заведённые здесь, — дизайн-система портала: в проекте 3 они переезжают в каркас приложения без изменений. Визитка встретится с ними ещё раз: её содержимое (название, таблица расписания) переедет в портал, а описание компании останется жить на визитке.
