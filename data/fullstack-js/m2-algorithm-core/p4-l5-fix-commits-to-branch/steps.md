# Шаги урока: Fix-коммиты в ветку

---

### Правки прямо в feature-ветке

**kind:** `text`

Делай правки прямо в feature-ветке (PR обновится автоматически). Отдельная ветка для фиксов не нужна.

```
git switch feat/string-comparison
```

Внеси исправления. Для каждого исправления — отдельный коммит с осмысленным сообщением (но можно и группировать и/или делать один комит на все коменты, зависит от стиля, количества изменений, ...):

```
git add string-utils/is-more.js
git commit -m "Исправить проверку на пустую строку в isMore"
```

Примеры хороших commit-сообщений для правок:
- `Исправить проверку типов в isEqual`
- `Добавить тест на префиксный случай в isLess`
- `Убрать дублирующийся код проверки типов`
- `Поправить имена аргументов для ясности`

После всех правок:

```
git push
```

(Без `-u` — связь с удалённой веткой уже настроена.)

**Термины:**
fix-коммит — отдельный коммит с исправлением по ревью;
Resolve conversation — кнопка закрытия обсуждения под комментарием

---

### Ответы на комментарии

**kind:** `text`

На каждый комментарий ревьюера нужно ответить.

**Шаблоны ответов:**

Если исправил:
```
Исправил, добавил проверку на пустую строку. Спасибо, что заметил!
```

Если не согласен и объясняешь:
```
Оставил как есть, потому что [причина]. [Ссылка на документацию или логическое объяснение].
```

Если комментарий — предложение, и ты его принял:
```
Хорошая идея, переименовал. Так действительно понятнее.
```

После ответа нажми **Resolve conversation** (кнопка под комментарием) — это покажет, что вопрос закрыт.

Все критические замечания исправлены, все conversations resolved? Переходи к следующему уроку — запрос повторного ревью.
