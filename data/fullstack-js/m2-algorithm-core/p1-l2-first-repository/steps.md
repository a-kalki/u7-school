### Инициализация репозитория и git init

**kind:** `text`

Изучи материал по началу работы с Git:

- [Git Get Started](https://www.w3schools.com/git/git_getstarted.asp) — инициализация репозитория, `git init`
- [Git Ignore](https://www.w3schools.com/git/git_ignore.asp) — файл `.gitignore`

**Термины:**
`git init` — команда, превращающая обычную папку в git-репозиторий;
`.gitignore` — текстовый файл со списком того, что Git должен игнорировать;
Untracked files — «неотслеживаемые» файлы: Git их видит, но в историю они пока не попадают

После прочтения перейди в папку с проектами где ты содаешь и работаешь с учебными материалами, например: `cd ~/dev/`.

Создай свой первый репозиторий:

```
mkdir js-algorithms
cd js-algorithms

# создаем в папке проекта гит репозиторий (скрытая папка `.git`):
git init
```

Создай начальные файлы:

```
# Linux / macOS / Git Bash:
touch .gitignore

# Windows (cmd):
type nul > .gitignore
```

### Проверь имя основной ветки

**kind:** `text`

Сразу после `git init` проверим, как называется твоя основная ветка:

```
git branch --show-current
```

Для этого курса имя основной ветки должно быть **`main`** — это современный стандарт, его использует GitHub по умолчанию.

- Если увидел `main` — всё в порядке, иди дальше
- Если увидел что-то другое, то выдай ИИ ассистенту (например ChatGPT) промпт: "Я выполнил `git init`, но основная ветка называется не main. Как переименовать текущую ветку в main? И настроить чтобы команда `git init` создавала эту ветку по умолчанию?".  
Возможно нужно указать свою операционную систему и используемый терминал.

Добейся, чтобы `git branch --show-current` показывал `main`.

Почему мы не даём готовую команду: чем дальше мы будем идти по учебе, тем сложнее проблемы тебе нужно будет решать самостоятельно.

### Настройка .gitignore

**kind:** `text`

Настрой `.gitignore` — открой его в редакторе и добавь:

```
node_modules/
.env
.DS_Store
dist/
```

Проверь, что Git видит файлы:

```
git status
```

Ты должен увидеть `.gitignore` в секции **Untracked files**.

Других файлов не будет, мы добавили другие исключения для примера. Ты можешь проверить что `.gitignore` работает добавив нужные папки и файлы и снова запустив `git status`, папки и файлы из `.gitignore` не должны появиться.
