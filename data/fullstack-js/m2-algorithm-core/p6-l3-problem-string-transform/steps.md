# Шаги урока: Проблема: трансформация строк

---

### Состав API проекта — 8 функций

**kind:** `text`

Первые два проекта дали тебе посимвольное сравнение и поиск подстрок. Следующая ступень — **трансформация**: функции, которые из исходной строки получают новую строку. Извлечь часть, обрезать пробелы, заменить вхождение, дополнить до длины, поменять регистр.

**Состав API проекта — 8 функций:**

| Функция | Что делает |
|---------|-----------|
| `substring(str, start, end)` | подстрока от start до end с нормализацией индексов |
| `slice(str, start, end)` | подстрока с поддержкой отрицательных индексов |
| `trim(str)` | строка без пробелов в начале и конце |
| `replace(str, search, replacement)` | замена первого вхождения |
| `replaceAll(str, search, replacement)` | замена всех вхождений |
| `pad(str, length, char, side)` | дополнение строки символами до длины |
| `upperCase(str)` | перевод в верхний регистр (латиница и кириллица) |
| `lowerCase(str)` | перевод в нижний регистр (латиница и кириллица) |

Все функции живут в уже знакомой папке `string-utils/`.

**Термины:**
трансформация — операция, которая из исходной строки получает новую строку; сама исходная строка при этом не меняется (строки в JS иммутабельны)

### Правила реализации

**kind:** `text`

Правила те же, что в проектах 3 и 5:

- **Запрещены встроенные методы строк** и свойство `.length` — только `len(str)` из своего проекта 3 и посимвольная обработка
- Для `upperCase`/`lowerCase` разрешены `charCodeAt()` и `String.fromCodePoint()` — они понадобятся для работы с кодами символов
- **TDD-цикл для каждой функции:** заглушка → JSDoc → тесты (RED → GREEN → REFACTOR) → коммит
- **JSDoc сразу после заглушки** — правило прошлого урока действует для всех 8 функций

### Ветка проекта — обязательна для нового кода

**kind:** `text`

Докстринги ушли прямо в main: там код проектов 3 и 5. Но **новый код всегда идёт в отдельной ветке** — правило «один проект — одна ветка» остаётся в силе. Начинаем от свежего main (если ветка предыдущего проекта ещё не смержена — отпочковывайся от нее):

```
git switch main
git pull origin main
git switch -c feat/string-transform
```

Проверь: `git branch --show-current` → `feat/string-transform`.

Дальше — по накатанной: TDD-цикл для каждой функции, коммит после каждой, push и PR в конце проекта.
