# Шаги урока: Первый коммит

---

### Git Commit: создание коммитов

**kind:** `text`

Изучи материал по коммитам в Git:

- [Git Commit](https://www.w3schools.com/git/git_commit.asp) — создание коммитов, `git add`, `git commit`, `git log`

**Термины:**
`git add` — добавить изменения в stage (подготовить к коммиту);
stage (индекс) — «полка» подготовки: то, что войдёт в следующий коммит;
`git commit` — зафиксировать подготовленное как коммит;
коммит-сообщение — пояснение к коммиту, по которому история читается без открытия кода;
`git log` — просмотр истории коммитов

### Правила хорошего commit-сообщения

**kind:** `text`

Хорошие сообщения — половина пользы от Git: по истории можно понять, что и зачем менялось, не открывая код. Эти правила будут проверять и ревьюеры.

**Главное правило — инфинитив (повелительное наклонение):**
Коммит в Git — это не запись в личном дневнике («я вчера сделал»), а самостоятельный патч-инструкция, который изменяет репозиторий. Поэтому общепринятый стандарт commit conventions требует формулировать сообщение как действие:
- **Отвечай на вопрос «Что сделать?»** (инфинитив): «Добавить», «Реализовать», «Исправить», «Обновить».
- **Мысленная подсказка:** начни фразу с «Этот коммит должен (что сделать?) → ...»:
  - *«Этот коммит должен: Добавить .gitignore»* ✅
  - *«Этот коммит должен: Реализовать функцию len»* ✅
  - *«Этот коммит должен: Исправить проверку пустых строк»* ✅

**Почему НЕ прошедшее время?**
Формы прошедшего времени («Добавил», «Сделана», «Реализована», «Исправлено») считаются плохим тоном: они создают разнобой в родах и лицах («добавил» / «добавила») и противоречат природе Git-патча.

**Краткость и понятность:**
- Кратко — первая строка до 72 символов
- Понятно без контекста: **что** сделано, а не **как**

Примеры:

```
✅ Добавить .gitignore
✅ Реализовать isMore — лексикографическое сравнение
✅ Исправить обработку пустых строк в isEqual
❌ Добавил .gitignore (прошедшее время)
❌ Реализован isMore (прошедшее время)
❌ fix / обнова / чё-то поменял (бессмысленно без контекста)
```

### Сделай первый коммит

**kind:** `text`

**Добавление файлов в stage**

Есть несколько вариантов команды `git add`:

```
# Добавить конкретный файл (рекомендуется — точно знаешь что коммитишь)
git add .gitignore

# Добавить все файлы в текущей папке и подпапках
git add .

# Добавить все файлы в репозитории (где бы ты ни находился)
git add -A
```

Перед коммитом всегда проверяй что попало в stage:

```
git status
```

Зелёным подсвечены файлы готовые к коммиту, красным — изменённые но не добавленные.

**Создание коммита**

```
git commit -m "Добавить .gitignore"
```

Флаг `-m` позволяет написать сообщение прямо в командной строке. Если опустить `-m`, Git откроет текстовый редактор для ввода сообщения.

Проверь результат:

```
git log --oneline
```

### История коммитов: git log

**kind:** `text`

Ты сделал первый коммит — посмотри на историю:

```
git log --oneline
```

Пока в ней одна строка. Попробуй также:

```
git log -3           # последние 3 коммита
git log --graph      # графическое представление (пока одна ветка — main)
```

Эта история будет расти с каждым уроком. По ней ревьюеры (и ты сам через месяц) смогут понять, что и когда происходило в проекте.
