# Сложность алгоритмов: O-нотация

**Краткое содержание:**
O(1), O(n), O(n²), O(log n), O(n log n). Анализ своих функций. Правила оценки.

**Время:** ~20 мин

**Основные темы:**
- Зачем вообще оценивать сложность
- O-нотация — язык сложности
- O(1) — константная сложность
- O(n) — линейная сложность
- O(n²) — квадратичная сложность
- O(n log n) — сложность твоей quickSort
- O(log n) — логарифмическая сложность
- Как оценить сложность — три правила
- Вопросы на понимание
- Оцени свои функции
- Сохрани понимание
- Термины урока

**Термины:**
* **Сложность алгоритма** — оценка того, как растёт время работы при увеличении объёма данных.
* **O-нотация (Big O)** — язык записи верхней границы роста алгоритма: «во сколько раз дольше при росте данных».
* **O(1) (константная)** — время работы не зависит от размера данных.
* **O(log n) (логарифмическая)** — каждый шаг отбрасывает половину данных (например, `binarySearch`).
* **O(n) (линейная)** — время растёт пропорционально размеру данных (обычно один цикл).
* **O(n log n) (линейно-логарифмическая)** — например, `quickSort` в среднем случае.
* **O(n²) (квадратичная)** — вложенный цикл; при удвоении n время растёт примерно в 4 раза.
* **Порядок роста** — как время зависит от n после отбрасывания констант и младших членов.
