# Шаги урока: Ревьюим чужой homework-PR

---

### Найди PR для ревью

**kind:** `text`

Открой общий чат и найди сообщения с чужими PR (🔍 «PR на ревью» / закреплённые сообщения). Правила выбора:

- **Не свой** PR — очевидно, но упомянем
- Если у большинства уже есть ревью — выбери PR, у которого **меньше всего** ревью и апрувов: там твоя помощь нужнее всего
- Если у всех уже есть по двум и более апрувам, не повод чтобы не делать ревью. Делать ревью, это полезно и нужно не только автору PR, но и тебе. Ты развиваешь через этот процесс свои навыки
- Открыл ссылку → вкладка **Files changed** — так ты увидишь, что именно изменилось, а не просто файл целиком

**Термины:**
Files changed — вкладка PR с diff: какие строки изменены;
построчный комментарий — комментарий, привязанный к конкретной строке diff

### Проведи ревью по памятке

**kind:** `text`

Пройдись по текстовому чек-листу из урока 2:

1. **Полнота:** есть ли все разделы — «Кто я», цели на модуль, конспекты?
2. **Структура:** заголовки по уровням, списки там, где перечисления?
3. **Markdown:** чекбоксы и форматирование отрисуются на GitHub? (смотри вкладку Preview или Files changed)
4. **Читаемость:** нет ли «простыней» текста, опечаток?

Запиши минимум **одно содержательное предложение** в формате:

```
Предлагаю X, потому что Y.
```

«Содержательное» — значит про конкретное место в файле. «Круто сделано!» — приятно, но это не ревью (хотя если действительно увидел полезное решение, то отметь это. Ревью это не только про ошибки, но и про удачные решения).

Если нашёл настоящую проблему (раздел пропущен, файл не отрисовывается) — это критическое замечание: «Нужно X, потому что Y».

**Как оставить комментарий:** в Files changed наведи на строку → появится синий плюс → пиши.

### Заверши ревью и ответь на вопросы

**kind:** `text`

Закончи ревью вердиктом через **Review changes**:

- Только предложения → **Approve** — да, ты как студент спокойно можешь ставить апрув, так и задумано
- Нашёл проблему → **Request changes** + объясни, что автор должен исправить, чтобы получить апрув
- Нечего сказать по существу → **Comment**

Затем ответь на вопросы (в конспект или вслух):

1. Что было сложнее — найти предложение или критическое замечание? Почему?
2. Ты поставил Request changes. Что автор должен сделать, чтобы получить твой апрув?
3. Что полезного из чужого homework.md ты можешь перенести в свой?

Если ревьюить было страшно — нормально. Формула: изучить файлы внимательно + «действие + потому что» + доброжелательный тон — всё, что требуется.
