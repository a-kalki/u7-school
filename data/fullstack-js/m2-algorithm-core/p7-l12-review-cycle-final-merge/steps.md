### Ревью-цикл: напоминания

**kind:** `text`

Полная методика — в проекте 4 (уроки 4–6). Короткий ориентир:

1. **Пришли комментарии** → раздели на 🐛 баги / 🎨 стиль / 📝 документацию / 💡 предложения, определи позицию по каждому
2. **Правки** → прямо в `feat/array-basics`, одно исправление = один коммит, затем `git push`
3. **Ответы** → на каждый комментарий + Resolve conversation
4. **Re-request review** → иконка 🔄 у ревьюеров + сообщение в чат
5. **2 апрува + все resolved** → переходи к мержу

На что особенно смотреть в этом PR: у мутабельных функций отмечена мутабельность в JSDoc? В тестах проверяется и возврат, и состояние массива? Нет ли тестов, зависящих друг от друга?

### Мерж и чистка

**kind:** `text`

Когда 2 апрува собраны и всё resolved (и `bun test` зелёный локально):

1. GitHub → **Merge pull request** → **Merge commit** → **Confirm merge** → **Delete branch**
2. Локально:

```
git switch main
git pull origin main
git branch -d feat/array-basics
git fetch --prune
git branch -a
```

Проверь по `git log --oneline`: 9 функций — в `main`.

Ответь на вопросы (устно или в конспекте):
