# Шаги урока: Как читать чужой код

---

### Порядок чтения: сигнатура → тесты → реализация

**kind:** `text`

Чужой код читают не подряд, а в правильном порядке:

1. **Сигнатура.** Как функция называется, что принимает, что возвращает? Уже из описания должно быть понятно назначение. Сверься со спецификацией задачи
2. **Тесты.** Пролистай тестовый файл — описания тестов это «спецификация на человеческом языке». Какие случаи покрыты? Каких нет?
3. **Реализация.** Теперь читай код. Ты уже знаешь, что должна делать функция и какие случаи обещаны тестами — сверяй реальность с обещаниями

**Термины:**
сигнатура (или контракт) — имя функции, её аргументы и возвращаемое значение;
спецификация — описание ожидаемого поведения функции;
дублирование — повторение одного и того же кода в нескольких местах

### На что смотреть

**kind:** `text`

При чтении держи в голове пять вопросов (это чек-лист ревью кода из проекта 2):

1. **Корректность.** Работает ли логика на «нормальных» данных? Мысленно прогони тест вручную: возьми пример, пройди цикл по шагам
2. **Граничные случаи.** Пустая строка? Строка из пробелов? Код различает `'A'` и `'a'`? Аргументы не-строки дают `TypeError`?
3. **Правила модуля.** Нет ли запрещённых методов (`.length`, `.indexOf()`, `.includes()`...)? Нет ли прямого сравнения длинных строк?
4. **Читаемость.** Понятны ли имена (`code1` vs `charCodeA`)? Нет ли дублирования, которое просится в функцию?
5. **Тесты.** Покрыты ли все граничные случаи? Нет ли тестов, которые всегда проходят?

Всё, что ты находишь, формулируй по правилам: «Предлагаю X, потому что Y» / «Нужно X, потому что Y».

### Чем ревью кода отличается от ревью текста

**kind:** `text`

В проекте 2 ты ревьюил текст (homework.md). Код — другое:

- **Можно выполнить.** Тесты можно запустить локально, а логику — мысленно прогонять по шагам. Не стесняйся открыть редактор и проверить сомнительный случай
- **Есть однозначный критерий.** Текст может быть «просто со вкусом другим», а код либо проходит тест, либо нет
- **Цена ошибки выше.** Пропущенный баг в тексте — опечатка; пропущенный баг в коде — сломанная функция у всех, кто её использует
- **Формулируй точнее.** «Код не работает» — это не ревью. «`isLess('a', 'ab')` вернёт `true`, а должна `false`, потому что префикс совпадает» — это ревью

### Практика: мысленный прогон

**kind:** `text`

Возьми любой свой тест из `string-utils` (например, граничный случай isEqual) и мысленно прогони свою реализацию по шагам: с каким аргументами вошла, что происходит на каждой итерации цикла, что вернулась. Запиши, где было трудно удержать в голове — это и есть места, где ревьюер будет смотреть особенно внимательно.
