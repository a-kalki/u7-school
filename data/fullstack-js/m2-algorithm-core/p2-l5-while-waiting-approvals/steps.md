# Шаги урока: Пока ждёшь апрувы

---

### Следи за чатом и уведомлениями

**kind:** `text`

Пока PR ждёт ревью, твоя задача — не пропустить, когда придут комментарии. Следить нужно в двух местах:

- **Общий чат:** обычная практика в командах, как сделал ревью написать в чате: "Сергей, твой PR отревьюен мной."
- **GitHub:** вкладка **Pull requests** в твоём репозитории показывает активность; иконка колокольчика (Notifications) — уведомления о комментариях и ревью; продублируются на почту

Проверь настройки: на GitHub открой Settings → Notifications и убедись, что уведомления о **Participating and @mentions** включены. Настройки можешь спросить у ИИ-ассистента, если что-то непонятно.

Важный принцип: **за свой PR отвечаешь ты**. Никто не будет персонально звать тебя посмотреть комментарии. Максимум, напишут что сделали ревью.

**Термины:**
notification — уведомление GitHub или почты о событии в твоём PR;
эскалация — постепенное усиление напоминаний: личка → чат → другой ревьюер → ментор

---

### Что делать, если ревьюер не отвечает

**kind:** `text`

Код-ревью зависит от людей, а люди иногда заняты. Запомни алгоритм:

1. **Через 1–2 дня:** вежливое напоминание в личку или чат: «Привет, посмотри PR, пожалуйста»
2. **Ещё через день:** пингануть в общем чате: «@username, жду ревью на PR»
3. **Если тишина:** найти другого ревьюера (правило модуля — 2 апрува, не обязательно от тех же людей)
4. **Крайний случай:** сообщить ментору, будет разбор в команде и командной работе

Главное — не молчать неделю. Вежливое напоминание — это нормально.

И в обратную сторону тоже: если тебя просят посмотреть чужой PR — не тяни. Скорость ревью в группе складывается из скорости каждого.
