# Шаги урока: Как работает код-ревью

---

### Зачем нужно ревью, если код и так работает

**kind:** `text`

«У меня всё работает — зачем кто-то должен это проверять?» — самый частый вопрос новичка. Вот что даёт ревью на самом деле:

- **Вторая пара глаз.** Автор всегда «слеп» к своим ошибкам: он знает, что *хотел* написать, и читает то, что имел в виду. Ревьюер читает то, что написано на самом деле
- **Знание не оседает в одной голове.** Если файл знает только автор, его уход = потеря знаний. После ревью код понимают минимум двое
- **Обучение в обе стороны.** Ревьюер видит чужие приёмы, автор — чужие стандарты. Это самый быстрый способ вырасти в команде
- **Дисциплина.** Зная, что код прочитает живой человек, пишешь аккуратнее: имена понятнее, история коммитов чище

Ревью — это не «поиск виноватых» и не бюрократия. Это совместная работа над качеством: автор и ревьюер по одну сторону баррикад, а по другую — проблема в коде.

**Термины:**
код-ревью — по англ. `code review`: проверка изменений другими людьми до слияния;
ревьюер — по англ. `reviewer`: тот, кто проверяет чужие изменения;
автор — создатель PR, тот, кто вносил изменения;
уведомление — по англ. `notification`: сигнал о событии (комментарий, ревью) на GitHub или в почте

### Как работает код-ревью на GitHub

**kind:** `text`

Изучи механику код-ревью на GitHub:

- [GitHub Send Pull Request](https://www.w3schools.com/git/git_remote_send_pull_request.asp) — раздел про ревью

После прочтения ответь себе:

1. Какие три действия может выбрать ревьюер при завершении ревью: Comment, Approve, Request changes. Чем они отличаются?
2. Может ли автор PR смержить его сам, если ревьюер поставил Request changes?
3. Что произойдёт с комментариями ревьюера после того, как автор исправит код? Останутся ли они в PR?

### Кто такие ревьюеры в нашем курсе

**kind:** `text`

В нашем курсе ревьюеры — это **другие студенты группы и менторы**. Механика у нас своя, живая:

- Создал PR → выложил сообщение со ссылкой в общий чат («нужны 2 апрува»)
- Любой участник чата может открыть твой PR и отревьюить
- Собрал 2 апрува → сам делаешь мерж

Тебе предстоит побывать в обеих ролях: и автора (твой homework-PR уже ждёт ревью), и ревьюера (чужие PR висят в том же чате).

**Карта проекта 2:** сначала правила ревью, потом тренировка на образце, затем настоящее ревью чужого PR — и финальный мерж своего.
