### Проблема: какое API мы строим

**kind:** `text`

До сих пор ты пользовался встроенным API строк JavaScript. Теперь — строим **своё**: библиотеку `string-utils` с функциями сравнения строк, с нуля.

Сравнение строк — одна из фундаментальных операций в программировании: сортировка списков, поиск, валидация данных — всё это в итоге сводится к сравнению. Именно поэтому оно — отличный первый проект на TDD.

**API проекта — 7 функций:**

| Функция | Что делает |
|---------|-----------|
| `len(str)` | длина строки |
| `isEqual(a, b)` | равны ли строки |
| `isNotEqual(a, b)` | не равны ли строки |
| `isMore(a, b)` | `a` лексикографически больше `b` |
| `isLess(a, b)` | `a` лексикографически меньше `b` |
| `isMoreOrEqual(a, b)` | `a` больше или равна `b` |
| `isLessOrEqual(a, b)` | `a` меньше или равна `b` |

**Как работаем:** по методологии TDD — сначала тест, потом код. Каждый шаг будет заканчиваться коммитом, чтобы к концу проекта у тебя была осмысленная история изменений.

**Термины:**
API — по англ. `Application Programming Interface`: набор готовых функций, которыми пользуется разработчик;
библиотека — набор переиспользуемых функций, собранных в отдельных файлах;
TDD — по англ. `Test-Driven Development`: разработка «от теста» — сначала тест, потом код;
зелёные тесты — все проверки прошли (цвет галочек в выводе `bun test`)

**Результат проекта:** ветка `feat/string-comparison` с 7 реализованными функциями и зелёными тестами, созданный PR (его ревью — тема проекта 4).

Но прежде чем писать код — правила игры. Они жёсткие, и это неспроста.

### Правила реализации функций

**kind:** `text`

Перед тем как писать код — важные правила. В этом модуле ты реализуешь функции-аналоги встроенного API JavaScript **с нуля**, поэтому использование готовых методов и свойств **запрещено**.

**Запрещённые свойства:**
- `.length` у строк и массивов — используй свою `len(str)` или `len(arr)`

**Запрещённые методы строк:**
- `.toUpperCase()`, `.toLowerCase()`, `.indexOf()`, `.includes()`, `.slice()`, `.substring()`, `.trim()`, `.replace()`, `.replaceAll()`, `.repeat()`, `.padStart()`, `.padEnd()`, `.charAt()`, `.startsWith()`, `.endsWith()` — и любые другие
- **Исключение:** `.charCodeAt()` и `String.fromCodePoint()` **разрешены** (понадобятся для получения кодов символов — см. урок 4 этого проекта)

**Запрещённые методы массивов:**
- `.push()`, `.pop()`, `.unshift()`, `.shift()`, `.indexOf()`, `.lastIndexOf()`, `.includes()`, `.fill()`, `.reverse()`, `.concat()`, `.slice()`, `.join()`, `.splice()`, `.flat()`, `.forEach()`, `.map()`, `.filter()`, `.some()`, `.every()`, `.find()`, `.findIndex()`, `.reduce()` — и любые другие

**Запрещённые операторы:**
- Нельзя сравнивать строки длиннее 1 символа напрямую: `'hello' > 'world'`, `'abc' === 'def'` — только **посимвольно**
- Одиночные символы сравнивать можно: `'a' < 'b'`, `str[i] === 'x'`

**Разрешено:**
- Прямое обращение по индексу: `str[i]`, `arr[i]`
- Сложение строк: `result += current`, `str = str + ' '`
- Операторы сравнения чисел: `<`, `>`, `===`, `!==`
- `delete` для удаления элементов массива
- Циклы: `for`, `while`
- Условия: `if/else`
- Исключения: `throw`, `try-catch`
- `typeof` для проверки типов

Если сомневаешься, можно ли использовать какой-то метод — **нельзя**. Всё, что ты реализуешь, ты должен написать сам.

Ревьюеры в проекте 4 будут проверять соблюдение этих правил — оно входит в чек-лист ревью.

### Рабочий цикл проекта и создание ветки

**kind:** `text`

Весь проект идёт в одной feature-ветке — цикл тебе знаком:

```
ветка feat/string-comparison → коммиты после каждой функции → push → PR → сообщение в чат
```

**Создай ветку от свежего main** (сам, ты это уже делал дважды):

```
git switch main
git pull origin main
git switch -c feat/string-comparison
```

Проверь: `git branch --show-current` → `feat/string-comparison`.

В этой ветке ты проработаешь весь проект. Коммиты — после каждой функции (они будут в шагах уроков). Push и PR — в конце проекта, уроком 8.
