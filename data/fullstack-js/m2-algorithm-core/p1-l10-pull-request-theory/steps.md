### Теория Pull Request

**kind:** `text`

Изучи, что такое Pull Request и GitHub Flow:

- [GitHub Flow](https://www.w3schools.com/git/git_github_flow.asp) — как устроен рабочий процесс
- [GitHub Send Pull Request](https://www.w3schools.com/git/git_remote_send_pull_request.asp) — создание PR

**Термины:**
Pull Request (PR) — просьба влить ветку в `main` + площадка для обсуждения изменений;
GitHub Flow — рабочий процесс: ветка → коммиты → push → PR → ревью → мерж;
код-ревью — проверка изменений другими людьми до слияния;
мерж — по англ. `merge`: слияние ветки в `main`;
diff — разница между версиями: красным удалённые строки, зелёным добавленные

После прочтения ответь себе:

1. Что такое Pull Request? Чем он отличается от простого `git push`?
2. Зачем нужно код-ревью, если код и так работает? Почему компании тратят время разработчиков на проверку чужого кода?
3. Опиши своими словами шаги GitHub Flow: от создания ветки до мержа.

> Если приходят новые осознания в ходе работы над уроками, то можешь закрепить их в файле `homework.md`, в процессе записи идет улучшение понимания и запоминания

### Вопросы на понимание

**kind:** `text`

Ответь на вопросы:

1. Почему Pull Request создают **из ветки в `main`**, а не работают с коммитами прямо в `main`? (Подсказка: что видит ревьюер, если изменения изолированы в ветке?)
2. Представь, что ревьюер попросил исправить ошибку. Ты внёс правки в ту же ветку, сделал коммит и `git push`. Нужно ли создавать новый PR? Почему?
3. Почему GitHub показывает **diff** (какие строки изменились), а не просто список файлов? Зачем это ревьюеру?

Если есть сложности с ответами — скопируй вопросы и задай их своему ИИ-ассистенту.
