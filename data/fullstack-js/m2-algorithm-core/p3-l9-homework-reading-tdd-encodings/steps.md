### На выбор: две статьи

**kind:** `text`

Обе статьи — **опциональные**, но очень рекомендуются: они углубляют то, что ты только что делал руками.

1. **[Что нужно знать каждому разработчику о кодировках и наборах символов для работы с текстом](https://habr.com/ru/articles/158639/)** — почему 😀 занимает 2 «символа», как устроены UTF-8 и UTF-16. Логичное продолжение урока 4 про таблицы символов.

2. **[TDD: разработка быстрее и качественнее](https://habr.com/ru/articles/925446/)** — разбор TDD на реальных примерах. Почему красный-зелёный-рефакторинг — это дисциплина мышления, а не просто порядок действий.

**Термины:**
кодировка — правила, по которым символы превращаются в байты;
UTF-8 — самая распространённая кодировка: символ кодируется 1–4 байтами;
red-green-refactor — цикл TDD: падающий тест → рабочее решение → чистка кода

Можно прочитать одну, обе или ни одной — на твоё усмотрение. Если читал — законспектируй (шаг 2).

### Конспект и сдача (если читал)

Конспект — в `homework.md`, раздел «Конспекты». Некодовые обновления — прямым пушем в `main`, без ветки и PR (урок 8 проекта 2):

> 📁 Помни про роли файлов: конспект — в `homework.md` (твои личные записи), а не в `README.md` (визитка проекта).

```
git switch main
git pull origin main
```

Добавь в `homework.md`:

```markdown
## Кодировки и/или TDD

- (5–7 пунктов того, что стало понятнее или удивило)
```

Закоммить и отправь на GitHub напрямую:

```
git add homework.md
git commit -m "Добавить конспект статей про кодировки и TDD"
git push origin main
```

Без PR, чата и апрувов — конспект уже на GitHub.

> 💡 Не жди мержа кодового PR из урока 8: конспект идёт прямо в `main` и открытому PR не мешает.
