# Шаги урока: Как тестировать мутабельные функции

---

### Два результата теста

**kind:** `text`

Тест мутабельной функции проверяет **два** результата:

1. **Возвращаемое значение** — что функция вернула (новую длину, удалённый элемент).
2. **Состояние массива после вызова** — изменился ли он и как.

```javascript
import { test, expect } from 'bun:test';
import { pop } from './array-utils/pop.js';

test('pop удаляет последний элемент и возвращает его', () => {
  const arr = [10, 20, 30];
  const result = pop(arr);

  expect(result).toBe(30);       // 1. возвращённое значение
  expect(len(arr)).toBe(2);      // 2. массив стал короче
  expect(arr[0]).toBe(10);       //    первый элемент на месте
  expect(arr[1]).toBe(20);
});
```

Важно: для каждого теста создавай **новый** массив. Если переиспользовать один массив между тестами — мутация в первом тесте сломает второй. Это частный случай более общего правила — следующий шаг.

**Правило:** мутабельная функция = в тесте проверяй и `result`, и исходный массив после вызова.

**А если функция не мутирует?** Это тоже часть контракта, и её тоже нужно проверять: иначе мутирующий баг пройдёт незамеченным — тест на возвращаемое значение останется зелёным, а исходный массив окажется испорчен. Добавь отдельный тест, который вызывает функцию и проверяет, что массив не изменился:

```javascript
test('at не мутирует массив', () => {
  const arr = [10, 20, 30];
  at(arr, 1);
  expect(len(arr)).toBe(3);   // длина та же
  expect(arr[0]).toBe(10);    // элементы на месте
  expect(arr[2]).toBe(30);
});
```

**Термины:**
самодостаточный тест — тест, который сам создаёт свои данные и не зависит от других тестов и порядка запуска;
хрупкость теста (или кода) — зависимость результата от несущественных условий (порядок запуска, общие с другими тестами данные, детали реализации): сейчас всё зелёное, но ломается от малейшего изменения

### Тесты всегда независимы

**kind:** `text`

Каждый тест должен быть **самодостаточным** — он не полагается на то, что отработал какой-то другой тест, и не рассчитывает, что другой тест оставил данные «в нужном виде». Если запустить тесты в любом порядке, по одному или все сразу — каждый должен проходить одинаково.

**Почему это критично именно с мутабельными функциями.** Мутабельная функция меняет свой аргумент. Если два теста используют один и тот же массив, то тест, который запустился первым, меняет массив — и второй тест видит уже «испорченные» данные. Результат второго теста начинает зависеть от порядка запуска и от того, сработал ли первый. Это невидимая хрупкость: всё зелёное, пока тесты бегут в одном порядке, и падает при перестановке.

**Плохо** — общий массив, тесты зависят друг от друга:
```javascript
const arr = [1, 2, 3];

test('push возвращает новую длину', () => {
  const result = push(arr, 4);
  expect(result).toBe(4);          // OK, но arr теперь [1,2,3,4]
});

test('pop возвращает последний элемент', () => {
  const result = pop(arr);
  expect(result).toBe(4);          // проходит ТОЛЬКО потому, что push уже отработал!
});
```

Поменяй тесты местами — второй тест сломается, хотя код функции не изменился. Это и есть нарушение независимости.

**Хорошо** — каждый тест готовит свои данные с нуля:
```javascript
test('push возвращает новую длину', () => {
  const arr = [1, 2, 3];
  const result = push(arr, 4);
  expect(result).toBe(4);
});

test('pop возвращает последний элемент', () => {
  const arr = [1, 2, 3];
  const result = pop(arr);
  expect(result).toBe(3);
});
```

Теперь порядок не важен: каждый тест сам создаёт свой массив и сам отвечает за его состояние.

**Правила независимости тестов:**
- Каждый тест сам создаёт свои данные (массивы, строки, объекты) — не берёт их «снаружи» и не из другого теста.
- Каждый тест сам приходит к своему результату через свой вызов функции — не использует побочный эффект чужого теста.
- Тест не должен полагаться на порядок выполнения: представь, что твои тесты перемешали — они всё равно должны проходить.
- Один тест = одна проверяемая идея. Несколько связанных проверок внутри одного теста допустимы, но «подготовка» для следующего теста — нет.

### Вопросы на понимание

**kind:** `text`

Ответь на вопросы. Если не знаешь — проверь гипотезу кодом через `bun`.

**1.** Функция `push(arr, item)` возвращает новую длину массива. Достаточно ли в тесте проверить только возвращаемое значение? Почему нет?

**2.** Ты написал тест:
```javascript
const arr = [1, 2, 3];
push(arr, 4);
push(arr, 5);
expect(len(arr)).toBe(5);
```
Тест прошёл. Но в чём проблема такого теста? (Подсказка: что если `push` добавляет элемент не в конец, а в начало?)

**3.** Для мутабельной функции проверка массива после вызова обязательна — мутация и есть результат. А если функция не должна мутировать (например `concat`) — нужно ли проверять исходный массив? Что может пройти незамеченным, если этого не делать?
