# Шаги урока: Измеряем скорость: бенчмарк сортировок и поиска

---

### Зачем измерять и как правильно

**kind:** `text`

Ты реализовал четыре алгоритма, которые делают «одно и то же». Чтобы увидеть разницу в скорости, нужен замер. В JavaScript время замеряют через глобальную `performance.now()` — она возвращает миллисекунды с долями.

Но **один замер — это шум**: на время влияют нагрев движка, сборщик мусора, другие процессы. Поэтому правильный стенд:
1. **прогревает** функцию (первый вызов не замеряем);
2. запускает функцию **несколько раз**;
3. берёт **минимальное** время — оно ближе всего к «чистой» скорости алгоритма.

---

### Нативный JS: почему это важно для замера

**kind:** `text`

В этом проекте мы измеряем **скорость алгоритмов**. Если алгоритм внутри вызывает наши собственные функции из `array-utils/`, замер покажет не то, что нам нужно.

Вспомни `len` из проекта 7: чтобы посчитать длину, она **идёт циклом** по массиву, пока не дойдёт до `undefined`. То есть каждый вызов `len` — это O(n) лишних операций. Внутри сортировки это может утроить и учетверить время: например, `quickSort`, который должен быть одним из самых быстрых, из-за накладных расходов покажет себя медленнее пузырька — и вся статистика потеряет смысл.

**Поэтому в этом проекте — только нативный JS.** Никаких наших функции из `array-utils/`.

Только так стенд покажет честную разницу между алгоритмами.

### Скрипт замера: создай файл sorting/sort-benchmark.js

**kind:** `text`

Ниже готовый стенд для замера. Пока только изучи ее.

```javascript
import { bubbleSort } from './bubble-sort.js';
import { insertionSort } from './insertion-sort.js';
import { selectionSort } from './selection-sort.js';
import { quickSort } from './quick-sort.js';
import { binarySearch } from './binary-search.js';

const SIZES = [100, 500, 1000, 2000, 4000, 8000];
const RUNS = 5;

function randomArray(size) {
  const arr = [];
  for (let i = 0; i < size; i++) {
    arr.push(Math.floor(Math.random() * size));
  }
  return arr;
}

function measure(fn, input, repeat = 1) {
  fn(input); // прогрев — первый вызов не замеряем

  let best = Infinity;
  for (let r = 0; r < RUNS; r++) {
    const start = performance.now();
    for (let i = 0; i < repeat; i++) {
      fn(input);
    }
    const perCall = (performance.now() - start) / repeat;
    if (perCall < best) best = perCall;
  }
  return best;
}

const algorithms = [
  { name: 'bubbleSort', fn: bubbleSort },
  { name: 'insertionSort', fn: insertionSort },
  { name: 'selectionSort', fn: selectionSort },
  { name: 'quickSort', fn: quickSort },
];

for (let s = 0; s < SIZES.length; s++) {
  const input = randomArray(SIZES[s]);
  let line = 'n=' + SIZES[s];
  for (let a = 0; a < algorithms.length; a++) {
    const ms = measure(algorithms[a].fn, input);
    line = line + '  |  ' + algorithms[a].name + ': ' + Math.round(ms * 100) / 100 + 'мс';
  }
  console.log(line);
}

// Поиск: линейный (indexOf) против бинарного (binarySearch)
const searchSize = 1000000;
const sorted = [];
for (let i = 0; i < searchSize; i++) {
  sorted.push(i); // уже отсортированный массив
}
const target = searchSize - 1; // ищем последний элемент — худший случай для перебора

const linearSearch = () => sorted.indexOf(target);
const binarySearchForTarget = () => binarySearch(sorted, target);

// binarySearch слишком быстрый для одного замера, поэтому повторяем его много раз
const linearUs = measure(linearSearch, sorted, 5) * 1000;
const binaryUs = measure(binarySearchForTarget, sorted, 10000) * 1000;

console.log('--- Поиск в массиве из ' + searchSize + ' элементов (ищем ' + target + ') ---');
console.log('indexOf (перебор): ' + Math.round(linearUs * 100) / 100 + 'мкс');
console.log('binarySearch: ' + Math.round(binaryUs * 100) / 100 + 'мкс');
```

### Если что-то пойдет не так

**kind:** `text`

Сейчас мы будем запускать наш стенд. На всякий случай обсудим случаи когда что то может пойти не так.

**«Maximum call stack size exceeded» (переполнение стека).**
Причина: `quickSort` на большом **уже отсортированном** массиве — рекурсия уходит на глубину n (опорный элемент — первый).
Что править: в `sort-benchmark.js` — `SIZES = [100, 500, 1000, 2000]` (в эксперименте уже так). Если всё равно падает — уменьши размеры.

**«Cannot find module './quick-sort.js'».**
Причина: неверный путь импорта (скрипт лежит в `sorting/`, туда же должны лежать и алгоритмы).
Что править: в начале `sort-benchmark.js` проверь строки `import { ... } from './...-sort.js'`. Все пять файлов должны быть рядом, в папке `sorting/`.

**Скрипт работает долго.**
Причина: пузырёк/вставки/выбор — медленные на больших массивах.
Что править: в `sort-benchmark.js` — `const SIZES = [...]`, убери большие значения (8000, 4000).

**В выводе одни 0мс.**
Причина: на маленьких размерах время слишком мало, чтобы его заметить.
Что править: увеличь `RUNS` или размеры в `SIZES`. Для поиска — увеличь `repeat`.

### Термины урока

**kind:** `text`

Пройдись по основным понятиям урока. Если что-то не можешь объяснить своими словами — вернись к соответствующему шагу.

**Термины:**
* **Бенчмарк** — измерение времени работы кода на разных наборах данных.
* **Прогрев (warmup)** — первый вызов до замеров: движок оптимизирует функцию, поэтому его время не показательно.
* **Шум измерений** — случайные колебания времени (сборка мусора, другие процессы); поэтому берём минимум из нескольких запусков.
* **`performance.now()`** — встроенная функция, возвращает миллисекунды с высокой точностью.
* **Микросекунда (мкс)** — 1/1000 миллисекунды; нужна для очень быстрых операций вроде `binarySearch`.
* **Нативный вызов** — встроенный метод JS без накладных расходов наших функций из `array-utils/`.
* **Худший случай** — данные, на которых алгоритм работает дольше всего (для перебора — поиск последнего элемента).
