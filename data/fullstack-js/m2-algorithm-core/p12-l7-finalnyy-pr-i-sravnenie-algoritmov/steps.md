### Создание PR по шаблону

**kind:** `text`

Создай PR: base `main` ← compare `feat/sorting`.

**Заголовок:**
```
Проект 12: Сортировка и бинарный поиск — 5 функций и бенчмарк
```

**Описание — заполни по шаблону:**

```markdown
## Что сделано

Реализованы 4 алгоритма сортировки и бинарный поиск (папка sorting/):

- bubbleSort(arr) — сортировка пузырьком, O(n²)
- insertionSort(arr) — сортировка вставками, O(n²), почти O(n) на отсортированных данных
- selectionSort(arr) — сортировка выбором, O(n²), минимум обменов
- quickSort(arr) — быстрая сортировка, O(n log n) в среднем, рекурсия
- binarySearch(arr, target) — бинарный поиск в отсортированном массиве, O(log n)
- sort-benchmark.js — стенд замера скорости сортировок (100…8000) и поиска (1 000 000)

## Особенности реализации

- Все функции иммутабельные — исходный массив не меняется
- В проекте используется только нативный JS (arr.length, arr.slice(), arr.push(),
  arr.concat(), arr.indexOf()) — чтобы замер показывал чистую скорость алгоритмов,
  а не накладные расходы наших функций из array-utils/
- quickSort рекурсивный; pivot — первый элемент; на уже отсортированных данных
  деградирует до O(n²)
- binarySearch предполагает отсортированный массив

## Результаты бенчмарка

| n | bubbleSort | insertionSort | selectionSort | quickSort |
|---|---|---|---|---|
| 100 | … | … | … | … |
| 500 | … | … | … | … |
| 1000 | … | … | … | … |
| 2000 | … | … | … | … |
| 4000 | … | … | … | … |
| 8000 | … | … | … | … |

Поиск на 1 000 000 элементов: indexOf — … мкс, binarySearch — … мкс.

## Как запустить тесты

bun test

## Как запустить бенчмарк

bun sorting/sort-benchmark.js
```


**Важно:** Обрати внимание, в описании к PR есть загадочные `O(n²)`, что это за обозначения тема следующего урока. Пока просто копируй как есть.

Что важно для ревьюеров, может быть не очевидно — обязательно указывай. Если считаешь, что команда «в теме», часть разделов можно сократить.

### Ревью-цикл, мерж и ретро: напоминания

**kind:** `text`

Полная методика — в проекте 4. Короткий ориентир:

1. **Пришли комментарии** → разбери на 🐛 баги / 🎨 стиль / 📝 документацию / 💡 предложения
2. **Правки** → в той же ветке, одно исправление = один коммит, затем `git push`
3. **Ответы** → на каждый комментарий + Resolve conversation
4. **Re-request review** → 2 апрува + все resolved → мерж
5. **Мерж** → `git switch main && git pull && git branch -d feat/sorting && git fetch --prune`

На что смотреть в этом PR: все функции иммутабельные и это подтверждено тестами? В коде сортировок действительно нет `len`/`push`/`slice` из `array-utils/`? У `quickSort` есть базовый случай? Бенчмарк замеряет именно алгоритмы, а не подготовку данных?
