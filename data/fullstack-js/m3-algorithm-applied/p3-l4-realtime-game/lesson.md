# Проект 2: Игра реального времени на тиках (PR 3)

**Краткое содержание:**
Выходим на пик мастерства в разработке консольных аркад. В третьем практическом проекте мир больше не ждёт нажатия клавиш: время непрерывно течёт, объекты движутся сами по таймеру, а реакция игрока решает всё. Мы подробно изучаем механику игровых тиков (tick rate), асинхронное состояние, буферизацию ввода для защиты от разворота на 180°, работу со структурами очередей координат и генерацию случайных объектов без пересечений. Студент самостоятельно выбирает одну из динамических игр («Змейка» или «Космический уворачивальщик»), **с нуля собирает точку входа `run.js`**, реализует логику с тестами и защищает финальный Pull Request 3.

**Время:** ~45 мин

**Основные темы:**
- Разница между пошаговым миром и миром реального времени: как работают тики
- Параметр `tickRateMs` в игровом ядре `engine.js` и баланс частоты кадров
- Новая степень свободы: самостоятельная сборка точки входа `run.js`
- Каталог игр реального времени на выбор: «Змейка» и «Космический уворачивальщик»
- Архитектура «Змейки»: очередь координат тела `FIFO`, движение головы и рост при питании
- Проблема разворота на 180°: буферизация намерения движения
- Алгоритм генерации еды: как случайным образом выбрать незанятую клетку без зависаний
- Архитектура «Уворачивальщика»: падающие волны препятствий, удаление вышедших за экран объектов
- Написание тестов для логики на тиках через подачу событий `{ type: 'TICK' }`
- Сдача Pull Request 3 и критерии готовности к финальному ревью

**Термины:**
* **Тик (Tick)** — квант времени в игровом цикле. Фиксированный интервал (например, каждые 120 миллисекунд), по истечении которого мир делает один шаг вперёд независимо от нажатий клавиш.
* **Частота тиков (Tick Rate)** — количество тиков за секунду либо период одного тика в миллисекундах (`tickRateMs`).
* **Очередь координат (Coordinate Queue / FIFO)** — последовательность точек тела змейки, где новая голова добавляется в начало, а старый кончик хвоста удаляется с конца.
* **Буфер направления (Input Direction Buffer)** — переменная или очередь намерений игрока, предотвращающая самоубийственный разворот объекта на 180° внутри одного и того же тика.
* **Коллизия (Collision)** — физическое пересечение координат двух объектов (головы со стеной, корабля с метеоритом, головы с собственным телом).
* **Свободное пространство (Free Cell Sampling)** — алгоритмический выбор случайных координат из множества ячеек, не занятых телом змейки или препятствиями.

### Время пошло: Как работают тики в терминале

В предыдущих уроках вызов `update(state, action)` происходил только тогда, когда палец игрока касался клавиши. Если игрок отходил от компьютера на час — игра замирала на месте.

В играх реального времени мир живёт собственной жизнью:
- Змейка ползёт вперёд даже если вы не трогаете клавиатуру.
- Метеориты падают сверху вниз с постоянной скоростью.

Для этого в ядре `engine.js` предусмотрен параметр `tickRateMs`. Если при запуске движка указать этот параметр, движок запускает таймер:

```text
       ┌─────────── Каждые N миллисекунд ──────────┐
       │                                           │
       ▼                                           │
[ Системный таймер ] ──► { type: 'TICK' }          │
                              │                    │
[ Нажатие клавиши  ] ──► { type: 'MOVE', dir }     │
                              │                    │
                              ▼                    │
                   update(state, event)            │
                              │                    │
                              ▼                    │
                     render(view) ─────────────────┘
```

Обратите внимание на ключевой вывод: **функция `update` остаётся совершенно синхронной и детерминированной!** Ей всё равно, откуда пришло событие: от нажатия клавиши пользователем или от таймера ядра с типом `'TICK'`. Это делает тестирование игр реального времени простым и предсказуемым.

### Новый уровень ответственности: создаём `run.js` сами

В Уроках 1, 2 и 3 файл запуска `run.js` выдавался в готовом виде. Вы лишь наблюдали за тем, как он устроен.

В Уроке 4 вы делаете этот шаг **самостоятельно**:
1. Вы создаёте файл `arcade/games/<game>/run.js`.
2. Сами импортируете `startEngine` из `../../engine.js`.
3. Сами подключаете нужный рендерер и адаптер ввода из `../../render/grid.js`.
4. Сами настраиваете интервал `tickRateMs` (например, `140` для Змейки или `90` для Уворачивальщика).
5. Связываете свои функции `createState`, `update`, `getView` с ядром.

Пример шаблона точки входа для игры на тиках:
```javascript
// arcade/games/snake/run.js
import { startEngine } from '../../engine.js';
import { renderGrid, createDirectionAdapter } from '../../render/grid.js';
import { createState, update, getView } from './snake.js';

startEngine({
  title: 'Змейка',
  tickRateMs: 140,              // ядро шлет { type: 'TICK' } каждые 140мс
  adapter: createDirectionAdapter(),
  render: renderGrid,
  createState,
  update,
  getView,
});
```

#### Вариант А: Классическая «Змейка» (Snake)
* **Эмодзи:** 🐍
* **Сложность:** Выше средней
* **Игровое поле:** Символьная сетка 15×15 или 20×15.
* **Суть правил:** Змейка начинает с длины в 3 сегмента и непрерывно ползёт в выбранную сторону. Игрок меняет направление стрелками или WASD. На поле случайным образом появляется еда `*`. При поедании еды длина змейки увеличивается на 1, начисляются очки, а новая еда возникает на свободной клетке. Столкновение со стеной или собственным хвостом приводит к поражению.

##### Ключевые алгоритмические задачи «Змейки»:

1. **Хранение тела (Очередь точек):**
   Тело змейки — это массив объектов координат `[{ x, y }, { x, y }, ...]`, где нулевой элемент `body[0]` — голова.
   - На каждом тике вычисляются координаты новой головы: `newHead = { x: head.x + dx, y: head.y + dy }`.
   - Новая голова добавляется в начало: `newBody = [newHead, ...body]`.
   - Если еда не была съедена — кончик хвоста отрезается: `newBody.pop()`.
   - Если еда съедена — хвост **не** отрезается (змейка выросла!), а еда создаётся заново.

2. **Защита от разворота на 180° (Буферизация ввода):**
   Если змейка ползёт вправо (`dir = 'RIGHT'`), а игрок быстро нажимает клавишу «Влево» (`dir = 'LEFT'`), змейка врезалась бы в собственный второй сегмент и погибла.
   - Поэтому событие клавиатуры не должно сразу менять текущее направление движения тела; оно лишь обновляет `nextDir` (намерение).
   - При попытке сменить вектор на противоположный (`dir === 'RIGHT'` и нажато `'LEFT'`) команда игнорируется.
   - Применение `dir = nextDir` происходит **только в момент тика `'TICK'`**, когда совершается реальный шаг.

3. **Генерация еды без пересечений:**
   Нельзя просто вызывать `Math.random()` наугад в бесконечном цикле `while`. Когда змейка займёт 80% поля, такой цикл начнёт «буксовать».
   - Правильный алгоритмический подход: сформировать список всех пустых клеток поля, не входящих в `body`, и выбрать случайный элемент из этого списка.

#### Вариант Б: «Космический уворачивальщик» (Space Dodger)
* **Эмодзи:** 🚀
* **Сложность:** Средняя
* **Игровое поле:** Вертикальная полоса 12×15.
* **Суть правил:** Корабль игрока `A` находится в самом нижнем ряду поля и может перемещаться только влево и вправо. Сверху непрерывно появляются метеориты `*` и падают вниз. Игрок должен уворачиваться от падающих угроз. Каждое препятствие, успешно упавшее за нижний край экрана, приносит +10 очков выживания. При столкновении с метеоритом — конец игры.

##### Ключевые алгоритмические задачи «Уворачивальщика»:

1. **Перемещение препятствий на тике:**
   Препятствия хранятся в виде массива объектов: `hazards: [{ x: 3, y: 0 }, { x: 7, y: 2 }]`.
   - На каждом тике координата Y каждого метеорита увеличивается на 1: `hazard.y + 1`.
   - Метеориты, у которых `y >= height`, фильтруются: `hazards.filter(h => h.y < height)`.
   - Число отфильтрованных метеоритов умножается на 10 и добавляется к очкам игрока (`score`).

2. **Генерация новых волн:**
   С заданной вероятностью (например, каждые 2-3 тика) в нулевой строке `y = 0` создаётся новый метеорит со случайной координатой `x` в диапазоне `[0, width - 1]`.

3. **Проверка коллизии:**
   После сдвига проверяется, совпали ли координаты корабля `{ x: playerX, y: height - 1 }` с координатами хотя бы одного метеорита:
   `hazards.some(h => h.x === playerX && h.y === height - 1)`.

### Тестирование игр реального времени

Главная прелесть детерминированной функции `update(state, event)` в том, что для её тестирования **не нужно ждать реального времени**!

Вам не нужны задержки `setTimeout`: вы просто вызываете `update` с событием тика столько раз, сколько шагов хотите смоделировать:

```javascript
// games/snake/snake.test.js
import { describe, expect, it } from 'bun:test';
import { createState, update } from './snake.js';

describe('Змейка на тиках', () => {
  it('двигает голову вперед по направлению на каждом тике', () => {
    let state = createState({ width: 10, height: 10 });
    const initialHeadX = state.body[0].x;
    state.dir = 'RIGHT';

    // Эмулируем один шаг времени
    state = update(state, { type: 'TICK' });

    expect(state.body[0].x).toBe(initialHeadX + 1);
  });

  it('запрещает самоубийственный разворот на 180 градусов', () => {
    let state = createState();
    state.dir = 'RIGHT';

    // Игрок жмет Влево
    state = update(state, { type: 'MOVE', direction: 'LEFT' });
    // Тик времени
    state = update(state, { type: 'TICK' });

    // Направление не должно было смениться на противоположное
    expect(state.dir).toBe('RIGHT');
  });

  it('фиксирует поражение при ударе в стену', () => {
    let state = createState({ width: 5, height: 5 });
    state.body = [{ x: 4, y: 2 }];
    state.dir = 'RIGHT';

    state = update(state, { type: 'TICK' });

    expect(state.status).toBe('lost');
  });
});
```
