# Слой сущности: правила валидации и фабрика заказа — краткая выжимка

- Слой `app/entity` — ядро предметной области: описывает структуру данных заказа и правила их целостности без внешних зависимостей от сети или файловой системы.
- Заказ состоит из 6 полей: `id`, `customer`, `amount`, `isPaid`, `status`, `review`. Все поля **строго обязательны**, кроме `review` (отзыв опционален).
- Валидаторы в `validator.js`: чистые функции, которые приводят сырые значения к типам JavaScript (`number`, `boolean`), проверяют бизнес-правила и при ошибке **бросают `OrderValidationError`**.
- Фабрика `createOrder(data)` в `order.js`: используется обработчиками для валидации полей заказа и сборки чистого объекта без лишних query-параметров.
- Архитектурная цепочка: `handler` валидирует входные данные (напрямую через `validateId` или через фабрику `createOrder`) → передаёт проверенные данные в `repo` → `repo` сохраняет на диск. При ошибке исключение перехватывается сервером и возвращается клиенту в виде JSON `{ error: '...' }` со статусом `400`.
- Репозиторий — простое CRUD-хранилище: сохраняет и выдаёт данные без повторных проверок.
- Разработка ведётся по TDD: студент самостоятельно пишет тесты на позитивные сценарии и на выброс исключений в `validator.test.js` и `order.test.js`.
- В следующем уроке переходим к хранению: получаем готовую инфраструктуру `infra/file-storage.js`, осваиваем моки и пишем первую функцию репозитория `getOrder(id)`.
