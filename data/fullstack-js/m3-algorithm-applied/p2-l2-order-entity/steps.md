# Шаги урока: Слой сущности: правила валидации и фабрика заказа

### Заказ в интернет-магазине: доменная модель и ответственность слоя

**kind:** `text`

В этом уроке мы создадим сердцевину нашего приложения — слой `app/entity`.

Весь проект ты выполняешь на ветке: `feat/http-service`. Создай папку `app/entity/` внутри каталога проекта `m2-m3-algorithms/m3-p2-http/`.

Слой сущностей отвечает за две вещи:
1. Определение того, из каких полей состоит заказ и какие значения допустимы (валидатор).
2. Гарантию того, что внутри приложения не может существовать «сломанный» или недозаполненный заказ (фабрика).

**Поля заказа:**
- `id`: уникальный номер заказа (целое число больше нуля).
- `customer`: имя покупателя (непустая строка).
- `amount`: сумма заказа (число больше нуля).
- `isPaid`: отметка об оплате (логическое значение `true` или `false`).
- `status`: состояние заказа (строка `'new'`, `'completed'` или `'canceled'`).
- `review`: отзыв клиента (строка, **единственное необязательное поле**).

**Важные архитектурные договорённости:**
- **Все поля заказа, кроме `review`, строго обязательны.** Нельзя создать заказ без суммы, без покупателя или без статуса.
- Данные приходят в приложение из внешнего мира (из адресной строки HTTP-запроса) в виде **строк**. Поэтому задача слоя сущностей — не просто проверить данные, но и выполнить их безопасное **приведение к типам JavaScript** (`Number`, `Boolean`).
- Обработчик (`handler`) оркестрирует выполнение: разбирает query-параметры, вызывает `validateId` или фабрику `createOrder`.
- Если хотя бы одно поле некорректно — валидатор **бросает исключение `OrderValidationError`**. Сервер централизованно перехватит эту ошибку и вернёт клиенту ответ с JSON-объектом `{ error: '...' }` и кодом `400`.
- Репозиторий (`repo`) — простое хранилище данных: сохраняет и возвращает то, что ему передали, не проводя повторных проверок.

### Класс ошибки и список статусов: файл app/entity/validator.js

**kind:** `text`

Создай файл `app/entity/validator.js`.

Чтобы сервер мог отличать ошибки валидации данных от других ошибок программы, нам нужен специальный класс ошибки — `OrderValidationError`. Также нам понадобится константа с разрешёнными статусами заказа.

Добавь в `app/entity/validator.js` следующий базовый код:

```javascript
export class OrderValidationError extends Error {
  constructor(message) {
    super(message);
    this.name = 'OrderValidationError';
  }
}

export const ORDER_STATUSES = ['new', 'completed', 'canceled'];
```

### Доменные валидаторы: правила и приведение типов

**kind:** `text`

Создай тестовый файл `app/entity/validator.test.js`.

Каждый валидатор — это функция, которая принимает одно сырое значение. Если значение корректно, валидатор возвращает приведённое значение. Если значение нарушает правила или обязательное поле отсутствует — функция **бросает `OrderValidationError`** с понятным сообщением.

Реализуй 6 функций валидации:

#### 1. `validateId(raw)`
* **Назначение:** проверка номера заказа. Обязательное поле.
* **Правило:** целое положительное число (строго больше нуля).
* **Приведение типа:** значение приводится к числу.
* **Ошибки:** дробные числа (`3.5`, `'3.5'`), числа `<= 0` (ноль и отрицательные), строки букв (`'abc'`), отсутствие значения (`undefined`, `null`), ошибки приведения `NaN`, `Infinity` — бросают `new OrderValidationError('Некорректный ID заказа')`.

#### 2. `validateCustomer(raw)`
* **Назначение:** проверка имени клиента. Обязательное поле.
* **Правило:** непустая строка. Лишние пробелы по краям удаляются.
* **Ошибки:** нестроковые типы, пустая строка `''` или строка только из пробелов `'   '` — бросают `new OrderValidationError('Укажите имя клиента')`.

#### 3. `validateAmount(raw)`
* **Назначение:** проверка суммы заказа. Обязательное поле.
* **Правило:** конечное положительное число (строго больше нуля). Допускаются дробные рубли/копейки (например, `99.9`).
* **Приведение типа:** преобразуется к числу.
* **Ошибки:** `0`, отрицательные числа, строки нечисел, `NaN`, `Infinity`, `undefined`, `null` — бросают `new OrderValidationError('Сумма должна быть положительным числом')`.

#### 4. `validateIsPaid(raw)`
* **Назначение:** проверка признака оплаты. Обязательное поле.
* **Правило:** строго логическое значение.
* **Приведение типа:**
  - `true` или строка `'true'` возвращают булево `true`.
  - `false` или строка `'false'` возвращают булево `false`.
* **Ошибки:** пустая строка, `undefined`, `null`, числа, любые другие строки (`'yes'`) — бросают `new OrderValidationError('Некорректное значение оплаты')`.

#### 5. `validateStatus(raw)`
* **Назначение:** проверка статуса заказа. Обязательное поле.
* **Правило:** значение обязано быть одной из строк списка `ORDER_STATUSES` (`'new'`, `'completed'`, `'canceled'`).
* **Ошибки:** отсутствие значения, пустая строка, неизвестный статус (`'archived'`) — бросают `new OrderValidationError('Некорректный статус заказа')`.

#### 6. `validateReview(raw)`
* **Назначение:** проверка отзыва. **Опциональное поле.**
* **Правило:** клиент не обязан оставлять отзыв.
* **Поведение:**
  - Если передано `undefined`, `null` или пустая строка `''` — возвращает `undefined`.
  - Если передана непустая строка — возвращает очищенную от концевых пробелов строку.
* **Ошибки:** если передано нестроковое значение (число, объект), не являющееся `null`/`undefined` — бросает `new OrderValidationError('Отзыв должен быть строкой')`.

Задача: реализовать все функции валидаторов. Работай по методологии TDD: **Заглушка -> { TEST -> RED -> GREEN }**. Тесты каждого валидатора должны быть в своем скоупе. А все тесты в одном общем скоупе.

### Фабрика createOrder: файл app/entity/order.js

**kind:** `text`

Создай файл `app/entity/order.js` и тестовый файл `app/entity/order.test.js`.

Фабрика `createOrder` используется в слое обработчиков (`app/handler/`): она избавляет обработчик от необходимости вручную вызывать каждый валидатор по отдельности и собирает проверенные данные заказа в единый объект.

#### Контракт функции:
* **Имя:** `createOrder(data)`
* **Вход:** объект сырых данных (например, `{ customer: 'Анна', amount: '3500', isPaid: 'true', status: 'new' }`). Если аргумент не передан, функция по умолчанию использует пустой объект `{}`.
* **Выход:** объект с проверенными полями и правильными типами данных.
* **Исключения:** если хотя бы одно обязательное поле отсутствует или нарушает правила, выполнение прерывается исключением `OrderValidationError`.

#### Критерии приемки
1. Возвращает все поля объекта заказа полученные из входных данных;
2. Каждое поле заказа валидируется;
3. Все посторонние поля не попадают в конечный результат;
4. Если во входном ключа нет, то в возвращаемом объекте этого ключа тоже нет;
5. Исходный объект `data` не должен мутироваться.

Пример: на входе `{ id: '3', amount: '3000', isPaid: 'true', shipped: 'true' }`, на выходе `{ id: 3, amount: 3000, isPaid: true }`.

Тестовые случаи и тесты на тебе. Реализуй функцию и нажимай "Выполнено".

### Контракты и критерии приёмки

**kind:** `text`

Сведи реализацию с контрактами функций слоя `app/entity`:

- **`validateId(raw)`:** вход — любое значение, результат при успехе — число (`number > 0`), при ошибке — `throw OrderValidationError`.
- **`validateCustomer(raw)`:** вход — любое значение, результат при успехе — непустая строка (`string`), при ошибке — `throw OrderValidationError`.
- **`validateAmount(raw)`:** вход — любое значение, результат при успехе — положительное число (`number > 0`), при ошибке — `throw OrderValidationError`.
- **`validateIsPaid(raw)`:** вход — любое значение, результат при успехе — булево (`true` / `false`), при ошибке — `throw OrderValidationError`.
- **`validateStatus(raw)`:** вход — любое значение, результат при успехе — `'new'` / `'completed'` / `'canceled'`, при ошибке — `throw OrderValidationError`.
- **`validateReview(raw)`:** вход — любое значение, результат при успехе — строка или `undefined`, при ошибке — `throw OrderValidationError`.
- **`createOrder(data)`:** вход — объект данных, результат при успехе — объект заказа из 6 полей, при ошибке — `throw OrderValidationError`.

**Критерии приёмки:**
1. В каталоге `app/entity/` созданы файлы: `validator.js`, `validator.test.js`, `order.js`, `order.test.js`.
2. Валидаторы и фабрика реализованы в чистом JavaScript c JSDoc-аннотациями.
3. Валидаторы корректно приводят строковые значения к типам `number` и `boolean`.
4. Все поля кроме `review` обязательны. Отсутствие обязательного поля приводит к `OrderValidationError`.
5. Поле `review` опционально: при отсутствии значения возвращается `undefined`.
6. Фабрика `createOrder` создаёт гарантированно валидный объект заказа и игнорирует посторонние свойства.
7. Все тесты запускаются командой `bun test app/entity/` и успешно проходят без ошибок.
