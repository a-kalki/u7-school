# Первая игра: Черепашка на сетке (PR)

**Краткое содержание:**
Переходим к первой самостоятельной практической разработке в проекте «Аркада». Наша задача — оживить классического робота-исполнителя: «Черепашку», которая перемещается по двумерной сетке, слушается команд игрока, поворачивается во все стороны света и рисует траекторию движения пером. Мы разбираем работу с координатами в 2D-матрицах, управление направлением, инварианты границ поля и чистое состояние. Вы получаете готовый рендерер и файл запуска, самостоятельно реализуете модуль логики `turtle.js`, покрываете его тестами и оформляете PR.

**Время:** ~35 мин

**Основные темы:**
- Двумерные координаты в программировании: экранная система координат (Y вниз, X вправо)
- Векторы направления: 4 стороны света (Север, Восток, Юг, Запад)
- Состояние исполнителя: координаты `x`, `y`, угол направления `dir`, флаг пера `penDown`
- Матрица следов: хранение пройденного пути без мутации исходных данных
- Ограничение границ (clamping): безопасное перемещение без падений за пределы сетки
- Разделение обязанностей: почему рендерер не решает, куда пойти черепашке
- Тестирование игровой логики: изоляция функций от экрана с помощью `bun test`
- Процесс сдачи PR: ветвление git, оформление описания и ревью в общем чате

**Термины:**
* **Индексация матрицы (Row-Major Order `grid[y][x]`)** — стандарт адресации двумерных массивов, где первый индекс указывает на номер строки (вертикальная координата Y), а второй — на номер столбца (горизонтальная координата X).
* **Экранные координаты** — система координат в графических интерфейсах, где точка отсчёта `(0, 0)` находится в верхнем левом углу, ось X направлена вправо, а ось Y — вниз.
* **Инвариант состояния (State Invariant)** — гарантированное правило целостности данных, соблюдаемое при любых изменениях (координаты объекта всегда находятся в пределах поля `[0, width - 1]` и `[0, height - 1]`).
* **Клампинг (Clamping)** — программное ограничение числового значения заданным допустимым диапазоном `[min, max]`, предотвращающее выход за границы массивов.
* **Вектор направления (Direction Vector)** — представление движения парой числовых смещений `{ dx, dy }`, избавляющее логику от условных операторов `switch/case` при вычислении новой позиции.
* **Проекция состояния (State Projection / `getView`)** — чистая трансформация внутреннего состояния объекта в структуру, удобную для отображения рендерером, без мутации оригинального `state`.
* **Иммутабельное обновление** — создание нового объекта состояния через оператор расширения (`{ ...state, ... }`) вместо прямой мутации свойств исходного объекта.
* **Изолированное тестирование домена** — тестирование бизнес-логики без моков файловой системы, таймеров и терминала благодаря чистоте функций `createState` и `update`.

### Концепция игры: Черепашка на координатной сетке

«Черепашка» (Turtle Graphics) — одна из фундаментальных концепций в обучении программированию, созданная математиком Сеймуром Пейпертом в языке Logo. Черепашка — это интерактивный робот-художник на клетчатом холсте:
1. Шагает вперёд или назад вдоль своего взгляда;
2. Поворачивает на 90° налево или направо на месте;
3. Опускает и поднимает перо для рисования следа;
4. Стирает нарисованный узор клавишей `C`;
5. Мягко упирается в границы холста при попытке выйти за пределы поля.

#### Что видит игрок в терминале:
- **Клетчатый холст:** поле фиксированного размера 10×10 в рамке.
- **Иконка Черепашки:** отображается стрелкой в зависимости от направления:
  - `▲` — смотрит на Север (вверх, уменьшение Y);
  - `►` — смотрит на Восток (вправо, увеличение X);
  - `▼` — смотрит на Юг (вниз, увеличение Y);
  - `◄` — смотрит на Запад (влево, уменьшение X).
- **След на холсте:** когда перо опущено (`penDown: true`), каждая ячейка, где побывала Черепашка, помечается точкой `·`. Когда перо поднято, Черепашка перемещается без меток, позволяя переходить в другие участки холста.
- **Статус-бар:** внизу экрана отображаются текущие координаты `(x, y)`, сторона света, статус пера и количество шагов.

Игровой интерес заключается в том, чтобы управлять этой кистью и рисовать геометрические узоры (спирали, квадраты, лесенки), управляя пространственным состоянием.

### Экранная система координат и стороны света

В математике ось Y обычно направлена снизу вверх. Однако в компьютерных терминалах и графических библиотеках всё устроено иначе:
- Начало координат `(x = 0, y = 0)` — это **самый верхний левый угол**.
- Ось `x` идёт слева направо (от `0` до `width - 1`).
- Ось `y` идёт **сверху вниз** (от `0` до `height - 1`).

Поэтому смещение на один шаг при разных сторонах света выглядит так:
- **Север (North, `'N'`):** смещение `dx = 0, dy = -1` (вверх), символ Черепашки `▲`.
- **Восток (East, `'E'`):** смещение `dx = +1, dy = 0` (вправо), символ Черепашки `►`.
- **Юг (South, `'S'`):** смещение `dx = 0, dy = +1` (вниз), символ Черепашки `▼`.
- **Запад (West, `'W'`):** смещение `dx = -1, dy = 0` (влево), символ Черепашки `◄`.

#### Циклический поворот сторон света
Стороны света упорядочены по часовой стрелке: `['N', 'E', 'S', 'W']`.
- Поворот **направо** (по часовой стрелке): переходит к следующему индексу в массиве. После `'W'` (индекс 3) мы снова возвращаемся к `'N'` (индекс 0) через оператор остатка от деления: `(currentIndex + 1) % 4`.
- Поворот **налево** (против часовой стрелки): переходит к предыдущему индексу: `(currentIndex + 3) % 4`.

### Состояние игры (`State`)

В соответствии с правилом нашего трека, мы не создаём классы `class Turtle`. Состояние — это обычный легковесный объект:
- `width` (число, по умолчанию `10`) — ширина поля;
- `height` (число, по умолчанию `10`) — высота поля;
- `x` (число, по умолчанию `0`) — текущая колонка Черепашки (`0..width - 1`);
- `y` (число, по умолчанию `0`) — текущая строка Черепашки (`0..height - 1`);
- `direction` (строка, по умолчанию `'E'`) — текущее направление взгляда (`'N'`, `'E'`, `'S'`, `'W'`);
- `penDown` (булево, по умолчанию `false`) — режим рисования (перо поднято);
- `trail` (массив строковых координат `['x,y']`) — след опущенного пера (по умолчанию пустой `[]`);
- `stepsCount` (число, по умолчанию `0`) — счётчик выполненных перемещений.

### Контракт функций модуля `games/turtle/turtle.js`

Ваша главная задача в этом уроке — создать файл `games/turtle/turtle.js` со следующими экспортируемыми функциями:

#### 1. `createState(options = {})`
Инициализирует и возвращает начальный объект состояния:
- По умолчанию размер поля `width = 10`, `height = 10`;
- Стартовая позиция: `x = options.x ?? 0`, `y = options.y ?? 0`;
- Направление по умолчанию: `direction = options.direction ?? 'E'`;
- Режим пера по умолчанию: `penDown = options.penDown ?? false`;
- Массив `trail`: если `penDown === true`, то начальная позиция `['0,0']` (или `[`${x},${y}`]`) попадает в след; иначе пустой массив `[]`;
- Счётчик шагов: `stepsCount = 0`.

#### 2. `update(state, event)`
Принимает текущее состояние и объект события, возвращает обновлённое состояние игры (иммутабельно).
Обрабатывает следующие типы событий (`event.type`):
- `'TURN_RIGHT'` — поворот направления на 90° по часовой стрелке (`N → E → S → W → N`);
- `'TURN_LEFT'` — поворот направления на 90° против часовой стрелки (`N → W → S → E → N`);
- `'TOGGLE_PEN'` — переключение режима пера (`penDown`). Если перо опускается, текущая координата добавляется в `trail`;
- `'CLEAR_TRAIL'` — очистка нарисованного следа (пустой массив `trail`);
- `'FORWARD'` — шаг на 1 клетку вперёд по текущему направлению `direction` с учётом границ поля;
- `'BACKWARD'` — шаг на 1 клетку назад вдоль направления `direction`.

#### 3. `getView(state)`
Принимает текущее состояние и возвращает объект представления для рендерера:
- `grid` — двумерная матрица символов (массив строк размером `height` на `width`);
- `x`, `y`, `direction`, `penDown`, `stepsCount` — как в `state`.

**Правила построения `grid`:**
- Изначально матрица `height` на `width` заполнена пробелами `' '`;
- След пройденного пути из `state.trail` помечается точками `'.'`;
- Текущая позиция Черепашки по координатам `[state.y][state.x]` обозначается символом направления:
  - `'N'` ➔ `'▲'`
  - `'E'` ➔ `'►'`
  - `'S'` ➔ `'▼'`
  - `'W'` ➔ `'◄'`

### Тестирование логики через `bun test`

Игры тестируются очень легко, когда логика отделена от рендеринга! Поскольку функции `createState` и `update` чистые, вам не нужно эмулировать клавиатуру или терминал. Достаточно проверить, как меняется объект состояния:

```javascript
// games/turtle/turtle.test.js
import { describe, expect, it } from 'bun:test';
import { createState, update } from './turtle.js';

describe('Черепашка на сетке', () => {
  it('поворачивается направо', () => {
    let state = createState({ width: 10, height: 10, direction: 'N' });
    expect(state.direction).toBe('N');

    state = update(state, { type: 'TURN_RIGHT' });
    expect(state.direction).toBe('E');

    state = update(state, { type: 'TURN_RIGHT' });
    expect(state.direction).toBe('S');
  });

  it('не выходит за верхнюю границу поля', () => {
    let state = createState({ width: 5, height: 5, x: 0, y: 0, direction: 'N' });
    const nextState = update(state, { type: 'FORWARD' });
    expect(nextState.y).toBe(0); // осталась на месте
  });
});
```

Для запуска тестов используйте команду:
```bash
bun test games/turtle/
```
