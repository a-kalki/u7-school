# Инфраструктура хранения и инструменты мокирования — краткая выжимка

- **Персистентность** обеспечивает сохранность данных между перезапусками процесса за счёт записи на диск через синхронный модуль `'node:fs'`.
- Получили готовый файл `infra/file-storage.js` с функциями `saveToFile` и `loadFromFile`. Он чистый: ничего не знает про заказы и HTTP.
- Проверили round-trip через физический файл: данные сохраняются и восстанавливаются без потерь.
- Тестировать физический диск в тестах бизнес-логики нельзя: это медленно, оставляет мусор на диске и делает тесты зависимыми друг от друга.
- **Тестовые дублёры (Test Doubles):**
  - **Стаб (Stub):** отвечает заготовленными данными (`mockReturnValue`, `mockImplementation`);
  - **Спай (Spy):** шпионит за методом существующего объекта (`spyOn(obj, method)`), по умолчанию исполняет оригинальный метод, требует `mockRestore()`;
  - **Мок (Mock):** проверяет взаимодействие (`toHaveBeenCalledTimes`, `toHaveBeenCalledWith`).
- **Инструменты `bun:test`:**
  - `mock(fn)` — автономная функция с памятью вызовов (нужно вызывать сам созданный мок);
  - `spyOn(obj, 'method')` — наблюдение за методом объекта с возможностью вернуть оригинал через `mockRestore()`;
  - `mock.module(path, factory)` — подмена модуля в загрузчике Bun для файлов с прямым статическим `import`.
- **Гигиена тестов:** `mockClear()` (очистка истории вызовов в `beforeEach`), `mockReset()` (сброс вызовов и реализации), `mockRestore()` (снятие шпиона).
- Закрепили инструменты на практике в `infra/mock-demo.test.js`.
