# Сетевой транспорт: HTTP, Bun.serve и маршрутизация — краткая выжимка

- HTTP работает по схеме «запрос — ответ». Клиент передаёт метод (`GET`), адрес ресурса и параметры в строке адреса (`query`).
- URL состоит из хоста, пути (`pathname`, по которому выбирается роут) и параметров (`query`, которые мы парсим функцией `getQueryParams`).
- Коды статусов ответа: `200 OK` (успех), `400 Bad Request` (ошибка в запросе клиента), `404 Not Found` (роут или запись не найдены).
- Получили готовый файл `server/server.js`: обёртка над `Bun.serve`, которая слушает порт, ищет путь в таблице `routes`, отдаёт обработчику сырой URL строкой и централизованно перехватывает ошибки через `try / catch`:
  - `OrderValidationError` -> JSON со статусом `400 Bad Request`;
  - `NotFoundError` (выброшенный обработчиком) -> JSON со статусом `404 Not Found`;
  - отсутствие роута в таблице -> `404 Not Found` («Маршрут не найден»).
- Получили готовую точку входа `server/main.js`, которая объединяет `runServer` с таблицей `routes`.
- Подготовили заготовку таблицы маршрутизации `server/route.js`.
- Проверили запуск сервера и отправку запросов через `curl`, веб-браузер и `fetch` в консоли инструментов разработчика.
- В следующем уроке пишем тонкие обработчики пяти роутов — по файлу на роут (`list-orders.js`, `get-order.js` и др.), связывающие сеть с репозиторием.
