### Как устроен обмен по HTTP

**kind:** `text`

Протокол HTTP — это текстовый протокол обмена сообщениями.
Клиент (браузер или терминальная утилита) открывает сетевой канал к серверу и передаёт запрос, сокращенно так:

```http
GET /get?id=101 HTTP/1.1
Host: localhost:3000
User-Agent: curl/8.4.0
```

Сервер обрабатывает этот запрос и отправляет ответ:

```http
HTTP/1.1 200 OK
Content-Type: application/json

{"id":101,"customer":"Анна","amount":5000}
```

В нашем проекте все пять операций будут использовать метод **`GET`**, а параметры будут передаваться прямо в строке адреса (query-параметры).

Более полно разбор сетевых взаимодействий `http-{server <--> client}` мы будем проходить на этапе "Продвинутый js".

---

### Структура адреса: хост, path и query

**kind:** `text`

В адресе `http://localhost:3000/get?id=101` выделяются три важные для сервера части:
- `localhost:3000` — локальный адрес нашего компьютера и порт, на котором запущен процесс.
- `/get` — **path (путь запроса)**. По пути сервер понимает, какую операцию запросил клиент.
- `id=101` — **query (параметры)**.

---

### Коды статуса ответа

**kind:** `text`

Каждый ответ сервера содержит числовой трёхзначный код статуса:
- **`200 OK`** — операция завершилась успешно. В теле ответа передаются запрошенные данные.
- **`400 Bad Request`** — клиент передал неверные данные (например, пропущено обязательное поле `customer` или `id` не является числом).
- **`404 Not Found`** — запрошен несуществующий путь (роут не зарегистрирован) или запись с таким `id` отсутствует в базе.

Клиентские программы (и браузер) ориентируются именно на этот числовой код, чтобы понять, успешен ли запрос.

### Готовый файл сервера: `server/server.js`

**kind:** `text`

Создай каталог `server/` внутри папки проекта `m2-m3-algorithms/m3-p2-http/`.

Создай файл `server/server.js` и вставь готовую реализацию серверной обёртки:

```javascript
export function runServer(routes, port = 3000) {
  const server = Bun.serve({
    port,
    fetch(request) {
      const url = new URL(request.url);
      const handler = routes[url.pathname];

      if (!handler) {
        return new Response(
          JSON.stringify({ error: 'Маршрут не найден' }),
          {
            status: 404,
            headers: { 'Content-Type': 'application/json; charset=utf-8' },
          }
        );
      }

      try {
        // Передаём в обработчик ПОЛНЫЙ сырой URL строкой:
        const result = handler(request.url);
        return new Response(
          result, // перевести в json обязанность обработчика
          {
            status: 200,
            headers: { 'Content-Type': 'application/json; charset=utf-8' },
          }
        );
      } catch (error) {
        let status = 500;
        if (error.name === 'NotFoundError') {
          status = 404;
        } else if (error.name === 'OrderValidationError') {
          status = 400;
        }

        return new Response(
          JSON.stringify({ error: error.message }),
          {
            status,
            headers: { 'Content-Type': 'application/json; charset=utf-8' },
          }
        );
      }
    },
  });

  console.log(`Сервер запущен на http://localhost:${port}`);
  return server;
}
```

Данный код запускает локальный http-сервер на переданном порту. Каждый раз когда приходит запрос на этот порт, то вызывается метод `fetch` и туда передается объект `Request` со свойством `url` где хранится полный адрес запроса.

Далее сервер выполняет четыре ключевые задачи:
1. Выбирает обработчик из переданной таблицы по пути `pathname`.
2. Если путь не найден — возвращает `404 Not Found`.
3. Вызывает обработчик запроса передав ему `url`.
4. Централизованно перехватывает ошибки через `try / catch`: в зависимости от типа ошибки возвращает соответсвующий статус ошибки

Наши обработчики зарегистрированы в `routes`, каждый раз когда приходит запрос то обработчик запроса выбирается из этой таблицы.

### Заготовка таблицы роутов: `server/route.js`

**kind:** `text`

Создай файл `server/route.js` — в него ты будешь подключать готовые функции-обработчики:

```javascript
/**
 * Таблица маршрутизации приложения: путь -> обработчик.
 */
export const routes = {
  // В следующем уроке ты подключишь сюда свои функции:
  // '/get': handleGetOrder,
};
```

Заметь, регистрация обработчика это фактически привязка путь - функция (без вызова). Сервер сам вызовет обработчик и передаст ему url.

---

### Точка входа: `server/main.js`

**kind:** `text`

Создай файл `server/main.js` — это точка входа нашего приложения, объединяющая сервер и маршрутизатор:

```javascript
import { runServer } from './server.js';
import { routes } from './route.js';

runServer(routes, 3000);
```

Этот файл будет запускать наш сервис с реальными маршрутами. Как только ты зарегистрируешь обработчик в `server/route.js`, его можно будет запускать командой `bun run server/main.js` и проверять вживую.

### Тестовый запуск: убедись, что сервер работает

**kind:** `text`

Давайте мы проверим, что наш сервер работает. Для этого в одном файле мы создадим обработчика, зарегистрируем его в таблице роутинга и запустим сервер.

Создай временный файл `server/demo.js` для быстрой проверки:

```javascript
import { runServer } from './server.js';
import { getQueryParams } from '../../utils/business/get-query-params.js';

// это наш тестовый обработчик
function pingHandler(requestUrl) {
  const params = getQueryParams(requestUrl);
  const name = params.name || 'гость';

  return JSON.stringify({ message: `Привет, ${name}!` });
}

// регистрируем его в route
const testRoutes = {
  '/ping': pingHandler,
};

// запускаем сервер передав роутинг с тестовым обработчиком
runServer(testRoutes, 3000);
```

Запусти в терминале:

```bash
bun run server/demo.js
```

Сервер выведет строку: `Сервер запущен на http://localhost:3000`.

Набери в браузере `http://localhost:3000/ping?name=Nurbolat`. Должна отобразиться JSON-строка:
```json
{"message":"Привет, Nurbolat!"}
```

Не закрывай терминал, жми "Выполнено".

### Проверка через терминал и браузер

**kind:** `text`

> Будем тестить через программу `curl`, при необходимости установи его

Не закрывая окно с работающим сервером, открой второй терминал:

1. **Проверка через curl:**
```bash
curl "http://localhost:3000/ping?name=Анна"
# Ответ: {"message":"Привет, Анна!"}
```

2. **Проверка с флагом `-i` (просмотр заголовков и кода статуса):**
```bash
curl -i "http://localhost:3000/ping"
# В ответе видно HTTP/1.1 200 OK
```

3. **Проверка несуществующего пути:**
```bash
curl -i "http://localhost:3000/unknown"
# В ответе видно HTTP/1.1 404 Not Found
```

4. **Проверка в браузере:**
Открой вкладку в браузере и перейди по адресу: `http://localhost:3000/ping?name=Студент`. Браузер покажет JSON-ответ.

5. **Проверка через `fetch` в консоли браузера:**
На этой же странице нажми `F12` (или `Cmd+Option+I` на macOS), перейди во вкладку **Console** (Консоль) и выполни:
```javascript
const res = await fetch('/ping?name=DevTools');
const data = await res.json();
console.log('typeof data:', typeof data);
console.log('data:', data);
```
Так ты воочию увидишь, как фронтенд отправляет HTTP-запрос к нашему бэкенду и парсит полученный JSON-ответ.

После проверки останови тестовый сервер сочетанием клавиш `Ctrl+C` в первом терминале и удали временный файл `server/demo.js`.

### Термины урока

**kind:** `text`

Пройдись по понятиям урока.

**Термины:**
* **HTTP** — протокол прикладного уровня модели клиент-сервер.
* **Path** — часть URL, определяющая маршрут запроса.
* **Query** — строка параметров запроса после знака `?`.
* **Код ответа** — числовой статус результата обработки http запроса (`200`, `400`, `404`).
* **Маршрутизация** — диспетчеризация запросов к соответствующим обработчикам.
