# Шаги урока: Финал проекта: архитектура CRUD, PR и код-ревью

### Архитектурные итоги: слои проекта

**kind:** `text`

Мы построили полноценное модульное приложение. Вспомни, какую ответственность несёт каждый созданный слой:

1. **`utils/`** — утилиты: чистые переиспользуемые функции общего назначения (`toCSV`, `fromCSV`, `getQueryParams`).
2. **`infra/`** — слой технологии: низкоуровневая персистентность (`file-storage.js`): сохранение и чтение файлов через синхронный `node:fs`.
3. **`app/entity/`** — ядро предметной области: тип заказа и фабрика `createOrder` (`order.js`) и доменные правила (`validator.js`).
4. **`app/repo/`** — хранилище: умеет сохранять и восстанавливать заказы.
5. **`app/handler/`** — обработчики: оркестрирует функциями для получения конечного результата запроса.
6. **`server/`** — сетевой шлюз: знает как принимать http-запросы и кому передать.

Слои строго изолированы. Реализации и тесты собираются как лего в единое целое.

### Концепция CRUD: четыре кита веб-сервисов

**kind:** `text`

Наш сервис реализует четыре фундаментальные операции над данными, которые в мировой индустрии называют **CRUD**:

- **Create (создание):**
  - Что означает: создание новой сущности.
  - Наш HTTP-маршрут: `GET /create?...`
  - Метод репозитория: `addOrder`
- **Read (чтение одной сущности):**
  - Что означает: получение записи по ID.
  - Наш HTTP-маршрут: `GET /get?id=...`
  - Метод репозитория: `getOrder`
- **Read (чтение коллекции):**
  - Что означает: получение списка всех записей.
  - Наш HTTP-маршрут: `GET /list`
  - Метод репозитория: `listOrders`
- **Update (обновление):**
  - Что означает: изменение существующей сущности по ID.
  - Наш HTTP-маршрут: `GET /update?id=...`
  - Метод репозитория: `updateOrder`
- **Delete (удаление):**
  - Что означает: удаление сущности по ID.
  - Наш HTTP-маршрут: `GET /delete?id=...`
  - Метод репозитория: `deleteOrder`

Поздравляем: **ты спроектировал и реализовал настоящий CRUD-сервис**.
По этим же принципам строятся микросервисы и веб-приложения на любом языке программирования (Node.js, Go, Python, Java).

### Подготовка к PR

**kind:** `text`

Перед созданием Pull Request запусти полный тестовый прогон:

```bash
bun test
```

Проверь состояние рабочей директории:

```bash
git status
```

Не должно быть забытых временных файлов (например, тестовых csv на диске) или незакоммиченных правок.

Убедись, что код аккуратно отформатирован и не содержит неиспользуемых переменных и отладочных `console.log`.

### Отправка ветки и создание PR

**kind:** `text`

Отправь функциональную ветку в удалённый репозиторий:

```bash
git push -u origin feat/http-service
```

Создай Pull Request из ветки `feat/http-service` в ветку `main`.

**Заголовок PR:**
> Проект «HTTP-сервис»: слоистая архитектура, CRUD и Bun.serve

**Шаблон описания PR:**
```markdown
### Что сделано:
1. Выстроена слоистая архитектура проекта: `infra/`, `app/entity/`, `app/repo/`, `app/handler/`, `server/`.
2. Реализованы доменные валидаторы и фабрика `createOrder`, подготавливающая валидный заказ (`validator.js`, `order.js`).
3. Подключена персистентность через синхронный `node:fs` и формат CSV.
4. Создан репозиторий заказов с паттерном Read-Modify-Write и генерацией `id` (`order-repo.js`).
5. Реализованы тонкие обработчики пяти роутов CRUD — по файлу на роут (`list-orders.js`, `get-order.js` и др.) — и зарегистрированы в маршрутизаторе (`route.js`).
6. Сервис протестирован тремя способами: curl, веб-браузер, fetch в консоли DevTools.
7. Все слои бизнес-логики покрыты изолированными тестами по TDD с использованием моков.
```
