### Идеи для твоей собственной игры

**kind:** `text`

Вот несколько вдохновляющих направлений, которые отлично ложатся на нашу архитектуру:

1. **🏓 Пинг-понг / Арканоид (Pong / Breakout):**
   - Ракетка двигается влево/вправо внизу экрана;
   - Мячик летает с отражением от стен (`dx = -dx`, `dy = -dy`);
   - В Арканоиде сверху расположены кирпичи, исчезающие при попадании.

2. **🧱 Тетрис (Tetris):**
   - Падающие фигурки (тетромино) из 4 блоков;
   - Поворот фигурок, сдвиг по тику, удаление заполненных горизонтальных линий;
   - Рост сложности по уровням: используй делитель тиков (системный vs игровой тик), чтобы с каждым уровнем фигурки падали быстрее.

3. **🐦 Flappy Bird:**
   - Птичка падает вниз под действием гравитации на каждом тике (`dy += 1`);
   - Нажатие пробела подбрасывает птичку вверх;
   - Справа налево движутся препятствия-колонны.

4. **🏰 Подземелье / Roguelike:**
   - Герой исследует комнату, собирает сокровища и ключи;
   - Простые враги, делающие шаг к игроку на каждый его ход.

5. **🧬 Игра «Жизнь» Конвея (Conway's Game of Life):**
   - Клеточный автомат с правилами рождения и смерти клеток по тикам таймера.

Учитывай что у тебя есть готовый терминальный движок. Но адаптер ввода, рендерер вывода и саму игру ты пишешь сам. Ментор ничего не выдаст.

### Старт бонусного проекта

**kind:** `text`

Если решился делать, то не забудь создать ветку и папку. Назови и ветку и папку префиксом `bonus-game`, например: `/games/bonus-game-life`.

Перед тем как писать код, составь краткое ТЗ в файле `arcade/games/<твоя-игра>/README.md`:

```markdown
# Игра: <Название>

## 1. Концепция и цель
Краткое описание механики и условий победы/поражения.

## 2. Структура состояния (State)
Какие поля хранятся в объекте state?
- ширина и высота поля;
- координаты объектов;
- счёт и здоровье;
- статус ('PLAYING', 'WON', 'GAME_OVER').

## 3. Список действий (Actions)
Какие действия происходят по нажатию клавиш и по тикам времени?
- кнопки управления;
- экшен 'TICK' (если игра динамическая).

## 4. Визуализация (getView)
Какими символами отображаются объекты на экране?
```

### Реализация, запуск и демонстрация

**kind:** `text`

Реализуй игру придерживаясь архитектуры нашего движка.

После реализации, запусти свою игру в терминале:

```bash
bun arcade/games/<твоя-игра>/run.js
```

Покажи игру друзьям или коллегам! Проверь, понятен ли интерфейс, удобно ли управление, работают ли клавиши `R` (перезапуск) и `Q` (выход).

Обязательно прогони тесты:

```bash
bun test arcade/games/<твоя-игра>/
```

### Термины урока

**kind:** `text`

Пройдись по понятиям урока. Убедись, что ты можешь объяснить каждое из них своими словами.

**Термины:**
* **Контрактное проектирование (Contract-First Design)** — инженерный подход, при котором разработка системы начинается с фиксации точной спецификации структур данных (`State`, `View`) и сигнатур функций до написания кода.
* **Персистентность данных (Persistence)** — долговременное сохранение состояния приложения на энергонезависимый носитель (запись таблицы рекордов в файл средствами среды выполнения Bun) между перезапусками процесса.
* **Инверсия управления (Inversion of Control / Hollywood Principle)** — архитектурный принцип ядра/движка: инфраструктура сама управляет жизненным циклом программы и вызывает переданные функции разработчика в нужные моменты.
* **Протокольное расширение интерфейса** — расширение возможностей вывода через прямое обращение к стандарту терминала (управляющие ANSI-последовательности цветов, ASCII-колокольчик `\x07`).
* **Процедурная генерация (Procedural Generation)** — алгоритмическое построение структур данных и игровых полей на основе детерминированных правил и генераторов псевдослучайных чисел.
