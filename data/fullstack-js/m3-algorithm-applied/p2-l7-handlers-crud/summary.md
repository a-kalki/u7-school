# Реализация обработчиков API: самостоятельная практика — краткая выжимка

- Самостоятельно реализованы четыре оставшихся обработчика API: `handleListOrders`, `handleCreateOrder`, `handleUpdateOrder`, `handleDeleteOrder`.
- Каждый обработчик спроектирован по принципу тонкого оркестратора: распаковывает параметры URL, валидирует данные через `validateId` и фабрику `createOrder`, вызывает методы `order-repo.js` и возвращает результат в виде строки JSON (`JSON.stringify`).
- Ошибки валидации (`OrderValidationError`) и отсутствие записей (`NotFoundError`) выбрасываются в виде исключений и централизованно превращаются сервером в ответы `400` и `404`.
- Для каждого обработчика написан отдельный файл модульного теста с моками репозитория.
- Все маршруты зарегистрированы в таблице `server/route.js`.
- Полный прогон `bun test app/handler/` проходит со 100% успехом.
- В следующем уроке подводим архитектурные итоги, разбираем концепцию CRUD, проводим полный прогон тестов, оформляем финальный PR и проходим код-ревью.
