# Проект: Пошаговая игра (PR)

**Краткое содержание:**
Переходим ко второму практическому рубежу в «Аркаде». Здесь вы выбираете одну из классических пошаговых головоломок: «2048», «Сокобан», «Сапёр» или «Крестики-нолики». Мы подробно разбираем алгоритмическую начинку каждого варианта: сдвиги и слияния матриц, распространение волны (BFS) при открытии мин, физику двойных коллизий при толкании ящиков и проверку победных линий. Вы узнаете, как запросить пакет игры у ментора, как устроена работа с универсальным рендерером сеток, напишете чистую доменную логику, покроете её собственными тестами и защитите свой Pull Request перед сокурсниками.

**Время:** ~40 мин

**Основные темы:**
- Принцип пошаговой игры: мир меняется только в ответ на действие игрока
- Каталог пошаговых игр на выбор: карточки механик, правила и алгоритмическая сложность
- Алгоритм сдвига и схлопывания чисел для «2048»: обработка строки через фильтрацию нулей
- Алгоритм каскадного раскрытия в «Сапёре»: волновой обход в ширину (BFS) для 8 соседей
- Алгоритм толкания ящиков в «Сокобане»: векторное сложение координат и проверка препятствий
- Алгоритм проверки победных линий в «Крестиках-ноликах»: сканирование лучей в матрице
- Универсальный модуль сетки `tui/grid.js`: повторное использование кода
- Взаимодействие с ментором: получение стартового пакета в чате и сдача PR сокурсникам на peer-review

**Термины:**
* **Событийно-ориентированная пассивная модель (Event-Driven / Turn-based)** — модель выполнения программы, в которой логика находится в состоянии ожидания и вычисляет новый шаг исключительно в ответ на пришедшее событие ввода.
* **Высокая связность (High Cohesion)** — принцип организации кода, объединяющий тесно связанные по смыслу функции (ввод и вывод общего интерфейса сетки) в едином модуле `tui/grid.js` без избыточного дробления.
* **Переиспользование модулей (Code Reuse)** — архитектурная организация общих инфраструктурных компонентов (универсальный рендерер сетки, фабрики адаптеров направлений) для независимых потребителей.
* **Обход в ширину (BFS / Breadth-First Search)** — фундаментальный алгоритм обхода графа или матрицы волной через очередь (FIFO), используемый для каскадного раскрытия смежных ячеек (Flood Fill в Сапёре).
* **Очередь (Queue / FIFO — First-In, First-Out)** — линейная структура данных, в которой элементы обрабатываются строго в порядке их поступления.
* **Каскадная валидация (Cascade Validation / Предусловия)** — последовательная проверка условий допустимости операции (например, проверка препятствия перед объектом и свободного места за ним перед выполнением сдвига).
* **Граничные случаи (Edge Cases)** — нетипичные экстремальные условия выполнения алгоритма (полное заполнение матрицы, попытка хода за границу, нулевой сдвиг), требующие обязательного покрытия тестами.

### Природа пошаговых игр: Архитектура без таймеров

В пошаговой игре отсутствует понятие реального времени:
- Нет функции `setInterval` или периодических тиков.
- Движок `engine.js` работает в пассивном режиме: он ждёт нажатия клавиши от операционной системы.
- Когда клавиша нажата, движок вызывает `update(state, action)`.
- Если действие допустимо — вычисляется новый снимок состояния и рендерится один обновлённый кадр.
- После этого программа снова «засыпает» до следующего нажатия.

Это идеальная среда для оттачивания алгоритмического мышления: вам не нужно переживать о задержках кадров, гонках потоков или скорости реакции игрока. Всё внимание сосредоточено на **чистых преобразованиях структур данных**.

### Каталог игр на выбор (Набор 1)

Вы выбираете **одну** игру из четырёх предложенных. Выбирайте то, что вам ближе по интересам и уровню амбиций.

---

#### Вариант А: «2048» (Числовая сетка)
* **Эмодзи:** 🔢
* **Сложность:** Средняя
* **Игровое поле:** Числовая матрица 4×4.
* **Суть правил:** Сдвиг всех плиток стрелками влево, вправо, вверх или вниз. Одинаковые соседние числа при столкновении объединяются в удвоенное число (`2 + 2 = 4`, `4 + 4 = 8`). После каждого результативного хода в случайной пустой клетке появляется новая плитка (2 или 4). Цель — собрать плитку 2048.

##### Алгоритмическая изюминка:
Главная задача — реализовать чистую функцию сдвига одной одномерной строки: `slideRow(row)`.
1. Отфильтровать все нули: `[2, 0, 2, 4] -> [2, 2, 4]`.
2. Пройтись слева направо: если два соседних числа равны, объединить их: `[2, 2, 4] -> [4, 4]`, увеличив счёт очков.
3. Дополнить строку нулями справа до исходной длины 4: `[4, 4, 0, 0]`.
4. Для сдвига вправо — развернуть строку (`reverse`), применить `slideRow` и развернуть обратно.
5. Для вертикальных сдвигов — транспонировать матрицу (поменять строки и столбцы местами), применить горизонтальный сдвиг и транспонировать обратно.

#### Вариант Б: «Сокобан» (Кладовщик в лабиринте)
* **Эмодзи:** 📦
* **Сложность:** Средняя
* **Игровое поле:** Символьная карта лабиринта (стены `#`, пустота ` `, цели `.`, ящики `$`, игрок `@`).
* **Суть правил:** Игрок толкает ящики к целевым клеткам. Тянуть ящики назад нельзя. Если ящик задвинут в тупик — уровень проигран или требует рестарта. Победа наступает, когда все ящики стоят на целевых клетках.

##### Алгоритмическая изюминка:
Проверка вектора перемещения:
1. Вычисляем клетку назначения игрока: `toX = player.x + dx`, `toY = player.y + dy`.
2. Если в `(toX, toY)` стена — ход запрещён.
3. Если в `(toX, toY)` пусто — игрок просто переходит туда.
4. Если в `(toX, toY)` ящик:
   - Вычисляем клетку за ящиком: `boxToX = toX + dx`, `boxToY = toY + dy`.
   - Если за ящиком стена или второй ящик — **двойная коллизия**: ход запрещён!
   - Если за ящиком свободно или цель — ящик сдвигается в `(boxToX, boxToY)`, а игрок встаёт на `(toX, toY)`.

#### Вариант В: «Сапёр» (Minesweeper)
* **Эмодзи:** 💣
* **Сложность:** Выше средней
* **Игровое поле:** Сетка 9×9 (или 8×8) с 10 скрытыми минами и курсором игрока `[ ]`.
* **Суть правил:** Игрок перемещает курсор стрелками. Пробел — открыть ячейку. Клавиша `f` — поставить флажок мины. Если открыта мина — мгновенный проигрыш. Если открыта пустая клетка без соседних мин (число 0) — поле должно автоматически каскадно раскрыть весь прилегающий безопасный остров.

##### Алгоритмическая изюминка:
1. **Подсчёт соседних мин:** для ячейки `(x, y)` проверяются все 8 соседей со смещениями от -1 до +1 по обеим осям.
2. **Каскадное открытие (BFS / Обход в ширину):**
   - Если число мин вокруг клетки равно 0, создаём очередь координат: `queue = [[x, y]]`.
   - Пока очередь не пуста, извлекаем клетку, открываем её.
   - Если вокруг неё тоже 0 мин, добавляем всех её нераскрытых соседей в очередь.
   - Используем структуру данных `Set` для учёта уже посещённых клеток, чтобы избежать зацикливания.

---

#### Вариант Г: «Крестики-нолики 3×3» или «Четыре в ряд»
* **Эмодзи:** ❌⭕
* **Сложность:** Базовая / Комфортная
* **Игровое поле:** Сетка 3×3 (или поле 6×7 для «4 в ряд»).
* **Суть правил:** Игра для двух игроков на одном терминале (ход X, затем ход O) с курсорным управлением. Побеждает тот, кто первым выстроит непрерывную линию своих символов.

##### Алгоритмическая изюминка:
Универсальный алгоритм проверки победы:
- Не нужно хардкодить все комбинации вручную!
- Проверка строится через сканирование лучей от поставленного символа в 4 направлениях: горизонталь, вертикаль и две диагонали.
- Подсчёт совпадений в обе стороны луча.

### Архитектурная поддержка: Универсальный `tui/grid.js`

Чтобы вам не пришлось писать сложный рендеринг рамок и ячеек, в проекте уже реализован универсальный модуль `tui/grid.js`. Он содержит:
- `renderGrid({ title, grid, stats, controls, cursor, status })` — отрисовка символьных матриц с наложением рамок Unicode (`┌─┐│└─┘`), курсора `[X]` и статусов победы/поражения.
- `renderNumberGrid({ title, grid, score, bestScore, status })` — специализированная отрисовка числовых сеток с красивым выравниванием колонок (для 2048).
- `createDirectionAdapter()` — готовый адаптер ввода для стрелок и клавиш WASD.
- `cursorActionAdapter()` — готовый адаптер ввода для курсора со стрелками и клавишами действия (Пробел, `f`, `Enter`).

### Регламент взаимодействия с ментором и сдача работы

1. **Выбор игры:** Изучите карточки вариантов выше и выберите одну игру.
2. **Запрос пакета в чате:** Напишите ментору сообщение в учебном чате:
   > «Привет! В проекте Аркада я выбираю игру **<Название игры>**. Выдай, пожалуйста, стартовый пакет.»
3. **Получение пакета:** Ментор пришлёт вам:
   - Файл детального технического задания с точными именами функций и свойствами состояния (`README.md`);
   - Готовый файл запуска `run.js` для выбранной игры;
   - Модуль универсального TUI интерфейса `arcade/tui/grid.js` (Слой 2).
   *(Логику игры и собственные юнит-тесты вы проектируете и пишете самостоятельно!)*
4. **Открытие рабочей ветки по Git-flow:**
   - Переключитесь на актуальный `main` и откройте ветку под игру:
     ```bash
     git checkout main
     git pull origin main
     git checkout -b feature/<game-name>
     ```
     (например, `feature/sokoban` или `feature/game-2048`).
   - **Важное правило:** вся работа над игрой, размещение файлов от ментора (`README.md`, `run.js`), логика и тесты ведутся строго в этой ветке! Это позволяет любому сокурснику при код-ревью переключиться на ветку (`git checkout feature/<game-name>`) и сразу получить готовую сборку для локального тестирования.
5. **Реализация и тестирование:**
   - Поместите полученные от ментора файлы `README.md` и `run.js` в папку `arcade/games/<game>/`;
   - Создайте файл логики `arcade/games/<game>/<game>.js` и реализуйте требуемые чистые функции;
   - Создайте файл тестов `arcade/games/<game>/<game>.test.js`, напишите сценарии проверки чистых функций и краевых случаев:
     ```bash
     bun test arcade/games/<game>/
     ```
   - Проверяйте игру вживую в терминале:
     ```bash
     bun arcade/games/<game>/run.js
     ```
6. **Сдача Pull Request на peer-review сокурсникам:**
   - Закоммитьте все файлы игры в рабочей ветке:
     ```bash
     git status
     git add arcade/games/<game>/
     git commit -m "feat(arcade): реализовать логику игры <Название> и тесты"
     ```
   - Запушьте ветку на GitHub:
     ```bash
     git push -u origin feature/<game-name>
     ```
   - Откройте Pull Request в ветку `main` на GitHub.
   - В описании PR приложите скриншот игрового процесса в терминале или короткую запись.
   - Отправьте ссылку сокурсникам в учебный чат:
     ```text
     🔍 PR на ревью: [Пошаговая игра: <Название игры> (логика и тесты)]
     📎 Ссылка: https://github.com/<твой-username>/fullstack-js/pull/<номер>
     📋 Жду ваших комментариев и апрувов!
     ```

#### Что проверяется на код-ревью (чек-лист для сокурсников и ментора):
- **Чистота функций:** Отсутствие мутаций входных параметров `state` там, где это ломает предсказуемость;
- **Декомпозиция:** Сложные алгоритмы (например, сдвиг строки или каскад раскрытия) вынесены в понятные вспомогательные чистые функции;
- **Покрытие тестами:** Написаны авторские тесты, проверены не только победные ходы, но и ошибочные действия (удар в стену, попытка хода на занятую клетку, поражение);
- **Читаемость:** Понятные имена переменных и отсутствие «магических чисел».
