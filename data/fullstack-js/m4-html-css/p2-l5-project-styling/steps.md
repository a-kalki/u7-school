### Оформляем таблицу

**kind:** `text`

Открой визитку и посмотри на таблицу: ячейки слиплись, шапка ничем не отличается от данных. У таблицы на твоей странице должно стать так:

- **границы** — у всех ячеек, толщиной 1px, цветом границ; соседние границы слиты в одну линию;
- **воздух в ячейках** — внутренний отступ 4px по вертикали и 8px по горизонтали;
- **текст ячеек** — по левому краю;
- **шапка таблицы** (`thead`) — фон как у страницы, чтобы зрительно отделиться от данных;
- строка «Итого» уже выделяется жирным — это сделал `<strong>` в HTML, стили ей не нужны.

**Сделай:** добавь в конец `styles.css` (все токены тебе знакомы из p2-l4):

```css
table {
  width: 100%;                              /* на всю ширину карточки */
  border-collapse: collapse;                /* соседние границы сливаются в одну линию */
}

th, td {
  border: 1px solid var(--color-border);    /* сетка: тонкая рамка цветом границ */
  padding: var(--space-1) var(--space-2);   /* воздух в ячейках: 4px по вертикали, 8px по горизонтали */
  text-align: left;                         /* текст ячеек по левому краю */
}

thead th {
  background: var(--color-bg);              /* шапка на фоне страницы — зрительно отделяется */
}
```

**Сделай:** сохрани и обнови страницу.

**Получишь:** таблица с ровной сеткой границ, дышащими ячейками и выделенной шапкой. Страница выглядит законченной.

Хочешь понять, а не просто скопировать: в DevTools → Styles снимай галочки с правил по очереди — сразу видно, за что каждое отвечает.

**Сделай:** (проверка каскада) в DevTools → Styles выбери любую `td` и посмотри, какие правила на неё действуют.

**Получишь:** видны твои правила из `styles.css` — и ничего инлайн. Если видишь перечёркнутые строки — где-то спор правил; разберись, кто победил и почему.

### Оформляем в Git

**kind:** `text`

Вся работа проекта 2 идёт в ветке `p2-styling` — ты в ней с первого урока проекта. История должна рассказывать проект: коммиты по шагам (`p2: accent headings`, `p2: visit card`, `p2: palette and typography`, `p2: design tokens`), финальный — `p2: table and ready for review`.

**Сделай:** запушь ветку и открой pull request: в описании — что изменилось и чем твоё оформление отличается от соседей по потоку (одним абзацем).

```bash
git add -A
git commit -m "p2: table and ready for review"
git push -u origin p2-styling
```

**Получишь:** второй PR в свой репозиторий. Дальше — код-ревью, как в проекте 1: работу смотрят студенты потока, замечания правишь новыми коммитами в той же ветке. Два апрува — и ветку можно мерджить в `main`. На ревью смотрят и структуру, и применение норм.

### Термины урока

**kind:** `text`

- **border-collapse** — от англ. `border` — «граница» + `collapse` — «схлопывать»: соседние границы ячеек сливаются в одну линию
- **инлайн** — от англ. `inline` — «в строке»: проверка каскада: в Styles видно, что стили не инлайн, а из styles.css (не путать с инлайн-элементами p1-l3)
- **токен** — от англ. `token` — «жетон, знак»: проверка: в файле ноль сырых значений вне `:root` — всё через токены
- **ревью** — от англ. `review` — «обзор, повторный просмотр»: работу смотрят другие студенты потока и оставляют замечания
- **апрув** — от англ. `approve` — «одобрять»: отметка в PR «код можно принять»; для мерджа нужно две
