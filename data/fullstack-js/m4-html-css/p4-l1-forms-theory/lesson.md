# Формы: input, select, label, button

**Краткое содержание:**
Как собирают данные от пользователя: контейнер `form`, поля `input` разных типов, выпадающие списки `select`/`option`, кнопка `button`. Связка `label` с полем через `for` и `id` и встроенная валидация (`required`, `type`, `:valid`/`:invalid`). В модуле 3 формы приложения ещё не собираем — теорию проходим на мини-заданиях вне приложения и применяем в одном месте: селектах-фильтрах «Результата». Плюс наполняем секцию «Календарь».

### Подробный конспект

#### 1. Форма и её поля

Поля собираются в контейнер `<form>`:

```html
<form action="/submit" method="post">
  <label for="name">Имя</label>
  <input type="text" id="name" name="name" required>
  <button type="submit">Отправить</button>
</form>
```

- `action` — куда отправлять данные (адрес на сервере), `method` — как (`get` или `post`). В модуле 3 отправлять некуда: форма нужна ради разметки и полей;
- `id` у поля и `for` у `label` **связывают** подпись и поле: клик по подписи ставит курсор в поле.

Связка `label` важна и для доступности: скринридер прочитает подпись вместе с полем. Правило: **у каждого поля есть `label`.**

#### 2. Типы полей

`type` у `input` определяет вид поля и встроенную проверку:

| `type` | Для чего |
|---|---|
| `text` | обычный текст |
| `email` | почта: браузер проверит формат |
| `number` | только числа (`min`, `max`, `step`) |
| `date` | дата с календариком |
| `password` | скрытый ввод |

Атрибут `required` запрещает отправку, пока поле пустое, а `name` даёт полю имя для отправки на сервер.

**Сделай:** замени поле имени на поле почты (`type="email"`) и добавь `required`.

**Получишь:** при попытке отправить форму с пустым или неправильным адресом браузер покажет подсказку и не даст отправить.

#### 3. Список и кнопка

Для выбора из вариантов — `select` с вложенными `option`:

```html
<label for="dept">Отдел</label>
<select id="dept" name="dept">
  <option>ИТ-отдел</option>
  <option selected>Бухгалтерия</option>
</select>
```

`selected` помечает вариант, выбранный по умолчанию. Кнопку отправки делает `<button type="submit">`.

#### 4. Валидация и группировка — вкратце

- `required`, `type` и другие атрибуты — **встроенная валидация** браузера. Состояние поля доступно в CSS через псевдоклассы `:valid` (корректно) и `:invalid` (нет): например, `input:invalid { border-color: #b30000; }` подсветит ошибку;
- поля можно группировать в `<fieldset>` с заголовком `<legend>` — смысловая рамка вокруг группы;
- проверка в браузере — не замена серверной: данные всё равно проверяют на сервере. Подробно форму мы оживим в модуле 4.

**Сделай:** (эксперимент) добавь `input:invalid { border-color: #b30000; }` и убери `required` — посмотри, как меняется поведение подсветки.

### Термины урока

- **форма** — от лат. `forma` — «вид, образ»: контейнер для полей ввода
- **`form`** — от англ. `form` — «форма»: тег, объединяющий поля для отправки данных
- **`label`** — от англ. `label` — «ярлык, подпись»: подпись поля; связывается с полем через `for` и `id`
- **`input`** — от англ. `input` — «ввод»: поле ввода; его назначение задаёт `type`
- **`select`** — от англ. `select` — «выбирать»: выпадающий список
- **`option`** — от англ. `option` — «вариант»: пункт списка `select`
- **`button`** — от англ. `button` — «кнопка»: элемент нажатия
- **`required`** — от англ. `require` — «требовать»: поле обязательное
- **валидация** — от лат. `validus` — «крепкий, законный»: проверка корректности введённых данных
- **`fieldset`/`legend`** — от англ. `field` — «поле» + `set` — «набор» / `legend` — «легенда»: группа полей и её заголовок
