### Что делаем

**kind:** `text`

Это финальный урок проекта 1. Всю вёрстку ты вёл по ходу уроков: каркас и название (p1-l2), описание и отделы (p1-l3), штатное расписание (p1-l4). Новый код писать почти не придётся — осталось убедиться, что всё на месте и похоже на образец, и сдать работу.

Инструмент — **сверка с растром**: открой рядом свою страницу в браузере и растр `p1-visit-card`, который ментор выдал в начале проекта. Иди сверху вниз.

В проекте 1 сверяем **структуру и содержание**: зоны, тексты, порядок. Внешний вид — тема проекта 2, поэтому твоя «голая» страница и оформленный растр будут похожи, но не одинаковы.

### Сверка с образцом

**kind:** `text`

На твоей странице должно быть:

- **заголовок страницы** (`h1`) — имя компании, один на страницу;
- **абзац** (`p`) — описание, чем занимается компания (1–2 предложения, текст твой);
- **заголовок раздела** (`h2`) — «Отделы»;
- **ненумерованный список** (`ul`) — 4 отдела: ИТ-отдел, Бухгалтерия, Отдел продаж, HR-отдел;
- **заголовок раздела** (`h2`) — «Штатное расписание»;
- **таблица** (`table`) — три колонки «Отдел — Должность — Оклад»: шапка в `thead` с `th scope="col"`, 5 строк данных в `tbody` и строка «Итого 2400000», где слово растянуто на две колонки, а важность выделена `<strong>`.

**Сделай:** сравни свою страницу с растром блок за блоком. Совпадает порядок зон? Совпадают тексты и числа?

**Получишь:** расхождения, если есть, мелкие и легко чинятся: опечатка в названии отдела, забытый `scope`, число с пробелом. Исправь.

### Чек-лист самопроверки

**kind:** `text`

Пройди по пунктам — каждый «да» или чиним:

- [ ] Вкладка браузера: «ТОО «Дала Технолоджи»»; кириллица не сломана
- [ ] Один `h1`; два `h2`; иерархия без прыжков
- [ ] В DevTools → Elements дерево: `h1 → p → h2 → ul(4 li) → h2 → table(thead + tbody)`
- [ ] У блоков данных есть адреса: `company-name` (h1), `departments` (ul), `staff` (table)
- [ ] Таблица: 3 колонки, 5 строк данных, итоговая строка с `colspan` и `<strong>`
- [ ] Числа — голые: `600000`, без пробелов и символов валют
- [ ] Никаких `<div>` и `<script>` — только смысловые теги
- [ ] Вложенность в коде — 2 пробела за уровень

### Оформляем в Git

**kind:** `text`

Вся работа проекта 1 шла в ветке `p1-visit-card` — ты завёл её в первом уроке. Проверь, что история коммитов рассказывает проект (`p1: document skeleton`, `p1: description and departments`, `p1: staff table`).

**Сделай:** убедись, что нет незакоммиченных изменений, и запушь ветку:

```bash
git add -A
git commit -m "p1: ready for review"
git push -u origin p1-visit-card
```

Создай Pull Request в свой репозиторий: base — `main`, compare — `p1-visit-card`. Опиши в PR, что это визитка предприятия: какие зоны собраны, где какие адреса у блоков данных.

**Получишь:** первый PR проекта. Дальше — код-ревью, как в модуле 2: работу смотрят другие студенты потока и оставляют замечания. Два апрува — и ветку можно мерджить в `main`.
