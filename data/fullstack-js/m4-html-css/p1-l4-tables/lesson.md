# Таблицы: штатное расписание

**Краткое содержание:**
Таблица — главный способ показать данные «строки × колонки». Собираем её по деталям: `<table>`, строки `<tr>`, заголовочные ячейки `<th>`, ячейки данных `<td>`, секции `<thead>`/`<tbody>`. Объединяем ячейки `colspan` для строки «Итого» и делаем последний большой шаг визитки — штатное расписание с эталонными данными.

### Подробный конспект

#### 1. Когда таблица — правильный выбор

Таблица — для **табличных данных**: то, что честно живёт в строках и колонках. Штатное расписание, табель, прайс. А вот *располагать элементы страницы* таблицами — ошибка из 2000-х: для расположения есть CSS (проект 3). Правило: **таблица — только данные**.

#### 2. Собираем таблицу по одной детали

**Сделай:** после списка отделов добавь заголовок и пустую таблицу:

```html
<h2>Штатное расписание</h2>
<table>
</table>
```

**Получишь:** на странице — только заголовок. Пустая таблица ничего не рисует: таблица — это каркас, наполним ячейками.

**Сделай:** добавь первую строку таблицы с тремя заголовочными ячейками (добавляй между открывающими и закрывающими тегами таблицы `table`):

```html
<tr>
  <th>Отдел</th>
  <th>Должность</th>
  <th>Оклад</th>
</tr>
```

**Получишь:** строку с тремя жирными ячейками по центру. `<tr>` (table row) — строка, `<th>` (table header) — заголовочная ячейка; жирность и центрирование браузер даёт сам.

**Сделай:** добавь строку данных под ней:

```html
<tr>
  <td>ИТ-отдел</td>
  <td>Разработчик</td>
  <td>600000</td>
</tr>
```

**Получишь:** вторая строка — обычным шрифтом, ячейки выровнены по колонкам. `<td>` (table data) — ячейка данных. Заметь: три колонки в обеих строках, ровно как в шапке.

#### 3. Секции thead и tbody

Строку с шапкой оборачивают в `<thead>`, данные — в `<tbody>`:

```html
<table>
  <thead>
    <tr>
      <th>Отдел</th>
      <th>Должность</th>
      <th>Оклад</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>ИТ-отдел</td>
      <td>Разработчик</td>
      <td>600000</td>
    </tr>
  </tbody>
</table>
```

**Сделай:** оберни свои строки в `<thead>` и `<tbody>`, как выше. Обнови страницу.

**Получишь:** внешне ничего не изменилось — и это нормально. Секции нужны не глазу, а смыслу: шапку можно стилизовать отдельно (сделаем в проекте 2), а в модуле «DOM» JS будет искать данные именно в `tbody`. Ставим их всегда.

#### 4. Доступность: scope

Заголовкам колонок добавляют `scope="col"` — «этот `th` описывает колонку»:

```html
<th scope="col">Оклад</th>
```

**Сделай:** добавь `scope="col"` всем трём `th`.

**Получишь:** на вид — ноль изменений. Для экранных дикторов — понятная таблица. Доступность часто «невидима», но входит в качество вёрстки.

#### 5. colspan: ячейка в несколько колонок

Строка «Итого» занимает три колонки, но у неё всего два значения: слово «Итого» (две колонки) и сумма:

```html
<tr>
  <td colspan="2"><strong>Итого</strong></td>
  <td><strong>2400000</strong></td>
</tr>
```

**Сделай:** добавь эту строку последней в `tbody`. Проверь: `colspan="2"` + одна ячейка = 3 колонки.

**Получишь:** «Итого» растянулось на две колонки, сумма — в третьей, строка не «поехала». `<strong>` здесь по смыслу: итоговая строка — важная.

**Сделай:** (эксперимент) убери `colspan="2"`, оставь просто `<td>Итого</td>`, обнови.

**Получишь:** строка сломалась: последняя ячейка выпала в четвёртую несуществующую колонку, таблица покосилась. Правило: сумма `colspan` в строке = числу колонок таблицы. Верни `colspan`.

#### 6. Числа без форматирования

В ячейках с деньгами пишем `600000`, а не `600 000 ₸`. Пробелы и символы валют — красиво, но в модуле «DOM» JS прочитает эти числа из страницы и будет считать. Отсюда правило всего продукта: **данные — голые числа**. Красивый формат добавим в самом конце, средствами JS.

#### 7. id: маркируем источник данных

Продолжим маркировку из p1-l3. Таблица — главный источник данных визитки: дай ей адрес.

**Сделай:** добавь атрибут таблице: `<table id="staff">`.

**Получишь:** разметка не изменилась, но у таблицы теперь точный адрес `staff`. В модуле «DOM» твой скрипт прочтёт строки этой таблицы именно по нему — поэтому маркируем сейчас, пока структура свежа в голове.

Правило наших проектов: блоки с данными всегда имеют id. В визитке их три: `company-name` — название, `departments` — отделы, `staff` — штат.

### Шаг визитки: штатное расписание

**Сделай:** дострой таблицу до полной: 5 строк данных из эталонного набора — ИТ-отдел: Разработчик 600000, Тестировщик 450000; Бухгалтерия: Бухгалтер 500000; Отдел продаж: Менеджер по продажам 400000; HR-отдел: HR-менеджер 450000. Затем строка «Итого — 2400000» через `colspan` и `<strong>`. Пройди глазами по колонкам: данные в каждой строке соответствуют шапке.

**Получишь:** таблица «Отдел — Должность — Оклад»: 5 строк + итог. В DevTools → Elements найди `thead` и `tbody` — структура читается; у таблицы — адрес `staff`.

**Сделай:** `git add -A && git commit -m "p1: staff table"`.

Визитка собрана целиком. Осталась сверка с образцом — это проектный урок.

### Термины урока

- **`<table>`** — от англ. `table` — «таблица»: только для данных «строки × колонки», не для расположения элементов
- **`<tr>`** — от англ. `table row` — «строка таблицы»: одна строка
- **`<th>`** — от англ. `table header` — «заголовок таблицы»: заголовочная ячейка; жирная и по центру от браузера
- **`<td>`** — от англ. `table data` — «данные таблицы»: ячейка данных
- **`<thead>`** — от англ. `table head` — «шапка таблицы»: секция шапки; стилизация отдельно + JS в модуле «DOM» ищет данные в tbody
- **`<tbody>`** — от англ. `table body` — «тело таблицы»: секция данных
- **`scope`** — от англ. `scope` — «область действия»: к чему относится заголовок: `col` — к колонке, `row` — к строке
- **`colspan`** — от англ. `column` — «колонка» + `span` — «охватывать»: на сколько колонок растянуть ячейку
- **`<caption>`** — от англ. `caption` — «подпись»: подпись над таблицей; у нас роль подписи играют h2
- **layout** — от англ. `layout` — «раскладка, планировка»: расположение элементов на странице. Раньше (примерно до 2010 г.), таблицами размечали страницы. Сейчас есть удобные инструменты разметки, отсюда правило: таблицы только для табличных данных, никогда для разметки
