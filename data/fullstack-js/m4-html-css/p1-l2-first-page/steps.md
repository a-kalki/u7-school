### Скелет страницы

**kind:** `text`

Каждая HTML-страница начинается одинаково — с каркаса (boilerplate):

```html
<!DOCTYPE html>
<html lang="ru">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>Название страницы</title>
</head>
<body>
  <!-- всё видимое содержимое здесь -->
</body>
</html>
```

**За что отвечает каждая часть:**

- `<!DOCTYPE html>` — «делай по современным стандартам». Всегда первая строка, всегда такая.
- `<html lang="ru">` — корневой элемент; `lang="ru"` сообщает: страница на русском. Важно для экранных дикторов и поисковиков.
- `<head>` — метаданные: информация *о* странице. На самой странице не отображается.
- `<body>` — всё видимое: текст, списки, таблицы.

Такой каркас называют **boilerplate** — заготовка, которую копируют в каждый новый проект.

> Можешь сохранить этот каркас в отдельный файл `html-template.html`, чтобы всегда держать под рукой.

### Кодировка и заголовок вкладки

**kind:** `text`

Метаданные — невидимая, но важная часть страницы. Разберём ключевые:

- `<meta charset="UTF-8">` — кодировка. Русские буквы живут именно благодаря ей.
- `<meta name="viewport" ...>` — правила масштабирования на экранах разной ширины. Пока вставляй «как есть».
- `<title>` — заголовок вкладки браузера.

**Сделай:** (эксперимент) создай файл `hello-world.html` с каркасом из прошлого шага. Временно удали строку с `charset` и открой страницу в браузере.

**Получишь:** вместо кириллицы — «крякозябры» вида `РўРћРћ`. Вот зачем нужна кодировка. Верни строку на место.

Самое интересное: пользователь видит из `<head>` только `<title>` — в заголовке вкладки. Всё остальное — служебное.

### Подключаем CSS

**kind:** `text`

CSS живёт в отдельном файле и подключается в `<head>`:

```html
<link rel="stylesheet" href="styles.css">
```

`href` — путь к файлу. Наши файлы лежат рядом, поэтому путь короткий.

**Сделай:** рядом с `hello-world.html` создай `hello-world.css` и подключи его. В `<body>` добавь:

```html
<p>Привет, Мир!</p>
```

Сохрани и открой файл в браузере (двойной клик по файлу или `Ctrl+O`). Ты должен увидеть приветствие.

**Сделай:** добавь в CSS-файл правило:

```css
body {
  color: red;
}
```

Сохрани и обнови страницу (`F5`).

**Получишь:** страница стала красной. Как именно CSS находит элементы и меняет их вид — разберём во втором проекте; пока важен сам факт: HTML и CSS живут в разных файлах и связаны одной строкой `<link>`.

### Репозиторий проекта: шаг визитки

**kind:** `text`

Пора завести проект, который пройдёт через весь модуль.

**Сделай:** создай репозиторий `payroll-portal` — так же, как в предыдущих модулях: `git init`, связал с репозиторием на GitHub. Добавь `README.md` и `.gitignore` по необходимости. Первые файлы закоммить прямо в основную ветку `main` и запушь в удалённый репозиторий.

Затем создай ветку для первого проекта — вся его работа будет жить в ней:

```bash
git checkout -b p1-visit-card
```

Создай два файла:

```
payroll-portal/
  index.html   ← создаём сейчас
  styles.css   ← пока пустой, с комментарием /* стили появятся в проекте 2 */
```

**Сделай:** в `index.html` вставь каркас из начала урока и сделай три изменения:
1. в `<title>` — `ТОО «Дала Технолоджи»`;
2. внутри `<body>` — заголовок `<h1>ТОО «Дала Технолоджи»</h1>`;
3. не забудь `<link rel="stylesheet" href="styles.css">` в `<head>`.

Открой `index.html` в браузере.

**Получишь:** вкладку «ТОО «Дала Технолоджи»» и крупный заголовок на странице. Страница «голая» — так и должно быть.

### Рабочий цикл и проверка в DevTools

**kind:** `text`

Рабочий цикл вёрстки: создал/изменил файл → **сохранил** (`Ctrl+S`) → обновил вкладку браузера (`F5`). И так по кругу — десятки раз за урок. Привыкай сразу: не сохранил — браузер покажет старое, и ты будешь искать несуществующую ошибку.

**Сделай:** включи «выбрать элемент» (`Ctrl+Shift+C`), кликни по заголовку прямо на странице — он откроется в дереве Elements. Поменяй его текст прямо в браузере на что-нибудь смешное, потом обнови страницу.

**Получишь:** убедился, что дерево в DevTools — это твоя страница; и что правки в DevTools не сохраняются в файл.

### Термины урока

**kind:** `text`

- **boilerplate** — от англ. `boiler` — «котёл» + `plate` — «пластина»: из полиграфии: пластины для многократной печати одинакового текста; каркас-заготовка, которую копируют в каждый проект
- **тег** — от англ. `tag` — «ярлык, бирка»: пометка вида `<p>`, описывающая, что это за фрагмент
- **атрибут** — от лат. `attributum` — «приписанное»: пара `имя="значение"` внутри открывающего тега
- **метаданные** — от греч. `meta` — «о чём-то»: «данные о данных»: то, что в `<head>`, а не на странице
- **`<html>`** — от `HyperText Markup Language`: корневой элемент страницы; всё живёт внутри него
- **`<head>`** — от англ. `head` — «голова»: служебная «голова» документа: метаданные, не видимые на странице
- **`<body>`** — от англ. `body` — «тело»: видимое «тело» страницы: всё содержимое
- **`<title>`** — от англ. `title` — «название»: заголовок вкладки браузера
- **`<meta>`** — от греч. `meta` — «о»: метатеги: кодировка, масштабирование и прочее «о странице»
- **charset** — от англ. `character set` — «набор символов»: `UTF-8` — кодировка, умеющая в кириллицу
- **viewport** — от англ. `view` — «вид» + `port` — «отверстие»: «окно просмотра»: как страница масштабируется на экране
- **`<link>`** — от англ. `link` — «связь»: подключение внешнего файла, например `styles.css`
