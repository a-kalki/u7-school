# Проект 3: каркас портала

**Краткое содержание:**
Финал проекта 3. Каркас собран по ходу урока p3-l4: шапка, сайдбар, рабочая область и секции с заглушками. В этом уроке сверяем работу с растром-образцом, проверяем «прилипание» шапки и сайдбара, проходим чек-лист и отправляем проект на код-ревью через pull request.

### Что делаем

Каркас уже готов: шапка (p3-l4), оболочка «сайдбар + main» на grid, пять секций, первая из которых содержит таблицу «Штат», остальные — заглушки. Новый код почти не нужен: осталось сверить работу с образцом и сдать.

Инструмент тот же, что в проектах 1 и 2, — **сверка с растром**: открой рядом свой портал в браузере и растр `p3-app-shell`, который ментор выдал в начале проекта.

### Сверка с образцом

Иди сверху вниз и сверь. **На твоей странице должно быть…**

- **шапка** (`header`) на всю ширину: слева квадратный логотип 32×32 с акцентной заливкой, рядом название компании; отступы внутри — 8px по вертикали и 24px по бокам, снизу — тонкий разделитель;
- **каркас** ниже шапки — из двух колонок: узкий сайдбар слева и широкая рабочая область справа;
- **сайдбар** (`aside`) шириной 200px: белый, с разделителем справа; список из пяти пунктов — Штат, Календарь, Сотрудники, Табель, Результат; первый пункт подсвечен мягким акцентом и жирный;
- **рабочая область** (`main`) — пять секций сплошным потоком, все видимы: Штат, Календарь, Сотрудники, Табель, Результат;
- в секции «Штат» — таблица из визитки: «Отдел — Должность — Оклад», 5 строк, строка «Итого 2400000»;
- четыре остальные секции — с абзацем-заглушкой.

**Сделай:** пройди по списку и растру. Что-то не сходится — найди причину в DevTools → Elements / Styles и поправь.

**Получишь:** портал, собранный из тех же зон, что в образце. Отличия в деталях (шрифты, скругления, оттенки вне норм) допустимы — их обсудим на ревью.

### Проверка «прилипания»

Главная механика каркаса — шапка и сайдбар стоят на месте, а прокручивается только рабочая область.

**Сделай:** прокрути страницу колесом. Для проверки временно вставь в одну из секций много текста (или продублируй секции), прокрути и убедись, что шапка с сайдбаром не уехали.

**Получишь:** прокрутка живёт **внутри** `main`, а не на всей странице. Если уезжает вся страница — вернись к шагу «Фиксация каркаса» в p3-l4 и проверь `height`, `flex: 1` и `overflow-y`.

### Чек-лист самопроверки

- [ ] Семантические зоны на месте: `header`, `aside`, `main`, `section`; дерево в DevTools читается как содержание
- [ ] Шапка — flex-строка: лого 32×32 акцентного цвета + `h1` 20px; отступы 8×24px, разделитель снизу 1px
- [ ] Каркас — grid из двух колонок: `200px` и `1fr`
- [ ] Сайдбар: ширина 200px, фон поверхностей, разделитель справа 1px; пункты 8×16px
- [ ] Активный первый пункт подсвечен цветом мягкого акцента и жирным
- [ ] Пять секций идут сплошным потоком, все видимы; зазор между ними 16px
- [ ] Секции: фон поверхностей, рамка 1px, отступ 16px; заголовки `h2` — 18px, акцентные
- [ ] При прокрутке шапка и сайдбар стоят, прокручивается только `main`
- [ ] Таблица «Штат» перенесена целиком, включая «Итого 2400000»; числа по-прежнему голые
- [ ] Мягкий акцент добавлен в `:root` отдельным токеном, а не сырым значением в правиле
- [ ] Никаких `<script>` — JS в этом модуле не подключается

### Термины урока

- **растр** — от лат. `rastrum` — «грабли, решётка»: изображение-образец, с которым сверяют вёрстку
- **app shell** — от англ. `app` — «приложение» + `shell` — «оболочка»: каркас приложения
- **ревью** — от англ. `review` — «обзор»: работу смотрят другие студенты потока и оставляют замечания
- **апрув** — от англ. `approve` — «одобрять»: отметка в PR «код можно принять»; для мерджа нужно две

### Оформляем в Git

Вся работа проекта 3 шла в ветке `p3-shell` — ты завёл её в первом уроке проекта. История должна рассказывать проект: коммиты по шагам (`p3: start app shell`, `p3: app shell`, `p3: sections with placeholders`), финальный — `p3: ready for review`.

**Сделай:** запушь ветку и открой pull request: base — `main`, compare — `p3-shell`. В описании — что изменилось и как устроен каркас (одним абзацем).

**Получишь:** третий PR в свой репозиторий. Дальше — код-ревью, как раньше: замечания правишь новыми коммитами. Два апрува — и ветку можно мерджить в `main`.

### Куда это растёт

Каркас готов, но четыре секции из пяти пусты. В проекте 4 наполним их данными: календарь, сотрудников, табель и посчитанный «Результат». Секции пока стоят сплошным потоком — переключать их по клику в сайдбаре научит JavaScript в модуле «DOM».
