# Как устроен веб: браузер, HTML, CSS и JS

**Краткое содержание:**
Три языка веб-страницы: HTML — структура, CSS — оформление, JavaScript — поведение. Разница между сайтом и веб-приложением и куда мы идём в модулях 3–4. И первая встреча с главным инструментом модуля — DevTools: откроем чужую страницу, заглянем внутрь и подредактируем её прямо в браузере.

### Подробный конспект

#### 1. Три языка веб-страницы

Каждая страница — работа трёх технологий:

- **HTML** — структура и содержимое: *что* на странице. Заголовки, абзацы, списки, таблицы.
- **CSS** — оформление: *как* это выглядит. Цвета, шрифты, отступы, расположение.
- **JavaScript** — поведение: *как* страница реагирует на клики и ввод.

Аналогия с домом: HTML — каркас и комнаты, CSS — отделка и интерьер, JS — электрика и автоматика.

В модуле 3 мы строим каркас и отделку. **JS не трогаем вовсе** — портал будет «мёртвым» и оживёт только в модуле 4.

#### 2. Сайт и веб-приложение

**Сайт** — страницы для чтения: корпоративная визитка, блог. Кликнул по ссылке — ушла новая страница.
**Веб-приложение** — реагирует на тебя: клики обрабатываются, суммы пересчитываются, интерфейс меняется без перезагрузки.

Наш продукт — портал предприятия «ТОО «Дала Технолоджи»» — сейчас будет статичным сайтом: все данные (штат, сотрудники, табель, зарплаты) жёстко впишем в HTML. В модуле 4 JS прочитает их прямо из страницы и научится считать.

#### 3. Как браузер показывает страницу

Браузер читает HTML-файл, строит из него дерево элементов и рисует его, применяя CSS. Нет CSS — будет «голая» страница: чёрный текст на белом. Именно такой будет наша первая визитка — и это нормально: сначала структура, потом красота.

Браузер прощает ошибки разметки: страница откроется, даже если ты забыл закрыть тег. Но может выглядеть будет не так, как задумано. Поэтому проверяем не «открылось ли», а *что именно* открылось — через DevTools.

#### 4. Рабочее место

Понадобятся два инструмента, оба у тебя уже есть:

- **Браузер** — Chrome, Edge или Firefox.
- **Редактор кода** — VS Code или тот, в котором ты работал в модулях 1–2.

Проект модуля будет жить в репозитории `payroll-portal/` — заведём его на следующем уроке.

> При желании ты можешь для всех учебных модулей создать один репозиторий. В этом случае структуру папок продумай самостоятельно

#### 5. DevTools: рентген любой страницы

Открой DevTools: `F12` или `Ctrl+Shift+I` (`Cmd+Option+I` на macOS). Или правый клик по любому элементу страницы → **Inspect** («Просмотреть код»).

Слева — **Elements**: дерево HTML. Справа — стили выбранного элемента. Здесь же всё можно править прямо в браузере.

**Сделай:** открой любую новостную страницу, кликни правой кнопкой по заголовку новости → Inspect. В дереве Elements найдётся именно этот заголовок. Дважды кликни по его тексту в дереве и впиши что-нибудь своё — например, «Эту новость написал я».

**Получишь:** заголовок на странице мгновенно поменяется. Никакой магии: ты отредактировал копию страницы в памяти браузера.

**Сделай:** обнови страницу (F5).

**Получишь:** заголовок вернулся к настоящему. Правки в DevTools — временные, до перезагрузки. Настоящий код живёт в файлах — DevTools только для осмотра и экспериментов.

#### Инструмент «Выбрать элемент»

Самый удобный способ знакомиться с чужой страницей — инструмент **«Выбрать элемент»**:

- **Где находится:** иконка-курсор в левом верхнем углу панели DevTools (курсор в рамочке). Ещё быстрее — горячая клавиша `Ctrl+Shift+C` (`Cmd+Shift+C` на macOS).
- **Как работает:** включил — курсор на странице меняется. Водишь мышью — элементы подсвечиваются, рядом всплывает ярлык: имя тега, размеры, цвет текста и фона. **Клик** — элемент раскрыт в дереве Elements. Выход — `Esc` или повторный клик по иконке.
- **Связь в обе стороны:** наведение на строку в дереве подсвечивает элемент на странице; клик в дереве — выбирает элемент. Страница и дерево — одно и то же, увиденное дважды.

**Сделай:** на той же новостной странице включи «выбрать элемент» (`Ctrl+Shift+C`) и медленно проведи курсором по логотипу, картинке и подвалу.

**Получишь:** каждый элемент подсвечивается, в ярлыке — его тег и размеры: у логотипа один, у картинки другой. Так страница «рассыпается» на отдельные элементы, как под рентгеном.

**Сделай:** кликни по подвалу — он раскрылся в дереве Elements. Теперь води мышью по строкам дерева: `<footer>`, `<div>`, `<a>`...

**Получишь:** на странице подсвечивается именно тот элемент, на строке которого курсор. Кликом выбирают элемент со страницы, наведением в дереве — находят его на странице. Кстати, на реальных сайтах увидишь и семантические теги (`header`, `main`, `footer`), и «div-суп» — как повезёт авторам.

**Шпаргалка клавиш:**

| Клавиши | Что делают |
|---|---|
| `F12` или `Ctrl+Shift+I` | открыть/закрыть DevTools |
| `Ctrl+Shift+C` | включить «выбрать элемент» |
| ПКМ → Inspect | открыть DevTools и сразу выбрать элемент |
| `Esc` | выйти из режима выбора |
| `F5` | обновить страницу (сброс правок из DevTools) |

Этим инструментом мы будем пользоваться весь модуль: вёрстка проверяется глазами и DevTools.

#### 6. Дорожная карта модуля

**Цель модуля:** дать основы, познакомить с тем из чего состоит страница, как он формируется. Мы пройдем по самым верхушкам. Пройдя этот модуль вы не станете специалистом по верстке сайтов. Но будете довольно хорошо понимать как выстраиваются сайты.

Наам предстоит сделать четыре проекта — одна растущая работа:

| Проект | Что делаем | Результат |
|---|---|---|
| П1 «Первые страницы» | HTML без стилей | визитка предприятия |
| П2 «Оформляем» | CSS, дизайн-токены | оформленная визитка |
| П3 «Каркас портала» | flexbox, grid | каркас приложения с сайдбаром |
| П4 «Разделы с данными» | формы, состояния | портал целиком с данными |

Каждый проект достраивает предыдущий — ничего не переписывается с нуля. К концу модуля у тебя будет готовый UI приложения, с которым модуль 4 сделает остальное.

### Термины урока

- **HTML** — от `HyperText Markup Language`, «язык разметки гипертекста»: гипертекст — текст со ссылками, разметка — пометки, описывающие структуру
- **CSS** — от `Cascading Style Sheets`, «каскадные таблицы стилей»: каскад — «водопад», правила «текут» вниз по странице (подробно в П2)
- **JavaScript** — назван «в честь» Java маркетингом 1995 года, с языком Java не связан; на сайте живёт в файлах `.js`
- **DOM** — от `Document Object Model`, «объектная модель документа»: дерево элементов, которое браузер строит из HTML
- **DevTools** — от `Developer Tools`, «инструменты разработчика»: встроенный в браузер набор для осмотра и отладки страниц
- **Inspect** — от англ. `inspect`, «осматривать»: пункт меню ПКМ, показывает элемент в дереве Elements
- **сайт** — от англ. `site`, «место, участок»: набор связанных страниц для просмотра
- **веб-приложение** — от англ. `web application`, «приложение в сети»: страница, реагирующая на действия пользователя
