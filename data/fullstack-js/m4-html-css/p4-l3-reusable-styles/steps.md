# Шаги урока: Переиспользуемые стили: базовый класс и модификатор

---

### Теория урока на w3schools

**kind:** `text`

В портале одни и те же элементы повторяются: таблиц уже несколько, будет ещё больше; где-то кнопки, где-то карточки. Если стилизовать каждый элемент по отдельности, файл разрастётся, а правки придётся делать в десяти местах. Решение — **переиспользуемые компоненты**: один набор стилей, который применяется ко многим местам.

Прочитай страницу курса:

- [HTML & CSS: Reusable Components](https://www.w3schools.com/htmlcss/htmlcss_reusable_components.asp)

Обрати внимание на приём «базовый класс + модификатор» и на то, как стили удерживаются внутри компонента.

---

### Идея компонента

**kind:** `text`

**Компонент** — кусочек интерфейса с готовым набором стилей: карточка, кнопка, таблица, бейдж. Компонент описывают один раз классом, а потом ставят этот класс на все похожие элементы.

Ключевое слово здесь — **область видимости (scope)**: правило компонента должно задевать только его элементы и не «протекать» на соседей. Поэтому селекторы вроде `.btn` точнее, чем свободный `button`.

---

### Базовый класс и модификатор

**kind:** `text`

Разные кнопки похожи, но отличаются оттенком: главная — акцентная, второстепенная — прозрачная. Вместо двух независимых классов делают **базовый + модификатор**:

```css
.btn {
  padding: 8px 16px;
  border: 1px solid #2b5fd9;
  background: #2b5fd9;
  color: #fff;
}

.btn-primary {
  background: #2b5fd9;
}

.btn-ghost {
  background: transparent;
  color: #2b5fd9;
}
```

В разметке: `class="btn btn-primary"` — базовый класс отвечает за форму и отступы, модификатор меняет только то, чем кнопки отличаются.

**Сделай:** в песочнице сделай две кнопки: главную и «прозрачную». Общие свойства — в `.btn`, различия — в модификаторах.

**Получишь:** две кнопки одинаковой формы, но разного веса. Правка общего свойства в одном месте меняет обе.

### Наш случай: классы для таблиц

**kind:** `text`

В портале таблиц много, и у них есть повторяющиеся особенности:

- **числовые ячейки** выравнивают по правому краю — разряды выстраиваются, суммы сравниваются мгновенно. Приём мы запланировали ещё в p2-l3;
- **строки итогов** выделяют жирным;
- строку с названием компании (в «Календаре») — приглушённым цветом.

Для этого заведём **служебные (utility) классы** — маленькие классы «на одно свойство»:

| Класс | Что делает | Где применяем |
|---|---|---|
| `num` | числа по правому краю | все числовые ячейки и их заголовки |
| `total-row` | жирный текст строки | строки ИТОГО |
| `company` | приглушённый текст | название компании в «Календаре» |

**Сделай:** заведи эти классы в `styles.css`:

- `num` повесь на числовой столбец «Оклад» в таблице «Штат» (и на заголовок, и на ячейки);
- `company` — на строку с названием предприятия в «Календаре» (та, что ты добавил в p4-l1);
- в строке «Итого» таблицы «Штат» **убери `<strong>`** и повесь `total-row` на весь `<tr>`.

**Почему класс, а не `<strong>`.** `<strong>` — смысловой тег «важно», и умеет он только одно: жирный. Строка итога — это **роль**: завтра ей понадобится фон или линия сверху — и `<strong>` уже "не справится" с этим. При желании тег `strong` можно оставить для экранных ридеров.

**Получишь:** числа в «Штате» встали по правому краю, а строка «Итого» стала жирной через класс `total-row`.

### Термины урока

**kind:** `text`

- **компонент** — от лат. `componentis` — «составляющий»: переиспользуемый кусок интерфейса со своим набором стилей
- **scope** — от греч. `skopos` — «цель, кругозор»: область видимости стилей: кого задевает правило
- **базовый класс** — общие стили компонента
- **модификатор** — от лат. `modificare` — «изменять»: класс, меняющий одно отличие компонента
- **utility-класс** — от англ. `utility` — «полезность»: служебный класс «на одно свойство»: `num`
- **BEM** — от `Block Element Modifier` — «блок, элемент, модификатор»: соглашение именовать классы по роли
- **`colspan`** — от англ. `column` — «колонка» + `span` — «охват»: объединение ячеек по горизонтали
