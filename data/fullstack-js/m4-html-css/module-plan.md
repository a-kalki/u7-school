# Модуль 3 «HTML & CSS» — план модуля

> **Источник видения:** `./concept.md` (общая концепция модулей 3 и 4). Этот план самодостаточен, но при изменении видения обновляются оба файла. Перед генерацией шагов обязательно читать `conductor/guides/lesson-design.md`.

## 1. Мета

- **Курс:** Fullstack-js; **модуль 3** (после «Синтаксис» и «Алгоритмика»)
- **Длительность:** 4 проекта, ~4–5 недель (проект = 3–10 дней, ориентир — неделя)
- **Формат:** теория через курс w3schools «htmlcss» (локальные копии `data/sources/w3-school/htmlcss/`), закрепление мини-заданиями, практика — вёрстка сквозного продукта
- **Связка:** М3 (вёрстка) + М4 «DOM» (логика) = одна большая задача: приложение «Портал предприятия». Модуль 4 работает с HTML, свёрстанным в этом модуле

## 2. Цель и результат модуля

**Цель:** студент изучает основы HTML и CSS и свёрстывает UI будущего приложения — «Портал предприятия» на чистом HTML и CSS с **жёстко вшитыми данными**, знакомится с основами UX.

**Результат модуля:** полностью свёрстанный портал: шапка с логотипом и названием компании, сайдбар с разделами (Штат, Календарь, Сотрудники, Табель, Результат), в main — секции всех разделов с данными, включая посчитанный «Результат» за октябрь с итогами по отделам. Все секции видимы и идут сплошным потоком (скрытие неактивных и переключение по сайдбару добавит JS в М4). Портал «мёртвый», но выглядит цельно и наполнено.

**Ключевой принцип:** все данные приложения студент вшивает в HTML буквально, по эталонному набору из `concept.md` §5. Числа в данных — без форматирования (`600000`, не `600 000 ₸`).

Каждый пункт сайдбара — свой раздел данных. Данные всех таблиц и «Результат» — эталонный набор `concept.md` §5 (включая посчитанные итоги §5.3).

## 4. Что студент уже умеет / чего не знает

- **Умеет** (М1–М2): функции, массивы, объекты-структуры, циклы, import/export, Git/PR/ревью, чтение чужого кода.
- **Не знает:** HTML, CSS (с этого модуля), DOM, события браузера (М4), ООП/классы (будущие модули). В уроках М3 JS не используется: портал статичен; `<script>` не подключается (это работа М4).

## 5. Контракт и свобода (принцип модуля; полно — в `concept.md` §3)

**Мы даём:** референс-макет — HTML-референсы в `./reference/` по каждому проекту: `p1-visit-card/`, `p2-visit-card-styled/`, `p3-app-shell/`, `p4-static-portal/` (каждая — index.html + styles.css, образец структуры проекта студента; растр для студентов готовит владелец); перечень обязательных зон/элементов; эталонный набор данных (`concept.md` §5) — единый для потока; **нормы оформления — конкретные значения по элементам и группам (§7.1)**; чек-лист результата каждого проекта.

**Студент решает:** как применить нормы и собрать разметку — сам находит нужный элемент в своей странице, подбирает селектор/класс и CSS-свойство, вешает указанное значение; разбивку на блоки и нейминг классов; организацию CSS; детали, не охваченные нормами (конкретный шрифт, скругления, декор); порядок работы.

Следствие: работы студентов различаются в деталях, но визуально сопоставимы с референсом — на ревью обсуждаем и вариативность, и точность применения норм.

## 6. Чему учим и чему не учим

**Учим:** семантический HTML (структура, текст, списки, таблицы, формы-теория); CSS (селекторы, каскад, box model, цвета, шрифты, переменные-токены); layout (поток, flexbox, grid — каркас приложения); состояния hover/focus/active; переиспользуемые стили (класс + модификатор); доступность вкраплениями (label, alt, контраст); DevTools (Elements) как инструмент проверки.

**Не учим (осознанно):** адаптивность/responsive (предлагается опционально для дополнительного изучения и внедрения); препроцессоры, сборщики, фреймворки; position/z-index (упоминание вскользь); анимации (опционально); дизайн-системы как теория.

**Формы:** теория (input, select, label, button, required) проходится в проекте 4 на мини-заданиях вне приложения + простое применение в портале — селекты-фильтры «Результата». Формы ввода/редактирования данных (кнопки «изменить», поля добавления) не вёрстаются — они появятся в М4 при переводе разделов на ввод.

## 7. Данные для вёрстки

Все таблицы и карточки наполняются эталонным набором `concept.md` §5:

- шапка: название «ТОО «Дала Технолоджи»», место под логотип
- сайдбар: 5 пунктов разделов

- «Календарь»: название компании + таблица месяцев с нормами: сентябрь 2026 — 21, октябрь 2026 — 22
- «Сотрудники»: 5 строк — имя, фамилия, должность, отдел, дата приёма
- «Табель»: 10 строк «месяц — сотрудник — отработанные дни» (2 месяца × 5 сотрудников)
- «Результат»: два селекта-фильтра (месяц, отдел — статичные, значением по умолчанию октябрь / все отделы) + вшитая таблица расчёта за октябрь из `concept.md` §5.3: строки сотрудников по отделам, строки ИТОГО по каждому отделу и ИТОГО по предприятию

### 7.1. Нормы оформления (значения для проектных постановок; соответствуют референсам)

Принцип: **значения задаём мы, применение — за студентом.** В постановках и шагах формулируем человеческим языком: «у заголовков секций цвет — тёмно-синий #2b5fd9, размер — 18px» — студент сам находит элемент в своей разметке, подбирает свойство и применяет значение. Готовый CSS не выдаём.

**Токены (вводятся в П2; «мягкий акцент» добавляется в П3 для активного пункта меню; живут в CSS-переменных):**

| Токен | Значение | Назначение |
|---|---|---|
| фон страницы | `#f4f5f7` | body |
| фон поверхностей | `#ffffff` | карточки, секции, шапка, сайдбар |
| текст | `#222222` | основной |
| приглушённый текст | `#666666` | описания, подписи |
| акцент | `#2b5fd9` | заголовки секций, лого, активный пункт |
| мягкий акцент | `#e8eefb` | фон активного пункта меню |
| границы | `#d9dce3` | рамки, разделители |
| отступы | `4 / 8 / 16 / 24` px | базовая шкала (ступени: xs/s/m/l) |

**Элементы (по мере появления в проектах):**

| Элемент | Норма |
|---|---|
| шрифт | системный `sans-serif` (конкретное семейство — свобода студента) |
| заголовок H1 | 24px в визитке (П2); 20px в шапке портала (П3) |
| заголовок H2 (секция/визитка) | 18px, цвет акцента |
| карточка визитки (П2) | фон поверхностей, граница 1px, внутренний отступ 24px, max-width 680px, по центру |
| секция портала (П3) | фон поверхностей, граница 1px, внутренний отступ 16px |
| таблица | границы 1px у всех ячеек, отступ ячейки 4×8px, шапка таблицы — фон страницы, числа — по правому краю |
| строка итогов | жирный текст (без фона) |
| шапка | внутренние отступы 8×24px, разделитель снизу 1px; лого — квадрат 32px (фон акцент, белый символ) |
| сайдбар | ширина 200px, фон поверхностей, разделитель справа 1px; пункт — отступы 8×16px |
| активный пункт меню | фон мягкого акцента + жирный текст |
| наведение на пункт (П4) | фон страницы |
| зазор между секциями | 16px |
| селекты фильтров (П4) | отступы 4×8px, граница 1px |

Значения — рабочие: при смене дизайна референсов обновить таблицу и постановки.

## 8. Проекты и уроки

Именование папок: `data/fullstack-js/m3-html-css/p<N>-l<M>-<kebab-name>/` (правила — `lesson-design.md`). По каждому уроку: сначала `lesson.md` + `summary.md`; `steps.md` — отдельный этап.

**Принцип эволюции:** проекты — развитие одной работы: каждый следующий дополняет предыдущую, ничего не переписывается с нуля. Путь: визитка (П1) → оформленная визитка (П2, та же разметка с одной обёрткой-карточкой + CSS) → каркас портала (П3: `h1`-название переезжает в шапку, таблица расписания — в секцию «Штат», добавляются сайдбар и секции-заглушки) → портал с данными (П4: заглушки наполняются). Описание «чем занимается компания» живёт только в визитке (П1–П2).

**Про теги:** какие теги использовать — студент выбирает **из изученного**: программа уроков (w3) вводит теги вовремя (семантические зоны — к П3, формы — к П4). В проектных постановках указываем состав зон («шапка: лого и название», «сайдбар: 5 пунктов»), готовую разметку не даём. Сайдбар в П3 — список пунктов (`ul > li`, без ссылок): клики на пунктах появятся в М4.

## 9. Критерии завершения модуля (чек-лист итога)

- [ ] «Штат»: таблица отдел — должность — оклад, 5 строк + строка «Итого 2400000»
- [ ] «Календарь»: карточка компании + месяцы сентябрь 2026 (21) и октябрь 2026 (22)
- [ ] «Сотрудники»: 5 строк с датами приёма; «Табель»: 10 строк с колонкой месяца
- [ ] «Результат»: селекты месяц/отдел (статичные) + вшитая таблица октября из §5.3 с ИТОГО по отделам и предприятию
- [ ] Данные всех таблиц = эталонный набор `concept.md` §5; числа без форматирования
- [ ] Активный пункт сайдбара подсвечен классом
- [ ] Палитра/типографика в CSS-переменных; есть стили hover/focus
- [ ] Git: коммиты по проектам, работа в ветках, PR в свой репозиторий
- [ ] Студент может объяснить каждую зону своей вёрстки и свои классы (защита на ревью)

## 10. Правила генерации уроков (кратко; полно — `concept.md` §9, `lesson-design.md`)

- `lesson.md` — интерактивный конспект: каждая концепция закрывается парой **«Сделай» (конкретное действие/код) → «Получишь» (ожидаемый результат в браузере)**; сухой пересказ источника запрещён. `summary.md` — выжимка 10–15 строк.
- **Живость:** в каждом уроке 1–4 эксперимента «отойти вбок» — пощупать тему за пределами лекции (сломать тег, поменять значение, проверить крайний случай глазами).
- **Термины урока:** в конце каждого урока (перед источниками) — раздел «Термины урока» таблицей «Термин / Расшифровка / Суть». В расшифровке — расширенное название термина с происхождением: «тег `p` — от англ. `paragraph` — «абзац»», «CSS — от `Cascading Style Sheets` — «каскадные таблицы стилей»». Стиль образца: «лексикографический (от греческого lexikon — словарь + grapho — пишу)». Только термины, встречающиеся в этом уроке.
- **Визитка/портал растут по ходу уроков:** в конце теоретического урока — блок «Шаг визитки»: что добавить в проект-файл по теме урока и каким коммитом зафиксировать. Проектный урок тогда лёгкий: сверка с растром-образцом от ментора по списку зон («на странице должно быть: это — заголовком, это — ненумерованным списком…») + чек-лист + Git, без детального ТЗ.
- Теория без видео: первый шаг урока — ссылка на страницу w3; если тема не покрыта w3 полностью — своя мини-теория в шагах **с обязательным закрепляющим заданием**; для w3-теории закрепление опционально, если источник сам даёт упражнения.
- Мини-задания: одна концепция, 1–3 минуты («что будет со вёрсткой, если...», «добавь блок, который...»).
- Минимум один шаг «сделай по текстовой задаче» в уроке (в этом модуле если целесообразно в данном уроке).
- Только изученное: концепции HTML/CSS не опережают свои уроки (порядок таблиц §8).
- Мини-задания — маленькие HTML/CSS-фрагменты; проверка — глазами и DevTools.
- Данные в примерах и проектах — только эталонный набор `concept.md` §5; числа без форматирования.
- Всё на русском; файлы студента в kebab-case (`payroll-portal/`, `styles.css`).
- Проектный урок (`p<N>-l<последний>`) — сверка с растром по списку зон естественным языком, без готового кода.
- **Сдача работ:** ментору лично работы не сдаются. Ветка проекта заводится в первом уроке проекта (`p<N>-<название>`), в проектном уроке — PR. Код-ревью делают другие студенты потока; **2 апрува → можно мерджить** в `main`. Сам процесс ревью в уроках не описываем — к нему ведём: ветка с начала, коммиты по шагам, PR в конце.
- **Ведение студента нормами (§7.1):** в проектных шагах указываем значения по элементам и группам человеческим языком («у пунктов меню: внутренние отступы 8×16px; у активного пункта — фон #e8eefb и жирный текст»). Студент сам находит элемент в своей разметке, подбирает селектор/класс и CSS-свойство, применяет значение. Готовый CSS-код и готовую разметку не выдаём. Значения — только из §7.1 (едины с референсами).
- JS в М3 не используется и не подключается.
