# Текст и списки: заголовки, абзацы, семантика — краткая выжимка

- Заголовки `h1–h6` — оглавление страницы: один `h1`, разделы — `h2`; уровень по смыслу, не по размеру
- Несуществующего тега (`h7`) не бывает: браузер рисует его как обычный текст — словарь HTML фиксирован
- `<p>` — абзац (сам отталкивается от соседних); `<br>` — только перенос внутри текста, абзацы им не делают
- Незакрытый тег захватывает всё дальше по документу — закрывающие теги не формальность
- `<strong>` — важность (жирный), `<em>` — акцент (курсив); инлайн-теги не разрывают строку; просто жирное — `<b>`
- **Блочные теги** (`h1`, `p`, `ul`, `table`) — вся ширина, с новой строки; **строчные** (`strong`, `em`, `span`) — внутри строки
- **Семантический** тег сообщает смысл (`h1`, `p`, `table`); **нейтральные** — обёртки без смысла: `div` (блочный), `span` (строчной)
- Смысловые обёртки зон: `main` — уже в П2 (карточка визитки); в П3 придут `header`, `section`, `aside`, `footer`, `nav`
- Анатомия: `<тег атрибут="значение">содержимое</тег>`; `class` — метка группы (пригодится в П2), `title` — подсказка
- `<ul>` — без порядка (маркеры), `<ol>` — с порядком (номера); пункт — `<li>`; выбор списка — смысловой
- Семантические теги лучше «div-супа»; правило модуля: есть смысловой тег — бери его
- **id** — уникальный адрес элемента; латиница, kebab-case; правило проектов: у блоков с данными id обязателен; в DevTools → Elements ищется через Ctrl+F `#company-name`
- Шаг визитки: p-описание → h2 «Отделы» → ul (ИТ-отдел, Бухгалтерия, Отдел продаж, HR-отдел); адреса `company-name` и `departments`
