# Шаги урока: Функция toCSV(data)

---

### Что такое CSV

**kind:** `text`

**CSV (Comma-Separated Values, «значения через запятую»)** — текстовый формат таблицы: каждая строка — одна запись, ячейки разделены запятой, первая строка обычно содержит заголовки столбцов.

Вот таблица:

| name | age | city |
|------|-----|------|
| Анна | 25 | Москва |
| Борис | 30 | Питер |

Она же в CSV — обычный текст:

```
name,age,city
Анна,25,Москва
Борис,30,Питер
```

В пост-СНГ регионе разделителем часто служит точка с запятой: там дробная часть числа пишется через запятую, и её не нужно путать с разделителем ячеек. Например, таблица температур:

```
city;00:00;06:00;12:00;18:00
Astana;14,5;13,2;22,7;18,0
Almaty;22,5;21,0;31,6;28,2
```

CSV используют для обмена таблицами между программами: выгрузка из базы, экспорт и импорт в Excel и Google Таблицы, отчёты. Формат простой и компактный — его понимает любая табличная программа.

### Что такое JSON и как он записывает значения

**kind:** `text`

**JSON (JavaScript Object Notation)** — текстовый формат представления данных. Он вырос из синтаксиса объектов JavaScript, но сегодня используется во всех языках: ответы API, конфиги, документы в базах.

Сделаем сериализацию объекта:

```js
const anna = { name: "Анна", age: 25, city: "Uralsk", home: "25", isWorked: true, pet: null };
const annaAsJson = JSON.stringify(anna); // сериализация — из объекта в строку

console.log(typeof annaAsJson); // string
console.log(annaAsJson);
```

Теперь обратная операция — превратим JSON-строку обратно в объект:

```js
const annaAsJson = '{ "name": "Анна", "age": 25, "city": "Uralsk", "home": "25", "isWorked": true, "pet": null }';
const anna = JSON.parse(annaAsJson); // десериализация — из строки в объект

console.log(typeof anna); // object
console.log(anna);
```

Так как JSON — это строка, его можно записать в файл `*.json` или передать по сети. Ниже — запись объекта в виде чистого JSON (например, в файле):

```json
{ "name": "Анна", "age": 25, "city": "Uralsk", "home": "25", "isWorked": true, "pet": null }
```

Самое важное для нас — **у JSON у каждого типа своя однозначная запись**, поэтому по тексту всегда видно тип:

| Значение JS | Запись в JSON |
|---|---|
| строка `'Анна'` | `"Анна"` |
| строка `'25'` | `"25"` |
| число `25` | `25` |
| число `-3.14` | `-3.14` |
| `true` / `false` | `true` / `false` |
| `null` | `null` |
| `undefined` | — (записи нет) |
| `NaN`, `Infinity` | `null` (JSON их не поддерживает) |

**Главное правило: строка всегда в двойных кавычках, остальные типы — без кавычек.** Кавычки — единственный признак, отличающий строку `'25'` от числа `25`: без них они в тексте неразличимы.

В JSON есть и объекты (`{...}`), и массивы (`[...]`), но нам они не понадобятся: наша таблица плоская.

Отдельно про `undefined`: в JSON его нет. Внутри объекта такой ключ просто исчезает (`JSON.stringify({ a: undefined })` → `{}`). Поэтому в нашем формате `undefined` мы закодируем пустой ячейкой.

Но у JSON есть один минус. Если мы сохраняем массив одинаковых объектов, то ключи придётся сохранять для каждого объекта:

```json
[
  { "name": "Анна", "age": 25 },
  { "name": "Виталий", "age": 17 },
  { "name": "Нурлан", "age": 28 }
]
```

Более компактный формат — это CSV. Рассмотрим его в следующем шаге.

### Проблема: типы теряются

**kind:** `text`

Тот же массив объектов в CSV хранился бы так:

```csv
name,age
Анна,25
Виталий,17
Нурлан,28
```

Вроде бы идеально. Первая строка — ключи. Последующие: одна строка — один объект. Но в стандартном CSV есть и проблемы. Рассмотрим на следующем объекте:

```js
const anna = { name: 'Anna', age: 25, home: '25', pet: 'true', isWorked: true };
```

В стандартном CSV это будет сохранено так:

```csv
name,age,home,pet,isWorked
Anna,25,25,true,true
```

В итоге в стандартном CSV мы теряем типы. Строка `'25'` и число `25` записываются одинаково. Строка `'true'` и булево `true` тоже станут неразличимы. Та же проблема со значениями `false` и `null`.

**Вывод:** стандартный формат CSV нам не подходит из-за потери типов.

---

### Решение: наш формат

**kind:** `text`

Договоримся: **берём структуру от CSV (компактно), а значения пишем так, как это делает JSON (типы не теряются).** Получится не CSV и не JSON, а наш собственный формат — «велосипед».

**Как хранится значение** (ровно по правилам JSON):

| Значение JS | Ячейка |
|---|---|
| `'Анна'` | `"Анна"` |
| `'25'` | `"25"` |
| `25` | `25` |
| `true` / `false` | `true` / `false` |
| `null` | `null` |
| `undefined` | *(пусто)* |
| `NaN`, `Infinity` | `null` |

Тот же объект:

```js
const anna = { name: 'Anna', age: 25, home: '25', pet: 'true', isWorked: true };
```

В нашем формате это сохранится так:

```csv
name,age,home,pet,isWorked
"Anna",25,"25","true",true
```

**Экранирование строк.** Строка в JSON всегда в кавычках, и кавычки сами защищают запятые: `"Анна, Борис"` — это одно значение, а не два. Но некоторые символы внутри строки нужно экранировать, иначе запись сломается:

| Символ | В ячейке | Код символа |
|---|---|---|
| `"` | `\"` | — |
| `\` | `\\` | — |
| перенос строки (LF) | `\n` | 10 |
| возврат каретки (CR) | `\r` | 13 |
| табуляция (TAB) | `\t` | 9 |

Объект:

```js
const team1 = {
  name: 'frontend',
  developers: 'Anna, Nurlan',
  address: 'Uralsk\nAbay street, "25"',
  room: '4th floor, office: 4'
};
```

Сохранится в нашем формате так:

```csv
name,developers,address,room
"frontend","Anna, Nurlan","Uralsk\nAbay street, \"25\"","4th floor, office: 4"
```

Это упрощённое подмножество JSON. Разберём строку из поля `address`: перенос строки в ней превратился в `\n`, а кавычки вокруг `25` заэкранированы — `\"25\"`. При этом запятые внутри значения экранировать не нужно: внешние кавычки уже защищают их, поэтому `Anna, Nurlan` так и остаётся внутри одной ячейки.

**Два разных переноса — не путай их:**
- перенос-**разделитель** между записями (в конце строки) — **реальный** символ `\n` (LF, код 10), ровно один на строку. В коде это `result += '\n'`;
- перенос **внутри значения** — пара символов `\` + `n` (живёт внутри кавычек). В коде это `result += '\\n'`.

В тексте задачи оба обозначаются как `\n`, поэтому всегда держи в голове контекст: где именно находится этот символ.

**Правила ключей.** Ключи пишутся без кавычек, поэтому ключ должен быть «стандартным»: непустая строка без `,`, `"`, `\` и переносов. Если ключ не подходит — выбрасываем `TypeError`.

**Ограничения нашего формата**:
- массив **плоских** объектов с одинаковыми ключами;
- ключи берутся по первому объекту;
- значения — только примитивы: строка, число, boolean, `null`, `undefined`. Вложенные объекты и массивы не поддерживаются.

### Закрепим понимание JSON

**kind:** `text`

Проверь в `bun repl` (или файлом через `bun`), что понимаешь разницу между **кодом** и **значением строки в памяти**. Это ключ к экранированию — и к тому, как записывать ожидания в тестах.

**A. Что лежит в памяти.** Набери:

```js
'a\nb'.length     // 3 — перенос это ОДИН символ
'a\\nb'.length    // 4 — слэш и n это ДВА символа
'a"b'.length      // 3
```

`'a\nb'` в исходнике — это `a`, перенос, `b`: пара `\` + `n` нужна только в коде. `'a\\nb'` — это `a`, обратный слэш, `n`, `b`: в коде слэш пишется `\\`.

**B. Как это записывает JSON.** Сравни:

```js
JSON.stringify('a\nb')    // "a\nb"    — length 6
JSON.stringify('a\\nb')   // "a\\nb"   — length 7
JSON.stringify('a"b')     // "a\"b"    — length 6
```

JSON ничего не «додумывает»: он берёт значение из памяти и заменяет спецсимволы парами. Перенос (1 символ) → `\n` (2 символа), обратный слэш (1 символ) → `\\` (2 символа).

**C. Круг возвращает исходное значение:**

```js
JSON.parse(JSON.stringify('a\nb')).length    // 3
JSON.parse(JSON.stringify('a\\nb')).length   // 4
```

**D. Ловушка исходника.** Сколько символов в этих строках?

```js
'a\"b'.length     // 3 — \" в коде это просто кавычка, слэш исчез
'a\\"b'.length    // 4 — \\ это один слэш, плюс кавычка
```

Вывод: **в значении** обратный слэш всегда один; **в коде** его пишут `\\`. Наша `escapeString` работает со значениями, а тесты пишутся кодом — поэтому в ожиданиях ты будешь видеть `\\`.

### Архитектура решения

**kind:** `text`

В этом шаге идёт высокоуровневый разбор архитектуры решения. Если хочешь спроектировать её сам(а), не читай дальше и отмечай шаг как «Выполнено».

Прежде чем писать код, разложим задачу на функции и распределим роли. Получится **один менеджер** и **три специалиста**.

**Менеджер — `toCSV(data)`.** Получает задачу целиком: «преврати массив объектов в текст». Он отвечает за **структуру таблицы**: проверить вход, взять заголовки, расставить разделители, собрать строки. Какое конкретно значение попадёт в ячейку, он не решает.

**Исполнители:**
- `isValidKey(key)` — решает про **один ключ**: годится ли он в заголовок.
- `serializeValue(value)` — решает про **одно значение**: как записать его по правилам нотации JSON.
- `escapeString(value)` — специалист по экранированию: прячет спецсимволы внутри строки.

Кто кого использует:

```text
toCSV
 ├── isValidKey        ← для каждого ключа заголовка
 └── serializeValue    ← для каждого значения каждой строки
      └── escapeString ← только для значений-строк
```

`isValidKey` и `serializeValue` ничего не знают друг о друге и не вызывают `toCSV` — это «листья» дерева вызовов.

**Зачем так:** менеджер описывает «что» (как устроена таблица), исполнители — «как» (правило для одного ключа, одного значения и одной строки). Благодаря этому менеджер читается как план, а исполнителей можно писать по отдельности.

Но есть и правило тестирования: тестируем с точки зрения клиента. Исполнители — это внутренняя реализация функции `toCSV`, поэтому тесты не должны проверять их отдельно. Тесты видят `toCSV` как «чёрный ящик»: проверяют только её поведение на входе и выходе, не заглядывая внутрь.

Гарантировать это помогает `export` только для `toCSV`: остальные функции-исполнители остаются приватными, и снаружи их никто не вызовет.

### Разбор алгоритма toCSV

**kind:** `text`

В этом шаге идёт высокоуровневый разбор алгоритма. Если хочешь вывести алгоритм сам(а), не читай дальше и отмечай шаг как «Выполнено».

Собираем строку в таком порядке:

1. Проверить, что `data` — массив. Пустой массив → `''`.
2. Заголовки — ключи первого объекта: `keys(data[0])`. Каждый ключ проверить через `isValidKey`.
3. Записать ключи через `,` и завершить строку `\n`.
4. Для каждого объекта: обойти ключи, каждое значение превратить в ячейку функцией `serializeValue`, разделить `,`, завершить строку `\n`.

Функция `serializeValue(value)` — это и есть сериализация одного значения по правилам нотации:
- `undefined` → `''`;
- `null` → `'null'`;
- boolean → `'true'` / `'false'`;
- число → `String(value)`, но `NaN` и `Infinity` → `'null'`;
- строка → `'"'` + `escapeString(value)` + `'"'`;
- объект/массив → `TypeError`.

А вот `escapeString` предлагаем реализовать самостоятельно.

Итого в `toCSV` три вспомогательные функции: `isValidKey(key)`, `serializeValue(value)` и `escapeString(value)`.

### Реализация toCSV()

**kind:** `text`

Реализуй функцию `toCSV(data)` — сериализацию массива объектов в наш текстовый формат. Создай файлы `business-utils/to-csv.js` и `business-utils/to-csv.test.js`, следуй TDD.

**Функция принимает:**
- `data`: `array` — массив плоских объектов с одинаковыми ключами

**Функция возвращает:** `string` — первая строка ключи, далее строки данных.

**Важно:** функция **иммутабельная**. `JSON.stringify` использовать нельзя. Используй свои `keys`, `len`.

Тестовые случаи (каждый — отдельный `test(...)`). Сгруппируй их по блокам.

**Базовые:**
- Пустой массив → `''`: `toCSV([])`
- Один объект: `toCSV([{ a: 1 }])` → `'a\n1\n'`
- Несколько объектов: `toCSV([{ a: 1 }, { a: 2 }, { a: 3 }])` → `'a\n1\n2\n3\n'`
- Порядок ключей берётся из первого объекта: `toCSV([{ b: 2, a: 1 }])` → `'b,a\n2,1\n'`
- Отсутствующий ключ в следующем объекте → пустая ячейка: `toCSV([{ a: 1, b: 2 }, { a: 3 }])` → `'a,b\n1,2\n3,\n'`
- Лишний ключ в следующем объекте игнорируется: `toCSV([{ a: 1 }, { a: 2, b: 3 }])` → `'a\n1\n2\n'`

**Типы (обрати внимание на falsy-значения `0` и `false`):**
- Строка и число: `toCSV([{ name: 'Anna', age: 25 }])` → `'name,age\n"Anna",25\n'`
- Строка `'5'` против числа `5`: `toCSV([{ a: '5' }])` → `'a\n"5"\n'`, а `toCSV([{ a: 5 }])` → `'a\n5\n'`
- Число `0` не должно исчезнуть: `toCSV([{ a: 0 }])` → `'a\n0\n'`
- `false` не должен исчезнуть: `toCSV([{ a: true }, { a: false }])` → `'a\ntrue\nfalse\n'`
- Отрицательное дробное: `toCSV([{ a: -3.14 }])` → `'a\n-3.14\n'`
- `null` → `'a\nnull\n'`
- `undefined` → пустая ячейка `'a\n\n'`
- Пустая строка `''` → `'a\n""\n'` (это НЕ то же самое, что `undefined`)
- `NaN`, `Infinity`, `-Infinity` → `null`
- Строка `'null'` → `'a\n"null"\n'` (не путать со значением `null`)
- Строка `'true'` → `'a\n"true"\n'`

**Экранирование:**
- Запятая внутри строки: `toCSV([{ name: 'Anna, Boris' }])` → `'name\n"Anna, Boris"\n'`
- Кавычка: `toCSV([{ s: 'say "hi"' }])` → `'s\n"say \\"hi\\""\n'`
- Обратный слэш: `toCSV([{ s: 'a\\b' }])` → `'s\n"a\\\\b"\n'`
- Перенос строки: `toCSV([{ s: 'a\nb' }])` → `'s\n"a\\nb"\n'`
- Табуляция: `toCSV([{ s: 'a\tb' }])` → `'s\n"a\\tb"\n'`
- Возврат каретки: `toCSV([{ s: 'a\rb' }])` → `'s\n"a\\rb"\n'`
- Всё сразу: `toCSV([{ s: 'a, "b"\nc\\d' }])` → `'s\n"a, \\"b\\"\\nc\\\\d"\n'`

**Разделитель и переносы:**
- Реальный `\n` в конце каждой строки: `toCSV([{ a: 1 }])` → `'a\n1\n'`; проверь `.length === 4` и `.charCodeAt(1) === 10` (LF, один символ)
- Последняя строка тоже завершается переносом: `toCSV([{ a: 1 }]).endsWith('\n')` → `true`
- Литерала `\` + `n` среди разделителей нет: `toCSV([{ a: 1 }]).includes('\\n')` → `false`
- Перенос внутри значения не разрывает строку: `toCSV([{ s: 'a\nb' }])` → `'s\n"a\\nb"\n'`, и `.split('\n').length === 3` (заголовок, запись, хвост)

**Ключи:**
- Ключ с пробелом — допустим: `toCSV([{ 'first name': 'Anna' }])` → `'first name\n"Anna"\n'`
- **Нестандартный ключ** — это пустой ключ (`''`) или ключ, который содержит любой из символов `,`, `"`, `\`, перенос строки или возврат каретки. Такой ключ сломал бы строку заголовков (она пишется без кавычек), поэтому `toCSV` выбрасывает `TypeError`. Проверь каждый случай отдельным тестом: `''`, `'a,b'`, `'a"b'`, `'a\\b'`, `'a\nb'`, `'a\rb'`.

**Ошибки:**
- Аргумент не массив → `TypeError` (проверь `'x'`, `123`, `null`, `undefined`, `{}`)
- Значение — объект или массив → `TypeError` (проверь `[{ a: {} }]` и `[{ a: [] }]`)

### Сохрани изменения

**kind:** `text`

### Термины урока

**kind:** `text`

Пройдись по основным понятиям урока. Если что-то не можешь объяснить своими словами — вернись к соответствующему шагу.

**Термины:**
* **CSV (Comma-Separated Values)** — таблица в виде текста: строки разделяются переносом, колонки — запятой, первая строка — заголовки.
* **JSON (JavaScript Object Notation)** — нотация записи объекта в текстовом формате. Позволяет позже восстановить объект в точности.
* **Сериализация** — превращение значения или структуры данных в текст для хранения или передачио
* **Экранирование** — замена спецсимволов (`"`, `\`, перенос и др.) на безопасные последовательности (`\"`, `\\`, `\n`), чтобы они не ломали формат.
* **Наш формат («велосипед»)** — собственный формат: структура как у CSV, значения как в JSON.
* **Ключ (заголовок)** — имя колонки, берётся из ключей первого объекта.
* **Значение** — содержимое ячейки: строка, число, boolean, `null` или `undefined`.
* **Примитив** — простое значение (строка, число, boolean, `null`, `undefined`), в отличие от объекта или массива.
* **Иммутабельность** — свойство функции не менять входные данные, а возвращать новый результат.
* **Десериализация** — обратное превращение текста в значение или структуру (например, `JSON.parse`).
* **`JSON.stringify(value)`** — встроенная функция, превращающая значение JS в JSON-строку (сериализация).
* **`JSON.parse(text)`** — встроенная функция, превращающая JSON-строку обратно в значение JS (десериализация).
* **Архитектура решения** — состав участников (функции, классы), их ответственности и связи: кто о ком знает и кого вызывает.
* **Алгоритм решения** — последовательность шагов и поток данных между участниками.
* **Проектирование** — процесс разработки архитектуры и алгоритма решения до написания кода.
* **Менеджер** — функция верхнего уровня, отвечающая за общий результат и структуру (здесь `toCSV`).
* **Исполнитель** — вспомогательная функция с одной узкой ответственностью (здесь `isValidKey`, `serializeValue`, `escapeString`).
* **Дерево вызовов** — схема, показывающая, какая функция какую вызывает.
* **Чёрный ящик** — подход к тестированию: проверяем только входы и выходы функции, не заглядывая в её реализацию.
* **LF / CR / TAB** — управляющие символы: перенос строки (LF, код 10), возврат каретки (CR, код 13), табуляция (TAB, код 9).
* **Придумать велосипед** — сделать собственное решение вместо готового стандартного (в нашем случае — свой формат вместо чистых CSV/JSON).
