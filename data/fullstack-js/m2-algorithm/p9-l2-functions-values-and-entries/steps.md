# Шаги урока: Функции values(obj) и entries(obj)

---

### Реализация values(obj)

**kind:** `text`

> Убедись, что ты в ветке `feat/object-methods`.

Реализуй функцию `values(obj)` — аналог `Object.values()`. Создай файлы `objects/values.js` и `objects/values.test.js`, следуй TDD.

**Функция принимает:**
- `obj`: `object` — объект, значения которого нужно получить

**Функция возвращает:** `array` — массив значений свойств объекта

**Важно:** функция **иммутабельная** — не меняет исходный объект.

Тестовые случаи (каждый — отдельный `test(...)`):
- Должна вернуть массив значений: `values({ a: 1, b: 2, c: 3 })` → `[1, 2, 3]`
- Должна вернуть пустой массив для пустого объекта: `values({})` → `[]`
- Должна вернуть значения разных типов: `values({ name: 'Анна', age: 25, active: true })` → `['Анна', 25, true]`
- Должна корректно обрабатывать `null` и `undefined` среди значений: `values({ a: null, b: undefined })` → `[null, undefined]`
- Унаследованные свойства не должны попадать в результат (добавь свойство в `Object.prototype` перед вызовом и удали после — для чистоты теста).
- Должна выбросить `TypeError` если `obj` равен `null`
- Должна выбросить `TypeError` если `obj` не объект

### Реализация entries(obj)

**kind:** `text`

Реализуй функцию `entries(obj)` — аналог `Object.entries()`. Создай файлы `objects/entries.js` и `objects/entries.test.js`, следуй TDD.

**Функция принимает:**
- `obj`: `object` — объект, пары [ключ, значение] которого нужно получить

**Функция возвращает:** `array` — массив пар `[ключ, значение]`

**Важно:** функция **иммутабельная**. Используй композицию через `keys(obj)`.

Тестовые случаи (каждый — отдельный `test(...)`):
- Должна вернуть массив пар: `entries({ a: 1, b: 2 })` → `[['a', 1], ['b', 2]]`
- Должна вернуть пустой массив для пустого объекта: `entries({})` → `[]`
- Каждая пара должна быть массивом из двух элементов: ключ и значение
- Должна корректно обрабатывать значения разных типов: числа, строки, `null`, массивы
- Должна выбросить `TypeError` если `obj` равен `null`
- Должна выбросить `TypeError` если `obj` не объект

### Вопросы на понимание

**kind:** `text`

Ответь на вопросы. Если не знаешь — проверь гипотезу кодом через `bun`.

**1.** Ты реализовал `values` через `keys`. Сколько раз ты вызвал `for...in` для получения значений — явно или косвенно (через `keys`)? А сколько раз — если бы скопировал логику `keys` в `values`?

**2.** В `entries` ты создаёшь массив `[key, obj[key]]` для каждой пары. Что будет, если значение изменится после того, как `entries` уже отработала и вернула результат? Повлияет ли это на уже возвращённый массив пар?

**3.** Можно ли реализовать `keys` через `entries`? То есть сначала получить массив пар, а потом из каждой пары взять первый элемент? Это тоже была бы композиция, но в какую сторону?

**4.** Сравни два подхода к `values`:
```javascript
// Подход А: через keys
const objKeys = keys(obj);
for (let i = 0; i < len(objKeys); i++) {
  push(result, obj[objKeys[i]]);
}

// Подход Б: через entries
const objEntries = entries(obj);
for (let i = 0; i < len(objEntries); i++) {
  push(result, objEntries[i][1]);
}
```
Какой эффективнее по памяти? Почему?
