# Сохранение и чтение файла (Bun API)

**Краткое содержание:**
Шестая бизнес-утилита — сохраняем массив объектов в настоящий текстовый файл на диске и читаем его обратно. Знакомимся с файловым API Bun (`Bun.write`, `Bun.file().text()`), пишем асинхронные функции `saveToFile(path, data)` и `loadFromFile(path)` поверх готовых `toCSV`/`fromCSV` и проверяем round-trip через реальный физический файл без моков.

**Время:** ~20 мин

**Основные темы:**
- Зачем файл
- Файловый API Bun
- Функция saveToFile(path, data)
- Функция loadFromFile(path)
- Комплект объектов для проб
- Round-trip через файл
- Вопросы на понимание
- Сохрани изменения
- Термины урока

**Термины:**
* **Файл** — именованное хранилище данных на диске, переживает перезапуск программы.
* **`Bun.write(path, text)`** — асинхронная запись строки в файл (создаёт или перезаписывает).
* **`Bun.file(path)`** — объект-файл Bun; `.text()` читает содержимое, `.exists()` проверяет наличие.
* **Асинхронность** — операция возвращает `Promise`; результат получают через `await`, не блокируя программу.
* **`async` / `await`** — синтаксис для работы с асинхронными операциями «как с обычными».
* **UTF-8** — кодировка текста, в которой Bun пишет и читает файлы.
* **Персистентность** — свойство данных сохраняться между запусками программы.
* **Round-trip через файл** — `loadFromFile` после `saveToFile` возвращает исходные данные и типы.
* **LF / CRLF** — варианты переноса строки (`\n` и `\r\n`); `fromCSV` читает оба.

### Цепочка

`toCSV` и `fromCSV` работают со строками. Осталось научиться класть строку в файл и доставать её обратно. Полная цепочка выглядит так:

```
массив объектов → toCSV → строка → файл → строка → fromCSV → массив объектов
```

### API Bun

1. `await Bun.write(path, text)` — записать строку в файл (создаёт или перезаписывает), вернёт число байт.
2. `await Bun.file(path).text()` — прочитать файл как строку.
3. `await Bun.file(path).exists()` — проверить, существует ли файл.

Файловые операции асинхронные, поэтому функции объявляются через `async`, а вызовы делаются через `await`. Как мы разбирали во вводном уроке l4, всю глубокую теорию промисов и асинхронности мы изучим в курсе **«Продвинутый JavaScript»**, а сейчас просто используем правило: работаешь с файлом → ставь `async` перед функцией и `await` перед операцией Bun. Код внутри выполняется последовательно, шаг за шагом. Bun читает и пишет UTF-8; наши переносы строк (`\n`) сохраняются как есть.

```javascript
async function saveToFile(path, data) {
  const text = toCSV(data);
  await Bun.write(path, text);
}

async function loadFromFile(path) {
  const text = await Bun.file(path).text();
  return fromCSV(text);
}
```

### Что важно

- `loadFromFile` для несуществующего файла выбрасывает ошибку (ENOENT) — это нормально: значит, файл ещё не создавали.
- Round-trip через файл: `await loadFromFile(path)` после `await saveToFile(path, data)` возвращает те же данные и типы.
- На Windows файл, сохранённый вручную, может получить CRLF (`\r\n`) — `fromCSV` пропускает `\r` вне строки.
