# Шаги урока: homework.md в отдельной ветке

---

### Ветка под задачу: docs/homework

**kind:** `text`

Любая работа в репозитории — даже написание одного файла — делается в отдельной ветке. Основная ветка `main` остаётся чистой и стабильной, а изменения попадают в неё только через Pull Request.

**Имена веток принято начинать с префикса**, который говорит, какого рода работа в ней идёт:

- `feat/` — новая функциональность (код)
- `docs/` — документация (тексты)
- `fix/` — исправление ошибки
- `refactor/` — правка кода, улучшение

**Термины:**
префикс ветки — слово перед `/` в имени ветки, сразу говорящее о типе работы;
рабочая ветка — по англ. `feature branch`: ветка под конкретную задачу;
изоляция изменений — коммиты в ветке не видны в `main`, пока не пройдёт ревью и мерж

Ты создаёшь документ — значит, префикс `docs/`:

```
git switch -c docs/homework
```

Проверь:

```
git branch
```

Звёздочка на `docs/homework`. В этой ветке ты создашь `homework.md` и `README.md`, и именно она станет твоим первым Pull Request.

---

### Создай homework.md

**kind:** `text`

В корне репозитория (там же, где `.gitignore`) создай файл `homework.md` и наполни его по шаблону — **своими словами**, шаблон это только каркас:

```markdown
# homework

## Кто я

Пара предложений о себе: откуда, чем занимаешься, почему пришёл в разработку.

## Цели на модуль «Алгоритмика»

- [ ] цель один
- [ ] цель два
- [ ] цель три

## Конспекты

_Здесь появятся конспекты статей из домашних заданий._

> 💬 **Заметка для ревьюера:** это мой первый Pull Request. Если видишь,
> как улучшить оформление файла — предложи правку через ревью.
> Например: сделать что-то жирным, добавить подзаголовок или список.
> Не стесняйся — это тренировка и для тебя, и для меня ;-)
```

Обрати внимание на заметку для ревьюера в конце. Она не случайна: твой первый PR — это текст, а не код, и предложить «сделай абзац жирным» ревьюеру гораздо проще, чем критиковать программу. Эта заметка гарантирует, что ты получишь живые предложения по оформлению — и научишься их принимать.

Когда наполнишь файл, проверь, как он выглядит: открой его в VS Code и включи предпросмотр (**Ctrl+Shift+V**) — заголовки, списки и чекбоксы должны отрисоваться.

### Создай README.md — визитку репозитория

**kind:** `text`

В репозитории появились (и будут жить дальше) два «текстовых» файла. У них разные роли — не путай их:

- **`README.md`** — визитка репозитория, для всех, кто на него заходит: ревьюеров, других студентов, будущих работодателей. Отвечает на вопросы: что это за проект, что внутри, как запустить. GitHub рендерит README прямо на главной странице репозитория — это первое, что видит человек
- **`homework.md`** — твои личные записи: цели, конспекты статей, заметки. Для тебя и ревьюеров, а не для «пользователей проекта»

Простое правило: **README — про проект, homework — про тебя**.

Создай в корне репозитория файл `README.md` и наполни по шаблону:

```markdown
# js-algorithms

Учебный репозиторий: модуль «Алгоритмика».

## Что внутри

- `homework.md` — мои цели на модуль и конспекты статей
- практики и функции для работы со строками появятся по ходу модуля
```

По мере учёбы будешь дополнять README: новые разделы, инструкции запуска. Проверь в предпросмотре (Ctrl+Shift+V), что заголовки и список отрисовались.

Оба файла — `homework.md` и `README.md` — попадут в `main` твоим первым Pull Request.

### Закоммить homework.md и README.md

**kind:** `text`

```
git add README.md homework.md
git status
git commit -m "Добавить homework.md и README.md: знакомство с проектом"
git log --oneline
```

Теперь в ветке `docs/homework` есть коммит, которого нет в `main`. В этом и смысл ветки: изменения изолированы, пока не пройдут ревью.

> Push (отправку на GitHub) сделаем в уроке 11 — сразу вместе с созданием Pull Request.
