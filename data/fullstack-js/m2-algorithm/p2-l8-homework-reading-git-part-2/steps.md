### Пуш прямо в `main`

**kind:** `text`

**Задание.** В этот раз обойдёмся без ветки, PR и код-ревью. Будем обновлять файл прямо в main.

Останься (или прыгни) на `main` и обнови его:

```
git switch main  # переключиться в main
git pull origin main  # забрать из удаленного репозитория и объединить с локальным
```

Открой `homework.md` и добавь в раздел «Конспекты»:

```markdown
## Git для новичков (часть 2) — командная работа

- (5–7 пунктов того, что стало понятнее после прочтения статьи)
```

Закоммить:

```
git add homework.md
git commit -m "Добавить конспект статьи Git для новичков (часть 2)"
```

В этот раз — без ветки, без PR и без апрувов. Конспект лежит в твоём локальном `main`, и ты отправляешь его в удалённый репозиторий напрямую:

```
git push origin main
```

Готово: конспект уже на GitHub. Открой страницу репозитория и найди свой коммит в истории `main`.

**А как же код-ревью?** Это осознанное исключение. В некоторых командах прямое обновление `main` разрешено для мелких правок без кода — документация, заметки, опечатки, конспекты. Когда изменение крошечное и риск минимален, полный цикл с PR может быть избыточен.

Но у этого приёма есть жёсткая граница:

> ⚠️ **Весь код — только через PR и код-ревью.** Это правило в наших проектах не отменяется: любой код ты, как и раньше, проводишь через ветку → PR → чат → 2 апрува → мерж (механика — урок 11 проекта 1 и урок 7 этого проекта). Прямой пуш показан здесь в образовательных целях: знай, что так бывает, как это делается и когда может быть уместно.
