### Ревью-цикл: напоминания

**kind:** `text`

Полная методика — в проекте 4 (уроки 4–6). Короткий ориентир:

1. **Пришли комментарии** → прочитай каждый, раздели на 🐛 баги / 🎨 стиль / 📝 документацию / 💡 предложения, определи позицию по каждому
2. **Правки** → прямо в `feat/string-transform`, одно исправление = один коммит («Исправлено: ...»), затем `git push`
3. **Ответы** → на каждый комментарий («Исправил...» / «Оставил как есть, потому что...») + Resolve conversation
4. **Re-request review** → иконка 🔄 у ревьюеров + сообщение в чат
5. **2 апрува + все resolved** → переходи к мержу

Особое внимание на этот раз — к замечаниям по JSDoc: описание отвечает на «что делает», а не «как делает»? Контракт полный: параметры, возврат, ошибки?

### Мерж и чистка

**kind:** `text`

Когда 2 апрува собраны и всё resolved (и `bun test` зелёный локально):

1. GitHub → **Merge pull request** → **Merge commit** → **Confirm merge** → **Delete branch**
2. Локально:

```
git switch main
git pull origin main
git branch -d feat/string-transform
git fetch --prune
git branch -a
```

Проверь по `git log --oneline`: 8 функций — в `main`.
