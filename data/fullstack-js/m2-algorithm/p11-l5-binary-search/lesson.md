# Бинарный поиск: ищем в отсортированном массиве

**Краткое содержание:**
Студент реализует `binarySearch` — поиск элемента в отсортированном массиве делением пополам. Урок замыкает картину: зачем нужны сортировки из прошлых уроков — чтобы искать за ~log n шагов вместо n.

### 1. Зачем сортировать: быстрый поиск

В прошлых уроках ты реализовал четыре сортировки. Естественный вопрос: а зачем? Одна из главных причин — **быстрый поиск**.

Твой `indexOf(arr, item)` из проекта 5 ищет перебором: в худшем случае проходит все n элементов — это O(n). Если массив **отсортирован**, можно искать гораздо быстрее — **бинарным поиском**, который на каждом шаге отбрасывает половину оставшихся элементов.

### 2. Идея: как искать слово в словаре

Как ты ищешь слово в бумажном словаре? Открываешь примерно посередине, смотришь: нужное слово раньше или позже по алфавиту. Отбрасываешь половину книги и повторяешь. В словаре на 100 000 слов слово находится за ~17 шагов.

Бинарный поиск делает то же самое с отсортированным массивом:
1. Смотрим в середину диапазона.
2. Если элемент равен искомому — нашли.
3. Если искомое меньше — ищем в левой половине.
4. Если больше — в правой.
5. Повторяем, пока не нашли или диапазон не опустел.

### 3. Реализация binarySearch

Файл `sorting/binary-search.js`:

```javascript
import { len } from '../arrays/len.js';

export function binarySearch(arr, target) {
  if (!Array.isArray(arr)) throw new TypeError('Ожидается массив');
  let left = 0;
  let right = len(arr) - 1;
  while (left <= right) {
    const mid = left + Math.floor((right - left) / 2);
    if (arr[mid] === target) return mid;
    if (arr[mid] < target) left = mid + 1;
    else right = mid - 1;
  }
  return -1;
}
```

Разбор:
- `left` и `right` — границы диапазона, в котором мы ищем.
- `mid` — середина диапазона. `Math.floor((right - left) / 2)` — целочисленное деление пополам (считаем через `right - left`, чтобы индексы не вышли за границы при больших массивах).
- Если `arr[mid] === target` — возвращаем индекс.
- Если `arr[mid] < target` — искомое правее: сдвигаем `left`.
- Иначе — искомое левее: сдвигаем `right`.
- Цикл закончился (`left > right`) — элемента нет, возвращаем `-1`.

**Предусловие:** функция предполагает, что `arr` отсортирован по возрастанию. На неотсортированном массиве результат не определён.

**Сложность:** на каждом шаге диапазон уменьшается вдвое, поэтому шагов примерно `log2(n)`. Для массива из 1 000 000 элементов — ~20 шагов. Это O(log n).

### 4. Когда бинарный поиск выгоден

Ключевой вопрос: стоит ли сортировать ради быстрого поиска?

- **Один поиск.** Если искать нужно один раз, а массив не отсортирован — проще пройти его перебором за O(n). Сортировка (O(n log n)) плюс бинарный поиск (O(log n)) обойдутся дороже, чем один проход O(n).
- **Много поисков.** Если поиск будет выполняться много раз (m раз), выгодно **один раз заплатить** за сортировку O(n log n) и дальше каждый поиск делать за O(log n) вместо O(n). При больших m это окупается.

То есть сортировка — это разовая «плата», которая делает каждый последующий поиск дешёвым.

### 5. Тестовые случаи

- Пустой массив: `binarySearch([], 5)` → `-1`
- Один элемент найден: `binarySearch([7], 7)` → `0`
- Один элемент не найден: `binarySearch([7], 5)` → `-1`
- Элемент в начале: `binarySearch([1, 2, 3, 4, 5], 1)` → `0`
- Элемент в конце: `binarySearch([1, 2, 3, 4, 5], 5)` → `4`
- Элемент в середине: `binarySearch([1, 2, 3, 4, 5], 3)` → `2`
- Элемент отсутствует: `binarySearch([1, 2, 3, 4, 5], 10)` → `-1`
- Чётная длина: `binarySearch([1, 3, 5, 7], 3)` → `1`
- Не массив: `binarySearch('abc', 1)` → `TypeError`
