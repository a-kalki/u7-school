# Структуры данных: массив, связанный список, дерево

**Краткое содержание:**
Урок вводит понятие структур данных и показывает, как выбор структуры влияет на сложность операций. Студент сравнивает массив (уже знакомый), связанный список и бинарное дерево поиска (BST) — три структуры с разными компромиссами.

### 1. Почему структура данных влияет на сложность

До сих пор мы говорили о сложности алгоритмов. Но O-нотация зависит не только от алгоритма, но и от того, **как организованы данные**. Один и тот же алгоритм может быть O(1) на одной структуре и O(n) на другой.

Пример: «получить элемент по индексу» — O(1) в массиве, но O(n) в связанном списке. Алгоритм один и тот же (`arr[i]`), но за кулисами происходит разное.

### 2. Массив (Array)

Массив — последовательность элементов, расположенных в памяти **подряд**, как вагоны поезда. Ты знаешь адрес первого элемента и можешь мгновенно вычислить адрес любого другого: `адрес[i] = адрес[0] + i × размер_элемента`.

| Операция | Сложность | Почему |
|----------|----------|--------|
| Доступ по индексу `arr[i]` | O(1) | Прямой расчёт адреса в памяти |
| Вставка в конец `push` | O(1) | Запись в следующую свободную ячейку |
| Вставка в начало `unshift` | O(n) | Нужно сдвинуть ВСЕ элементы на 1 вправо |
| Удаление из середины `splice` | O(n) | Нужно сдвинуть все элементы после удалённого влево |
| Поиск значения `indexOf` | O(n) | В худшем случае перебор всех элементов |

Вывод: массив хорош для **доступа по индексу** и **добавления в конец**, но плох для вставки/удаления в середине.

### 3. Связанный список (Linked List)

Связанный список — цепочка узлов, где каждый узел содержит данные и **ссылку на следующий** узел. Как квест со стрелками: «иди туда, там следующая записка».

```
[данные | →]    [данные | →]    [данные | →]    null
  голова          узел 2          узел 3         (конец)
```

| Операция | Сложность | Почему |
|----------|----------|--------|
| Доступ по индексу | O(n) | Нужно пройти от головы по цепочке до нужного узла |
| Вставка в начало | O(1) | Создать узел, направить его ссылку на старую голову |
| Вставка в середину | O(n) | Сначала нужно ДОЙТИ до места вставки |
| Удаление из начала | O(1) | Переместить голову на следующий узел |
| Поиск значения | O(n) | Перебор по цепочке |

Вывод: связанный список хорош для **частых вставок/удалений в начале**, но плох для доступа по индексу. Мы не реализовывали его в модуле, но полезно знать что это альтернатива массиву с другим набором компромиссов.

### 4. Дерево (Tree) и бинарный поиск

Дерево — иерархическая структура: у каждого узла может быть несколько «детей». Частный случай — **бинарное дерево поиска (BST)**: у каждого узла не более двух детей, слева — меньшие значения, справа — большие.

```
          8
        /   \
       3     10
      / \      \
     1   6     14
```

Поиск в BST: на каждом шаге сравниваем искомое значение с текущим узлом и уходим либо влево, либо вправо — отбрасывая половину оставшихся узлов.

| Операция | Сложность (сбалансированное) | Сложность (вырожденное) |
|----------|-----------------------------|------------------------|
| Поиск | O(log n) | O(n) |
| Вставка | O(log n) | O(n) |
| Удаление | O(log n) | O(n) |

Почему две колонки? Если дерево **сбалансировано** (левая и правая половины примерно равны), каждый шаг отбрасывает половину → O(log n). Если дерево **вырождено** (все узлы по одной стороне — как связанный список), поиск вырождается в O(n).

### 5. Сводка: структура данных и сложность

| Структура | Доступ | Поиск | Вставка (начало) | Вставка (конец) |
|-----------|--------|-------|-----------------|----------------|
| Массив | O(1) | O(n) | O(n) | O(1) |
| Связанный список | O(n) | O(n) | O(1) | O(n) |
| BST (сбаланс.) | O(log n) | O(log n) | O(log n) | O(log n) |

Главная мысль: **нет одной «лучшей» структуры данных**. Есть компромиссы. Массив быстр для чтения, список — для вставок в начало, дерево — для поиска в отсортированных данных. Выбор структуры зависит от того, какие операции ты делаешь чаще.
