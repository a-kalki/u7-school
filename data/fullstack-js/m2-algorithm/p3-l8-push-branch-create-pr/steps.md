# Шаги урока: Пуш ветки и создание Pull Request

---

### Финальный прогон всех тестов

**kind:** `text`

Запусти полный прогон:

```
bun test
```

Убедись, что все **7 функций** проходят тесты: `len`, `isEqual`, `isNotEqual`, `isMore`, `isLess`, `isMoreOrEqual`, `isLessOrEqual`.

Если какой-то тест упал — исправь реализацию и перезапусти. Проверь также:

- `git status` — working tree clean, ты в ветке `feat/string-comparison`
- `git log --oneline` — осмысленная история: по коммиту на каждую функцию

**Не забудь про README** — визитку репозитория (урок 8 проекта 1): в разделе «Что внутри» опиши `string-utils` (7 функций сравнения) и добавь инструкцию запуска тестов. Коммит — в ту же ветку.

---

### Пуш ветки

**kind:** `text`

Отправь ветку на GitHub (сам, по памяти из проектов 1–2):

```
git push -u origin feat/string-comparison
```

Проверь, что ветка появилась на GitHub: выпадающий список веток над списком файлов.

---

### Создание Pull Request

**kind:** `text`

Создай PR: base `main` ← compare `feat/string-comparison`.

**Заголовок:**
```
Проект 3: TDD и 7 функций сравнения строк
```

**Описание — заполни по шаблону:**

```markdown
## Что сделано

Реализованы 7 функций для сравнения строк (библиотека string-utils):

- len(str) — длина строки
- isEqual(a, b) — посимвольное равенство
- isNotEqual(a, b) — неравенство
- isMore(a, b) — лексикографическое «больше»
- isLess(a, b) — лексикографическое «меньше»
- isMoreOrEqual(a, b) / isLessOrEqual(a, b) — «больше/меньше или равно»

Все функции реализованы через TDD: тесты → реализация → рефакторинг.
Аргументы валидируются: TypeError для не-строк, RangeError для диапазонов.

## Как запустить тесты

bun test
```

### Сообщение в чат

**kind:** `text`

Выложи сообщение в общий чат по знакомому шаблону:

```
🔍 PR на ревью: [Проект 3: TDD и 7 функций сравнения строк]
📎 Ссылка: https://github.com/твой-username/js-algorithms/pull/N
📋 Нужно 2 апрува для мержа
```

Твой PR будет собирать ревью несколько дней — это нормальный ритм. **Само ревью и доведение до мержа — тема проекта 4.** Пока ждёшь — можно делать уроки следующего проекта. Т.е. проработка код-ревью и работа над следующими проектами идут параллельно.
