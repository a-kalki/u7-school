# Pull Request: теория — краткая выжимка

- PR — просьба влить ветку в `main` + площадка для обсуждения изменений
- `git push` отправляет коммиты, PR запускает процесс проверки перед слиянием
- GitHub Flow: ветка → коммиты → push → PR → ревью → мерж
- Код-ревью: ловит ошибки, распространяет знание о коде, держит единый стиль
- PR всегда из ветки в `main` — ревьюер видит изолированный diff изменений
- Новые коммиты в ветку автоматически попадают в открытый PR — новый PR не нужен
- Ревьюер смотрит diff (какие строки изменились), а не весь проект
