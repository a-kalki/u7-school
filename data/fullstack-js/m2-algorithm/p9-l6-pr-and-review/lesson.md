# Пуш и Pull Request для проекта 9

**Краткое содержание:**
Финальный шаг проекта 9: отправка кода на GitHub, создание PR, приглашение ревьюеров. Студент завершает цикл «ветка → push → PR → ревью → правки → 2 аппрува → мерж».

### Что пушим

- **Ветка:** `feat/object-methods`
- **5 функций** в папке `objects/`:

| Функция | Описание | Особенность |
|---------|----------|-------------|
| `keys` | Массив собственных ключей объекта | `for...in` + `hasOwnProperty` |
| `values` | Массив значений | Композиция через `keys` |
| `entries` | Массив пар `[ключ, значение]` | Композиция через `keys` |
| `cloneDeep` | Глубокое копирование | Рекурсия, проверка `null` до `typeof` |
| `isEqualDeep` | Глубокое сравнение | Рекурсия, `hasOwnProperty` для проверки ключей |

### Пуш и PR

```bash
git push -u origin feat/object-methods
```

Заголовок PR: **Проект 9: Объекты — keys, values, entries, cloneDeep, isEqualDeep**

В описании перечислить все 5 функций с особенностями, указать `bun test` для запуска. Добавить 2 ревьюеров, закрепить сообщение в чате.

### На что обратить внимание ревьюерам

1. **Композиция:** `values` и `entries` не дублируют `for...in`, а используют `keys`
2. **null в cloneDeep:** отдельная проверка до `typeof`, иначе `TypeError`
3. **hasOwnProperty в isEqualDeep:** различает `{ x: undefined }` и `{}`
4. **Иммутабельность:** все 5 функций не меняют исходные объекты
5. **Рекурсия:** `cloneDeep` и `isEqualDeep` корректно обрабатывают вложенные структуры
