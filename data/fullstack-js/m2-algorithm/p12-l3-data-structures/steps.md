# Шаги урока: Структуры данных — массив, список, дерево

---

### Почему структура данных имеет значение

**kind:** `text`

До сих пор мы говорили о сложности алгоритмов. Но одна и та же операция может иметь разную сложность на разных структурах. Пример: «получить элемент по индексу» — O(1) в массиве, но O(n) в связанном списке. Алгоритм один, а за кулисами — разное.

В этом уроке мы сравним три структуры: массив (ты его знаешь), связанный список и бинарное дерево поиска.

---

### Массив — знакомый, но не идеальный

**kind:** `text`

Массив хранит элементы в памяти **подряд**. Зная адрес первого, можно мгновенно вычислить адрес любого: `адрес[i] = адрес[0] + i × размер`. Поэтому доступ по индексу — O(1).

Но за скорость доступа приходится платить: чтобы вставить элемент в начало, нужно сдвинуть ВСЕ существующие элементы на одну позицию вправо. Твой `unshift` делает именно это — O(n).

Таблица операций массива (проверь на своих функциях):
- `arr[i]` (at) — O(1)
- `push` — O(1)
- `pop` — O(1)
- `unshift` — O(n)
- `shift` — O(n)
- `splice` (из середины) — O(n)
- `indexOf` — O(n)

**Вопрос:** ты делаешь приложение-таблицу с данными: пользователь часто сортирует по разным колонкам и переходит к конкретной строке по номеру. Массив — хороший выбор? Почему?

### Связанный список — зеркальный компромисс

**kind:** `text`

Связанный список хранит элементы **где попало** в памяти, но каждый элемент содержит ссылку на следующий. Как квест со стрелками:

```
[Анна | →]    [Борис | →]    [Вера | →]    null
 голова          узел 2         узел 3       (конец)
```

в коде структура выглядит так:
```js
const vera = {
  name: "Вера",
  next: null
}
const boris = {
  name: "Борис",
  next: vera
}
const anna = {
  name: "Анна",
  next: boris
}
```

Чтобы получить 3-й элемент, нужно пройти от головы по цепочке: голова → узел 2 → узел 3. Три шага для трёх элементов. Поэтому доступ по индексу — O(n).

Но вставить элемент в начало очень легко: создать новый узел, направить его ссылку на старую голову, и всё. O(1). Никаких сдвигов.

Таблица операций:
- Доступ по индексу — O(n)
- Вставка в начало — O(1)
- Удаление из начала — O(1)
- Вставка в середину — O(n) (нужно дойти)
- Поиск — O(n)

Связанный список — это «зеркальный» компромисс к массиву. Массив: быстрый доступ, медленная вставка в начало. Список: наоборот.

### Бинарное дерево поиска (BST)

**kind:** `text`

Дерево — иерархическая структура. Бинарное дерево поиска (BST) устроено так:
- У каждого узла не более двух детей
- **Слева** — значения **меньше** текущего
- **Справа** — значения **больше** текущего

```
          8
        /   \
       3     10
      / \      \
     1   6     14
```

Поиск числа 6: начинаем с 8 → 6 < 8, идём налево к 3 → 6 > 3, идём направо к 6 → нашли за 3 шага.

На каждом шаге мы отбрасываем половину оставшихся узлов. Поэтому поиск — O(log n). Но только если дерево **сбалансировано** (левая и правая половины примерно равны).

Если добавлять элементы по возрастанию (1, 2, 3, 4, 5...), дерево выродится в связанный список — все узлы по одной стороне. Тогда поиск станет O(n).

**Вопрос:** что нужно сделать, чтобы дерево оставалось сбалансированным при любом порядке добавления элементов? (Кратко: существующие алгоритмы — AVL-дерево, красно-чёрное дерево — автоматически балансируют дерево при вставке.)

Кстати, принцип BST знаком тебе по `quickSort` из проекта 11: там ты выбирал опорный элемент и делил массив на «меньше» и «больше». BST — та же идея «разделяй и властвуй», только застывшая в структуре: «меньше» всегда слева, «больше» — справа. Поэтому поиск в сбалансированном BST — O(log n), а `quickSort` в среднем — O(n log n): оба выигрывают от деления пополам.

### Три структуры — три компромисса

**kind:** `text`

Сводная таблица:

| Структура | Доступ | Поиск | Вставка в начало | Вставка в конец |
|-----------|--------|-------|-----------------|----------------|
| Массив | O(1) | O(n) | O(n) | O(1) |
| Связанный список | O(n) | O(n) | O(1) | O(n) |
| BST (сбаланс.) | O(log n) | O(log n) | O(log n) | O(log n) |

Главная мысль: **нет одной «лучшей» структуры**. Выбор зависит от задачи.

### Сохрани понимание

**kind:** `text`

Три структуры — три набора компромиссов. Запомни главное:

- **Массив:** быстрый доступ (O(1)), медленная вставка в начало (O(n))
- **Связанный список:** медленный доступ (O(n)), быстрая вставка в начало (O(1))
- **BST:** быстрый поиск (O(log n)), но только если дерево сбалансировано

Выбор структуры = выбор того, какие операции будут быстрыми, а какие медленными.
Чем больше будет количество данных, тем больше повода думать о структуре данных и алгоритме работы. Если данных меньше 10-100, выбери самую простую структуру данных и алгоритм работы с ней.
