# Шаги урока: Функция fromCSV(csvString)

---

### Почему не подходят split и indexOf

**kind:** `text`

Теперь перед нами стоит обратная задача. Из текста (файла) восстановить объект. У нас разделители столбцов запятые и как будто задача не такая уж сложная, рассмотрим.

В `parseUrl` и `getQueryParams` ты искал разделители через `indexOf` и отрезал подстроки через `slice`. Здесь такой подход не работает. Посмотри на строку, которую выдаёт `toCSV` для `[{ members: 'Anna, Boris', team: 'frontend' }]`:

```
members,team
"Anna, Boris","frontend"
```

Если просто сделать `split(',')`, значение разорвётся на три части `['"Anna', ' Boris"', 'frontend']` и мы получим ошибку программы.

```js
console.log('"Anna, Boris","frontend"'.split(','));
```

Запятая после `Anna` — это НЕ разделитель колонок, а часть значения. Один и тот же символ `,` играет две разные роли в зависимости от контекста: снаружи кавычек он разделяет ячейки, внутри — обычный символ.

Вывод: строку нужно читать **посимвольно** и отслеживать контекст — находимся мы внутри строки или снаружи.

### Конечный автомат: паттерн и два состояния

**kind:** `text`

Разбор строки посимвольно — это классическая задача для паттерна **«конечный автомат»** (finite state machine, FSM). Конечный автомат — модель с набором состояний и правилами перехода между ними. В каждый момент автомат находится ровно в ОДНОМ состоянии, а входной символ определяет: остаться или перейти в другое состояние и какое действие выполнить.

Конечные автоматы встречаются повсюду: разбор форматов (наш формат, JSON, URL), сетевые протоколы (TCP), проверка пользовательского ввода, регулярные выражения, поведение NPC в играх. Хорошее введение в тему: **[Понятие о конечных автоматах](https://habr.com/ru/companies/piter/articles/1039106/)**.

Наш автомат имеет два состояния. В ходе посимвольной итерации строки держи в уме ответ на вопрос «я внутри строки?».

**Состояние 1: СНАРУЖИ строки (`inString = false`)**

| Текущий итерируемый символ | Действие |
|--------|----------|
| `"` | Войти ВНУТРЬ строки: `inString = true`, добавить кавычку в поле |
| `,` | Завершить текущую ячейку, начать новую |
| `\n` | Завершить ячейку и строку, начать новую |
| `\r` | Игнорировать: это перевод каретки из Windows-файлов (CRLF) |
| любой другой | Добавить символ к текущей ячейке |

**Состояние 2: ВНУТРИ строки (`inString = true`)**

| Текущий итерируемый символ | Действие |
|--------|----------|
| `\` | Экранирование: добавить `\` и следующий символ как есть, пропустить обработанный (инкремент счетчика индекса) |
| `"` | Закрывающая кавычка: добавить и выйти НАРУЖУ (`inString = false`) |
| любой другой | Добавить символ к текущей ячейке |

Обрати внимание: обратный слэш нужен, чтобы кавычка внутри значения (`\"`) не воспринималась как закрывающая. Если её не учитывать, автомат преждевременно выйдет из строки.

### Трассировка на примере

**kind:** `text`

Возьми текст для `[{ n: 5, s: '5' }]` — строку `n,s\n5,"5"\n`. Здесь `\n` — **реальный перенос строки, один символ** (LF, код 10), а не пара `\` + `n`. Пройди по ней мысленно:

`№`: номер итерации;
`i`: индекс символа;
`ch`: текущий символ;
`inString`: состояние нашего конечного автомата (FSM);
`field`: текущее значение;
`действие`: что нужно сделать внутри блока цикла;

```
№  i  ch        inString  field      действие
────────────────────────────────────────────────────────
1  0  'n'       false     'n'        символ значения
2  1  ','       false     → завершить  push 'n' (значение собрано), сброс значения
3  2  's'       false     's'        символ значения
4  3  перенос   false     → завершить  push 's' (значение собрано), push строку (строка собрана), сброс значения
5  4  '5'       false     '5'        символ значения (число!)
6  5  ','       false     → завершить  push '5', сброс
7  6  '"'       false     → войти      field = '"', inString = true
8  7  '5'       true      '"5'        символ внутри строки
9  8  '"'       true      → выйти      field = '"5"', inString = false
10 9  перенос   false     → завершить  push '"5"', push строку, сброс
→ финал: поле пусто и строка пуста — ничего не добавляем
```

Пока в тексте нет обратного слэша, индекс `i` и номер итерации совпадают: каждый символ — своя итерация. Получим `rows = [['n', 's'], ['5', '"5"']]`. Первая строка — ключи; вторая — ещё не значения (ячейка `'5'` и ячейка `'"5"'`), их типы восстановит чтение нотации.

**Отдельный случай — экранирование.** Когда встречается пара `\` + символ, одна итерация цикла съедает **два** символа и `i` прыгает через один. Возьмём `[{ s: 'a\nb' }]` (в значении — реальный перенос, в тексте он записан парой `\` + `n`), в файле он будет сохранен как `s\n"a\nb"\n`:

```
№  i  ch        inString  field      действие
────────────────────────────────────────────────────────
1  0  's'       false     's'        символ значения
2  1  перенос   false     → завершить  push 's', push строку
3  2  '"'       false     → войти      field = '"', inString = true
4  3  'a'       true      '"a'       символ внутри строки
5  4  '\'       true      '"a\'      экранирование: добавить '\', i++, взять следующий символ
      └ та же итерация дочитывает 'n' → field = '"a\n'
6  6  'b'       true      '"a\nb'    следующая итерация (i шагнул 4 → 6)
7  7  '"'       true      → выйти      field = '"a\nb"', inString = false
8  8  перенос   false     → завершить  push '"a\nb"', push строку
→ финал: ничего не добавляем
```

Строка 5 — единственное место, где `i` подпрыгнул сразу на два. И именно поэтому автомат обязан сохранить пару `\` + `n` целиком: снятие экранирования — работа `deserializeValue`, а не нарезки.

### Как читать значение

**kind:** `text`

После разбора каждая ячейка — это запись по правилам JSON. Вытащить тип, это задача функции `deserializeValue(cell)`. `JSON.parse` использовать нельзя. Напомним, что входит в функцию и что она должна вернуть:

| Ячейка | Что это | Результат |
|---|---|---|
| `5` | без кавычек, цифры | число `5` |
| `"5"` | в кавычках | строка `'5'` |
| `true` / `false` | точное слово | boolean |
| `null` | точное слово | `null` |
| пустая | записи нет | `undefined` |
| `"say \"hi\""` | строка с экранированием | `say "hi"` |

Ключи (первая строка) читаются как обычный текст без кавычек — это имена колонок.

### Реализация fromCSV()

**kind:** `text`

Архитектура решения частично уже выполнена, алгоритм и реализация за тобой.

Реализуй функцию `fromCSV(text)` — десериализацию нашего формата обратно в массив объектов с восстановлением типов. Создай файлы `business-utils/from-csv.js` и `business-utils/from-csv.test.js`, следуй TDD.

**Функция принимает:**
- `text`: `string` — текст в нашем формате (первая строка — ключи)

**Функция возвращает:** `array` — массив объектов

**Важно:** функция **иммутабельная**. Используй посимвольный обход с флагом `inString` и свои `keys`, `len`.

Тестовые случаи (каждый — отдельный `test(...)`). Сгруппируй их по блокам.

**Базовые:**
- Пустая строка → `[]`: `fromCSV('')`
- Данных нет (только строка заголовков) → `[]`: `fromCSV('a\n')`
- Несколько строк: `fromCSV('a\n1\n2')` → `[{ a: 1 }, { a: 2 }]`
- Несколько колонок: `fromCSV('a,b\n1,2')` → `[{ a: 1, b: 2 }]`

**Типы:**
- Число: `fromCSV('a\n5')` → `[{ a: 5 }]`
- Строка (не число): `fromCSV('a\n"5"')` → `[{ a: '5' }]`
- Ноль: `fromCSV('a\n0')` → `[{ a: 0 }]`
- Отрицательное дробное: `fromCSV('a\n-3.14')` → `[{ a: -3.14 }]`
- boolean: `fromCSV('a\ntrue')` → `[{ a: true }]`, `fromCSV('a\nfalse')` → `[{ a: false }]`
- `null`: `fromCSV('a\nnull')` → `[{ a: null }]`
- Строка `'null'`: `fromCSV('a\n"null"')` → `[{ a: 'null' }]`
- `undefined` из пустой ячейки: `fromCSV('a\n\n')` → `[{ a: undefined }]` (проверь через `Object.hasOwn(result[0], 'a')`)
- Пустая строка `''`: `fromCSV('a\n""')` → `[{ a: '' }]` (отличается от `undefined`!)

**Экранирование:**
- Запятая внутри строки: `fromCSV('name\n"Anna, Boris"')` → `[{ name: 'Anna, Boris' }]`
- Кавычка: `fromCSV('s\n"say \\"hi\\""')` → `[{ s: 'say "hi"' }]`
- Обратный слэш: `fromCSV('s\n"a\\\\b"')` → `[{ s: 'a\\b' }]`
- Перенос строки: `fromCSV('s\n"a\\nb"')` → `[{ s: 'a\nb' }]`
- Табуляция: `fromCSV('s\n"a\\tb"')` → `[{ s: 'a\tb' }]`
- Возврат каретки: `fromCSV('s\n"a\\rb"')` → `[{ s: 'a\rb' }]`

**Пропуски и лишнее:**
- Пропущенная ячейка (строка короче заголовков) → `undefined`: `fromCSV('a,b\n1')` → `[{ a: 1, b: undefined }]`
- Лишняя ячейка игнорируется: `fromCSV('a\n1,2')` → `[{ a: 1 }]`
- Ключ с пробелом: `fromCSV('first name\n"Anna"')` → `[{ 'first name': 'Anna' }]`

**Разделитель строк и CRLF:**
- Реальный LF-разделитель: `fromCSV('a\n1\n')` → `[{ a: 1 }]` (финальный `\n` не создаёт лишнюю запись)
- Windows-файл с CRLF: `fromCSV('a\r\n1\r\n')` → `[{ a: 1 }]`
- CRLF и несколько колонок: `fromCSV('a,b\r\n1,2\r\n')` → `[{ a: 1, b: 2 }]`
- `\r` внутри значения (экранирован как `\r`) не путается с CRLF: `fromCSV('s\n"a\\rb"')` → `[{ s: 'a\rb' }]`

**Round-trip (главные проверки):**
- Типы сохраняются:
  ```
  fromCSV(toCSV([{ n: 5, s: '5', b: true, x: null }])) → [{ n: 5, s: '5', b: true, x: null }]
  ```
- Falsy-значения не теряются:
  ```
  fromCSV(toCSV([{ a: 0, b: false, c: '' }])) → [{ a: 0, b: false, c: '' }]
  ```
- Спецсимволы переживают круг:
  ```
  fromCSV(toCSV([{ s: 'a, "b"\nc\\d' }])) → [{ s: 'a, "b"\nc\\d' }]
  ```
- `undefined` переживает круг:
  ```
  fromCSV(toCSV([{ a: undefined, b: 5 }])) → [{ a: undefined, b: 5 }]
  ```

**Ошибки:**
- Аргумент не строка → `TypeError` (проверь `123`, `null`, `[]`)

### Вопросы на понимание

**kind:** `text`

Ответь на вопросы. Если не знаешь — проверь гипотезу кодом через `bun`.

**1.** Почему для разбора нужен посимвольный обход, а не `split`? Что именно ломает разделение по запятой?

**2.** Зачем конечному автомату флаг `inString`? Приведи пример текста, где без него разбор ошибётся.

**3.** Почему в `deserializeValue` проверки идут в таком порядке? Что вернёт `Number('null')`, если не обработать `null` раньше?

**4.** Ячейку `5` мы превращаем в число, а ячейку `"5"` — в строку. Откуда берётся разница, если после разбора это просто текст?

**5.** В конце обхода мы добавляем последнее поле и строку не всегда, а только если `field` не пуст или `row` не пуст. Что сломается, если добавлять всегда? Вспомни, что `toCSV` завершает вывод символом `\n`.

### Термины урока

**kind:** `text`

Пройдись по основным понятиям урока. Если что-то не можешь объяснить своими словами — вернись к соответствующему шагу.

**Роли: от бытовых слов к техническим**

В уроках мы давали роли функциям бизнес терминами — «менеджер» и «исполнитель\специалист». В технической речи те же роли звучат иначе, и полезно знать оба набора:

**Менеджер:** верхняя функция: задаёт порядок работы и собирает результат
  - оркестратор, координатор
**Исполнитель / специалист:** вспомогательная функция с одной узкой задачей
  - утилита (util, utility), хелпер (helper), worker

**Термины:**
* **Паттерн** — повторяемый, проверенный способ решения типовой задачи (в нашем случае — конечный автомат для разбора строки).
* **Посимвольный обход** — чтение текста символ за символом с учётом контекста (снаружи или внутри кавычек).
* **Трассировка** — ручной прогон алгоритма по шагам на конкретных данных: номер итерации, символ, состояние, действие.
* **Конечный автомат (FSM)** — модель разбора строки: набор состояний и правила перехода между ними по входным символам.
* **Состояние** — текущий режим автомата; у нас их два: «снаружи строки» и «внутри строки».
* **Переход** — смена состояния по входному сигналу (в нашем случае символу, например, `"` снаружи → войти внутрь).
* **Снятие экранирования** — обратная операция: `\"` → `"`, `\\` → `\`, `\n` → перенос строки.
* **Round-trip** — обратимость: `fromCSV(toCSV(data))` восстанавливает данные и их типы.
* **Примитив** — простое значение (строка, число, boolean, `null`, `undefined`), в отличие от объекта или массива.
* **Иммутабельность** — свойство функции не менять входные данные, а возвращать новый результат.
* **Сериализация** — превращение значения или структуры данных в текст.
* **Десериализация** — восстановление значения или структуры из текста.
* **Ячейка** — одно значение в строке данных (между разделителями-запятыми).
* **LF** — перенос строки в Unix-файлах: один символ `\n` (код 10).
* **CRLF** — перенос строки в Windows-файлах: `\r\n`. `fromCSV` пропускает `\r` вне строки, поэтому такой файл читается наравне с LF.
