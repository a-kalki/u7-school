# Файлы, форматы данных и Bun File API — краткая выжимка

- **Персистентность (persistence)**: сохранение данных на диск, чтобы они не терялись при завершении программы.
- **Bun File API**:
  - `await Bun.write('path/to/file.txt', text)` — быстрая запись строки в файл (создаёт или перезаписывает).
  - `await Bun.file('path/to/file.txt').text()` — чтение содержимого файла как строки.
- **Устройство текстового файла**: непрерывная последовательность байтов. Границы физических строк определяются символом перевода строки `\n` (байт 10, LF).
- **Главный инвариант нашего формата**: **1 строка файла = 1 объект** (первая строка — ключи/заголовки).
- **Катастрофа разорванной строки**: если в значении объекта есть символ `\n` (Enter), при прямой записи в файл запись разрывается на несколько физических строк. Структура файла разрушается, построчное чтение ломается.
- **Три мира перевода строки**:
  1. *В оперативной памяти JS*: 1 управляющий символ перевода строки (код 10, LF).
  2. *В файле на диске*: 2 печатных символа `\` и `n` подряд на одной физической строке (`\n`).
  3. *В коде программы JS*: литерал `'\\n'` (с удвоенным слэшем для движка языка).
- **Что берём от CSV**: компактная таблица, заголовки указаны один раз сверху, поля через запятую.
- **Что берём от JSON**: сохранение типов данных (числа без кавычек, строки в кавычках, экранирование спецсимволов через слэш).
- **Кроссплатформенность**:
  - В путях всегда используем прямой слэш `'folder/file.txt'` (Bun сам понимает его и в Windows, и в Linux/macOS).
  - При чтении файла игнорируем `\r` (Windows CRLF), чтобы файлы читались одинаково на любой ОС.
