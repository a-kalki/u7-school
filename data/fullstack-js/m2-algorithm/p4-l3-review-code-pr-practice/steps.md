# Шаги урока: Практика: ревью кодового PR одногруппника

---

### Найди кодовый PR для ревью

**kind:** `text`

Открой общий чат — там сейчас много PR из проекта 3 (все делают одно и то же задание, и это плюс: ты можешь **сравнивать подходы** к одной задаче).

Правила выбора:

- Не свой PR
- Выбирай PR с наименьшим числом ревью — там твоя помощь нужнее
- Открыл → вкладка **Files changed**

Если весь список разобран — попроси в чате, кому нужно ещё одно ревью, или возьми PR с одним апрувом и посмотри глазами второго ревьюера.

**Термины:**
мысленный прогон — выполнение кода в голове по шагам на конкретных данных

---

### Проведи ревью

**kind:** `text`

Читай по методике из прошлого урока: сигнатура → тесты → реализация. Проверяй по чек-листу:

1. **Корректность** — мысленно прогони 1–2 теста по шагам
2. **Граничные случаи** — пустые строки, пробелы, регистр, не-строки
3. **Правила модуля** — `.length`? запрещённые методы? сравнение длинных строк?
4. **Читаемость** — имена, дублирование
5. **Тесты** — покрыты ли обещанные случаи

Примеры хорошего тона:

```
Предлагаю вынести проверку типов в отдельную функцию — она
повторяется в isEqual и isNotEqual, а дублирование придётся
править в двух местах.

Нужно добавить тест на isLess('a', 'ab'): сейчас префиксный
случай не покрыт, а именно на нём чаще всего ошибаются.
```

**Оставь комментарии построчно:** в Files changed наведи на строку → синий плюс → пиши.

### Вердикт и рефлексия

**kind:** `text`

Заверши ревью через **Review changes**:

- Только предложения → **Approve**
- Нашёл баг или нарушение правил → **Request changes** + что именно исправить
- Сказать нечего → **Comment**

Ответь на вопросы (в конспект):

1. Что ты заметил в чужом коде, чего не заметил бы в своём?
2. Что из чужого подхода к тестам ты возьмёшь в свою реализацию?
3. Что было сложнее — найти проблему или сформулировать её вежливо и точно?
