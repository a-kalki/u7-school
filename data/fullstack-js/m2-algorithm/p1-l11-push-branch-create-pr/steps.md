# Шаги урока: Пуш ветки и создание Pull Request

---

### Финальная проверка

**kind:** `text`

Перед отправкой убедись, что всё в порядке:

1. Ты в ветке `docs/homework`: `git branch --show-current`
2. `git status` — working tree clean, все изменения закоммичены
3. `git log --oneline` — минимум два коммита: файлы `homework.md` + `README.md` и конспект статьи
4. В `homework.md` заполнены все разделы: «Кто я», цели, конспект, заметка для ревьюера; `README.md` — визитка репозитория

Если что-то не так — исправь сейчас, пока PR не создан.

---

### Пуш ветки

**kind:** `text`

Отправь ветку на GitHub:

```
git push -u origin docs/homework
```

Флаг `-u` свяжет локальную ветку с удалённой — так же, как с `main` в уроке 5. Следующие push из этой ветки можно делать просто `git push`.

Проверь, что ветка появилась на GitHub: открой репозиторий, нажми выпадающий список веток (кнопка слева над списком файлов, где написано `main`). Ты должен увидеть `docs/homework`.

---

### Создание Pull Request

**kind:** `text`

Создай свой первый настоящий Pull Request — из ветки в `main`:

1. GitHub после push обычно сам предлагает зелёную кнопку **Compare & pull request** — нажми её
2. Или вкладка **Pull requests** → **New pull request**, выбери base: `main`, compare: `docs/homework`
3. Направление обязательно `base: main` ← `compare: docs/homework` — это значит «предлагаю влить мою ветку в main»

**Термины:**
флаг `-u` (upstream) — связать локальную ветку с удалённой, чтобы дальше писать просто `git push`;
base — «куда» вливаем (`main`);
compare — «что» вливаем (твоя ветка);
pin — закреплённое сообщение в чате;
аппрув — по англ. `approve`: одобрение ревьюера

Заполни (и заодно потренируй markdown из урока 6):

**Заголовок:**
```
Знакомство: цели на модуль и первый конспект
```

**Описание — заполни по шаблону:**

```markdown
## Кто я

Два-три предложения о себе.

## Цели на модуль

- [ ] цель один
- [ ] цель два

## Что внутри

- homework.md — знакомство, цели и конспект статьи «Git для новичков (часть 1)»
- README.md — визитка репозитория: что за проект и что внутри
```

### Посмотри на PR глазами ревьюера

**kind:** `text`

Посмотри на созданный PR глазами ревьюера:

1. Перейди на вкладку **Files changed** — это diff: красным показаны удалённые строки, зелёным — добавленные (у тебя добавление новых файлов, значит все строки будут зелеными)
2. Пролистай изменения: видно ли по diff, что именно изменилось?
3. Представь, что ты видишь этот PR впервые. Понятно ли из описания, что сделано и как это проверить?

Если что-то непонятно — дополни описание PR (кнопка **Edit** рядом с заголовком).

### Сообщение в чат

**kind:** `text`

На ревью мы приглашаем в общем чате группы для студентов: создаёшь PR — отправляешь сообщение со ссылкой, студенты и менторы ревьюят. Для мержа (объединения веток) нужно получить **2 аппрува**.

**Шаблон сообщения:**

```
🔍 PR на ревью: [Знакомство: цели на модуль и первый конспект]
📎 Ссылка: https://github.com/твой-username/js-algorithms/pull/1
📋 Нужно 2 аппрува для мержа
```

> Не забудь обновить ссылку с шаблона в сообщении своей ссылкой. После отправки сообщения кликни на ссылку и проверь что она живая

Закрепи сообщение (pin), чтобы оно не потерялось в истории чата (когда сделаешь мердж, не забудь снять пин).

Дальше — жди апрувы. Как получить их быстрее и что делать с замечаниями — тема проекта 2.
