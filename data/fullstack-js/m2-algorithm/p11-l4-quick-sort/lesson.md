# Быстрая сортировка (quick sort)

**Краткое содержание:**
Четвёртый алгоритм сортировки — и первый рекурсивный. Быстрая сортировка применяет стратегию «разделяй и властвуй»: выбирает опорный элемент, разбивает массив на «меньше» и «больше» и сортирует части рекурсивно.

### 1. Идея: разделяй и властвуй

Быстрая сортировка не сравнивает каждый элемент с каждым. Вместо этого она:
1. Выбирает **опорный элемент** (pivot) — например, первый.
2. Разбивает остальные элементы на два массива: меньше опорного и больше (или равные).
3. Рекурсивно сортирует обе части.
4. Склеивает: отсортированные «меньше» + опорный + отсортированные «больше».

Это стратегия «разделяй и властвуй»: задача делится на две меньшие подзадачи, которые решаются тем же способом.

### 2. Алгоритм по шагам

1. Проверить тип: `arr` — массив.
2. Базовый случай: если `len(arr) <= 1` — вернуть копию (массив из 0 или 1 элемента уже отсортирован).
3. Выбрать `pivot = arr[0]`.
4. Пройти по элементам с индекса 1: меньшие `pivot` — в `less`, остальные — в `greater`.
5. Рекурсивно отсортировать `less` и `greater`.
6. Вернуть `concat(concat(quickSort(less), [pivot]), quickSort(greater))`.

### 3. Реализация

```javascript
function quickSort(arr) {
  if (!Array.isArray(arr)) throw new TypeError('Ожидается массив');

  const n = len(arr);
  if (n <= 1) return slice(arr, 0, n);

  const pivot = arr[0];
  const less = [];
  const greater = [];

  for (let i = 1; i < n; i++) {
    if (arr[i] < pivot) push(less, arr[i]);
    else push(greater, arr[i]);
  }

  return concat(concat(quickSort(less), [pivot]), quickSort(greater));
}
```

Рекурсия здесь та же, что в `cloneDeep` из проекта 9: базовый случай (маленький массив) + рекурсивный вызов на частях. Разница — здесь мы делим данные пополам, а не спускаемся по вложенной структуре.

### 4. Почему выбор опорного элемента важен

С первым элементом в роли опорного быстрая сортировка **деградирует на уже отсортированном массиве**: `pivot` оказывается минимумом, `less` всегда пустой, а `greater` содержит всё остальное. Тогда каждый шаг уменьшает задачу лишь на 1 — и алгоритм вырождается в ~n² операций, как у пузырька.

Проверь сам в консоли:

```javascript
quickSort([1, 2, 3, 4, 5, 6, 7, 8]);
```

И мысленно проследи, что происходит с `less` и `greater` на каждом шаге.

Классическое улучшение — брать опорным **средний** элемент (`arr[Math.floor(len(arr) / 2)]`) или случайный. Мы оставим первый для простоты, но в уроке 5 увидим последствия на отсортированных данных.

### 5. Граничные случаи

- `quickSort([])` → `[]`
- `quickSort([7])` → `[7]`
- `quickSort([1, 2, 3])` → `[1, 2, 3]` (но медленно — вырождается)
- `quickSort([3, 2, 1])` → `[1, 2, 3]`
- `quickSort([4, 2, 4, 1])` → `[1, 2, 4, 4]`
- `quickSort('abc')` → `TypeError`
