# Шаги урока: Мутабельность: изменение «на месте»

---

### Что такое мутабельность

**kind:** `text`

Массив передаётся в функцию **по ссылке**. Это значит, что функция работает с тем же самым массивом в памяти, а не с его копией. Если функция меняет массив — изменения видны снаружи.

Различают два типа операций:

- **Мутабельная** — изменяет исходный массив «на месте». Пример: `push` добавляет элемент в конец существующего массива.
- **Иммутабельная** — создаёт новый массив, исходный не трогает. Пример: `concat` возвращает новый массив из двух исходных.

В этом проекте функции `push`, `pop`, `unshift`, `shift` — **мутабельные**. А `len`, `at`, `indexOf`, `lastIndexOf`, `includes` — не мутируют массив (только читают).

Запомни: «мутировать» = «менять на месте то, что тебе дали».

### Мутабельная или иммутабельная?

**kind:** `text`

Посмотри на гипотетические функции и определи, мутируют они исходный массив или нет. Не запускай код — сначала подумай, потом проверь.

```javascript
// Наш len из проекта 1, но для массивов
function len(arr) {
  let count = 0;
  for (let i = 0; arr[i] !== undefined; i++) count++;
  return count;
}

// Функция A
function addToEnd(arr, item) {
  const length = len(arr);
  arr[length] = item;
  return length + 1;
}

// Функция B
function copyWith(arr, item) {
  const length = len(arr);
  const result = [];
  for (let i = 0; i < length; i++) result[i] = arr[i];
  result[length] = item;
  return result;
}
```

Вопросы:
1. Какая функция мутирует `arr`, а какая — нет?
2. Что выведет этот код:
```javascript
const a = [1, 2];
const ra = addToEnd(a, 3);
console.log('A:', a[2], ra);

const b = [1, 2];
const rb = copyWith(b, 3);
console.log('B:', b[2], rb[2]);
```

Проверь свои догадки, выполнив код через `bun`.

### Почему мутабельность опасна

**kind:** `text`

Представь: один и тот же массив используют две части программы. Одна часть мутирует массив, не предупредив другую — и та получает «испорченные» данные.

```javascript
const users = ['Анна', 'Борис', 'Вера'];

function takeFirst(list) {
  // гипотетический shift — удаляет первый элемент из list
  const first = list[0];
  // ...сдвигаем влево...
  return first;
}

const firstUser = takeFirst(users);
console.log('Взяли:', firstUser);
console.log('Осталось:', users[0], users[1], users[2]);
```

Без мутации `users` оставался бы нетронутым. С мутацией — `Анна` исчезает из исходного массива, и любой код, который рассчитывал на три элемента, сломается.

**Вывод:** мутабельные функции мощные, но требуют дисциплины. Нужно всегда знать — меняет функция свой аргумент или нет. Поэтому в JSDoc мы будем явно отмечать мутирующие функции.

### Как тестировать мутабельные функции

**kind:** `text`

Тест мутабельной функции проверяет **два** результата:

1. **Возвращаемое значение** — что функция вернула (новую длину, удалённый элемент).
2. **Состояние массива после вызова** — изменился ли он и как.

```javascript
import { test, expect } from 'bun:test';
import { pop } from './arrays/pop.js';

test('pop удаляет последний элемент и возвращает его', () => {
  const arr = [10, 20, 30];
  const result = pop(arr);

  expect(result).toBe(30);       // 1. возвращённое значение
  expect(len(arr)).toBe(2);      // 2. массив стал короче
  expect(arr[0]).toBe(10);       //    первый элемент на месте
  expect(arr[1]).toBe(20);
});
```

Важно: для каждого теста создавай **новый** массив. Если переиспользовать один массив между тестами — мутация в первом тесте сломает второй. Это частный случай более общего правила — смотри следующий шаг.

**Правило:** мутабельная функция = в тесте проверяй и `result`, и исходный массив после вызова.

### Тесты всегда независимы

**kind:** `text`

Каждый тест должен быть **самодостаточным** — он не полагается на то, что отработал какой-то другой тест, и не рассчитывает, что другой тест оставил данные «в нужном виде». Если запустить тесты в любом порядке, по одному или все сразу — каждый должен проходить одинаково.

**Почему это критично именно с мутабельными функциями.** Мутабельная функция меняет свой аргумент. Если два теста используют один и тот же массив, то тест, который запустился первым, меняет массив — и второй тест видит уже «испорченные» данные. Результат второго теста начинает зависеть от порядка запуска и от того, сработал ли первый. Это невидимая хрупкость: всё зелёное, пока тесты бегут в одном порядке, и падает при перестановке.

**Плохо** — общий массив, тесты зависят друг от друга:
```javascript
const arr = [1, 2, 3];

test('push возвращает новую длину', () => {
  const result = push(arr, 4);
  expect(result).toBe(4);          // OK, но arr теперь [1,2,3,4]
});

test('pop возвращает последний элемент', () => {
  const result = pop(arr);
  expect(result).toBe(4);          // проходит ТОЛЬКО потому, что push уже отработал!
});
```
Поменяй тесты местами — второй тест сломается, хотя код функции не изменился. Это и есть нарушение независимости.

**Хорошо** — каждый тест готовит свои данные с нуля:
```javascript
test('push возвращает новую длину', () => {
  const arr = [1, 2, 3];
  const result = push(arr, 4);
  expect(result).toBe(4);
});

test('pop возвращает последний элемент', () => {
  const arr = [1, 2, 3];
  const result = pop(arr);
  expect(result).toBe(3);
});
```
Теперь порядок не важен: каждый тест сам создаёт свой массив и сам отвечает за его состояние.

**Правила независимости тестов:**
- Каждый тест сам создаёт свои данные (массивы, строки, объекты) — не берёт их «снаружи» и не из другого теста.
- Каждый тест сам приходит к своему результату через свой вызов функции — не использует побочный эффект чужого теста.
- Тест не должен полагаться на порядок выполнения: представь, что твои тесты перемешали — они всё равно должны проходить.
- Один тест = одна проверяемая идея. Несколько связанных проверок внутри одного теста допустимы, но «подготовка» для следующего теста — нет.
