# Мутабельность: изменение массива «на месте»

**Краткое содержание:**
Урок вводит ключевое понятие — мутабельность. Студент учится различать операции, которые меняют исходный массив, и те, что создают новый. Это критически важно для всех функций проекта 5: `push`, `pop`, `unshift`, `shift` мутируют массив, а `len`, `at`, `indexOf`, `includes` — нет.

### 1. Что значит «изменить на месте»

Массив — это структура данных в памяти. Когда ты передаёшь массив в функцию, функция получает **ссылку** на тот же самый массив, а не его копию. Поэтому если функция меняет массив внутри себя — изменения видны снаружи.

```javascript
const arr = [1, 2, 3];
// гипотетическая мутабельная функция
addToEnd(arr, 4);
console.log(arr); // [1, 2, 3, 4] — исходный массив изменился!
```

Это и есть **мутабельная операция** — она изменяет объект, который получила.

### 2. Мутабельная vs иммутабельная

| Свойство | Мутабельная | Иммутабельная |
|----------|-------------|---------------|
| Исходный массив | меняется | не меняется |
| Возврат | обычно новое значение (длина, удалённый элемент) | новый массив |
| Пример из стандартного API | `push`, `pop`, `shift`, `unshift` | `concat`, `slice`, `map`, `filter` |

### 3. Почему мутабельность опасна

Если один и тот же массив используется в нескольких местах программы, мутация в одном месте «сломает» данные в другом:

```javascript
const users = ['Анна', 'Борис'];
function processFirst(list) {
  // гипотетический shift — удаляет первый элемент из list
  shift(list);
  return list[0]; // хотел вернуть первого пользователя
}
processFirst(users);
console.log(users); // ['Борис'] — Анна исчезла из исходного массива!
```

### 4. Как тестировать мутабельные функции

Для мутабельной функции тест проверяет **два** результата:
1. Возвращаемое значение (новая длина, удалённый элемент)
2. Состояние исходного массива после вызова

```javascript
const arr = [1, 2, 3];
const result = pop(arr);
expect(result).toBe(3);          // возвращённое значение
expect(len(arr)).toBe(2);        // массив стал короче
expect(arr[0]).toBe(1);          // первый элемент на месте
```

### 5. Тесты всегда независимы

Каждый тест должен быть **самодостаточным**: не полагаться на то, что отработал другой тест, и не рассчитывать на порядок выполнения. С мутабельными функциями это особенно опасно — если два теста используют один массив, первый тест меняет его, и второй тест видит «испорченные» данные. Результат становится зависимым от порядка запуска: всё зелёное, пока тесты бегут в одном порядке, и падает при перестановке.

Правила независимости:
- Каждый тест сам создаёт свои данные — не берёт их из другого теста.
- Тест не использует побочный эффект чужого теста.
- Если тесты перемешать — они всё равно должны проходить.
- Один тест = одна проверяемая идея.
