### Разминка: задачи A–E

**kind:** `text`

Для каждой функции определи сложность по O-нотации и объясни почему. Не запускай код — думай. Запиши ответы перед тем как смотреть дальше.

**A.** `sum(arr)` — сумма элементов массива (один цикл).

**B.** `hasDuplicates(arr)` — проверка на дубликаты (вложенный цикл: i от 0 до n, j от i+1 до n).

**C.** `allPairs(arr1, arr2)` — перебор всех пар из двух массивов (вложенный цикл).

**D.** `factorial(n)` — рекурсивное вычисление факториала (n вызовов).

**E.** `binarySearch(arr, target)` — это твоя функция из проекта 11: бинарный поиск в отсортированном массиве (каждый шаг делит диапазон пополам).

---

### Сверяем ответы A–E

**kind:** `text`

Проверь себя:

- **A (sum)** — O(n). Один цикл, проходит все элементы.
- **B (hasDuplicates)** — O(n²). Внешний цикл n итераций, внутренний — в среднем n/2. Константа отбрасывается → O(n²).
- **C (allPairs)** — O(n×m). Если массивы одинаковой длины → O(n²).
- **D (factorial)** — O(n). n рекурсивных вызовов, каждый O(1).
- **E (binarySearch)** — O(log n). Диапазон делится пополам на каждом шаге.

Если ошибся — не страшно. Разберись **почему** правильный ответ именно такой. Перечитай три правила из урока 12.1.

### Задача F: primesUpTo (посложнее)

**kind:** `text`

Оцени сложность решета Эратосфена (код в конспекте). Подсказки:

- Внешний цикл: `p` от 2 до √n
- Внутренний цикл: шагает с шагом `p`, а не 1
- Суммарное количество операций внутреннего цикла ≈ n/2 + n/3 + n/5 + n/7 + ...

Это известный результат: O(n × log(log n)). Не страшно если не получил точный ответ — это сложный случай.

### Задачи H–J: твои сортировки из проекта 11

**kind:** `text`

Теперь оцени сложность алгоритмов, которые ты сам написал в проекте 11.

**H.** `bubbleSort`: внешний цикл по n, внутренний по n-i.

**I.** `quickSort`: на каждом уровне рекурсии обрабатываются все элементы, уровней ~log n. Какова сложность в среднем? А если массив уже отсортирован и опорный — первый элемент?

**J.** `insertionSort`: какова сложность на уже отсортированном массиве? А на массиве в обратном порядке?

Запиши ответы, затем сверься.

---

### Сверяем ответы H–J

**kind:** `text`

- **H (bubbleSort)** — O(n²). Вложенный цикл: внешний n итераций, внутренний в среднем n/2.
- **I (quickSort)** — O(n log n) в среднем: n элементов × ~log n уровней рекурсии. В худшем случае (отсортированный массив, первый опорный) — O(n²): каждый раз «меньше» пустая, рекурсия глубины n.
- **J (insertionSort)** — O(n) на отсортированном (внутренний цикл не выполняется), O(n²) в обратном порядке (каждый элемент сдвигает все предыдущие).

Это ровно то, что ты наблюдал в бенчмарке: `insertionSort` резко ускорялась на отсортированном массиве, а `quickSort` — наоборот, деградировала.

### Когда константа имеет значение

**kind:** `text`

Порядок роста (n, n², log n) важнее константы при больших N. Но иногда константа решает.

Задача: алгоритм A работает за 0.001 × n секунд, алгоритм B — за 0.000001 × n² секунд.

- При n = 100: A = 0.1с, B = 0.01с → B быстрее
- При n = 1 000: A = 1с, B = 1с → одинаково
- При n = 10 000: A = 10с, B = 100с → A быстрее в 10 раз

**Вопрос:** при каком n алгоритм A обгонит B? Реши уравнение `0.001n = 0.000001n²`.

Мораль: на малых данных константа может перевешивать, но как только данные вырастают — **порядок роста решает всё**.
