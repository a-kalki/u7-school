# Функция parseUrl(url)

**Краткое содержание:**
Вторая бизнес-утилита — полноценный разбор URL на составные части: протокол, хост, порт, путь, query-строка, хэш. Студент применяет весь арсенал строковых функций для аккуратного нарезания URL по стандартным разделителям.

### 1. Что такое URL и зачем он нужен

URL (Uniform Resource Locator) — это адрес ресурса в интернете. Когда ты вводишь адрес в браузере или переходишь по ссылке, браузер использует URL чтобы:

1. **Понять, как подключиться** — протокол (`https`) говорит браузеру, что соединение должно быть зашифрованным.
2. **Найти сервер** — хост (`example.com`) говорит браузеру, к какому компьютеру в интернете обращаться. DNS-система преобразует доменное имя в IP-адрес.
3. **Подключиться к нужной программе** — порт (`8080`) говорит, какая программа на сервере обслуживает запрос. Если порт не указан, используется порт по умолчанию: 80 для HTTP, 443 для HTTPS.
4. **Попросить нужный ресурс** — путь (`/path/to/page`) говорит серверу, какой именно файл или данные нужны.
5. **Передать параметры** — query-строка (`?q=search`) передаёт дополнительные данные (поисковый запрос, номер страницы, фильтры).
6. **Указать на фрагмент** — хэш (`#section`) указывает браузеру на конкретное место внутри страницы (якорь). Хэш не отправляется на сервер — он обрабатывается только браузером.

### 2. Из каких частей состоит URL

Разберём полный URL и каждую его часть:

```
https://example.com:8080/path/to/page?q=search#section
^^^^^^   ^^^^^^^^^^^ ^^^^ ^^^^^^^^^^^^^ ^^^^^^^^^ ^^^^^^^
protocol  host       port  path          query     hash
```

| Компонент | Назначение | Разделитель | Пример |
|-----------|------------|-------------|--------|
| **protocol** | Способ соединения: `http` (обычное), `https` (зашифрованное) | `://` | `https` |
| **host** | Адрес сервера — домен (`example.com`) или IP (`192.168.1.1`) | после `://`, до `:`, `/`, `?` или `#` | `example.com` |
| **port** | Номер программы-обработчика на сервере. По умолчанию: 80 (http), 443 (https) | `:` после хоста | `8080` |
| **path** | Путь к ресурсу на сервере. Всегда начинается с `/` (корень) | после хоста/порта, до `?` или `#` | `/path/to/page` |
| **query** | Параметры запроса: `ключ=значение`, разделённые `&`. Начинается с `?` | `?` | `q=search` |
| **hash** | Якорь — указатель на фрагмент страницы. Не отправляется на сервер | `#` | `section` |

### 3. Ответственность каждой части

Каждая часть URL решает свою задачу в цепочке «пользователь → браузер → DNS → сервер»:

1. **Протокол** — браузер решает, устанавливать ли шифрованное соединение (TLS/SSL). Если указан `https`, браузер проверит сертификат сервера. Если `http` — данные передаются открытым текстом, и любой промежуточный узел может их прочитать.

2. **Хост** — DNS-система преобразует домен в IP-адрес. `example.com` → `93.184.216.34`. Браузер устанавливает TCP-соединение с этим IP.

3. **Порт** — на одном сервере может быть много программ (веб-сервер на 443, почта на 25, база данных на 5432). Порт — это «дверь» к конкретной программе. Порты 0–1023 зарезервированы для системных служб, 1024–65535 — для приложений.

4. **Путь** — сервер получает путь и решает, какой обработчик вызвать. `/api/users` может вернуть JSON, `/images/logo.png` — картинку, `/about` — HTML-страницу. Путь — это часть HTTP-запроса, которую сервер интерпретирует по своим правилам.

5. **Query-строка** — дополнительные данные, обычно влияющие на фильтрацию, сортировку или поиск. Например, `?page=2&sort=asc` означает «вторая страница результатов, сортировка по возрастанию». Query-строка также отправляется на сервер.

6. **Хэш** — в отличие от остальных частей, хэш **не отправляется на сервер**. Его обрабатывает только браузер: прокручивает страницу к элементу с указанным `id`. Это полезно для навигации внутри длинных страниц. Например, `#faq` — прокрутить к блоку часто задаваемых вопросов.

### 4. Почему порядок важен

URL — это не просто набор частей, а **упорядоченная** структура. Некоторые символы могут встречаться в нескольких компонентах:

- `:` есть и в протоколе (`https://`), и в порту (`:8080`)
- `/` есть и в `://`, и в пути
- `?` и `#` могут быть частью значения query-параметра (после кодирования)

Именно поэтому разбор URL идёт от внешних разделителей к внутренним — чтобы не перепутать одно с другим. Например, если сначала искать `/` для пути, мы можем ошибочно принять `//` из `://` за начало пути.

### 5. Алгоритм parseUrl

Функция принимает URL-строку и возвращает объект с полями `protocol`, `host`, `port`, `path`, `query`, `hash`. Отсутствующие компоненты — пустые строки.

```javascript
function parseUrl(url) {
  if (typeof url !== 'string') throw new TypeError('Ожидается строка');

  const result = {
    protocol: '',
    host: '',
    port: '',
    path: '',
    query: '',
    hash: '',
  };

  let rest = url;

  // 1. Выделяем protocol: ищем '://'
  const protocolEnd = indexOf(rest, '://');
  if (protocolEnd !== -1) {
    result.protocol = slice(rest, 0, protocolEnd);
    rest = slice(rest, protocolEnd + 3, len(rest));
  }

  // 2. Выделяем hash: ищем '#' с конца строки
  const hashStart = indexOf(rest, '#');
  if (hashStart !== -1) {
    result.hash = slice(rest, hashStart + 1, len(rest));
    rest = slice(rest, 0, hashStart);
  }

  // 3. Выделяем query: ищем '?'
  const queryStart = indexOf(rest, '?');
  if (queryStart !== -1) {
    result.query = slice(rest, queryStart + 1, len(rest));
    rest = slice(rest, 0, queryStart);
  }

  // 4. Выделяем path: ищем '/' после хоста
  const pathStart = indexOf(rest, '/');
  if (pathStart !== -1) {
    result.path = slice(rest, pathStart, len(rest));
    rest = slice(rest, 0, pathStart);
  } else {
    result.path = '/';
  }

  // 5. В остатке — host:port
  const portStart = indexOf(rest, ':');
  if (portStart !== -1) {
    result.host = slice(rest, 0, portStart);
    result.port = slice(rest, portStart + 1, len(rest));
  } else {
    result.host = rest;
  }

  return result;
}
```

### 6. Порядок разбора важен

Мы идём от «внешних» разделителей к «внутренним»:

1. **protocol** — `://` уникален и не встречается внутри других компонентов
2. **hash** — `#` в конце, отделяем первым (иначе попадёт в path или query)
3. **query** — `?`, отделяем до path
4. **path** — `/`, начинается от корня после хоста
5. **host:port** — то, что осталось

### 7. Граничные случаи

- `parseUrl('https://example.com')` → `{ protocol: 'https', host: 'example.com', port: '', path: '/', query: '', hash: '' }`
- `parseUrl('http://localhost:3000/api/users')` → `{ protocol: 'http', host: 'localhost', port: '3000', path: '/api/users', query: '', hash: '' }`
- `parseUrl('https://example.com/page?q=1#top')` → `{ protocol: 'https', host: 'example.com', port: '', path: '/page', query: 'q=1', hash: 'top' }`
- `parseUrl('https://example.com#hash')` → хэш отделён, path = `/`
- `parseUrl('example.com/path')` → `{ protocol: '', host: 'example.com', port: '', path: '/path', query: '', hash: '' }` (без протокола)
- `parseUrl('https://example.com:8080')` → порт `8080`
- `parseUrl(123)` → `TypeError`

### 8. Какие свои функции используем

- `len`, `indexOf`, `slice` — основа всей работы со строками
- Никаких дополнительных — вся логика строится на нарезании подстрок
