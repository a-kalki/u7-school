# Шаги урока: Функция parseUrl(url)

---

### Что такое URL

**kind:** `text`

URL (Uniform Resource Locator) — это адрес, по которому браузер находит ресурс в интернете. Каждый раз, когда ты открываешь сайт, переходишь по ссылке или запрашиваешь данные через JavaScript — используется URL.

Разберём полный URL и то, за что отвечает каждая его часть:

```
https://example.com:8080/path/to/page?q=search#section
^^^^^^   ^^^^^^^^^^^ ^^^^ ^^^^^^^^^^^^^ ^^^^^^^^^ ^^^^^^^
protocol  host       port  path          query     hash
```

**1. Протокол (protocol)** — `https`. Определяет **способ соединения** между браузером и сервером:
- `http` — обычное соединение, данные передаются открытым текстом
- `https` — шифрованное соединение (TLS/SSL). Браузер проверяет сертификат сервера, и весь трафик шифруется

Протокол всегда заканчивается комбинацией `://`.

**2. Хост (host)** — `example.com`. Адрес **сервера** в интернете. Это доменное имя, которое DNS-система преобразует в IP-адрес. `example.com` → `93.184.216.34`. Браузер устанавливает TCP-соединение с этим IP. Хост может быть и IP-адресом напрямую: `192.168.1.1`.

**3. Порт (port)** — `8080`. Номер **программы-обработчика** на сервере. На одном сервере может работать много программ: веб-сервер, почтовый сервер, база данных. Порт — это «дверь» к конкретной программе:
- Порты 0–1023 зарезервированы для системных служб (80 — HTTP, 443 — HTTPS, 22 — SSH)
- Порты 1024–65535 — для приложений

Если порт не указан явно, браузер использует порт по умолчанию: 80 для `http`, 443 для `https`.

**4. Путь (path)** — `/path/to/page`. Указывает серверу, **какой именно ресурс** нужен. Сервер получает путь и решает, какой обработчик вызвать:
- `/api/users` → вернуть JSON с пользователями
- `/images/logo.png` → вернуть файл картинки
- `/about` → вернуть HTML-страницу

Путь всегда начинается с `/` (корень). Если путь не указан, подразумевается `/`.

**5. Query-строка (query)** — `q=search`. **Дополнительные параметры** запроса. Начинается с `?`, параметры разделены `&`, каждый параметр — `ключ=значение`. Используется для фильтрации, сортировки, поиска:
- `?page=2&sort=asc` → «вторая страница, сортировка по возрастанию»
- `?q=javascript&lang=ru` → «поиск по слову javascript, язык русский»

Query-строка отправляется на сервер вместе с путём.

**6. Хэш (hash)** — `section`. **Якорь** — указатель на фрагмент внутри страницы. Начинается с `#`. В отличие от остальных частей, хэш **НЕ отправляется на сервер** — его обрабатывает только браузер:
- Прокручивает страницу к элементу с указанным `id`
- Используется в одностраничных приложениях для навигации (`#/profile`, `#/settings`)

**Почему порядок разбора важен.** Некоторые символы (`:`, `/`, `?`, `#`) встречаются в нескольких компонентах URL. Если разбирать в неправильном порядке, можно перепутать части. Например:
- `:` есть и в `://` протокола, и в `:8080` порта
- `?` и `#` могут быть частью значения query-параметра (после кодирования)

Поэтому разбор идёт от **внешних** разделителей к **внутренним**: сначала `://`, потом `#`, потом `?`, потом `/`, и в остатке — `host:port`.

### Реализация parseUrl()

**kind:** `text`

> Убедись, что ты в ветке `feat/business-utils`.

Реализуй функцию `parseUrl(url)` — разбор URL на составные части. Создай файлы `utils/parse-url.js` и `utils/parse-url.test.js`, следуй TDD.

**Функция принимает:**
- `url`: `string` — URL для разбора

**Функция возвращает:** `object` с полями:
- `protocol`: `string` — протокол (`http`, `https`) или пустая строка
- `host`: `string` — домен или IP
- `port`: `string` — порт или пустая строка
- `path`: `string` — путь, начинается с `/` (по умолчанию `/`)
- `query`: `string` — query-строка (без `?`) или пустая строка
- `hash`: `string` — хэш (без `#`) или пустая строка

**Важно:** функция **иммутабельная**. Используй свои `indexOf`, `slice`, `len` для разбора.

Тестовые случаи (каждый — отдельный `test(...)`):
- Должна разобрать полный URL: `parseUrl('https://example.com:8080/path?q=1#top')` → `{ protocol: 'https', host: 'example.com', port: '8080', path: '/path', query: 'q=1', hash: 'top' }`
- Должна разобрать URL без порта и query: `parseUrl('https://example.com/page')` → `{ protocol: 'https', host: 'example.com', port: '', path: '/page', query: '', hash: '' }`
- Должна разобрать URL с портом: `parseUrl('http://localhost:3000/api')` → `{ protocol: 'http', host: 'localhost', port: '3000', path: '/api', query: '', hash: '' }`
- Должна разобрать URL с query и hash: `parseUrl('https://example.com/page?q=1#section')` → проверить query и hash
- Должна разобрать URL без протокола: `parseUrl('example.com/path')` → `{ protocol: '', host: 'example.com', port: '', path: '/path', query: '', hash: '' }`
- Должна указать path `/` если пути нет: `parseUrl('https://example.com')` → `path: '/'`
- Должна разобрать URL только с хэшем: `parseUrl('https://example.com#section')` → `{ ..., path: '/', query: '', hash: 'section' }`
- Должна разобрать URL только с query: `parseUrl('https://example.com?q=1')` → `{ ..., path: '/', query: 'q=1', hash: '' }`
- Должна выбросить `TypeError` если аргумент не строка

### Вопросы на понимание

**kind:** `text`

Ответь на вопросы. Если не знаешь — проверь гипотезу кодом через `bun`.

**1.** Почему мы разбираем хэш (`#`) до query (`?`)? Что будет, если поменять порядок — сначала query, потом hash — на URL `https://example.com?q=1#top`?

**2.** Почему мы разбираем query до path? Что будет, если сначала path, потом query?

**3.** Может ли путь содержать символ `?` или `#`? Если да, как тогда правильно определить границу между путём и query-строкой?

**4.** В реальности порт — это число. Но в нашей функции он строка. Почему это приемлемо для данного уровня? Что нужно было бы сделать для числового порта?

**5.** Можно ли переиспользовать `getQueryParams` внутри `parseUrl` для разбора query-части? Что для этого нужно?
