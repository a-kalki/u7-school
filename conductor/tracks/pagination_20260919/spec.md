# Спецификация: Пагинация UI — универсальный пагинатор и перенос обрезок

> Готовит пагинатор для трека [peer-review-ui_20260916](../peer-review-ui_20260916/spec.md)
> (S07 потребляет готовым; идёт раньше него). Второй будущий потребитель —
> web-ui (ядро транспорт-независимое).

## Обзор

ООП-пагинатор без состояния в core: ядро `Paginator` (transport-neutral) +
бот-наследник `BotPaginator` (лимит Telegram, кнопки навигации, индикатор) +
`PageCache` (кеш страниц в памяти стори, привязка к эпохе диалога). Перенос
всех существующих «тупых обрезок» `#truncate(4000)` на пагинатор: дерево
программы потока (streams S03) и каталог курсов (courses S00, уровни 0–4).
Вместо молчаливой обрезки с «...» пользователь получает постраничный просмотр.

## Зафиксированные решения (из проектирования)

1. **Двухслойность.** Ядро в `packages/core/src/ui/pagination/` (работает со
   `string`, не знает домена, бота и MarkdownV2); бот-специфика в
   `packages/core/src/ui/bot/` — наследник ядра (паттерн как
   `UiStory → BotUiStory`).
2. **Адресация страниц.** Номер страницы — числовой сегмент callback-кода.
   Исследование UUID-сжатия (`bot-transport.ts`, `short-id.ts`): сжатие
   позиционно-независимо (сжимается каждый сегмент-полный-UUID, порядок не
   важен), штамп `:~<seq36>` дописывается в конец и снимается первым;
   числовой сегмент не трогается ни сжатием, ни разжатием. После сжатия код
   ~40 байт — лимит 64 байта не проблема. Список изменился и страница исчезла —
   clamp к существующей.
3. **Кеш страниц.** Разбиение детерминированно, но стори вправе собрать `Paged`
   один раз и не перечитывать домен при тыках. Кеш — в памяти стори (НЕ в
   персистной `BotSession`): одна запись на пользователя, валидность — эпоха
   диалога (`path` + `seq`); смена диалога или рестарт — тихая пересборка при
   первом тыке. Сессия и репо не забиваются мусором.
4. **Кнопки `‹ Пред` / `След ›` — одним рядом** (в клавиатуре над «Назад»).
5. **Страница — только целые блоки**; одинокий блок длиннее лимита — страница
   из одного блока с флагом `oversized` (элемент не рвём никогда).

## Функциональные требования

### Пагинатор (core)

- **ФР-1. Ядро `Paginator`** (`packages/core/src/ui/pagination/`) — объект-сервис
  без состояния: `paginate(blocks, opts) → Paged` — страницы из целых блоков;
  в странице: готовый `text` (можно слать напрямую), `items` (для web/кастомного
  рендера), `index`/`total`, курсоры `start`/`prevStart`/`nextStart`,
  `hasPrev`/`hasNext`, `oversized`; в результате: `pages`, `isEmpty`,
  `isSingle`. `page(paged, n) → Page | undefined` — доступ с clamp.
  `opts`: `limit`, `measure` (мера блока; дефолт — символы, для web — по
  количеству элементов), `separator`.
- **ФР-2. `BotPaginator`** (`packages/core/src/ui/bot/page-nav.ts`) — наследник
  `Paginator`, без состояния: `botLimit(headerLength)` (4096 − шапка − резерв),
  `navRows(page, cb)` → **один ряд** `‹ Пред`/`След ›` (кнопки только при
  наличии соседней страницы), `indicator(page)` → `Стр. N/M` (undefined на
  единственной странице).
- **ФР-3. `PageCache`** (`packages/core/src/ui/bot/page-cache.ts`) — маленький
  кеш: `put/get` по (telegramId, эпоха = path + seq); одна запись на
  пользователя (`put` перезаписывает), несовпадение эпохи — miss. Персистную
  сессию не трогает.

### Перенос обрезок

- **ФР-4. streams S03** («Программа курса»): блок = узел проекта с уроками
  (`tree-renderer` отдаёт блоки); `#truncate` и упоминание обрезки удалены;
  кеш страниц через `PageCache`; листание — edit на месте.
- **ФР-5. courses S00 уровни 0–4** (каталог): блок = жирный элемент уровня с
  inline-детьми; `#truncate` удалён; тот же паттерн (уровень 0 включён — риск
  переполнения без обрезки, перенос дёшев).

### Тестирование и данные

- **ФР-6.** Механика разбиения — юнит-тесты ядра с малым лимитом
  (`limit` — параметр; продовый лимит не хакаем).
- **ФР-7.** E2E минимум на **трёх страницах**: полный цикл листания (вперёд до
  конца и назад), edit на месте, `assertBotResponseValid`. Расширить
  fixtures-сид длинной программой курса (>4000 символов) — ручное тыканье в
  `dev:fixtures`.

### Документация

- **ФР-8.** ✅-пометки в ui-spec (streams S03, courses S00) по реализованному.
  Изменения UX согласованы с владельцем до старта трека (ui-spec — контракт);
  заметка S07 в peer-review/ui-spec.md («пагинатор готов») внесена при
  создании трека.

## Нефункциональные требования

- TDD; покрытие >80%; `bun run check` чисто по скоупу.
- `ui/pagination` не импортирует bot-слой и домены; `BotPaginator`/`PageCache`
  не знают доменов.

## За рамками

- S07 peer-review — трек peer-review-ui (потребляет готовый пагинатор).
- Мониторинг ментора, web-ui — будущие потребители пагинатора.
- Правки трека peer-review-ui (зависимость от готового пагинатора, удаление
  фазы хелпера) — выполнены при создании этого трека.

## Критерии приёмки

- `grep truncate` по сторям — пусто; S03 и уровни каталога на длинных данных
  листаются: целые элементы, edit на месте, одна страница — без кнопок навигации.
- E2E ≥ 3 страниц зелёные; `dev:fixtures` показывает многостраничную программу.
- Лимит 64 байта не нарушен (номер страницы не участвует в UUID-сжатии) — тест.
- Сессия/репо не хранят страницы; смена диалога сбрасывает кеш (пересборка).
