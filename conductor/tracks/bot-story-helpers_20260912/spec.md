# Спецификация: Декларативные хелперы ответов стори бота

## Обзор

**Проблема.** Стори бота строят ответы литералами `DialogResponse` вручную: ~120 полей ответа в 19 сторях шести контроллеров, 35+ `keyboard:`-литералов (в mentor даже написаны локальные клавиатурные хелперы), служебный шум (`isMultiple: false` в каждой клавиатуре). Язык ответов — транспортный (поля контракта), а не доменный («показать экран», «спросить», «уйти»).

**Решение.** Чистые функции-билдеры в `packages/core/src/ui/bot/response-builders.ts` + тонкие `protected`-делегаты на `BotUiStory`. Полная миграция: все стори, core-литералы (`bot-controller.ts`, `core/ui-app.ts`, `app/core/ui-app.ts`, `learning/shared.ts`), тесты на билдеры.

**Инвариант.** Хелперы возвращают те же структуры `DialogResponse` — контракт «Диалог и Экран» и транспорт не меняются, UI-поведение идентично, существующие тесты остаются зелёными без правок и служат регрессионной сетью.

## Функциональные требования

- **ФР-1. Билдеры (core).** Модуль `response-builders.ts`: `screen(text, keyboard?)`, `ask(text, context, keyboard?)`, `warn(text)`, `note(text)`, `go(path)`, `kb(rows, opts?)`, `btn(text, code)`, `btnUrl(text, url)`. Чистые функции без доступа к сессии/транспорту; экспорт из `@u7-scl/core/ui`.
- **ФР-2. Делегаты на `BotUiStory`.** Тонкие `protected`-методы (`this.screen(...)`, `this.ask(...)`, `this.warn(...)`, `this.note(...)`, `this.go(...)`, `this.kb(...)`, `this.btn(...)`/`this.btnUrl(...)`); `isMultiple: false` — по умолчанию, опция `multiple: true`.
- **ФР-3. Миграция стори.** Все 19 стори контроллеров (streams, courses, questionnaire, mentor, learning, app, user) переведены на хелперы; локальные kb-хелперы mentor удалены; комбинации-редкости (например `+ release`) — спредом: `{ ...this.ask(...), release: true }`.
- **ФР-4. Миграция core/app-литералов.** `bot-controller.ts` (`#errorScreen`, `unknownCommand`, handleError-литералы), `core/ui-app.ts` (4 литерала), `app/core/ui-app.ts` (7 литералов), `learning/shared.ts` — на билдеры.
- **ФР-5. Документация.** `conductor/code_styleguides/skills/bot-ui-story.md` — раздел «Хелперы ответов»: когда хелпер, когда литерал/spread; живой образец — мигрированная стори.

## Нефункциональные требования

- Чистота билдеров: детерминированные функции `аргументы → DialogResponse/KeyboardDescription`, без side-эффектов — тестируемость и переиспользование вне наследников.
- Существующие тесты стори/контроллеров **не редактируются**; если тест падает после миграции — ошибка миграции, а не теста.
- Три ворота качества чисто: `bun run lint`, `bun run tslint`, `bun test`.

## Критерии приёмки

1. `grep -rn "isMultiple" apps/u7-bot/src/controllers"` — только внутри `kb(...)`-применений (кроме осознанных `multiple: true`).
2. Стори не содержат «сырых» литералов `keyboard: { rows:` (кроме мест, где `KeyboardDescription` строится по частям доменной логикой — с комментарием).
3. Все тесты зелёные **без изменения ожиданий**; новые unit-тесты билдеров — полные (все функции, дефолты, kind-уведомления).
4. `bun run check` чист.
5. Визуально UI-поведение бота идентично (ручная верификация по чеклистам фаз).

## За рамками

- `finalize`-хелпер: 0 использований в коде; сценарии tasks-модуля покрываются `screen` (edit-на-месте) и `confirm()`. При появлении паттерна «зафиксировать старый экран + показать новый» — опция к `screen`, без ломки контракта.
- `updateScreen`/`newScreen`: семантика рендера (edit vs send) принадлежит транспорту (`ownerSeq`), стори не знает о владении.
- Изменение `DialogResponse`, транспорта, `DialogState`, UX-текстов.
