# Спецификация: Статусы и признаки студента — единый API

> Трек 1 из трёх этапа «отзывы» ([концепция](../../roadmap/metrics/peer-review-system.md), §3 и §5; порядок:
> этот трек → `peer-review-domain` → `peer-review-ui`).
> Зона: `packages/stream`.

## Обзор

Терминальные исходы студента выражаются **статусом + признаками**, а знания о них
инкапсулируются API зоны stream: клиенты (UI-лейблы, снапшоты кампаний peer-review,
будущее досье) не разбирают состояние студента сами и не размазывают switch-логику
по проекту.

Схема хранения **не меняется**: статусы `enrolled`, `active`, `abandoned`,
`advanced`, `not_advanced` и `abandonDetails` (`who: 'self'|'mentor'`,
`cause: 'voluntary'|'inactivity'|'by_mentor'`) остаются как есть — гейтинг,
события и переходы не затрагиваются. Новый слой — read-API над состоянием.

## Модель исходов (целевая)

| Статус | Категория | Признаки |
|---|---|---|
| `advanced` | завершил | прошёл |
| `not_advanced` | завершил | не прошёл |
| `abandoned` (+`abandonDetails`) | забросил | не начал · покинул сам · снят ментором |

- «Не начал» — выводимый признак: нет ни одного завершённого шага (независим от
  причины ухода: не начавший мог уйти сам или быть снят ментором — оба факта
  доступны, лейбл выбирает приоритет «не начал»).
- «Покинул сам» — `cause: voluntary` (self).
- «Снят ментором» — `cause: by_mentor` и `inactivity` (mentor).

## Функциональные требования

- **ФР-1. API исходов студента** в зоне stream (доменный read-слой над
  состоянием `Student`: функции/VO или методы агрегата — точное место по границам
  при реализации):
  - категория исхода: `завершил` (`advanced`, `not_advanced`) / `забросил`
    (`abandoned`) / нетерминальные (`enrolled`, `active`);
  - признаки завершения: `прошёл` / `не прошёл`;
  - признаки ухода: `не начал` (нет завершённых шагов) · `покинул сам` ·
    `снят ментором`;
  - вход — данные студента (статус, `abandonDetails`, завершённые шаги), без
    обращений к репозиториям.
- **ФР-2. Словарь продуктовых меток** — единый источник пользовательских строк
  для клиентских зон stream: «окончил», «окончил, не прошёл», «забросил», «не начал»,
  «покинул сам», «снят ментором». Составные лейблы карточек (например
  «не начал · покинул сам») собираются из словаря, а не дублируются.
  Решение владельца (v3.1): peer-review этот словарь не копирует — у кампаний
  собственная проекция исходов «завершил»/«забросил»/«не начал»
  (см. концепцию §3 и ФР-4).
- **ФР-3. Миграция клиентов**: затронутые треком места, где сейчас размазаны
  собственные switch по `status`/`cause` (лейблы в стори view-stream, monitor,
  learning и пр. — найти по grep на старте), переводятся на API/словарь.
- **ФР-4. `neverStarted` в API** — готовый потребитель: трек `peer-review-domain`
  строит отсюда проекцию исходов для снапшотов кампаний (категория исхода +
  признак «не начал» → `completed`/`dropped`/`never_started`), не вычисляет сам.

## Нефункциональные требования

- TDD (workflow проекта), покрытие нового кода >80%: все ветки статусов × cause,
  пограничные (abandoned без деталей — легаси-данные).
- `bun run lint` (biome), `bun run tslint` — чисто по скоупу трека.

## Зафиксированные решения (из сессии проектирования)

1. Шестой статус студента НЕ вводится: признаки — read-API, схема хранения без
   изменений (решение владельца: «лучше заплатить дополнительной работой» —
   инкапсуляцией, а не миграцией данных).
2. «Завершил» с признаками «прошёл/не прошёл» — надстройка над существующими
   `advanced`/`not_advanced`, они не сливаются в один статус.
3. API — единственный источник знаний об исходах: клиенты не лазят в состояние
   напрямую (желание владельца).

## За рамками

- Инвариант терминальности при завершении потока и событие `stream.completed` —
  трек [`peer-review-domain`](../peer-review-domain_20260916/spec.md) (ФР-1, ФР-2).
- Снапшоты кампаний peer-review и их исходы-проекции — потребитель;
  реализация в треке `peer-review-domain`.
- Изменение переходов, событий, гейтинга stream.

## Критерии приёмки

- Словарь меток и API исходов покрыты тестами всех веток; легаси-данные
  (abandoned без `abandonDetails`) не роняют лейблы.
- В местах, затронутых треком, нет собственных switch по `status`/`cause` вне
  нового API.
- `CI=true bun test`, `bun run lint`, `bun run tslint` — чисто по скоупу трека.
