# План: Тестовые миры

> Спецификация: [spec.md](./spec.md). Концепция: [test-worlds.md](../../guides/test-worlds.md).
> Порядок фаз строго последовательный: kit → материализация → миры → миграция тестов → зачистка.
> Фаза Red/Green — по `conductor/workflow.md` (§ Стандартный рабочий процесс задачи).

## Фаза 1. World-kit и WorldState

- [ ] Task: Каркас kit: типы `WorldState` (коллекции state-объектов агрегатов, plain-данные), конструкторы `person`/`course`/`stream`/`student`/`campaign`; детерминированные UUID из ключей; относительное время (`T-2д` → абсолютные даты при сборке)
    - [ ] Red: тесты каркаса (UUID стабилен между сборками; сборка падает на нарушении инварианта «судьба кампании == исход студента»)
    - [ ] Green: реализация
- [ ] Task: Инварианты роли/статуса и хронологии: роль пользователя == статус в потоке; регистрация ≤ зачисление ≤ исход; окно кампании согласовано с исходом (опорная шкала, производные даты)
    - [ ] Red: тесты инвариантов (контрпримеры: регистрация после старта потока; окно кампании до исхода)
    - [ ] Green: реализация
- [ ] Task: `world:check` — валидатор мира (CLI-функция + скрипт): собирает мир, печатает нарушения, ненулевой exit при ошибках
    - [ ] Red: тесты (валидный мир проходит; каждый инвариант ловится)
    - [ ] Green: реализация
- [ ] Task: Conductor - User Manual Verification 'Фаза 1' (Protocol in workflow.md)

## Фаза 2. Материализация, кеш, запуск

- [ ] Task: Адаптер материализации: WorldState → структура JSON-файлов (контракт «материализовать → адрес хранилища»; форма файлов — совместима с текущим сидом/репо)
    - [ ] Red: тесты (файлы созданы; повторная материализация идентична — детерминированность)
    - [ ] Green: реализация
- [ ] Task: Кеш материализации: ключ (имя мира + хеш исходников); повторный запрос без изменений мира не пересобирает; copy-on-write раздача копий по тегу (наследует механизм fixture-loader)
    - [ ] Red: тесты (второй вызов без пересборки; правка исходников → пересборка; копии изолированы)
    - [ ] Green: реализация
- [ ] Task: Манифест `world.json` (имя, хеш) в `data/fixtures/` + `world:list`; seed: `WORLD=<имя>` (дефолт `core-education`), бот логирует мир при старте
    - [ ] Red: тесты (манифест создан; дефолт применяется; лог)
    - [ ] Green: реализация
- [ ] Task: Conductor - User Manual Verification 'Фаза 2' (Protocol in workflow.md)

## Фаза 3. Мир core-education (продуктовый контент)

- [ ] Task: Состав мира: 3 курса; поток 1 — завершён (студент «прошёл» T-2д → живая кампания с 1 написанным отзывом; студент «забросил» T-30д → истёкшая кампания), ментор №2; поток 2 — активный (Андрей, Марина, Олег — без исходов), ментор dev; поток 3 — в приёме, без студентов
    - [ ] Red: тесты состава (сущности, связи, окна кампаний, инвариантный прогон)
    - [ ] Green: реализация
- [ ] Task: Продуктовое качество контента (ФР-9): уроки-шаги — названия + 1–2 осмысленных абзаца; человеческие имена; полные URL; тон прод-текстов
    - [ ] Red: тесты контента (не пустые абзацы; нет заглушек «Урок 1»/lorem; URL полные)
    - [ ] Green: наполнение
- [ ] Task: Реестр персон dev-режима из мира: `dev-persona.ts` берёт `/persona`-список из мира (dev + ментор №2 + студенты)
    - [ ] Red: тесты (список персон из мира; подмена работает)
    - [ ] Green: реализация
- [ ] Task: Conductor - User Manual Verification 'Фаза 3' (Protocol in workflow.md)
