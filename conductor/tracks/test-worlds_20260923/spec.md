# Спецификация: Тестовые миры

**Тип:** Refactor (инфраструктура тестирования)
**Концепция:** `conductor/guides/test-worlds.md`
**Утверждена владельцем:** 2026-09-23

## Обзор

Текущие фикстуры — независимые JSON-файлы (`tests/fixtures/templates/`), согласованность между модулями держится на ручной склейке и ломается (кампании противоречат судьбам студентов, роли — статусам). Заменяем их декларативными **тестовыми мирами**: мир описывается в TypeScript, генератор строит **WorldState** — типизированное состояние агрегатов, нейтральное к хранилищу. Из WorldState **материализуется** реальное состояние (сейчас — структура JSON-файлов, в будущем — БД), собирается один раз, кешируется и раздаётся тестам копиями. Инварианты проверяются при построении — неконсистентный мир не собирается.

**Принятые решения:** код миров — в `apps/u7-bot/tests/worlds/`; **все** текущие тесты переводятся на миры в пределах трека; состав миров определяется потребностями текущих тестов; старые templates удаляются полностью; дефолтный мир — `core-education`.

## Функциональные требования

- **ФР-1. World-kit:** конструкторы сущностей (`person`, `course`, `stream`, `student`, `campaign`, `application`…) со встроенными инвариантами (судьба кампании == исход студента, роль == статус в потоке, порядок дат хронологии); детерминированные UUID из ключей.
- **ФР-2. WorldState — центральный объект:** типизированные коллекции state-объектов агрегатов, **не привязанные к хранилищу** (по форме — то, что читают/пишут Repo-порты домена). Архитектурный задел под будущие СУБД: переход на Mongo/SQLite/Postgres — новый адаптер материализации «WorldState → БД», без изменения миров, kit и тестов. СУБД-адаптеры в треке **не реализуются**.
- **ФР-3. Адаптеры WorldState:** (а) материализация в JSON-файлы — для сида бота и тестов; контракт адаптера — «материализовать состояние, отдать адрес хранилища». СУБД-адаптеры — только контракт, без реализации.
- **ФР-4. Хронология мира:** опорная шкала относительного времени (`T-90д` регистрация → `T-60д` старт потока → события → исход); конструкторы выводят производные даты; инвариант порядка (регистрация ≤ зачисление ≤ исход; окно кампании согласовано с исходом).
- **ФР-5. Кеш материализованного состояния:** мир материализуется **один раз**; ключ кеша — имя мира + хеш исходников (изменился мир → новая материализация); **каждый тест получает изолированную копию** материализованного состояния (copy-on-write по тегу — механизм текущего `fixture-loader` сохраняется). Будущее: при материализации в БД — тот же контракт «создать один раз, раздавать копиями».
- **ФР-6. Персоны dev-режима из мира:** реестр персон — часть мира; `dev-persona.ts` берёт список `/persona` из него.
- **ФР-7. Запуск и валидация:** `WORLD=<имя>` для seed/dev (дефолт `core-education`); команда `world:check`; манифест `world.json` (имя, хеш исходников) в `data/fixtures/`; бот логирует загруженный мир при старте.
- **ФР-8. Миры:** `core-education` (курсы; завершённый поток с живой и истёкшей кампаниями; активный поток со студентами без исходов; поток в приёме; два ментора), `minimal`, + миры, которые выявятся потребностями текущих тестов.
- **ФР-9. Продуктовое качество контента:** уроки-шаги с осмысленными названиями и 1–2 абзацами текста; человеческие имена; полные URL; критерий скриншота (dev неотличим от прода).
- **ФР-10. Миграция тестов:** `fixture-loader`/`test-app` переводятся на миры; API для тестов сохраняет форму «запросил тег → получил копию состояния»; все текущие integration/e2e-тесты проходят; тестам со специфичными данными — свои миры/сцены.
- **ФР-11. Зачистка:** `tests/fixtures/templates/` и старый источник копирования удаляются; README и `bot-test.md` обновляются.

## Нефункциональные требования

- UUID-совместимость: существующие тесты не меняют ожидания по идентификаторам.
- `bun test` — зелёный, покрытие не снижается; biome/tsc — чисто.
- Скорость: повторные запуски тестов не пересобирают мир (кеш по хешу); копия материализованного состояния дешевле полной материализации.
- WorldState — plain-данные (JSON-сериализуемые), детерминированные для одного и того же мира.

## Критерии приёмки

1. `bun test` зелёный **при удалённых templates**.
2. `WORLD=core-education bun run dev:fixtures` — бот работает; `/persona` собирается из мира; уроки в боте — с абзацами контента.
3. `world:check` отвергает мир с нарушенным инвариантом: судьба ≠ исход; регистрация после запуска потока; окно кампании до исхода.
4. Кеш работает: повторный прогон тестов переиспользует материализованное состояние (нет пересборки при неизменном мире); после правки исходников мира состояние пересобирается.
5. Два теста на одном мире изолированы: мутации одного не видны другому.
6. Манифест `world.json` создаётся; при старте бот пишет имя мира.
7. Не осталось файлов фикстур, правимых руками.

## За рамками

- Реализация СУБД-адаптеров (Mongo/SQLite/Postgres) — только контракт материализации и форма WorldState.
- Вынос world-kit в отдельный пакет (когда появится второй потребитель — CLI/REST).
- Новые миры под будущие модули и баг-регрессы.
- Правки прод-кода (кроме seed и dev-persona).
- Детальная история событий каждого студента сверх опорной хронологии.
