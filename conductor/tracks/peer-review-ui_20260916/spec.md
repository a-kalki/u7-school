# Спецификация: UI отзывов (peer-review)

> Трек 2 из двух. **Зависит от трека** [peer-review-campaign_20260918](../../archive/peer-review-campaign_20260918/spec.md)
> (домен v4, UC, фасад, событие `student-campaign.created`).
> Экраны и тексты — утверждённая спека [ui-spec.md](../../../apps/u7-bot/src/controllers/peer-review/ui-spec.md)
> (S01–S07); она — источник истины по текстам, кнопкам и условиям видимости.

## Обзор

Пользовательский слой системы отзывов: приглашения по событиям судьбы
студента (`student.completed`/`student.abandoned` — сразу, «по горячим
следам»), хаб живых кампаний в главном меню, диалог написания отзывов,
постраничный просмотр отзывов потока. Плюс переиспользуемый хелпер пагинации
в core (второй потребитель — дерево учебной программы, сейчас «тупая обрезка» >4000).

## Функциональные требования

### Пагинация (core + streams)

- **ФР-1. Хелпер пагинации в `core` (bot-ui-story)** — чистая функция
  «элементы + рендерер элемента + лимит символов → страницы»: не знает домена;
  страница наполняется **целыми** элементами; лимит учитывает шапку экрана и
  клавиатуру (суммарно < 4096). Критерий «хорошести»: если абстракция не
  проходит критерии — локальная пагинация в S07 без форсирования (решение
  фиксируется в summary).
- **ФР-2. Адресация страниц** — кнопки-мосты `‹ Пред` / `След ›` с параметром
  страницы в callback-коде, листание — edit на месте (не новые сообщения);
  совместимо с «хлебными крошками» (активный экран один).
- **ФР-3. Рефактор nav-tree** (streams S03, `tree-renderer.ts`): дерево программы
  курса на хелпере пагинации — вместо обрезки.

### Контроллер peer-review (S02–S06)

- **ФР-4. Контроллер + стори кампании** (`apps/u7-bot/src/controllers/peer-review/`):
  - **S03** список адресатов: кнопки `Студент: {Имя}` / `Ментор: {Имя}`, `✅` при
    наличии моего отзыва, шапка с названием потока и остатком дней; адресация
    v4: субъекту «завершил» — ментор + завершившиеся/ещё учащиеся соученики,
    субъекту «забросил»/«не начал» — только ментор, ментору — только субъект;
  - **S04** перезапись: экран показывает текущий текст, ввод сразу заменяет,
    кнопка `❌ Назад`;
  - **S05** ввод: тексты-подсказки по направлению и исходу автора (спека),
    валидация 10–3500 — переспрос без потери контекста (`errorNotify`),
    `⏭️ Пропустить` → S03, `/cancel`;
  - **S06** сохранение → новый экран с обновлённым списком (`✅` появился);
  - истёкшее окно — экран-заглушка «возможность закрыта» (домен отклоняет).
- **ФР-5. Хаб S02** «Мои отзывы»: декларативная `menuButtons` «💬 Отзывы» — видна
  при наличии живых кампаний (фасад `hasLiveCampaigns`); экран — список живых
  кампаний с рендером по `myRole`: субъекту `🏁 Поток «{title}» · {M}/{K} ·
  {N} дн.`, ментору `🏁 Поток «{title}» · отзыв о {Имя} · {N} дн.` +
  `↩️ Главное меню`.

### Приглашения (S01) и просмотр (S07)

- **ФР-6. Приглашение S01** — подписка на `student-campaign.created`: два
  приглашения на кампанию — субъекту (текст по исходу субъекта: «завершил» /
  «забросил» / «не начал») и ментору («дайте отзыв о студенте {Имя}»);
  доставка через временную механику `ProactiveSender.invite` (ФР-6 bot-ui, до
  модуля задач), кнопка `💬 Отзывы` → сразу S03 кампании. Одно приглашение
  каждому получателю, напоминаний нет.
- **ФР-7. Просмотр S07** — из карточки потока (streams S02): кнопка `💬 Отзывы`
  видна при наличии хотя бы одного отзыва по потоку (фасад `hasReviews`);
  формат — группировка по адресатам с исходами-снапшотами; только чтение;
  пагинация ФР-1–2; `⬅️ Назад к потоку`.

## Зафиксированные решения (из сессии проектирования)

1. Приглашения — `invite` (ФР-6), замена на задачи модуля `task` — отдельная
   миграция (техдолг концепции §4.3), домен не меняется.
2. Пагинация — сначала хелпер с критериями «хорошести»; при провале критериев —
   локальная реализация в S07 (решение зафиксировать, не форсировать).
3. S07 — только чтение: кнопки перехода в живую кампанию из просмотра нет.
4. Хаб отзывов делается сразу (не бэклог) — решение владельца из спеки.
5. Лейблы исходов — собственный словарь peer-review («завершил» / «забросил» /
   «не начал», решение владельца); адресаты с исходом `in_progress`
   отображаются без лейбла исхода; сырые статусы студента и его словарь меток
   в UI отзывов не проникают.

## За рамками

- Домен, UC, фасады, репозитории — трек `peer-review-domain`.
- Анкеты в кампании («Заполнить анкету»), задачи-приглашения, напоминания —
  техдолг концепции (§4).
- Изменение карточки потока сверх кнопки «💬 Отзывы».

## Критерии приёмки

- Полный путь вручную: событие судьбы студента (`student.completed` /
  `student.abandoned`) → приглашения субъекту и ментору → написание/
  перезапись отзывов по правилам адресации v4 → ✅-маркеры → просмотр S07 с
  пагинацией из карточки потока.
- Хелпер пагинации используется в S07 и nav-tree (или зафиксировано решение
  об отказе с обоснованием).
- Истёкшее окно: заглушка на попытке писать; кнопка «Отзывы» в меню скрыта,
  если живых кампаний нет.
- `CI=true bun test`, `bun run lint`, `bun run tslint` — чисто по скоупу трека;
  спеки обновлены, tactics-draft.md удалён.
