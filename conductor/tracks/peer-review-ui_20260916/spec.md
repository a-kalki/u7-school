## Обзор

Пользовательский слой системы отзывов: приглашения по событиям судьбы
студента (`student.completed`/`student.abandoned` — сразу, «по горячим
следам»), хаб живых кампаний в главном меню, диалог написания отзывов,
постраничный просмотр отзывов потока — пагинация **готовым пагинатором**
трека pagination_20260919 (дерево программы и каталог уже листаются там).

## Функциональные требования

- **ФР-1. Пагинация S07 — готовый пагинатор** (трек pagination_20260919):
  `BotPaginator` + системный кеш `DialogCache` из core `ui/bot`; своя механика разбиения
  в этом треке не разрабатывается.
- **ФР-2. Контроллер + стори кампании** (`apps/u7-bot/src/controllers/peer-review/`):
  - **S03** список адресатов: кнопки `Студент: {Имя}` / `Ментор: {Имя}`, `✅` при
    наличии моего отзыва, шапка с названием потока и остатком дней; адресация
    v4: субъекту «завершил» — ментор + завершившиеся/ещё учащиеся соученики,
    субъекту «забросил»/«не начал» — только ментор, ментору — только субъект;
  - **S04** перезапись: экран показывает текущий текст, ввод сразу заменяет,
    кнопка `❌ Назад`;
  - **S05** ввод: тексты-подсказки по направлению (`direction`: «кто о ком») и,
    для «о менторе», — по 4-значному исходу автора (`myOutcome` из UC; скрыт
    от пользователя); валидация 10–3500 — переспрос без потери контекста
    (`errorNotify`), `⏭️ Пропустить` → S03, `/cancel`;
  - **S06** сохранение → новый экран с обновлённым списком (`✅` появился);
  - истёкшее окно — экран-заглушка «возможность закрыта» (домен отклоняет).
- **ФР-3. Хаб S02** «Мои отзывы»: декларативная `menuButtons` «💬 Отзывы» — видна
  при наличии живых кампаний (фасад `hasLiveCampaigns`; асинхронный контракт
  `Promise<MenuButton[]>` уже в core — трек outcomes, Фаза 5); экран — список живых
  кампаний с рендером по `myRole`: субъекту `🏁 Поток «{title}» · {M}/{K} ·
  {N} дн.`, ментору `🏁 Поток «{title}» · отзыв о {Имя} · {N} дн.` +
  `↩️ Главное меню` (имя субъекта — batch-UC `get-users-by-ids`).
- **ФР-4. Приглашение S01** — подписка на `student-campaign.created`: два
  приглашения на кампанию — субъекту (текст по `subjectOutcome` из события:
  «завершил и прошел»/«завершил и не прошел» — один текст; «забросил»;
  «не начал») и ментору («дайте отзыв о студенте {Имя}»);
  доставка через временную механику `ProactiveSender.invite` (ФР-6 bot-ui, до
  модуля задач), кнопка `💬 Отзывы` → сразу S03 кампании. Одно приглашение
  каждому получателю, напоминаний нет.
- **ФР-5. Просмотр S07** — из карточки потока (streams S02): кнопка `💬 Отзывы`
  видна при наличии хотя бы одного отзыва по потоку (фасад `hasReviews`);
  формат — группировка по адресатам, у автора — роль (из `direction`) и лейбл
  `authorOutcome`; только чтение; пагинация ФР-1; `⬅️ Назад к потоку`;
  имена авторов/адресатов — batch-UC `get-users-by-ids` до нарезки страниц.
- **ФР-6.** Обновить [ui-spec.md](../../../apps/u7-bot/src/controllers/peer-review/ui-spec.md)
  (пометки ✅ по реализованному) и ui-spec streams (кнопка S02); **удалить**
  `tactics-draft.md` (его решения разнесены по концепции и трекам); обновить
  §5 [концепции](../../roadmap/metrics/peer-review-system.md) при отклонениях.

## Зафиксированные решения (из сессии проектирования)

1. Приглашения — `invite` (ФР-6), замена на задачи модуля `task` — отдельная
   миграция (техдолг концепции §4.3), домен не меняется.
2. Пагинация — готовый пагинатор трека pagination_20260919 (критерии
   «хорошести» проверены там; перенос nav-tree и каталога выполнен там же).
3. S07 — только чтение: кнопки перехода в живую кампанию из просмотра нет.
4. Хаб отзывов делается сразу (не бэклог) — решение владельца из спеки.
5. Лейблы исходов — собственный 4-значный словарь peer-review («завершил и
   прошел» / «завершил и не прошел» / «забросил» / «не начал»; решения
   2026-09-20): сырые статусы студента и словарь меток stream в UI отзывов не
   проникают. Исход показывается только у автора отзыва (S07, `authorOutcome`);
   в приглашениях, кнопках и подсказках — никаких статусов и ролей участников
   (исход автора используется скрыто — выбор текста S01/S05).

## За рамками

- Домен, UC, фасады, репозитории — трек `peer-review-domain`.
- Пагинатор (ядро, бот-адаптер, кеш, перенос обрезок) — трек pagination_20260919.
- Анкеты в кампании («Заполнить анкету»), задачи-приглашения, напоминания —
  техдолг концепции (§4).
- Изменение карточки потока сверх кнопки «💬 Отзывы».

## Критерии приёмки

- Полный путь вручную: событие судьбы студента (`student.completed` /
  `student.abandoned`) → приглашения субъекту и ментору → написание/
  перезапись отзывов по правилам адресации v4 → ✅-маркеры → просмотр S07 с
  пагинацией (готовый пагинатор) из карточки потока.
- Истёкшее окно: заглушка на попытке писать; кнопка «Отзывы» в меню скрыта,
  если живых кампаний нет.
- `CI=true bun test`, `bun run lint`, `bun run tslint` — чисто по скоупу трека;
  спеки обновлены, tactics-draft.md удалён.
