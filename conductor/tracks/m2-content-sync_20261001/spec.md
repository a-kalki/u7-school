# Спека: Синхронизация контента модуля «Алгоритмика» (m2)

## 1. Обзор

Модуль «Алгоритмика» (`16b9026b-7cc6-4397-81bc-9a9791d3a76b`) был перепроектирован: старая
плотная схема из 12 проектов заменяется «спиралью» из **14 проектов (П1–П14)**.

- **П1–П5** уже доставлены в БД (`data/courses/*.json`), 45 уроков / 147 шагов.
- **П6–П8** (черновики `redesign-*`, старые П4–П6) — переработаны, в БД отсутствуют.
- **П9–П14** (старые П7–П12) — переработки нет, переходят почти без изменений.

При этом исходники `data/fullstack-js/m2-algorithm` отстали: содержат **12 старых проектов / 84 папки**
и не знают о редизайне. Из-за позиционного сопоставления `list-lessons.ts` подставляет новым урокам
чужие старые папки.

**Цель трека:** привести `data/fullstack-js/m2-algorithm` в соответствие новому учебному плану
(формат `lesson.md` + `steps.md` + `summary.md`) и довести **весь модуль m2** до `data/courses/*.json`.

## 2. Функциональные требования

1. **Перенос старья в системный `/tmp`** (только чтение, без бэкапов):
   - `data/fullstack-js/m2-algorithm` → `/tmp/m2-algorithm-old/`;
   - `redesign-m2/` → `/tmp/redesign-m2/` (источник генерации).
2. **Генерация md-папок** в `data/fullstack-js/m2-algorithm`: `pN-lM-<kebab>` строго по новому
   плану, в каждой — `lesson.md` (паспорт: заголовок, Краткое содержание, Время, Основные темы,
   Термины, Источники), `steps.md` (шаги, машиночитаемо), `summary.md`. Менторских файлов нет.
3. **П1–П5:** `steps.md` — из json (истина), `lesson.md`/`summary.md` — из черновиков
   (допустимо править). Правок в json нет.
4. **П6–П8:** md из черновиков; адаптация под решения трека (единый финальный урок, напоминания
   с П6, термины); вычитка → укладка в json **новыми uuid**.
5. **П9–П14:** md из `/tmp/m2-algorithm-old` (нумерация и имена — по новому плану), правки
   (термины, git → напоминания), вычитка → укладка в json **со старыми uuid**
   (`archived` → `published`). UC обновления нет — правка через инструмент прямого
   редактирования JSON с dry-run.
6. **Цель трека = весь контент m2 в json.** Работаем в dev; выкат в прод и обновление
   снапшота потока 7 — за рамками трека (отдельная задача при релизе).
7. **`.gitignore`-хвосты** временных файлов — зафиксировать и удалить в финале.

## 3. Нефункциональные требования

- Идемпотентность инструментов, обязательный **dry-run** перед записью.
- Git — источник отката: контент `data/courses/*.json` и `data/fullstack-js/` коммитится по батчам.
- Поток 3 (выпускники) не трогаем; его снапшот заморожен.
- Процесс: **md батча → ручная вычитка Нурболата → укладка в json → коммит** (вариант A).

## 4. Критерии приёмки

- В `m2-algorithm` есть только папки `p1…p14` нового плана; старых 84 нет.
- `steps.md` каждого урока сходится с json по составу и тексту шагов.
- Каждый батч вычитан Нурболатом.
- Весь m2 (П1–П14) присутствует в `data/courses/*.json` (П6–П14 — в статусе `published`).
- Ветка `track/m2-content-sync` содержит всю работу; `main` не тронут.

## 5. За рамками

- Модули 1, 3, 4.
- Выкат в прод, обновление снапшота потока 7, рассылка `distribute-lesson` (по отдельной отмашке).
- Правка `list-lessons.ts` / `distribute-mentor.ts`: при новой нумерации маппинг чинится сам.
- Реализация целевого Import/Export из roadmap `content-management.md` (v7) — отдельные треки.

## 6. Зафиксированные решения

- **Q1 (П6–П8):** используем готовые черновики (новые uuid); переписывание из старого не делаем.
- **Q2:** начиная с П6 финал — **один** урок (старый формат).
- **Q3:** начиная с П6 — **напоминания** (создать ветку, сделать коммит, …), без пошаговых инструкций.
- **Q4:** точечные правки → старые uuid; сильные переработки → новые uuid.
- **Формат `lesson.md`:** вариант A — компактный паспорт, без дублирования шагов.
- **Укладка:** по батчам сразу после вычитки (dev), без остановки прод-бота.
