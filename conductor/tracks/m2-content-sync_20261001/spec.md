# Спека: Модуль «Алгоритмика: ядро» (m2) — синхронизация контента, вывод П12, переименование модулей

## 1. Обзор

Модуль `16b9026b-7cc6-4397-81bc-9a9791d3a76b` («Алгоритмика») перепроектирован в «спираль» из
14 проектов (П1–П14). Трек приводит источники `data/fullstack-js/m2-algorithm` к новому плану
и доводит модуль до `data/courses/*.json`.

**Изменение рамок (2026-10-04).** Программа делится на «ядро» и «прикладную» часть; прикладной
контент выносится в отдельный будущий модуль:

- m2 переименовывается в **«Алгоритмика: ядро»** (`m2-algorithm-core`) и содержит 13 активных
  проектов: П1–П11, П13 (сортировка), П14 (сложность O);
- проект **П12 «Бизнес-утилиты»** выводится из m2: в БД остаётся его **прод-версия**
  (`v0.1.13`: 6 уроков / 32 шага, `status: archived`); переработанная 8-урочная версия удаляется
  из БД, а её md-папки `p12-*` переносятся в каталог будущего модуля;
- создаётся **модуль-пустышка «Алгоритмика: прикладное»** (`m3-algorithm-applied`, `draft`,
  без проектов, вне курса) — чтобы позиционное сопоставление каталогов и модулей в скриптах
  не ломалось.

**Снапшоты.** `CourseDs.buildSnapshot` отбирает только `published` проекты/уроки. Завершённые
потоки хранят `contentSnapshot` в своей записи и не пересобирают его, поэтому удаление ссылок
на старые проекты из `module.projects` их не ломает. Закрепляем тестами.

## 2. Функциональные требования

### 2.1 Контент m2 (13 проектов)

1. Перенос старья в `/tmp` (выполнено): оригиналы и черновики — только чтение.
2. Генерация md-папок `pN-lM-<kebab>` в m2 по плану (П1–П11, П13, П14); формат — `lesson.md`
   (паспорт) + `steps.md` (шаги) + `summary.md`, без менторских файлов.
3. **П1–П5:** `steps.md` — из json (истина), `lesson.md`/`summary.md` — из черновиков.
4. **П6–П8:** md из черновиков; новые uuid; адаптация (единый финал, напоминания, термины).
5. **П9–П11:** md из старых источников, правки (термины, git → напоминания); старые uuid
   (`archived` → `published`).
6. **П13–П14:** аналогично П9–П11; папки перенумерованы (`p13` → `p12`, `p14` → `p13`).
7. Процесс: md батча → ручная вычитка Нурболата → укладка в json → коммит.

### 2.2 Вывод П12 из m2 (архивация прод-версии)

1. Перед правкой — бэкап `data/courses/{modules,lessons,steps}.json`.
2. Проект `7af9f0e5-dd60-45b4-8b9d-1f442488c031` привести к состоянию `v0.1.13`: 6 уроков /
   32 шага, `status: archived`, состав/порядок уроков и `title` финала
   («Финальный PR и полный прогон проекта 10») — как в теге.
3. Удалить из `lessons.json`/`steps.json` 2 новых урока
   (`e6269535-7bf0-4b50-9760-ebb37a0f02e2`, `744b93e5-aca3-4cd0-9051-da9bedbe59e8`) и их шаги;
   вернуть `stepIds` общих уроков и статусы к прод-набору.
4. Ссылка на проект **удаляется** из `module.projects` m2: в модуле — только рабочие проекты.
   Уроки/шаги прод-версии остаются в `lessons.json`/`steps.json` со статусом `published`:
   политика чтения урока для ученика требует `published`, поэтому архивация сломала бы
   снапшоты прод-потоков. Контент доступен старым снапшотам по uuid урока/шага.
5. Данные 8-урочной версии из БД удаляются безвозвратно (сохраняются в md-папках и истории git).

### 2.3 Перенос П12 в будущий модуль

1. Создать каталог `data/fullstack-js/m3-algorithm-applied/`.
2. Перенести `p12-l1-*`…`p12-l8-*` из `m2-algorithm-core/` в `m3-algorithm-applied/` через
   `git mv` — имена сохраняются, незакоммиченные правки сохраняются.
3. Проекты/уроки в БД не создаются — наполнение будущего модуля отдельным треком.

### 2.4 Переименования

1. Каталоги (через `git mv`): `m2-algorithm` → `m2-algorithm-core`; `m3-html-css` → `m4-html-css`;
   `m4-dom` → `m5-dom`.
2. Папки внутри m2: `p13-*` → `p12-*`, `p14-*` → `p13-*`; нумерация папок непрерывна
   (`p1…p13`) и совпадает с позицией проекта в `module.projects`.
3. `title` модуля `16b9026b` → «Алгоритмика: ядро». Прочие поля не трогаем.

### 2.5 Модуль-пустышка «Алгоритмика: прикладное»

1. Создать модуль в `modules.json` на **3-й позиции** (между «Алгоритмика: ядро» и «HTML & CSS»).
2. Свойства:
   - `uuid` — новый;
   - `title` — «Алгоритмика: прикладное»;
   - `description` — прикладной модуль с явным акцентом на бизнес-сценарии: обработка
     входящих данных, сохранение в файл, первые консольные игры;
   - `authorId` — `8d9a56f6-51e7-49f0-ba58-2832b157e718`;
   - `targetAudience` — «Студенты, завершившие модуль «Алгоритмика: ядро»»;
   - `goal` — «Порешать алгоритмические задачи прикладного характера»;
   - `result` — «Ты сделаешь свои функции по обработке входящих данных и сохранишь их в файле,
     и по запросу вернешь результат. А также сделаешь свои первые консольные игры»;
   - `tags` — `[js, алгоритмы, практика]`;

   - `projects` — `[]`;

4. Назначение — сохранить позиционное сопоставление `readdirSync(DATA_DIR).sort()` ↔ `list-modules`
   в `list-lessons.ts` и `distribute-mentor.ts`.

### 2.6 Снапшоты потоков

1. Новые потоки (`create-stream` → `get-module-snapshot` → `CourseDs.buildSnapshot`) не включают
   `archived`-проект.
2. Завершённые потоки используют сохранённый `contentSnapshot` и не пересобирают его.
3. Добавить/расширить тесты: `buildSnapshot` исключает `archived`-проект; поток с сохранённым

### 8.2 Формат md-файлов

- **`lesson.md`** (паспорт): `# Заголовок`, `**Краткое содержание:**`, `**Время:**`,
  `**Основные темы:**`, `**Термины:**` (если есть), `### Источники`. Шаги не дублируются.
- **`steps.md`**: `# Шаги урока: <Заголовок>`, далее блоки через `---`:
  `### <Название шага>` + `**kind:** \`text\`` + тело. Порядок шагов — как в json.
- **`summary.md`**: `# <Заголовок> — краткая выжимка`, список тезисов, `[Полный конспект](./lesson.md)`.

Эталон формата — `data/fullstack-js/m4-html-css/p1-l1-how-web-works/` (бывший `m3-html-css`).

### 8.3 Инструменты

- `scripts/generate-m2-sources.ts` — генерация md из `data/courses/*.json` (модуль/уроки/шаги)
  по позиции модуля и проектов,
  режим dry-run.
- `scripts/deliver-m2.ts` — укладка/правка контента (`--create` П6–П8, `--update` П9+,
  `--check`, `--recreate` — новый проект + отвязка старого, `--recreate-lesson` — новый урок
  в существующем проекте + отвязка старого); адресация проектов по позиции;
  при расхождении шаги **отвязываются, а не удаляются** (старые снапшоты резолвят их по uuid).
  Dry-run обязателен.
- Модуль-пустышка — `create-module` (+ `enrich-module`) либо прямая запись в `modules.json`
  с dry-run и явной позицией (3-й).
- `scripts/list-lessons.ts` и `scripts/distribute-mentor.ts` читают `DATA_DIR = 'data/fullstack-js'`
  и сопоставляют каталог с модулем по позиции; корректность сохраняется новой нумерацией
  и модулем-пустышкой.
