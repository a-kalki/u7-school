# Спецификация: ActionFactory — `UiActions` и `UiRegistry`

> **Родительский документ:** [bot-ui-refactoring.md](../../bot-ui-refactoring.md), Трек 2
> **Дорожная карта:** [development-roadmap.md](../../development-roadmap.md), Релиз 1
>
> **Зависимости:** Трек 1 (bot_ui_base_20260807)

## Обзор

Механизм типизированных кросс-ссылок между стори. Каждая стори объявляет `publicActions`, контроллер собирает их, `UiRegistry` в `router.ts` объединяет и инжектит в стори через `init()`.

## Функциональные требования

1. Добавить поле `ui` в `BotUserStory` (core). Тип — `unknown`, конкретный тип задаётся через дженерик контроллера.
2. Создать `apps/u7-bot/src/ui-actions.ts`:
   - Тип `ControllerActions` — отображает `storyName → publicActions`
   - Тип `UiRegistry` — отображает `controllerName → ControllerActions`
3. Каждый стори добавляет `get publicActions()` — объект методов-фабрик колбэков.
4. Каждый контроллер собирает `publicActions` своих стори в `get publicActions()`.
5. `router.ts` собирает `UiRegistry` из всех контроллеров и инжектит в стори через `init(ui)`.
6. Кросс-ссылки между стори выполняются через `this.ui.*` (вместо `this.cbFor()`).
7. Типизация сквозная — выводится через `typeof` без дополнительных дженериков на стори.

## Нефункциональные требования

- Типизация предотвращает вызов несуществующего действия на этапе компиляции
- `tsc --noEmit` проходит без ошибок

## Критерии приёмки

- Поле `ui` доступно в каждой стори после `init()`
- `this.ui.controllerName.storyName.action(...)` работает и возвращает корректный callback-код
- Замена `cbFor()` → `this.ui.*` в существующих стори (трек 3+)
- Нет циклических зависимостей между контроллерами

## За рамками

- Реализация конкретных стори (только инфраструктура)
- Изменения в доменных слоях
