# Спецификация — Трек: Анкетные стори (bot-ui-dialog-questionnaire_20260905)

> **Материнский документ:** [bot-ui-session-architecture.md](../../bot-ui-session-architecture.md) — целевая архитектура bot-ui v4 (инварианты §3, контракты §4, рендер и валидация §5, команды §6, решения трека 1.1 §10.10–16). Трек 4 декомпозиции §9.

## Обзор

Миграция анкетных стори на контракт «Диалог и Экран»: fill, invite, render.ts.

## Функциональные требования

- Паттерн `finalize` («зафиксируй выбор → открой следующий вопрос»): текст стори пишет финальные маркеры сам, маркер ретира не используется (§5.1).
- Resume анкеты, `awaitInput`/`release` без `path`.
- Умирание takeover-подписок fill-событий → notify-текст (И3).
- `render.ts`: удаление `respondInContext`-хелперов.
- **Приглашения по варианту A** (решение владельца, ФР-6, §10.12): проактивный запуск диалога не возвращается — сервер только зовёт. `questionnaire:invite` (S01), continue-invite и abandon-warning — временный `ProactiveSender.invite(telegramId, { text, keyboard })`: кнопки штампуются seq **текущей эпохи** получателя на момент отправки; получателю без диалога транспорт открывает якорь `app/invite` (seq = 1) — приглашение не умирает; кнопка-мост `fill:resume:<id>` switch-ит диалог в fill (seq++); в тексте — подсказка /start на случай устаревшего экрана. Опция deep-link URL-кнопки (без штампа) — запасной канал. Метод `invite` и якорь — к удалению с tasks-system.
- Событие `questionnaire:start` (fill.start из каталога) — тоже вариант A: invite «начать анкету», открытие диалога — только действием пользователя.
- **Протокол «миграция без потери функциональности»** (решение владельца, ревью трека 3): до миграции — инвентаризация всех кнопок/реплик анкетных стори из `ui-spec.md` и кода → падающие тесты с точными keyboard-ассертами; миграция обязана воспроизвести каждую кнопку. Кнопочный проактив — только `invite`, никогда срезка в notify. `ui-spec.md` — источник истины: не подгоняется под реализацию; расхождение — вопрос владельцу.
- Валидация ответов — `errorNotify` (kind warn): переспрос без перерисовки экрана, `awaitInput`-контекст живёт.
- Команды: `/cancel` активного fill — сброс себя (контракт `U7BotUiStory`), прочее — дефолт pipe (`pass`); именных обработчиков нет.

## Нефункциональные требования

- Правило «трек уменьшает» (§9): никаких адаптеров совместимости.

## Критерии приёмки

- Скоуп трека целиком на новом контракте, тесты/линт/tsc скоупа зелёные; вне скоупа допустим красный tsc.
- Grep по скоупу: не осталось `BotResponse`/`respondInContext`/takeover-подписок.

## За рамками

- Mentor-стори (трек 5); sweep-механика домена questionnaire (не меняется).
- Удаление старых типов (трек 5); персистентность (трек 6).
