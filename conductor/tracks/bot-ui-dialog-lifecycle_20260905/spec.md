# Спец: Жизненный цикл диалога — операция входа, команды, kind-уведомления

**Трек 1.1** (доработка ядра `bot-ui-dialog-core`). Источник: [bot-ui-dialog-lifecycle.md](../../bot-ui-dialog-lifecycle.md) + решения владельца (сессия 2026-09-05).

## Обзор

Ядро контракта «Диалог и Экран» (core `packages/core/src/ui/bot/*`, транспорт `apps/u7-bot/src/infra/bot-transport.ts`) дорабатывается по трём осям: (1) явная операция входа в диалог и явное состояние «диалог не открыт» — устранение системной причины рассинхрона `seq` (проблема 1); (2) единый вход команд `handleCommand` — механизм в core, словарь и UX в u7-bot; (3) единый словарь kind-уведомлений для проактива и диалоговых реплик. Проблема 2 (проактивный запуск диалога) решена решением владельца: вариант A — диалог запускается только действием пользователя; легаси-проактив лечится модулем tasks-system, ядро для этого не меняется.

## Функциональные требования

**ФР-1. Явное состояние «диалог не открыт».** `BotSession.dialog?` — `undefined` означает «не открыт». Транспорт больше не создаёт ленивую сессию с фиктивным диалогом меню (`INITIAL_DIALOG_PATH`, `seq=0` удаляются).

**ФР-2. Единая операция входа.** `#enterDialog(session, path, mode)` — единственное место инкремента `seq`:

- `switch` (мосты, delegate): `path ≠` текущему → `seq+1`, input сброс; тот же path → продолжение без изменений;
- `reopen` (/start, /cancel): всегда `seq+1`, в т.ч. «меню → меню».

**ФР-3. Валидация кнопок без исключений.** Валидна ⟺ диалог открыт ∧ штамп == seq. Диалог не открыт → alert «Наберите /start»; штамп не совпал → alert «Экран устарел — нажмите /start». `seq` сохраняет роли: рендер-политика (`ownerSeq`), дубль-защита при смене эпох, легаси-штамп приглашения «на момент отправки».

**ФР-4. Единый вход команд.** Транспорт: один `handleCommand(ctx)` для всех слэш-команд — перехват в едином `message:text`-хендлере (фильтр `/`-префикса), без поимённой grammy-регистрации и без списка команд в рантайме. Core `BotUiApp.handleCommand(cmd, tgId, session)` — конвейер: (1) appCommand-хук приложения (в u7 → appController: системные/админ-команды, `/help` на меню → main-help), (2) активная стори `story.handleCommand` (обобщение `handleHelp`/`handleCancel`; `null` = «не моё»), (3) core-дефолты: start → reopen(menu) + welcome-хук; help → общий fallback; cancel → доменная очистка → reopen(menu). u7-bot: словарь команд + welcome-меню с описаниями (текущая логика); задел под `/tasks`.

**ФР-5. Kind-уведомления.** `NoticeKind = 'notify' | 'info' | 'warn'`; `NotificationPayload { kind?, text }` (дефолт `'notify'`, замена `tone`); `DialogResponse.info = { text, kind? }` (дефолт `'info'`, вместо `Screen`); единая таблица рендера 🔔/ℹ️/⚠️ в транспорте для обоих каналов.

**ФР-6. Легаси-контракт приглашений.** Документируется в архитектуре: кнопки проактивного приглашения валидны только у получателя с открытым диалогом той же эпохи (штамп на момент отправки); получателю без диалога — текст с подсказкой /start (опция deep-link URL-кнопки — трек 4). Реализация — трек 4; метод заявлен к удалению с приходом tasks-system.

**ФР-7. Документация контракта.** Обновить [bot-ui-session-architecture.md](../../bot-ui-session-architecture.md) (§4 состояние/типы, §5 рендер и валидация, §6 команды, §10 решения) и [bot-ui-dialog-lifecycle.md](../../bot-ui-dialog-lifecycle.md) (пометка о решениях).

**ФР-8. Обновление последующих треков.** Спеки/планы треков 2–5 (nav, learning, questionnaire, mentor) приведены в соответствие решениям: info-kind, `handleCommand` у сторей, приглашения анкет по варианту A.

## Нефункциональные требования

- Скоуп ядра зелёный: tsc/biome/тесты `packages/core/src/ui/bot/*` и `bot-transport` (+ его тесты).
- Прикладные стори не мигрируются — остаются заявленно красными до своих треков.
- Никаких адаптеров совместимости; новые механики не ломают уже мигрированные части ядра.

## Критерии приёмки

- Инвариант-тесты: первый `/start` (seq=1, кнопки живы), повторный `/start` (reopen, не no-op), кнопка до `/start` → «Наберите /start», дубль-тап по мосту (второй — alert), delegate «меню→меню» и кросс-контроллерный, `/help` три уровня (стори → main-help на меню → fallback), `/cancel`, notify/info не трогают сессию, kind-рендер обоих каналов, команды при не открытом диалоге (`/help`, `/cancel` работают без фиктивной сессии).
- Документация обновлена; треки 2–5 обновлены; легаси-зоны заявлены.

## За рамками

Миграция прикладных сторей (треки 2–5), персистентность сессий (трек 6), модуль tasks-system, удаление старых типов (трек 5), реализация приглашений анкет (трек 4).
