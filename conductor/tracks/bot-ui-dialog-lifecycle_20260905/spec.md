# Спец: Жизненный цикл диалога — операция входа, команды, kind-уведомления

**Трек 1.1** (доработка ядра `bot-ui-dialog-core`). Источник: [bot-ui-dialog-lifecycle.md](../../bot-ui-dialog-lifecycle.md) + решения владельца (сессия 2026-09-05).

## Обзор

Ядро контракта «Диалог и Экран» (core `packages/core/src/ui/bot/*`, транспорт `apps/u7-bot/src/infra/bot-transport.ts`) дорабатывается по трём осям: (1) явная операция входа в диалог и явное состояние «диалог не открыт» — устранение системной причины рассинхрона `seq` (проблема 1); (2) единый вход команд `handleCommand` — механизм в core, словарь и UX в u7-bot; (3) единый словарь kind-уведомлений для проактива и диалоговых реплик. Проблема 2 (проактивный запуск диалога) решена решением владельца: вариант A — диалог запускается только действием пользователя; легаси-проактив лечится модулем tasks-system, ядро для этого не меняется.

## Функциональные требования

**ФР-1. Явное состояние «диалог не открыт».** `BotSession.dialog?` — `undefined` означает «не открыт». Транспорт больше не создаёт ленивую сессию с фиктивным диалогом меню (`INITIAL_DIALOG_PATH`, `seq=0` удаляются).

**ФР-2. Единая операция входа.** `#enterDialog(session, path, mode)` — единственное место инкремента `seq`:

- `switch` (мосты, delegate): `path ≠` текущему → `seq+1`, input сброс; тот же path → продолжение без изменений;
- `reopen` (/start, /cancel): всегда `seq+1`, в т.ч. «меню → меню».

**ФР-3. Валидация кнопок без исключений.** Валидна ⟺ диалог открыт ∧ штамп == seq. Диалог не открыт → alert «Наберите /start»; штамп не совпал → alert «Экран устарел — нажмите /start». `seq` сохраняет роли: рендер-политика (`ownerSeq`), дубль-защита при смене эпох, легаси-штамп приглашения «на момент отправки».

**ФР-4. Единый вход команд — трёхуровневый pipe (ревизия фазы 2.1, решения владельца 2026-09-06).** Единственный обработчик команд на всех уровнях — `handleCommand` (uiApp → uiController → uiStory); именных обработчиков (`handleHelp`/`handleCancel`/`handleWelcome`/`handleStart`/appCommand-хук) нет ни на одном уровне.

- **Транспорт**: один `handleCommand(ctx)`, перехват `/`-префикса в едином `message:text`-хендлере; сам парсит конверт `CommandUpdate { command, args, telegramId, name?, username? }` (`@botname` отброшен, первый токен команда, `args` — вся строка после команды, стори сама решает как его парсить). Без поимённой grammy-регистрации, реестра команд и `setMyCommands`.
- **Core (ядро имён команд не знает)**: реакция едина для стори и контроллера —
  `CommandReaction = {reaction:'pass'} | {reaction:'continue', notice?} | {reaction:'stop', response}`
  (pass — не моё; continue — моё, обход продолжается, только текст-вклад; stop — терминал: info-only / screen / пусто).
  - `BotStory.handleCommand` — дефолт `pass`;
  - `BotController.handleCommand` — дефолт: pipe своих стори, агрегация: первый `stop` → `stop`; склейка `notice`-вкладов → `continue`; пусто → `pass`;
  - `BotUiApp.handleCommand` — резолвит актора, pipe контроллеров (активный первым, далее по порядку регистрации), агрегат: `stop` → `DialogResponse` (накопленные notices — info-нотисом над ответом); только `continue` → `{info: склейка}`; все `pass` → `null` (дефолты — уровень приложения).
- **u7UiApp (`U7BotUiApp.handleCommand`)**:
  - `/start` — НЕ через pipe: идемпотентная гост-регистрация → лог top-menu → `reopen(menu)` → welcome-экран; клавиатура — сбор `menuButtons(actor)` у всех стори через контроллеры (декларативные данные: кнопка, описание, приоритет — не обработчик);
  - прочие → pipe (`super`); `null` → дефолты u7: `/help` → общий help (header + описания из `menuButtons`); `/cancel` → `reopen(menu)` + короткое меню; прочее → info «Неизвестная команда».
- **Контракт u7-стори (`U7BotUiStory`)** — знает свой диалог-путь, `isActive(session)`:
  - `start` → исключение (сторож: `/start` обрабатывает uiApp, до стори не доходит);
  - `help` → активна → `stop{info: контекстная справка}`; неактивна → `pass` («вызов только активной» достигается pipe: неактивные не опрашиваются после stop);
  - `cancel` → активна → сброс себя + `stop{info: «Отменено. Наберите /start» или экран меню}` — только ответ стори; неактивна → `pass` без побочных действий (решение владельца: сброс только активной, «обход всех» не нужен — глобальный сброс диалога на меню делает uiApp);
  - дефолт прочее → `pass`.
- **app-контроллер**: `handleCommand`-override: `/log_level` → не-админ `stop{}` (тишина), админ `stop{info}` (parseLogLevel, тексты прежние); прочее → `super` (свои стори). `menuButtons`: кнопка «Помощь»; `CommunityStory` — кнопка сообщества.
- Поведение для пользователя неизменно: `/start` → welcome-меню; `/help` → контекстный стори или общий; `/cancel` → ответ активной или меню; `/log_level` — как было.

**ФР-5. Kind-уведомления.** `NoticeKind = 'notify' | 'info' | 'warn'`; `NotificationPayload { kind?, text }` (дефолт `'notify'`, замена `tone`); `DialogResponse.info = { text, kind? }` (дефолт `'info'`, вместо `Screen`); единая таблица рендера 🔔/ℹ️/⚠️ в транспорте для обоих каналов.

**ФР-6. Легаси-контракт приглашений.** Документируется в архитектуре: кнопки проактивного приглашения валидны только у получателя с открытым диалогом той же эпохи (штамп на момент отправки); получателю без диалога — текст с подсказкой /start (опция deep-link URL-кнопки — трек 4). Реализация — трек 4; метод заявлен к удалению с приходом tasks-system.

**ФР-7. Документация контракта.** Обновить [bot-ui-session-architecture.md](../../bot-ui-session-architecture.md) (§4 состояние/типы, §5 рендер и валидация, §6 команды, §10 решения) и [bot-ui-dialog-lifecycle.md](../../bot-ui-dialog-lifecycle.md) (пометка о решениях).

**ФР-8. Обновление последующих треков.** Спеки/планы треков 2–5 (nav, learning, questionnaire, mentor) приведены в соответствие решениям: info-kind, `handleCommand` у сторей, приглашения анкет по варианту A.

## Нефункциональные требования

- Скоуп ядра зелёный: tsc/biome/тесты `packages/core/src/ui/bot/*` и `bot-transport` (+ его тесты).
- Прикладные стори не мигрируются — остаются заявленно красными до своих треков.
- Никаких адаптеров совместимости; новые механики не ломают уже мигрированные части ядра.

## Критерии приёмки

- Инвариант-тесты: первый `/start` (seq=1, кнопки живы), повторный `/start` (reopen, не no-op), кнопка до `/start` → «Наберите /start», дубль-тап по мосту (второй — alert), delegate «меню→меню» и кросс-контроллерный, pipe-конвейер (триада реакций, активная первой, первый `stop` побеждает, склейка continue-нотисов, все `pass` → дефолт), `/help` (контекст активной — stop; меню → общий из menuButtons), `/cancel` (ответ активной — stop и только ответ; меню → короткое меню), `/log_level` (админ/не-админ), сбор `menuButtons` для welcome и описаний, notify/info не трогают сессию, kind-рендер обоих каналов, команды при не открытом диалоге (`/help`, `/cancel` работают без фиктивной сессии).
- Документация обновлена; треки 2–5 обновлены; легаси-зоны заявлены.
