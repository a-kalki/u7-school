# Спецификация: Программа модуля — drill-down навигация

**Тип:** feature
**Трек:** `module-program-nav_20260928`

## Обзор

Ввести единую механику **drill-down навигации** по контенту модуля и применить её в двух
местах:

- **Студент** — раздел «Моя учёба» → `📂 Уроки` (сейчас ручное дерево `nav-tree`).
- **Ментор** — карточка своего потока → `📖 Программа модуля` (сейчас `📖 Программа курса`,
  плоское дерево проектов/уроков без шагов).

Общее ядро навигации переиспользуется, различаются только «детали роли»: у студента —
статусы и доступность шагов, у ментора — чтение всего без статусов. `▶️ Продолжить учёбу`
(раздел прохождения) не меняется.

## Функциональные требования

**FR-0 (spec-first).** Реализация начинается с обновления `ui-spec.md` (learning, streams):
целевые экраны, кнопки, условия видимости и callback-адреса фиксируются в спецификации
ДО кода. `ui-spec.md` — отправная точка для последующих треков, устаревшие описания
экранов/кнопок недопустимы.

**FR-1. Уровни и карточки.** Навигация — по лестнице `модуль → проект → урок → шаг`,
каждый уровень — карточка:

- **Карточка модуля:** список проектов (жирным, кнопки с номерами `1.`, `2.`, …);
  под каждым проектом — его уроки обычным списком (для понимания состава следующего уровня).
- **Карточка проекта:** список уроков (жирным, нумерованные кнопки); под каждым уроком —
  заголовки его шагов.
- **Карточка урока:** одноуровневый список шагов (нумерованные кнопки для доступных шагов).
- **Карточка шага:** тело шага (заголовок, разделитель, код/текст).

**FR-2. Пояснения уровня.** На каждой карточке — подпись «где я» и «из чего состоит»:
например «Модуль состоит из N проектов», «Проект состоит из N уроков».

**FR-3. Навигация.**
- `◀️/▶️` — листание соседей **в пределах родителя** (последний урок проекта → следующего
  урока нет; на границе кнопка отсутствует).
- `⬅️ Назад` — на уровень выше (шаг → урок → проект → модуль).
- Кнопки уровня — по номерам, соответствующим списку.

**FR-4. Студент.**
- Все проекты и уроки видны всегда; у каждого пункта — статус
  `✅` пройден / `▶️` текущий / `🔒` закрыт и счётчик прогресса `(N/M)`.
- Вход в карточку шага разрешён только для **пройденных + текущего**; непройденный шаг —
  только заголовок со статусом, без кнопки входа.
- Листание шагов — по пройденным + текущему; на текущем «следующий» исчезает.
- Карточка шага — **только просмотр**: статус `▶️ В процессе` (текущий) / `✅` (пройденный),
  без кнопки «Выполнено».
- `▶️ Продолжить учёбу` в хабе — без изменений: открывает текущий шаг в разделе прохождения
  (`step-view`), где остаётся кнопка `✅ Выполнено`.

**FR-5. Ментор.**
- `📖 Программа курса` переименовывается в `📖 Программа модуля`.
- Та же карточная навигация, но **без** статусов, иконок, счётчиков и прогресса.
- Все шаги открыты, только чтение.
- Доступно владельцу потока / ADMIN (`StreamPolicy`).

**FR-6. Публичная карточка потока (S02).** Та же drill-down, но тела шагов недоступны —
только заголовки. Доступ к телам регулируется существующей `StepPolicy` (пройденные+текущий
для студента, всё для владельца/ADMIN); новых правил не вводится.

**FR-7. Общее ядро.** Навигация абстрагирована:
- модель карточки уровня (`NavLevel`) с детьми, номерами, статусами, мета и адресами
  `prev`/`next`/`back`;
- единый presenter: `NavLevel` → текст MarkdownV2 + клавиатура;
- единый рендер тела шага на базе `formatStepMessage` с режимами `student` / `readOnly`;
- единый формат адреса уровня со стабильными id (без индексов `phaseIdx`/`projectIdx`);
- резолверы контекста: источник `stream` (студент, ментор).

Контракт и каркас — в [conductor/guides/drill-down-navigation.md](../../guides/drill-down-navigation.md).

**FR-8. Выпиливание старого.** Удалить ручное дерево `#formatTreeBody` в `nav-tree` и
inline-рендер программы; проверить и убрать `tree-renderer`, если не останется потребителей;
не тащить `pagedScreen` в навигацию карточек.

## Нефункциональные требования

- Тексты — только через `md` (MarkdownV2), заголовки экранируются.
- Права — через `Policy`-объекты, без ручных проверок ролей.
- Кросс-контроллерные переходы — через `Routes`.
- Ноль новых query-UC: используются `get-stream`, `get-step`, `get-steps-by-lessons`
  с проброшенным `actor`.

## Критерии приёмки

- Студент: хаб → `📂 Уроки` → карточки модуля/проекта/урока/шага с нумерацией, статусами,
  листанием; в непройденный шаг попасть нельзя; на карточке шага нет «Выполнено».
- Ментор: карточка своего потока → `📖 Программа модуля` → все шаги читаются, статусов нет.
- `▶️ Продолжить учёбу` работает как раньше.
- `bun run lint`, `bun run tslint`, `bun test` — зелёные.

## За рамками

- Раздел прохождения (`step-view`: `complete-step`, переходы, завершение потока) — не меняется,
  только переиспользует общий рендер тела шага.
- Каталог курсов — отдельный трек `course-catalog-nav_20260928`.
- Создание и правка контента — вне scope.
