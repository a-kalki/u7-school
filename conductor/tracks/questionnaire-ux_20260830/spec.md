# Спецификация: UX анкет — маркировка выбора, редактирование на месте

## Обзор
Движок анкет написан до внедрения стандартных UI-возможностей бота (`editMessage`, удаление клавиатур у предыдущих сообщений, паттерны `editOrSend`/`respondInContext`). Сейчас каждый выбор порождает новое сообщение, радио-варианты не маркируются, история «вопрос–ответ» замусоривается. Трек приводит заполнение анкет к стандартному UX транспорта.

## Функциональные требования

### FR-1: Маркировка одиночного выбора (radio)
- При выборе варианта в вопросе с одиночным выбором сообщение с вопросом **редактируется** (editMessage): у выбранного варианта появляется маркер `(x)`, клавиатура вариантов **удаляется**.
- Затем следующий вопрос отправляется **новым сообщением** (sendMessage) — пользователь видит историю «вопрос → выбранный ответ».
- Автопереход сохраняется: кнопка «Далее» для одиночного выбора не появляется.

### FR-2: Мультивыбор — редактирование на месте
- Тоггл варианта (выбор/снятие) **редактирует то же сообщение**: маркеры `[x]`/`[ ]` обновляются, клавиатура остаётся.
- Кнопка «Далее» рендерится **только если выбран хотя бы один вариант**; если пользователь снял все варианты — кнопка «Далее» исчезает из отредактированного сообщения.
- Кнопка «Далее»: текущее сообщение редактируется — финальные маркеры `[x]`, **клавиатура удаляется**; следующий вопрос отправляется новым сообщением.

### FR-3: Унификация с возможностями BotResponse
- Сторя анкеты использует стандартные механизмы: комбинированный `BotCommand` (`editMessage` + `sendMessage` в одной команде), `session.lastBotMessage` — вместо унаследованных собственных решений.
- Поведение соответствует описанию из /help: после выбора кнопки клавиатура убирается, экран остаётся чистым.
- Проактивные сценарии (старт по событию, приглашение, resume после таймаута) — без регрессий: где `messageId` недоступен, остаётся `sendMessage`.

## Нефункциональные требования
- Обновить unit-тесты `fill.story` под контракты editMessage/sendMessage.
- Помимо unit-тестов — интеграционные и e2e тесты новых пользовательских сценариев в модуле u7-bot (по styleguide `conductor/code_styleguides/bot-test.md`).
- Сохранить MarkdownV2-безопасность (в transport уже есть fail-fast проверка).

## Критерии приёмки
1. Радио: выбор → `(x)` в отредактированном сообщении, кнопки убраны → новый вопрос новым сообщением.
2. Мульти: тогглы редактируют сообщение на месте (кнопки живы); «Далее» только при ≥1 выбранном варианте; при «Далее» кнопки убраны, маркировки видны → новый вопрос новым сообщением.
3. `/cancel`, приглашения, предупреждение о брошенной анкете, завершение — работают как раньше.
4. Likert-анкеты — проверить на регрессии (если используют общий рендер — адаптировать аналогично).

## За рамками
- Изменение текстов и содержимого самих анкет (пулы вопросов).
- Переработка доменного движка анкет (типы `QuestionnaireActionResponse` остаются).
