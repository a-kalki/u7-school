# Спека: Модуль «Алгоритмика: прикладное» — бизнес-утилиты и HTTP-сервис

## 1. Обзор

Модуль **«Алгоритмика: прикладное»** (`uuid fe37c988-13b8-4c80-964a-5d0d98e86885`,
каталог `data/fullstack-js/m3-algorithm-applied`, `status: draft`, вне `course.phases`)
наполняется учебным материалом двух проектов:

- **П1 «Бизнес-утилиты»** — разбор входных данных и сериализация в строку
  (`getQueryParams`, `parseUrl`, `groupBy`, файлы и форматы, `toCSV`, `fromCSV`).
- **П2 «HTTP-сервис»** — персистентность (`saveToFile`/`loadFromFile`), знакомство
  с локальным сервером (`Bun.serve`, роуты), реализация обработчиков с валидацией
  и моками, запуск и ручная проверка.

Инфраструктурный код (серверная заготовка) и учебный материал создаются **в одном треке**.
Модуль остаётся `draft`. **Аркада** (движок, рендереры, игры, FSM) — отдельный будущий трек.

**Предусловие.** Трек `m2-content-sync` закрыт: ветка `main` (`v0.2.0`), весь контент
m2 в `data/courses/*.json`, md `p12-*` перенесены в `m3-algorithm-applied`. Новый трек
ведётся в отдельной ветке от текущего `main`; работа соло, мердж локальный, без PR.
В рабочем дереве есть незакоммиченные правки владельца — их не смешивать с работой трека.

## 2. Функциональные требования

### 2.1 Структура модуля

Существующие md `p12-l1…l8` в `m3-algorithm-applied/` переиспользуются и **перенумеровываются**
под нумерацию проектов модуля (`p1`/`p2`).

**П1 «Бизнес-утилиты»** (папки `p1-l*`, 6 уроков + финал):

| № | Папка | Тема | Источник |
|---|---|---|---|
| 1 | `p1-l1-function-get-query-params` | `getQueryParams` | `p12-l1` |
| 2 | `p1-l2-function-parse-url` | `parseUrl` | `p12-l2` |
| 3 | `p1-l3-function-group-by` | `groupBy` | `p12-l3` |
| 4 | `p1-l4-files-and-formats` | Файлы, форматы и синхронный ввод-вывод | `p12-l4` |
| 5 | `p1-l5-function-to-csv` | `toCSV` | `p12-l5` |
| 6 | `p1-l6-function-from-csv` | `fromCSV` | `p12-l6` |
| 7 | `p1-l7-final-pr-and-review` | Финал П1: прогон + PR + code review + merge | `p12-l8` (переработать) |

**П2 «HTTP-сервис»** (папки `p2-l*`, 5 уроков + финал):

| № | Папка | Тема |
|---|---|---|
| 1 | `p2-l1-save-load-file` | `saveToFile` / `loadFromFile` (перенос `p12-l7`) |
| 2 | `p2-l2-server-intro` | Введение в сервер: HTTP, запрос/ответ, curl и браузер, `Bun.serve`, роуты `/create` и `/get`, передача полного url/path в обработчик |
| 3 | `p2-l3-mocks` | Моки: изоляция внешних зависимостей (теория и практика) |
| 4 | `p2-l4-handlers-create-get` | Реализация обработчиков `/create` и `/get`: бизнес-требования, валидация, тесты |
| 5 | `p2-l5-run-and-manual-test` | Интеграция в серверную инфраструктуру, запуск, ручной тест |
| 6 | `p2-l6-final-pr-and-review` | Финал П2: полный прогон + PR + code review + merge |

### 2.2 Серверная заготовка и контракт

- Обёртка — **`Bun.serve`** (нативный, без Elysia), два роута: **GET** `/create?...`
  и **GET** `/get?...`.
- **В уроке `p2-l2-server-intro` обёртка выдаётся полностью** кодом: `Bun.serve`, роуты,
  и — явно кодом — **как передаётся полный `path`/url в обработчик**. Обработчик сам парсит
  запрос (в уроке отдельно показываем, что Bun умеет парсить params сам, но заготовка
  отдаёт сырой путь — чтобы студент применил свой `getQueryParams`).
- **В задаче (`p2-l4`) обёртка повторно не выдаётся** — студент пишет только
  функции-обработчики.
- Регистрация обработчиков студентом:
  ```js
  runServer({
    '/create': handleCreate,
    '/get':    handleGet,
  });
  ```
- **`/create`**: `getQueryParams` → **валидация** → при ошибке ответ-ошибка
  (в файл ничего не пишется) → при успехе запись добавляется в `data.csv`
  (`toCSV` + `saveToFile`).
- **`/get`**: `loadFromFile` + `fromCSV` → отдаётся JSON.
- Данные — **один файл `data.csv` со списком записей**.
- **Задание формулируется «на бизнес-языке»**: назначение API, что делают, **пути отказа**,
  что и в каком виде возвращают, критерии приёмки.
- **Вся работа студента покрывается тестами** (TDD).

### 2.3 Моки

Отдельный урок `p2-l3-mocks`: что такое моки, какую проблему решают, виды/инструменты
(`mock`, `fn`, `spyOn`, …). Примеры: мок **файлового модуля целиком** и мок **своих
`loadFromFile`/`saveToFile`** — чтобы тесты обработчиков не трогали реальный диск.

### 2.4 Формат md

`lesson.md` (паспорт) + `steps.md` (шаги) + `summary.md`; термины урока, напоминания.
Mentor-файлы не создаются (по общим правилам `lesson-design.md`). Эталон формата —
`data/fullstack-js/m4-html-css/p1-l1-how-web-works/`.

### 2.5 Инфра-код

Вся серверная заготовка живёт **текстом в уроках-шагах** (kind `code`/`text`):
отдельной доставки файла студенту в системе нет. Студент копирует заготовку себе
и пишет обработчики.

### 2.6 Укладка в БД

- **Укладка — проектом целиком.** Проект (все его уроки и шаги) попадает в json за один
  заход и только после вычитки его md. Нельзя уложить сначала `l1`, а остальные уроки —
  в другой фазе. За один заход — один или несколько проектов.
- Проекты П1/П2 и уроки/шаги укладываются в `data/courses/{modules,lessons,steps}.json`
  (модуль `draft`, вне `course.phases`).
- Инструменты — с обязательным **dry-run**; перед правкой `data/courses/*.json` — бэкап
  или опора на git (по решению владельца).
- **Временные скрипты укладки в коммиты не попадают**: либо добавляются в `.gitignore`,
  либо удаляются до коммита.

### 2.7 Поток работы

Для каждого батча: **генерация md → вычитка и правка владельцем в md → укладка проекта
целиком в json → коммит.**

## 3. Нефункциональные требования

- Ветка — от текущего `main`; разработка соло, **мердж локальный, без PR**.
- Не смешивать работу трека с незакоммиченными правками владельца в рабочем дереве.
- `bun run check` зелёный (для скриптов/тестов); контент — md/json.
- Русский язык, без `$T1`-подобных шаблонных переменных, файлы студента в kebab-case.
- Git-флоу студента в уроках сохраняется: каждый проект заканчивается
  проверкой + PR + code review + merge (`Q10`).
- **В финале трека — ревизия мусора**: временные/черновые файлы, мёртвые ссылки,
  хвосты `.gitignore`; лишнее удаляется.

## 4. Критерии приёмки

- В модуле «Алгоритмика: прикладное» созданы проекты П1 (7 уроков) и П2 (6 уроков)
  с уроками и шагами в `data/courses/*.json`; модуль остаётся `draft`.
- md обоих проектов лежат в `data/fullstack-js/m3-algorithm-applied/` (`p1-*`, `p2-*`).
- В `p2-l2-server-intro` показаны: `Bun.serve`, роуты `/create` и `/get`, передача полного
  url/path в обработчик; в `p2-l4` заготовка не дублируется.
- Задание в `p2-l4` сформулировано на бизнес-языке, содержит валидацию и критерии приёмки;
  вся работа покрыта тестами; моки освещены в `p2-l3-mocks`.
- `bun run list-lessons 3` показывает структуру модуля.
- Ветка отдельная от `main`; `bun run check` зелёный.

## 5. За рамками

- **Аркада** (движок `engine.js`, рендереры, игры, FSM, тики) — отдельный трек.
- Регистрация «Алгоритмика: прикладное» в `course.phases` и публикация модуля.
- Выкат в прод.

- **Q8.** П1 включает `toCSV`/`fromCSV`; сохранение (save/load) — в П2.
- **Q9.** Всё (заготовка) — в уроках-шагах; доставки файлов нет.
- **Q10.** Каждый проект заканчивается проверкой + PR + code review + merge.
- **Q11.** Разработка трека — соло, локальный мердж, без PR.

- **Q18.** Временные скрипты укладки в коммиты не попадают.
- **Q19.** В финале — ревизия и удаление мусора.
