### Решения владельца по ходу вычитки (закреплять в соответствующих фазах)

- **П2, новый урок `p2-l2-file-crud-objects`.** После выдачи двух базовых функций
  работы с файлами (`saveToFile`/`loadFromFile`, урок `p2-l1`) студенты **сами** реализуют
  функции добавления нового объекта в файл, обновления объекта и чтения (поиска) объекта.
  Урок — **одно задание-объяснение на человеческом бизнес-языке** + критерии приёмки.
  Входные данные, тестовые случаи и тесты студенты пишут сами (готовых не давать).
  Сдвигает остальные уроки П2: сервер → `p2-l3`, моки → `p2-l4`, обработчики → `p2-l5`,
  запуск → `p2-l6`, финал → `p2-l7` (итого П2 = 7 уроков).
- **П2, API-роуты — не два, а пять (CRUD + list).** Роуты сервиса: `get`, `list`,
  `create`, `update`, `delete` (вместо прежних двух `/create` и `/get`).
  В финале П2 явно **объяснить студенту, что он сделал CRUD** (create/read/update/delete,
  где read = `get` + `list`).
- **П1, `p1-l7` переработан.** Вместо готового бизнес-сценария — **задание** с входными
  данными (строка URL + CSV-строка заказов), разложенное по 4 шагам: разобрать URL и получить
  `orderId` → восстановить объекты из CSV (`fromCSV`) → найти заказ по `id` → вернуть JSON.
  Есть критерии приёмки; тесты студент пишет сам.
