# Спецификация: Снятие с учёбы за бездействие, кик из группы, фильтр в карточке студентов

## Обзор
Проактивная система ухода за бездействующими студентами: ежедневный job отслеживает студентов (включая записавшихся, но не начавших), уведомляет их и менторов; ментор снимает студента с учёбы с подтверждением. Любой уход студента (самовыход или решение ментора) кикает его из Telegram-группы потока. Карточка студентов по умолчанию показывает только активных.

## Терминология (закрепляется в коде и документации)
**«Снять с учёбы»** — основной термин вместо «отчислить». Суть: мы не «отчисляем за несоответствие критериям», а «убираем тех, кто перестал заниматься добровольно».
- Кнопка ментора: «Снять с учёбы»; сообщение студенту: «Ты снят с учёбы из-за длительного отсутствия активности».
- Статус в UI: «Выбыл».
- В коде: ucLabel, docstring, тексты стори. Доменные сущности (`abandoned`, `mark-abandoned`) НЕ переименовываются.

## Функциональные требования

### FR-1: Job мониторинга бездействия
- Расписание: ежедневно в **19:00 UTC** (00:00 по Казахстану), `JobSchedule dailyAt`.
- Отслеживает студентов в статусах **active и enrolled**.
- Бездействие = время с последней активности (последний шаг) или, если шагов нет, **с даты зачисления** (`enrolledAt`).
- **≥5 дней** → уведомление студенту: «Вы уже не занимаетесь N дней, после 7 дней бездействия ментор может снять вас с учёбы за бездействие» + кнопка **«Покинуть учёбу»**.
- **≥7 дней** → уведомление ментору потока: «Студент A из группы B не занимался N дней» (+ строка «уведомления были ранее отправлены», если студенту слались предупреждения) + кнопка **«Снять с учёбы»**.
- Периодичность: студенту — с 5-го дня и далее **через день** (5, 7, 9…); ментору — с 7-го и далее **через день** (7, 9, 11…); пока студент не начал учиться или не снят с учёбы.
- Возобновление учёбы сбрасывает цепочку уведомлений.

### FR-2: Константы порогов
- Все пороги — **именованные константы в файле job'а**: `WARN_AFTER_DAYS = 5`, `REMOVE_AFTER_DAYS = 7`, `NOTICE_EVERY_DAYS = 2`.
- Задел на будущее: значения могут уехать в конфиг или поле потока (ментор задаёт своё), константы станут значением по умолчанию.

### FR-3: Типизированный маркер уведомлённости
- В агрегате Student хранится отметка об отправленных уведомлениях: **тип** (enum; сейчас один вид — предупреждение о бездействии; отдельные типы для студент/ментор) + дата последней отправки.
- Даёт idempotentность повтора «через день» и проверяемость строки «уведомления были ранее отправлены».

### FR-4: Самовыход «Покинуть учёбу»
- Кнопка → **confirm-диалог** → `drop-student` (abandoned, who=self, cause=voluntary).
- Доступно из статусов **active и enrolled** (расширение `drop()` — сейчас только из active).
- После самовыхода → **уведомление ментору**: «Студент A покинул учёбу».

### FR-5: Снятие с учёбы ментором
- Кнопка «Снять с учёбы» → **confirm-диалог** → `mark-abandoned` (cause=inactivity).
- Доступно для **active и enrolled** (расширение `markAbandoned()`).
- После снятия ментором → **уведомление студенту** с мягкой формулировкой («Ты снят с учёбы из-за длительного отсутствия активности»).

### FR-6: Кик из Telegram-группы
- При любом уходе студента (самовыход или решение ментора) бот **мягко удаляет** его из группы потока: `banChatMember` + `unbanChatMember` (может вернуться по инвайту).
- Механика: публикуется доменное событие **`student.abandoned`** (сейчас не публикуется) → подписка/ER в u7-bot → кик через grammy Api по `stream.telegramGroupId`.
- Нет группы / бот не админ → кик пропускается с записью в лог, снятие с учёбы завершается успешно.

### FR-7: Уведомление ментору о выходе из группы
- Когда студент **самостоятельно покидает** Telegram-группу потока (`chat_member`: left) — ментору приходит уведомление «Студент A покинул группу».
- Статус студента при этом **не меняется**.

### FR-8: Карточка студентов — фильтр выбывших
- Список студентов потока (monitor): по умолчанию **только активные** (active/enrolled) — и в тексте, и в кнопках.
- Кнопка-переключатель (напр. «👁 Показать выбывших» / «🙈 Скрыть выбывших»): показывает всех; в этом режиме **метрики тоже по всем**.
- Сводка **«Всего: N студентов, из них M активных, P выбывших»** — видна всегда, от переключателя не зависит.
- Существующие кнопки ⛔ и ✅ в списке остаются как есть.

## Нефункциональные требования
- TDD: unit-тесты на job (пороги 5/7, периодичность «через день», enrolled без шагов), расширение агрегата, подписки/ER в боте, стори monitor.
- Интеграционные и e2e тесты новых пользовательских сценариев в u7-bot (по `conductor/code_styleguides/bot-test.md`).
- Уведомления доставляются проактивно и не ломают текущий флоу пользователей (`ProactiveSender`).
- Термин «Снять с учёбы» закрепить в коде (ucLabel, комментарии) и документации.

## Критерии приёмки
1. Job в 19:00 UTC: студент 5+ дней получает предупреждение (5, 7, 9…), ментор 7+ дней получает уведомление (7, 9, 11…) с корректной строкой о ранее отправленных уведомлениях.
2. «Покинуть учёбу»: confirm → студент abandoned + кикнут из группы (мягко) + ментор уведомлён.
3. «Снять с учёбы»: confirm → abandoned + кик + студент уведомлён. Работает для enrolled-студентов без шагов.
4. Самостоятельный выход из TG-группы → ментору приходит уведомление, статус не меняется.
5. Карточка студентов: дефолт — только активные (текст, кнопки, метрики); сводка «Всего N, из них M активных, P выбывших» всегда; переключатель показывает всех с метриками по всем.
6. Возобновление учёбы студентом сбрасывает цепочку уведомлений.

## За рамками
- Настройка порогов 5/7 дней и времени job из конфига или поля потока (только константы-дефолты).
- Автоматическое снятие с учёбы без решения ментора.
- Изменение кнопок ⛔/✅ в списке студентов.
- Переименование доменных сущностей (`abandoned`, `mark-abandoned`, `drop-student`).
