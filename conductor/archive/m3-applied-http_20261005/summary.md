## 4. Архитектурные решения

1. **Разделение проекта П2 на два Pull Request:**
   * Слой данных (модели, правила валидации, файловое хранилище, репозиторий) самодостаточен и тестируется моками. Сдача его в PR 1 защищает студента от накопления ошибок при переходе к API.
   * Транспортный слой (Bun.serve, таблица маршрутов, 5 обработчиков) сдаётся во втором PR поверх обновлённого `main`.
2. **Централизованная обработка ошибок сервера:**
   * Ошибки валидации (`OrderValidationError`) и отсутствие записей (`NotFoundError`) выбрасываются бизнес-слоем и централизованно превращаются шлюзом в коды `400` и `404` без ручного оборачивания в каждом обработчике.
3. **Чистый JavaScript без TS/JSDoc-дженериков:**
   * Учебный код уроков написан на простом, читаемом JS, фокусируясь на алгоритмах, ответственности модулей и TDD.
