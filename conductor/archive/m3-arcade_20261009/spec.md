# Спецификация: Проект «Аркада» (m3-arcade)

> **Исходный концептуальный документ:** [arcade-sketch.md](./arcade-sketch.md)

## 1. Обзор
Разработка учебного проекта «Аркада» (интерактивные игры в консоли) в рамках Модуля 3 «Алгоритмика: прикладное». Студент создает игры для терминала, используя готовую инфраструктуру ввода-вывода (движок) и визуализации (рендеры).

### Ключевые требования и ограничения:
- **Уровень студента:** ООП **не изучалось**, только функции. Объекты и массивы — только как структуры данных (POJO / кортежи / матрицы).
- **Инструменты:** чистый **Bun** без `package.json` и npm-пакетов (запуск скриптов напрямую: `bun path/to/run.js`, тесты: `bun test`).
- **Архитектура 3 слоев:**
  1. Ядро терминала (`engine.js`) — raw-режим, «живое» поле без мерцания (`\x1b[?1049h`, `\x1b[H`, скрытие курсора), тики/цикл.
  2. Промежуточный слой (Адаптеры/Рендеры) — нормализация сигналов ввода, ASCII/Unicode псевдографика.
  3. Логика игры — чистые функции `createState()`, `update(state, event)`, `getView(state)`.
- **Точка входа игры:** настроенный файл запуска `run.js` для каждой игры, связывающий три слоя.

## 2. Рекомендуемая структура файлов у студента

Проект собирается в директории `arcade/` по шагам уроков. Структура простая, модульная и не требует сборщиков:

```
arcade/
├── engine.js                # Слой 1: игровое ядро (чёрный ящик, выдается в уроке 1)
├── tui/                     # Слой 2: интерфейсный слой TUI (адаптеры ввода и экраны)
│   ├── hangman.js           # TUI адаптеры виселицы (урок 1)
│   ├── turtle.js            # TUI адаптеры черепашки (урок 2)
│   ├── grid.js              # Универсальный 2D TUI сетки (для 2048, сокобана, сапера, змейки)
│   └── ...                  # Спец-адаптеры выбранных игр (выдает ментор)
└── games/                   # Слой 3: игры (логика + точка запуска)
    ├── hangman/             # Демо-игра из урока 1 (100% готова из коробки)
    │   ├── words.js         # Словарь терминов в base64 (RU/EN)
    │   ├── hangman.js       # Логика виселицы
    │   └── run.js           # Точка запуска: `bun games/hangman/run.js`
    ├── turtle/              # Задача 1 (PR 1, урок 2)
    │   ├── turtle.js        # Логика черепашки (пишет студент!)
    │   ├── turtle.test.js   # Тесты логики черепашки
    │   └── run.js           # Точка запуска: `bun games/turtle/run.js` (выдаем мы)
    ├── <игра-набор-1>/      # Задача 2 (PR 2, урок 3: 2048, сокобан, сапер...)
    │   ├── <игра>.js        # Логика игры (пишет студент!)
    │   ├── <игра>.test.js   # Тесты логики (пишет студент!)
    │   └── run.js           # Точка запуска (выдает ментор)
    └── <игра-набор-2>/      # Задача 3 (PR 3, урок 4: змейка, уворачивальщик...)
        ├── <игра>.js        # Логика игры (пишет студент!)
        ├── <игра>.test.js   # Тесты логики (пишет студент!)
        └── run.js           # Точка запуска (создает сам студент!)
```

### Команды запуска в терминале студента:
- Запуск игры: `bun games/<game>/run.js` (например, `bun games/hangman/run.js`)
- Запуск тестов игры: `bun test games/<game>/` (например, `bun test games/turtle/`)
- Запуск всех тестов проекта: `bun test`

## 3. Модель прохождения, распределение ролей и эталонный фонд

В репозитории создаётся **100% полный рабочий эталон для каждой игры**: ТЗ, рендерер, раннер `run.js`, логика игры и юнит-тесты. Все игры рабочие и проверяются через `bun test`. Ментор держит на руках полный комплект и выдаёт студенту только требуемые части:

| Урок / Игра | Что на руках у ментора / в репозитории | Что ментор выдает студенту в чате | Что делает студент | Формат сдачи |
|---|---|---|---|---|
| **Урок 1: Демо («Виселица»)** | 100% готовый эталон (ядро, рендер, слова, игра, раннер) | Выдается всё в уроке через бот | Запускает, играет, исследует слои | **Коммит в main** |
| **Урок 2: Задача 1 («Черепашка»)** | 100% готовый эталон (рендер, раннер, игра `turtle.js`, тесты) | Рендер, раннер `run.js`, ТЗ и сигнатуры | Пишет `turtle.js` и тесты | **PR 1** |
| **Урок 3: Задача 2 (Пошаговая игра)** | 100% готовый эталон каждой игры (ТЗ, рендер, раннер, логика, тесты) | ТЗ, рендер/адаптер, раннер `run.js`, заготовка тестов | Пишет логику выбранной игры и тесты | **PR 2** |
| **Урок 4: Задача 3 (Реальное время)** | 100% готовый эталон каждой игры (ТЗ, рендер, раннер, логика, тесты) | ТЗ с контрактами, рендерер/адаптер (БЕЗ раннера) | **Сам создает `run.js`**, логику и тесты | **PR 3** |
| **Урок 5: Бонус («Своя игра»)** | Инструкции, идеи, расширения движка | Идеи и паттерны расширения | Творческая разработка | Опционально |

## 4. Каталог игр

### 4.1. Демо в уроке 1 (Без PR, коммит в main)
- **«Виселица: Термины курса» (Hangman):** визуализация виселицы в матрице символов, термины курса по алгоритмам (двуязычные RU/EN, индикатор языка на экране, словарь закодирован в base64).

### 4.2. Задача 1 в уроке 2 (PR 1)
- **«Черепашка» (Робот на сетке):** поле 10×10, координаты, направление N/S/W/E, границы поля, след шагов.

### 4.3. Набор 1: Пошаговые игры на выбор (PR 2)
- **2048:** матрица 4×4, сдвиг и слияние рядов чисел.
- **Сокобан:** лабиринт, толкание ящиков, двойные коллизии.
- **Сапёр:** мины, 8 соседей, каскадное открытие пустых зон (BFS).
- **Крестики-нолики 3×3 / 4 в ряд:** проверка линий матрицы.

### 4.4. Набор 2: Игры реального времени на выбор (PR 3)
- **«Змейка» (Snake):** системные тики (`tickRateMs: 150`), очередь координат тела, генерация еды без наложений, буфер ввода против разворота на 180°.
- **«Космический уворачивальщик» (Space Dodger):** корабль внизу, падающие волны препятствий (`tickRateMs: 100`).

## 5. Доставка контента

- **В боте (текстовые шаги):**
  - Урок 1: теория, блоки кода `engine.js` и всех файлов готовой «Виселицы».
  - Урок 2: блоки кода рендера Черепашки, раннера `run.js`, ТЗ и контракты функций.
  - Карточки выбора игр (эмодзи, описание, механика, сложность).
- **Ментор (в чате по запросу):**
  - Выдает пакет файлов под выбранную студентом игру для PR 2 и PR 3.
  - Проводит ревью PR 1, PR 2, PR 3.
