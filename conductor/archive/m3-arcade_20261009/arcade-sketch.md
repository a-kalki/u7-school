# Набросок проекта «Аркада» — интерактивные игры в терминале

> **Статус:** рабочая концепция для модуля «Алгоритмика: прикладное».
> **Уровень студента:** ООП **не изучалось**, только функции. Объекты и массивы — **только как структуры данных** (POJO / кортежи).
> **Инструменты:** чистый **Bun** без `package.json` и npm-пакетов (запуск напрямую: `bun path/to/run.js`, тесты: `bun test`).
> **Формат трека:**
> - Демо-игра («Виселица») — полностью рабочая из коробки для изучения и разминки (коммит и пуш без PR);
> - 3 самостоятельные практические задачи (Черепашка + Игра 2 + Игра 3);
> - **Правило сдачи:** **1 игра = 1 Pull Request** (всего 3 PR).

---

## 1. Идея и архитектура: три слоя

### Идея
Студент создает интерактивные консольные игры для терминала (TUI), работая с готовой инфраструктурой. Студенту не нужно разбираться с низкоуровневым вводом/выводом, сырыми ANSI-кодами и перерисовкой экрана: движок, адаптеры ввода и рендеры выдаются готовыми. Студент пишет чистую функциональную логику: правила игры, обработку действий и вычисление нового состояния.

```
[ Терминал / Клавиатура ]
          │ (сырые байты клавиш / таймер)
          ▼
┌────────────────────────────────────────┐
│ Слой 1. Игровое ядро (engine.js)       │ ◄── Наша инфра (выдаем в уроке 1)
│  - Raw mode терминала, loop/тики       │
│  - Живой буфер экрана без мерцания     │
└──────────────────┬─────────────────────┘
                   │ key / tick
                   ▼
┌────────────────────────────────────────┐
│ Слой 2. Адаптер и Рендерер             │ ◄── Наша инфра (выдаем под каждую игру)
│  - Нормализатор ввода (RAW -> Action)  │
│  - Отрисовка матрицы/строк в TUI кадр  │
└──────────────┬───────────────▲─────────┘
        Action │               │ View
               ▼               │
┌────────────────────────────────────────┐
│ Слой 3. Логика игры                    │ ◄── Пишет студент (только чистые функции!)
│  - createState() -> State              │
│  - update(state, event) -> State       │
│  - getView(state) -> View              │
└────────────────────────────────────────┘
```

### Слой 1. Ядро (`engine.js`) — *выдаем в уроке 1*
- Включает raw-режим терминала (`process.stdin.setRawMode(true)`), перехватывая ввод клавиш посимвольно без ожидания Enter.
- **«Живое» поле без мерцания:** терминал переключается на альтернативный экран (`\x1b[?1049h`), курсор скрывается (`\x1b[?25l`), при каждом кадре курсор возвращается в начало координат (`\x1b[H`), перезаписывая буфер поверх без дерганого `console.clear()`.
- Управляет тиками времени (если задан `tickRateMs`) или ожидает действий игрока (пошаговый режим).
- Поддерживает системные команды: выход (`Ctrl+C`, `q`), рестарт (`r`).

### Слой 2. Промежуточный слой (Рендерер и Адаптер ввода) — *выдаем под каждую игру*
- **Адаптер ввода:** нормализует стрелки, WASD, пробел, буквы и тики в понятные события (`MOVE`, `ACTION`, `CHAR`, `TICK`).
- **Рендерер:** преобразует данные игры (`view`) в псевдографику экрана (сетка, рамка, счет, подсказки).

### Слой 3. Сама игра — *пишет студент (строго без ООП)*
- Никаких классов (`class`) и `this`. Состояние — обычный JS-объект.
- Функции чистые: `createState()`, `update(state, event)`, `getView(state)`.

### Раннер игры (точка входа `run.js`)
Файл, который связывает три слоя воедино и запускает игру:
```js
// games/turtle/run.js — запуск: bun games/turtle/run.js
import { startEngine } from '../../engine.js';
import { renderTurtle, inputAdapter } from '../../tui/turtle.js';
import { createState, update, getView } from './turtle.js';

startEngine({
  title: 'Черепашка',
  adapter: inputAdapter,
  render: renderTurtle,
  createState,
  update,
  getView,
});
```

## 3. Каталог игр

### 🟢 Демо-образец (Урок 1): «Виселица: Термины курса»
- **Статус:** Полностью рабочая готовая игра из коробки.
- **Механика:** Псевдографическая виселица в терминале. Загаданы термины из пройденных модулей курса (`РЕКУРСИЯ`, `МАССИВ`, `ОЧЕРЕДЬ`, `CLOSURE`, `STACK`, `BIG_O`).
- **Два языка:** На экране индикатор `Язык: RU` или `Язык: EN`.
- **Защита терминов:** Список слов зашифрован в base64, чтобы студент не подсмотрел ответы в коде.
- **Роль:** Дать вау-эффект в первом же уроке, закрепить терминологию и показать эталонный пример работы трех слоев.

---

### 🟡 Задача 1 (Урок 2, PR 1): «Черепашка» (Робот на сетке)
- **Тип:** Пошаговая (команды / стрелки).
- **Студент получает:** Рендерер поля, раннер `run.js`, ТЗ с контрактами функций (`createState`, `update`, `getView`).
- **Задача студента:** Реализовать логику движения робота на поле 10×10 (координаты `x, y`, направление N/S/W/E, границы поля, след), написать тесты.
- **Сложность:** ⭐☆☆☆☆

---

### 🟠 Задача 2 (Урок 3, PR 2, выбор из пошаговых игр)
*Студент получает от ментора: рендерер, адаптер, настроенный раннер `run.js`, ТЗ с контрактами.*

> **🎮 2.1: «2048»**
> - **Механика:** Поле 4×4. Сдвиг стрелкой смещает числа, одинаковые соседние складываются, спавнится новая двойка.
> - **Алгоритмы:** Сжатие и слияние числовых рядов матрицы, проверка доступных ходов.
> - **Сложность:** ⭐⭐⭐☆☆

> **🎮 2.2: «Сокобан» (Кладовщик)**
> - **Механика:** Игрок толкает ящики на целевые точки склада.
> - **Алгоритмы:** Двойная коллизия (игрок → ящик → свободная клетка), чтение текстовой карты.
> - **Сложность:** ⭐⭐☆☆☆

> **🎮 2.3: «Сапёр» (Minesweeper)**
> - **Механика:** Курсор по полю, открытие клеток, установка флагов мин.
> - **Алгоритмы:** Подсчет 8 соседей для клетки, каскадное открытие пустых зон (BFS).
> - **Сложность:** ⭐⭐⭐☆☆

> **🎮 2.4: «Крестики-нолики 3×3» / «Четыре в ряд»**
> - **Механика:** Дуэль двух игроков на сборку непрерывной линии.
> - **Алгоритмы:** Проверка линий матрицы по горизонтали, вертикали и диагоналям.
> - **Сложность:** ⭐⭐☆☆☆

---

### 🔴 Задача 3 (Урок 4, PR 3, выбор из игр реального времени)
*Студент получает от ментора: тело рендерера и адаптера, документацию контрактов (что придет на вход и что ожидает рендерер на выходе). Раннер `run.js`, структуру модулей и тесты студент проектирует сам!*

> **🎮 3.1: «Змейка» (Snake)**
> - **Механика:** Змейка постоянно ползет по тикам таймера (`tickRateMs: 150`). Игрок меняет направление стрелками. Змейка растет от еды. Столкновение со стеной или хвостом — проигрыш.
> - **Контракт входа/выхода:**
>   - *Вход:* события `{ type: 'MOVE', direction }` и `{ type: 'TICK' }`.
>   - *Выход для рендера:* матрица символов 20×20 (`#` стена, `@` голова, `o` тело, `*` еда), счёт, статус (`PLAYING` / `GAME_OVER`).
> - **Алгоритмы:** Очередь (FIFO) для координат звеньев, генерация случайных координат без наложения, буферизация клавиш (защита от разворота на 180°).
> - **Сложность:** ⭐⭐⭐☆☆

> **🎮 3.2: «Космический уворачивальщик» (Space Dodger)**
> - **Механика:** Кораблик игрока внизу экрана уворачивается от падающих препятствий (`tickRateMs: 100`).
> - **Контракт входа/выхода:**
>   - *Вход:* события перемещения влево/вправо и `{ type: 'TICK' }`.
>   - *Выход для рендера:* матрица с положением корабля и препятствий, время выживания (счёт).
> - **Алгоритмы:** Массив динамических объектов, генерация волн, коллизии.
> - **Сложность:** ⭐⭐☆☆☆

   - TUI модуль `tui/turtle.js` (блок кода);
