## Принятые архитектурные решения

1. **Маркер takeover — уровень uiApp, предупреждение — транспорт.** `SessionData` доступна транспорту всегда (интерактив + проактив), а uiApp владеет маршрутизацией callback'ов. Транспорт смотрит на структурное поле `takeover: true`, маркер в `code` ему не виден — слои не протекают.
2. **`editPrev` — явный флаг действия** (answer/next/текст), а не эвристика по `activeHandler.path`: takeover-resume приходит при чужом `activeHandler` и не должен редактировать чужое сообщение.
3. **Сброс цепочки простоя через общий `#resetIdleFlags`:** обе метки (`warnedAt`, `continueInvitedAt`) удаляются при любой активности — иначе приглашение сработало бы один раз за жизнь анкеты.
4. **Комбинированная команда** `editMessage`+`sendMessage` — штатный механизм `BotCommand`, транспорт уже скипает удаление клавиатуры при наличии `editMessage`.

## На что стоит посмотреть (ручная верификация)

1. **Radio:** начни анкету → выбери вариант → сообщение с вопросом должно показать `(x)` и **остаться в чате без кнопок**; следующий вопрос приходит отдельным сообщением.
2. **Multiple:** тогглы меняют `[x]`/`[ ]]` **в том же сообщении**; «Далее -->» появляется после первого выбора и исчезает при снятии всех; «Далее» убирает кнопки и шлёт следующий вопрос.
3. **Takeover:** начни заполнять анкету, брось, зайди в чужой флоу (например, ввод кодового слова потока) → через ~3ч простоя придёт приглашение с предупреждением внизу → «▶️ Продолжить анкету» перехватывает ввод без alert'а.
4. **Пороги job:** 3ч → приглашение, 6ч → предупреждение, 9ч → закрытие; повторные прогоны не дублируют ступени; ответ на вопрос сбрасывает цепочку.
5. **MarkdownV2:** маркеры и предупреждающая строка отображаются без «битых» символов (fail-fast валидация в транспорте не срабатывает).

## Известные ограничения

- Takeover-приглашение при отсутствии `ownerInfo.courseId` не имеет takeover-кнопки (только «⏭️ Прервать») — resume без курса не построить; в бою standard-анкеты всегда курсовые.
- Гонка «пустой ответ apply vs проактивный Q1» может снять клавиатуру первого вопроса до его показа — не влияет на поведение (клавиатуру пересоздаёт edit следующего шага); зафиксировано в e2e.
