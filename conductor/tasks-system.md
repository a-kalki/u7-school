# Система задач и уведомлений — Концепция

> v1 (2026-09-01). Выдержка из стратегической сессии: бизнес-проблема → бизнес-решение.
> Уровень документа — концепция продукта, без архитектурных деталей (они появятся
> в spec трека при планировании).

---

## Бизнес-проблема

Бот вырос из «терминала с одним диалогом» в инструмент, где система сама
инициирует общение: предупреждает о бездействии, просит ментора решить судьбу
студента, предлагает анкету после код-ревью. Проактивные сообщения исторически
оформлялись как обычные экраны диалога с кнопками — это породило класс проблем.

### Проблемы пользователя

1. **Хаос кнопок при серии сообщений.** Ментор получает несколько «кандидатов на
   снятие с учёбы» подряд — кнопки пропадают у сообщений в непредсказуемом
   порядке (у первого сообщения кнопки нет; нажал кнопку у второго — пропала у
   четвёртого). Невозможно понять, кого уже обработал, а кого нет.
2. **Анонимность действий.** Подтверждения («Снять студента с учёбы?») не
   содержат имени студента — при серии сообщений непонятно, о ком речь.
3. **Вторжение в текущий флоу.** Студент проходит урок — и прилетает сообщение с
   кнопками, перехватывающими ввод. Обучение прервано, контекст потерян.
4. **Потеря дел.** Предложение, на которое не ответили сразу, утонуло в истории
   чата: вернуться к нему некуда, дело потеряно.
5. **Дорогой выход.** Возможность «покинуть учёбу» доступна только через 5 дней
   бездействия: решивший уйти студент не может сделать это удобно — учёба
   «висит», группа у ментора загромождается.

## Бизнес-решение: pull вместо push

Кнопки из проактивных сообщений убираются полностью. Все касания бота делятся
на три канала:

| Канал | Суть | Кнопки | Жизненный цикл |
|---|---|---|---|
| **Уведомление** | «знай»: факт или предупреждение | нет | доставлена — всё |
| **Задача** | «сделай / реши» | только в списке задач | окно жизни, статусы, напоминания |
| **Возможность меню** | действие без срока («покинуть учёбу») | в главном меню | доступна всегда |

Центр решения — **единый список задач**: кнопка «Мои задачи» в главном меню и
команда `/tasks`. Система никогда не вторгается в текущий флоу: она лишь
уведомляет текстом «есть дело», пользователь сам решает, когда им заняться.

### Ключевые решения по сущностям

- **Задача — единая сущность.** «Предложение» не отдельная сущность, а способ
  рождения *опциональной* задачи (можно отказаться без последствий). «Вопрос с
  развилкой» — тоже задача (тип «требует решения»). Два измерения задачи:
  тип (форма выполнения) × обязательность (политика напоминаний).
- **Быстрые действия.** Задачи выполняются либо флоу, либо одной кнопкой прямо
  из списка («Продолжить», «Покинуть учёбу», «Снять с учёбы»). Плата за действие
  нулевая — конверсия максимальная. Опасные действия подтверждаются.
- **Память об отказе.** Отказ («не в этот раз») закрывает задачу и
  запоминается — система не долбит повторно.
- **Повтор ситуации обновляет задачу**, а не плодит дубликаты (бездействие
  растёт с 7 до 9 дней — та же задача, обновлённая).

## Пользовательские сценарии (как будет)

**Студент перестал заниматься.** Уведомление-предупреждение текстом (без
кнопок) → в списке задач появилась «Похоже, вы бросили учёбу» с кнопками
[Продолжить] / [Покинуть учёбу]. Нажал «Продолжить» — каскад предупреждений
сброшен осознанным сигналом. Нажал «Покинуть» — честный уход оформлен самим
студентом, задача ментора не создаётся вовсе.

**Ментор, несколько бездействующих.** Одно уведомление (или дайджест) вместо
пачки карточек → `/tasks` → список кандидатов, у каждого [Снять с учёбы] /
[Оставить]. Обработал — задача исчезла из списка на глазах. Кого обработал —
всегда видно по оставшимся пунктам.

**Анкета после код-ревью.** Опциональная задача с окном актуальности:
заполнил сейчас, вернулся позже (задача ждала в списке) или пропустил —
предложение не повторится до нового повода.

## Выгоды для бизнеса

- **Снижение нагрузки на менторов**: честные уходы оформляются студентами
  самостоятельно, каскад бездействия обрывается раньше ступени «снятие».
- **Ничего не теряется**: все дела в одном списке, у задач есть статусы,
  сроки и напоминания.
- **Уважение внимания**: флоу пользователя не прерывается никогда.
- **Выше конверсия важных действий**: кнопка готова в задаче — плата действия
  нулевая (оформленный уход, заполненная анкета).
- **Прозрачность**: висящие дела измеримы (сколько, как долго, кто исполнитель).

## Сопутствующие технические работы

Помимо модуля задач — устранение гонок доставки сообщений (упорядочивание
отправок в чат), из-за которых кнопки пропадали непредсказуемо. Детали — в
spec трека.

## Открытые вопросы

1. Политика напоминаний о висящих задачах: частота и тон.
2. Повторные окна после отказа (когда система вправе предложить снова).
3. Дайджест уведомлений: агрегировать пачку новых задач в одно сообщение?
4. Сортировка списка задач: свежесть × приоритет.
5. Брошенная анкета — задача или уведомление (тон продукта).
