# Bot-UI «Диалог и Экран» — концепция и инструкция

**Назначение:** как устроена обработка апдейтов Telegram-бота: адресация, слои, контракты стори. Читать перед работой с `packages/core/src/ui/bot/*` и `apps/u7-bot/src/*`.

**UX-концепция «хлебные крошки»:** история навигации остаётся в чате — каждый прошлый экран гасится (клавиатура снята, маркер «Вы выбрали: …» при известной кнопке), текущий — единственный живой. Механика транспорта при любой смене экрана/диалога, включая ответы без `screen`; стори про это не думает и не минимизирует переходы между стори искусственно — следы пути осознанно сохраняются.

---

## 1. Слои и ответственности

| Слой | Файл | Отвечает за |
|---|---|---|
| Транспорт | `apps/u7-bot/src/infra/bot-transport.ts` | КАК рисуется: сессии, штампы `:~seq36`, сжатие UUID, per-chat очередь, рендер (info→send, screen→edit/retire+send, input→await/release), гашение устаревшего экрана при любом ответе («хлебные крошки»), валидация кнопок (alert), реплики-подсказки ввода |
| Ядро uiApp | `packages/core/src/ui/bot/ui-app.ts` | ГДЕ живёт диалог: `enterDialog` — единственный seq++, маршрутизация кнопок по префиксам, pipe команд с агрегацией. Имён команд и текстов не знает |
| Контроллер | `bot-controller.ts` | Префикс `ctrl:` у кнопок, pipe своих стори (активная первой), ошибки стори → экран |
| Приложение uiApp | `apps/u7-bot/src/core/ui-app.ts` | ЧТО отвечать: `/start` (гость → welcome из menuButtons), дефолты help/cancel/unknown, сбор `menuButtons`, системные кнопки `app:main-menu`/`app:help` |
| Стори | наследники `BotUiStory` / `U7BotUiStory` | Доменные экраны и реплики; контекстные help/cancel активного диалога |

Диалог (`BotSession.dialog`) — `{ path: 'ctrl/story', seq, input? }`. Смена диалога — только `enterDialog` (switch — мост, seq++ при смене пути; reopen — /start, /cancel, всегда seq++). Экран валиден ⟺ диалог открыт ∧ штамп == seq. Меню — виртуальный диалог `app/menu` без стори (якорь seq).

## 2. Адресация апдейтов

| Апдейт | Адресация | Кто получает |
|---|---|---|
| Кнопка (callback) | адресная — адрес в коде кнопки | одна стори по префиксу; до домена невалидные отсекает транспорт (alert) |
| Текст без слэша | только активной — `dialog.path` + `dialog.input` | одна стори; обязана ответить; без ожидания/адресата — реплика-подсказка транспорта |
| Слэш-команда | активный первым, затем всем | pipe: активная стори → стори активного контроллера → остальные контроллеры по регистрации; первый `stop` побеждает; все `pass` → дефолты приложения |

`CommandReaction = pass | continue(notice?) | stop(response)` (`types.ts`). Прикладные имена команд ядро не знает; прямые пути uiApp мимо pipe — два: **`/start`** (гость → welcome) и **`/help`** (ниже). `/log_level` — НЕ исключение: обычная команда pipe, активная стори отвечает `pass` (не её команда), обработчик — app-контроллер (`stop`). Stop-ответ команды с `delegate` исполняется ядром — команда с экраном открывает диалог целевой стори (важно для `/tasks`).

- `/help` — решает uiApp: активная стори → только её `contextHelp()` (публичный мост uiApp → стори); во всех остальных случаях (меню, закрытый диалог, активная без справки) → общий справочник из `menuButtons` (info-реплика, работает и без открытого диалога). Инвариант: неактивная стори на /help не отвечает никогда — активность проверяет uiApp, не стори;
- `/cancel` — условная логика в pipe (контракт `U7BotUiStory.isActive`): активная стори → сброс себя + `stop`; неактивные — `pass`; пустой pipe → uiApp `reopen(menu)` + короткое меню;
- прочие команды — `pass` → подсказка «Неизвестная команда».

## 3. Ответы стори (DialogResponse)

- `screen` — показать экран (свой → edit, чужой → retire «Вы выбрали» + send; смена диалога без screen — прежний экран всё равно гасится, «хлебные крошки»);
- `finalize` — запечатать активный экран текстом без клавиатуры;
- `info` (→ `notify` в фазе 3) — тихая реплика поверх, экран и ввод не трогает;
- `awaitInput` / `release` — ждать / снять ожидание текста;
- `delegate` — переход в другую стори, исполняет uiApp до транспорта.

Ошибки: домен — экран (`handleError`); валидация ввода — реплика-переспрос (`errorNotify`, фаза 3) с сохранением контекста ввода.

## 4. Проактив (не апдейт — события домена)

`ProactiveSender` (`types.ts`): `notify` — только текст, сессию не трогает (инвариант И3); `invite` — ВРЕМЕННЫЙ (ФР-6): кнопки со штампом seq диалога получателя; без диалога транспорт открывает «временно активный» диалог-якорь `app/invite` (seq = 1) — приглашение не умирает, нажатие кнопки switch-ит диалог в целевую стори (seq++), /start делает reopen; удаляется с модулем tasks-system. Цепочка ретрансляторов: стори → контроллер → uiApp → транспорт.

## 5. Инструкция для новых стори

1. Унаследовать `U7BotUiStory`; `name` = префикс кнопок; кнопки главного меню — декларативно `menuButtons(actor)` (не обработчики!).
2. `handleCallback` — экраны по кодам кнопок; `handleMessage` — переопределяют только стори с `awaitInput` (дефолт ядра — реплика «Извините, на данном этапе сообщения не принимаются»); ввод без ожидания до стори не доходит (подсказка транспорта); команды — override `handleCommand` с реакциями pipe (дефолт — `pass`). Непринятые ветки callback — хелпер `unknownCommand()` (экран + warn-лог; на уровне контроллера — тот же экран для кодов без стори).
3. `isActive(session)` / `dialogPath` — контракт /cancel (активная — сброс себя, неактивная — pass); контекстная справка — `contextHelp()` (public: при /help uiApp задаёт её только активной стори).
4. Тексты — `md`-интерполяция (MarkdownV2, доменные данные экранируются автоматически; точки/дефисы в литералах — `\\.` `\\-`).
5. Меню/справка/«В меню» — системные маршруты uiApp, стори их не строит.
