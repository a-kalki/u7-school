# Drill-down навигация по контенту — концепция и каркас

**Назначение:** единый UX-паттерн пошагового просмотра иерархии учебного контента в
Telegram-боте. Используют: студент (`📂 Уроки`), карточка потока (`📖 Программа модуля`),
каталог (`📖 Программы курсов`). Читать перед изменением этих экранов.

Реализуется треками `module-program-nav_20260928` (ядро + «Программа модуля») и
`course-catalog-nav_20260928` (каталог курсов).

---

## 1. Идея

- Иерархия проходится по лестнице уровней: `модуль/курс → проект/этап → урок → шаг`.
- Каждый уровень — **карточка одного узла**, а не плоское дерево в одном сообщении.
- Пользователь всегда понимает: где он, из чего состоит следующий уровень, куда идти
  и как листать соседей.
- Последний уровень — самый глубокий доступный (обычно урок); внутрь него заходят только
  там, где это разрешено ролью.

## 2. Карточка уровня

- **Шапка-крошки** — путь до текущего узла (`📖 Программа модуля › {Проект} › {Урок}`).
- **Пояснение** — «{Уровень} состоит из N {детей}».
- **Список детей:** первый уровень — жирным и **нумерованным**; подуровень (дети детей) —
  обычным списком с отступом, чтобы сразу видеть состав следующего уровня.
- **Кнопки** — по одной на ребёнка, с номером; ведут внутрь.
- **Листание** `◀️ Пред. …` / `След. … ▶️` — соседи текущего узла **в пределах родителя**;
  на границе кнопки нет.
- **Назад** `⬅️ Назад к {родителю}` — на уровень выше; на верхнем уровне — выход по сценарию
  (хаб / поток / главное меню).
- Последний уровень — одноуровневый список (например, шагов урока).

## 3. Детали роли

Механика одна; различаются только «детали», задаваемые контекстом:

| Контекст | Прогресс/статусы | Тела шагов |
|----------|------------------|------------|
| Студент (`📂 Уроки`) | да (`✅/▶️/🔒` + `(N/M)`) | пройденные + текущий |
| Владелец потока / ADMIN (`📖 Программа модуля`) | нет | все (чтение) |
| Зритель (публичная карточка потока) | нет | только заголовки |
| Каталог курсов (любой зритель) | нет | только заголовки |

Доступ к телам определяет `StepPolicy`; UI лишь показывает то, что вернул домен, и не
запрашивает недоступное.

## 4. Каркас реализации

- **Модель уровня (`NavLevel` + `NavChild`)** — единая для всех контекстов: крошки, пояснение,
  дети (`id`, `index`, `title`, `emoji`, `meta`, `status`, `enterable`, `children`),
  адреса `prev`/`next`/`back`.
- **Presenter** — чистые функции: `NavLevel` → текст MarkdownV2 + клавиатура. Доменной
  логики не содержит.
- **Резолвер контекста** — по адресу отдаёт `NavLevel`: источник (поток/курс), прогресс
  (опционально), доступность тел. Источник данных — существующие query-UC (`get-stream`,
  `get-module-snapshot`, `list-courses`, `get-course`, `get-step`, `get-steps-by-lessons`);
  новых query-UC не требуется.
- **Единый адрес уровня** — стабильные id, не индексы `phaseIdx`/`projectIdx`.
- **Рендер тела шага** — общий (`formatStepMessage`), режимы `student` / `readOnly`.
- **Права** — через `Policy`-объекты, не в presenter и не ручными проверками ролей.

## 5. Правила и запреты

- Не рендерить inline-поддеревья вручную; `tree-renderer` для этого не использовать.
- Не тащить `pagedScreen` в карточки (пагинация — только для длинных списков кнопок).
- Не дублировать механику в каждой стори: общее — в ядре, детали — в резолвере.
- Заголовки — через `md` (MarkdownV2-экранирование обязательно).
