# Набросок проекта «Аркада» — интерактивные игры в терминале

> **Статус: черновик для обсуждения.** Тела шагов не описаны — только слои, ответственности и структура уроков/шагов. Решение о вставке в курс за Нурболатом.

## Идея

Небольшой **опциональный** проект «на интерес»: студент собирает интерактивные игры прямо в терминале, используя готовую инфраструктуру (чёрные ящики). Главный навык — паттерн **конечный автомат** и **разделение ответственности**: ввод → обработчик → рендер.

Формулировка в уроках: «все задания здесь — на интерес; делай то, что тебе интересно».

Ключевой принцип: инфраструктуру писал не студент, её **можно не читать** и **нельзя менять**. Студент пишет только чистую логику и отдаёт движку.

---

## Цель

**Учебная.** Закрепить конечный автомат и разделение ответственности на интерактивной задаче. Показать, что логику можно писать чистой функцией, ничего не зная о вводе-выводе, а готовую инфраструктуру — использовать как чёрный ящик.

**Продуктовая.** К концу проекта у студента есть набор рабочих интерактивных игр в терминале, которые можно запустить и показать.

## Задача для инфраструктуры

Полностью закрыть ввод-вывод, чтобы студент занимался только логикой:
- движок: ввод, цикл, очистка экрана, системные команды, тики;
- рендереры: превращение состояния в ASCII-строку;
- ничего из этого студент не пишет и не меняет.

## Задача для студента

- пишет чистый автомат игры: `createState` + `handleInput` (+ опц. `isFinished`);
- пишет тесты на логику (рендер — чёрный ящик);
- собирает игру, связывая свои функции с инфраструктурой;
- выбирает игры по интересу, начиная с обязательного вводного урока.

---

## Декомпозиция по слоям

### Слой A. Движок запуска — `engine.js` (инфра, чёрный ящик)

Responsibility: **жизненный цикл интерактивной сессии.**

- ловит ввод: в настоящем терминале — клавиша за клавишей (raw), вне TTY — построчно;
- по каждому входу зовёт `handleInput(state, key)`;
- берёт **возвращённое значение** и передаёт его в `render(...)`;
- чистит экран и печатает результат;
- системные команды: `q` — выход, `?` — помощь, `r` — рестарт (опц.);
- по желанию — «тики» по таймеру (для игр реального времени, см. «Змейку»);
- завершение игры узнаёт через `isFinished(state)` (опц.).

Не знает: конкретную игру, форму состояния, как рисовать.

### Слой B. Рендереры — `render/*.js` (инфра, чёрный ящик)

Responsibility: **чистое превращение состояния в строку ASCII.**

- `renderTurtle({ position, path })` — рисует поле, след и робота;
- `renderBoard(state)` — поле 3×3 для крестиков-ноликов;
- `renderSnake(state)` — поле для змейки;
- …по одному рендеру на игру.

Без ввода-вывода и без мутаций: одна и та же функция годится и для терминала, и для тестов. Меняется независимо от логики.

### Слой C. Логика игры — `games/<game>.js` (пишет студент)

Responsibility: **чистый конечный автомат.**

- `createState()` — начальное состояние;
- `handleInput(state, key)` — переход, возвращает новое состояние;
- опц. `isFinished(state)`.

Не знает: про ввод, экран и рендер.

### Слой D. Сборка — `games/<game>.main.js` (пишет студент, чуть-чуть)

Responsibility: **связать слои.**

```js
runGame({
  title: 'Черепашка',
  help: 'f — вперёд, b — назад, l/r — поворот',
  createState,          // слой C
  handleInput,          // слой C
  render: renderTurtle, // слой B (чёрный ящик)
});
```

### Решение по вопросу «кто вызывает рендер»

Рассматривались два варианта:

1. **Обработчик возвращает значение, движок зовёт рендер** (выбран).
2. Обработчик сам вызывает рендер.

Выбран вариант 1, потому что:
- `handleInput` остаётся **чистым** и легко тестируется без терминала;
- движок владеет порядком «стереть экран → нарисовать → напечатать»;
- логику и отрисовку можно менять независимо друг от друга;
- вариант 2 смешивает логику с побочными эффектами и ломает тестируемость.

Компромисс на будущее: если рендеру нужно не всё состояние, обработчик может вернуть представление (`view`), а движок передаст его в рендер. Для старта достаточно «состояние = представление».

---

## Первичные решения (сводка)

1. Инфраструктура — чёрный ящик: можно не читать, нельзя менять.
2. Обработчик **возвращает** значение, рендер зовёт **движок** (обработчик остаётся чистым).
3. Рендер — тоже чистая функция `состояние → строка`; по одному рендеру на игру.
4. Интерактивность: raw-клавиши в реальном терминале, построчный fallback вне TTY.
5. Реальное время (тики) — опциональная возможность движка, не обязательна с самого начала.
6. Задания «на интерес»: обязателен только вводный урок, остальные игры — по выбору.
7. Студент пишет и логику, и тесты; инфра — для ручной игры.
8. В этом файле — только структура; тела шагов позже.

## Структура уроков и шагов (без тел)

**Обязателен только L1** (вводный). Дальше — игры на выбор: студент берёт те уроки и задания, что ему интересны.

### L1. «Аркада: движок, обработчик, рендер» — вводный (обязательный)
1. Идея проекта и правило «всё на интерес».
2. Три слоя и их роли.
3. Контракт: `createState` / `handleInput` / `render`.
4. Запуск готовой демо-игры без правок.
5. (необязательно) Заглянуть внутрь чёрного ящика.
6. Вопросы на понимание.
7. Термины.

### L2. «Черепашка»
1. Постановка: поле, координаты, направление.
2. Состояние и таблица переходов (`f`/`b`/`l`/`r`).
3. Рендер `renderTurtle` как чёрный ящик.
4. Реализация `handleInput`.
5. Тесты логики (рендер — чёрный ящик).
6. Запуск в терминале.
7. Доп. задания: препятствия, след, границы.
8. Вопросы и термины.

### L3. «Крестики-нолики»
1. Постановка: поле 3×3, два игрока.
2. Состояние и переходы: ходы по очереди, победа, ничья.
3. Рендер `renderBoard`.
4. Реализация и тесты.
5. Запуск (ходы цифрами 1–9).
6. Доп. задание: соперник-бот.
7. Термины.

### L4. «Змейка» (сложнее, реальное время)
1. Постановка и отличие: время как событие (`tick`).
2. Состояние: тело, направление, еда.
3. Переходы: движение, рост, столкновения.
4. Рендер `renderSnake`.
5. Реализация и тесты на детерминированном состоянии.
6. Запуск.
7. Термины.

### L5. «Своя игра» (творческий)
1. Придумать игру.
2. Описать состояния и переходы.
3. Выбрать готовый рендер или (позже) написать свой.
4. Собрать и защитить.
