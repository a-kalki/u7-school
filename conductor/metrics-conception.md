## 1. Категории метрик

### Hard Skills — профессиональные компетенции

| Подкатегория | Описание | Кто оценивает | Способ сбора |
|---|---|---|---|
| Качество кода | Читаемость, структура, следование стандартам | Ментор, напарник | Анкета (peer_review, mentor_review, pair_programming) |
| Алгоритмическое мышление | Способность решать задачи, декомпозиция | Ментор, напарник | Анкета |
| Самостоятельность | Пишет код сам, а не копирует сгенерированный ИИ | Напарник (парное прог.) | Анкета (pair_programming) |
| Инструментарий | Владение git, IDE, терминалом, отладчиком | Ментор, напарник | Анкета |

### Soft Skills — личностные качества

| Подкатегория | Описание | Кто оценивает | Способ сбора |
|---|---|---|---|
| Коммуникация | Ясно выражает мысли, слушает, даёт обратную связь | Ментор, другие студенты | Анкета (peer_review, mentor_review) |
| Командность | Помогает другим, делится знаниями, работает в паре | Ментор, другие студенты | Анкета |
| Ответственность | Соблюдает дедлайны, доводит до конца, предупреждает о проблемах | Ментор | Анкета (mentor_review) |
| Инициативность | Задаёт вопросы, предлагает решения, выходит за рамки задания | Ментор | Анкета (mentor_review) |

### Вовлечённость — автоматические метрики

| Подкатегория | Описание | Источник |
|---|---|---|
| Посещаемость | Частота взаимодействия с ботом, не было длительных пауз | `stream` (автоматически) |
| Скорость прохождения | Время между шагами, медиана по группе | `stream` (автоматически) |
| Завершаемость | Доля завершённых модулей от доступных | `stream` (автоматически) |

## 2. Шкала оценки (Лайкерт 1–5)

Все анкетные вопросы используют единую шкалу:

| Балл | Значение |
|---|---|
| 1 | Полностью не согласен |
| 2 | Скорее не согласен |
| 3 | Нейтрально / затрудняюсь ответить |
| 4 | Скорее согласен |
| 5 | Полностью согласен |

Для каждой подкатегории формулируется набор **утверждений** (а не вопросов). Оценивающий выражает степень согласия.

Пример утверждения для «Самостоятельность»:
> «Студент пишет код самостоятельно, не используя ИИ-генерацию для целых решений»

Пример утверждения для «Коммуникация»:
> «Студент ясно и аргументированно объясняет свои решения»

## 3. Маппинг «утверждение → метрика»

Каждый вопрос в пуле анкет (см. Документ 2, трек 2.4) содержит метаданные:

```
questionCode: "peer_code_quality"
metricMapping:
  category: "hard_skills"
  subcategory: "code_quality"
  weight: 1.0
answers:
  - { answerCode: "1", answer: "Полностью не согласен" }
  - { answerCode: "2", answer: "Скорее не согласен" }
  - ...
  - { answerCode: "5", answer: "Полностью согласен" }
```

`weight` позволяет одним вопросам влиять сильнее других внутри одной подкатегории. По умолчанию 1.0.

---

## 4. Формулы агрегации

### 4.1 Балл по одной анкете

Для каждой подкатегории внутри одной анкеты:

```
score_subcategory = Σ (answer_score × weight) / Σ weight
```

Если в анкете несколько вопросов одной подкатегории — средневзвешенное. Если один вопрос — просто его балл.

### 4.2 Итоговый балл по подкатегории

У студента может быть несколько анкет одного типа (например, 3 peer_review от разных студентов). Итог:

```
final_subcategory = Σ (score_i) / N
```

Где N — количество анкет, содержащих эту подкатегорию.

### 4.3 Балл по категории

```
final_category = Σ (final_subcategory × subcategory_weight) / Σ subcategory_weight
```

Веса подкатегорий внутри категории равны по умолчанию (1.0), но могут быть скорректированы.

### 4.4 Общий рейтинг (опционально)

```
total_rating = Σ (final_category × category_weight)
```

### 4.5 Порог достоверности

Метрика считается **достоверной** только при наличии минимум N анкет:
- peer_review: минимум 2 анкеты от разных студентов
- mentor_review: минимум 1 анкета от ментора
- pair_programming: минимум 1 анкета

Если порог не достигнут — метрика отображается с пометкой «недостаточно данных».
