## 1. Категории и подкатегории метрик

### Профессионализм `professional_skills`

| Подкатегория (код) | Описание |
|---|---|
| Качество работы `work_quality` | Читаемость, структура, следование стандартам |
| Алгоритмическое мышление `algorithmic_thinking` | Декомпозиция, решение задач |
| Владение инструментарием `tooling` | Git, IDE, терминал, отладчик |

### Командные `team_skills`

| Подкатегория (код) | Описание |
|---|---|
| Коммуникативность `communication` | Ясно выражает мысли, слушает, даёт обратную связь |
| Инициативность `initiative` | Задаёт вопросы, предлагает решения, выходит за рамки |
| Честность `honesty` | Честен в оценках, не скрывает ошибки, способен давать правдивую обратную связь даже если это вызывает дискомфорт |
| Взаимовыручка `mutual_help` | Помогает другим, делится знаниями; открыт — не боится попросить о помощи сам |

### Личностные `personal_skills`

| Подкатегория (код) | Описание |
|---|---|
| Энтузиазм `enthusiasm` | Любопытен к изучению нового, вовлечён в процесс |
| Ответственность `responsibility` | Берёт задачи самостоятельно без указаний, соблюдает договорённости и правила, доводит до конца |
| Регулярность `regularity` | Дисциплина, стабильный темп занятий, посещаемость |

## 2. Шкала оценки (Лайкерт 1–5)

Все анкетные вопросы используют единую шкалу:

| Балл | Значение |
|---|---|
| 1 | Полностью не согласен |
| 2 | Скорее не согласен |
| 3 | Нейтрально / затрудняюсь ответить |
| 4 | Скорее согласен |
| 5 | Полностью согласен |

Для каждой подкатегории формулируется набор **утверждений** (а не вопросов). Оценивающий выражает степень согласия.

---

## 3. Роли оценивающих

| Роль (код) | Кто → Кого | Когда |
|---|---|---|
| `student_student` | Студент → Студент | Кросс-оценки |
| `mentor_student` | Ментор → Студент | Оценка ментором |
| `student_mentor` | Студент → Ментор | Обратная связь о менторе |

---

## 4. Контексты запуска анкет

| Контекст (код) | Описание | Роли по умолчанию |
|---|---|---|
| `module_completed` | Студент завершил модуль | `student_student` + `mentor_student` + `student_mentor` |
| `pair_programming` | Завершена сессия парного программирования | `student_student` |
| `code_review` | Завершено код-ревью | `student_student` |
| `initiative` | Инициативная анкета вне плановых | Любая |

## 5. Маппинг «утверждение → метрика»

Каждый вопрос в пуле анкет (см. Документ 2, трек 2.4) содержит метаданные:

```
questionCode: "peer_work_quality"
metricMapping:
  category: "professional_skills"
  subcategory: "work_quality"
  weight: 1.0
answers:
  - { answerCode: "1", answer: "Полностью не согласен" }
  - { answerCode: "2", answer: "Скорее не согласен" }
  - ...
  - { answerCode: "5", answer: "Полностью согласен" }
```

`weight` позволяет одним вопросам влиять сильнее других внутри одной подкатегории. По умолчанию 1.0.

## 6. Система весов

Шкала весов: `0.75` (пониженный), `1.0` (стандартный), `1.25` (повышенный). По умолчанию все подкатегории и категории имеют вес `1.0`.

```
category_score = Σ (subcategory_score × subcategory_weight) / Σ subcategory_weight
total_rating = Σ (category_score × category_weight) / Σ category_weight
```

### Таблица весов (начальная, все 1.0)

## 7. Формулы агрегации

### 7.1 Балл по одной анкете

Для каждой подкатегории внутри одной анкеты:

```
score_subcategory = Σ (answer_score × question_weight) / Σ question_weight
```

Если в анкете несколько вопросов одной подкатегории — средневзвешенное. Если один вопрос — просто его балл.

### 7.2 Итоговый балл по подкатегории

У студента может быть несколько анкет одной подкатегории (например, несколько peer_review). Итог:

```
final_subcategory = Σ (score_i) / N
```

Где N — количество анкет, содержащих эту подкатегорию.

### 7.3 Балл по категории

```
category_score = Σ (final_subcategory × subcategory_weight) / Σ subcategory_weight
```

### 7.4 Общий рейтинг

```
total_rating = Σ (category_score × category_weight) / Σ category_weight
```

### 7.5 Порог достоверности

Метрика считается **достоверной** только при наличии минимум N анкет:
- `module_completed`: минимум 2 анкеты от разных студентов
- `pair_programming`: минимум 1 анкета
- `code_review`: минимум 1 анкета

Если порог не достигнут — метрика отображается с пометкой «недостаточно данных».
