# Архитектура DMG (Domain Manifest Graph)

**Назначение:** целевая архитектура слоёв domain и api на основе декларативных манифестов. Единственное место, где описана новая архитектура: решения, слои, правила, агентный процесс, план перехода.

> Статус: **контур утверждён, переход не начат.** Старый код живёт по старым styleguide-ам (`code_styleguides/`, ddd-скиллы) до своей миграции.
> UI-слой (stories, автодокументация UI) проектируется позже по тем же принципам.

---

## Суть

Разработчик описывает каждую доменную сущность **один раз** в виде манифеста (агрегат, политика, ошибка, событие, UC, ER, Job, фасад, модуль). Из манифестов выводятся контракты для четырёх потребителей:

| Потребитель | Что получает |
|---|---|
| **Программист (DX)** | типы (`typeof manifest`), базовые классы без boilerplate, `Result` с исчерпывающими ошибками |
| **Транспорт (фронт↔бэк, сервис↔сервис)** | автороутинг, автовалидация, OPTIONS с JSON Schema входа/выхода, каталогом ошибок и описанием политики |
| **PO / аналитик** | живая документация: агрегаты и статусы, каскады «потянуть за верёвочку», каталог ошибок, карта контекстов |
| **LLM (MCP)** | UC как tools, доменный граф как resources |

Плюс пятый, служебный: **контрактные тесты** проверяют, что код соответствует декларациям.
