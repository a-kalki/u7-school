# Ошибки и Result

**Назначение:** как домен и API сообщают об отказах. Реализация `Result` — в `@u7-scl/core` (трек core).

---

## 1. Ключевые правила

1. Штатный бизнес-отказ («студент уже завершил», «нет прав», «не найден») — это **значение** `Err`, а не исключение.
2. `throw` допустим только для: бага, нарушения инварианта агрегата (данные повреждены), системного сбоя (диск, сеть).
3. Ar, ApiService, Policy-обёртки и UC возвращают `Result<T, E>`; тип `E` — union объявленных ошибок.
4. UC может вернуть **только** ошибки из своего манифеста (`errors`) плюс базовые ядра — проверяет компилятор.
5. Вызывающий код (story, фасад, ER) обрабатывает `Err` явно: `switch` по `code` с веткой по умолчанию.

## 2. Модель ошибки

`defineError({ code, kind, label, description, payload })`. `kind` определяет HTTP-статус и обработку:

| kind | HTTP | Примеры |
|---|---|---|
| `validation` | 422 | `INPUT_VALIDATION` |
| `unauthorized` | 401 | `UNAUTHORIZED` |
| `access` | 403 | `ACCESS_DENIED` (+ правило политики и `denyMessage`) |
| `not_found` | 404 | `STUDENT_NOT_FOUND` |
| `conflict` | 409 | `STUDENT_NOT_ACTIVE`, `STREAM_HAS_PENDING_STUDENTS` |
| `internal` | 500 | `SERVER_INTERNAL`, `OUTPUT_VALIDATION` |

- Агрегат объявляет свои ошибки в `defineAggregate({ errors })`.
- UC **ссылается** на них в `errors` — без переименования и ручного маппинга; результат метода Ar можно вернуть как есть.
- Базовые ошибки (`UNAUTHORIZED`, `INPUT_VALIDATION`, `ACCESS_DENIED`, `OUTPUT_VALIDATION`, `SERVER_INTERNAL`) подмешивает ядро.

## 3. Исполнение UC (`handle`)

Порядок: авторизация → валидация входа → `execute` → валидация выхода. Любое непредвиденное исключение внутри ловится, логируется и превращается в `SERVER_INTERNAL` — процесс не падает, вызывающий получает `Err`.

## 4. Совместимость на время перехода

- Новый метод вызова `appApi.run(uc, input, actor)` возвращает `Result`.
- Старый `appApi.execute` сохраняет поведение «бросить при ошибке» (для новых UC — разворачивает `Err` в исключение), чтобы не переписывать все stories разом.
- Story переводится на `run` вместе с миграцией UC, который она вызывает.

## 5. Тестирование

- Ar: тест на каждую ветку `Ok`/`Err` каждого бизнес-метода.
- UC: тест на каждую объявленную ошибку, которую UC может вернуть сам (не базовую).
- Ядро: тесты `handle()` на перехват исключений и валидацию выхода.
