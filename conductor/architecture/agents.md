# Агентный процесс

**Назначение:** кто из агентов что делает, как передаётся работа и когда агент останавливается. Промпты агентов — `.pi/agents/*.md` (пишутся после утверждения каталога правил).

---

## 1. Роли

| Роль | Делает | Пишет в |
|---|---|---|
| **orchestrator** (основная сессия с Нурболатом) | декомпозиция на срезы, бриф среза, вызов агентов, решения по спорным местам, план трека | `conductor/` (не пишет прод-код) |
| **domain-author** | entity, Ar, Policy, Error, Event, Service, **все манифесты**, unit-тесты домена | `packages/domain` |
| **api-author** | реализации UC/ER/Job, порты и реализации репозиториев, фасады, wiring модуля, тесты | `packages/<module>` |
| **migrator** | перевод существующего кода на новую архитектуру с сохранением поведения | `packages/domain`, `packages/<module>`, точечно вызывающие stories |
| **reviewer** | проверка по [rules.md](./rules.md), отчёт с ID нарушений | только чтение |
| ui-author | позже | — |

**Автор ≠ ревьюер.** Ревьюер не исправляет код, только выдаёт отчёт.

## 2. Единица работы — вертикальный срез

Срез = один агрегат со своими UC/ER/Job. Конвейер:

```
orchestrator: бриф среза
  → domain-author (или migrator)  → bun run check
  → api-author    (или migrator)  → bun run check
  → reviewer      → отчёт
  → orchestrator: решение → правки автором → повторное ревью при необходимости
```

Параллельно запускаются только срезы из независимых контекстов.

## 3. Артефакты передачи

- **Бриф среза** — `conductor/tracks/<track>/slices/<slice>.md`: границы, список манифестов и реализаций, поведение, которое нужно сохранить (для migrator), критерии приёмки, применимые правила.
- **Отчёт автора** — в конце брифа: что сделано, отклонения от брифа и почему.
- **Отчёт ревьюера** — там же: таблица `ID правила | файл:строка | суть | severity`.

## 4. Эталон

Агенты копируют паттерн из **эталонного среза** (контекст `wish`, см. [migration.md](./migration.md)), а не из описаний. Скиллы перестраиваются под артефакты: шаблон, чеклист с ID правил, ссылка на файл эталона.

## 5. Условия остановки (эскалация к orchestrator)

Агент прекращает работу и возвращает вопрос, если:

- правило из каталога противоречит задаче или другому правилу;
- нужно изменить другой контекст domain или чужой модуль за пределами брифа;
- нужно изменить контракт (input/output/errors), от которого зависят чужие вызывающие стороны;
- тесты падают в коде, который агент не трогал;
- требуется любое действие с данными в `data/` (агенты данные не трогают; миграции данных выполняет только orchestrator с подтверждением Нурболата).

## 6. Инфраструктура

- Пример subagent-расширения pi: изолированные процессы, агенты в `.pi/agents/*.md`, запуск с `agentScope: "project"`.
- Каждый агент получает минимальный набор инструментов под свою роль (reviewer — без write/edit).
