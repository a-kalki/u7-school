# Слои и пакеты

**Назначение:** что где живёт, кто кого может импортировать, как работать с состоянием.

---

## 1. Пакеты

```
@u7-scl/core       фреймворк: Result, define*, базовые классы (Aggregate, UseCase, ...),
                   базовые поля F.*, граф-движок. Ничего не знает о школе.
@u7-scl/domain     вся предметка + все манифесты. Чистый, синхронный.
@u7-scl/app        технический слой: замыкает дженерики приложения (AppMeta, Actor, appApi)
packages/<module>  реализации UC/ER/Job, репозитории (порты + infra), реализации фасадов, wiring
apps/*             транспорты: u7-bot (UI), cli; позже http, mcp, doc-gen
```

| Пакет | Может импортировать |
|---|---|
| core | — |
| domain | core |
| app | core, domain |
| module | core, domain, app (не другие модули) |
| apps | всё, но логику вызывает только через `appApi` (UC) и `UiService` |

## 2. Структура domain (предварительно, фиксируется эталоном)

```
packages/domain/src/
  shared/              поля и VO школы поверх core F.*
  <context>/           user, course, stream, wish, questionnaire, peer-review, ...
    index.ts           публичный API контекста — единственная точка входа для других контекстов
    module.ts          defineModule: паспорт контекста, dependsOn
    <entity>/          state (схема entity), ar, policy, errors, events, uc/ (контракты)
    er/, job/          контракты реакций и заданий
    services/          *-api-service, *-ui-service
    facade.ts          контракт фасада
```

Подпути экспорта: `@u7-scl/domain` (объекты и манифесты), `@u7-scl/domain/state` (схемы и типы entity — **только infra и UI**), `@u7-scl/domain/ui` (UiService — только UI). Межконтекстные импорты — только через `index.ts` и только в объявленные `dependsOn`.

## 3. Работа с состоянием (D-05)

- **Entity** — форма хранимого состояния (valibot-схема + тип). Принадлежит агрегату.
- Доступ к данным entity: сам Ar; реализация репозитория (`restore` / `snapshot`); UI-зона (stories, UiService) как данные компонента.
- UC, ER, Job, ApiService, Policy, реализации фасадов — только API доменных объектов.
- **Контракты ≠ entity:** input/output UC, payload событий, DTO фасадов — объявленные схемы. Output может выводиться из схемы entity (`v.pick`).
- Ar отдаёт идентификаторы и **методы-вопросы** (`isOwnedBy`, `isTerminal`), а не геттер на каждое поле.

## 4. Три уровня API домена (D-06)

1. **Aggregate** — бизнес-операции (возвращают `Result`), вопросы к состоянию, события. Не создаёт и не возвращает другой Ar.
2. **Policy** — декларативные правила (`rule`, `anyOf`, `allOf`, `hasRole`), решение `allowed | denied(rule, message)`. Читает агрегаты через их API.
3. **Service:**
   - `ApiService` — операция над ≥2 агрегатами или логика, нужная ≥2 UC. Может мутировать, возвращает `Result`.
   - `UiService` — только чтение, работает с view-данными, оперирует UI-терминами. ApiService его не импортирует.
   - Оба могут принимать `Loader<T> = () => Promise<T>` — **только** когда загрузка условная или дорогая; по умолчанию получают готовые агрегаты.

## 5. Модульные пакеты

- **UC** — оркестрация: загрузить Ar → Policy → Ar/ApiService → сохранить → опубликовать события. Бизнес-логики в UC нет.
- **Репозиторий** — порт объявляется в модуле, возвращает/принимает Ar.
- **Фасад** — контракт в domain, реализация в модуле. Отдаёт DTO/VO, **никогда не Ar**.
