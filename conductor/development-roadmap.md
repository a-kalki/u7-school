## Порядок выполнения и релизы

### Принцип упорядочивания

Порядок продиктован **бизнес-приоритетом и реальными зависимостями** (не иллюзией «фундамент прежде всего»):

1. **Сначала bot-ui-refactoring** — архитектурная чистка. Разрыв циклических зависимостей, единая точка сборки UI, ActionFactory. Это незаметно пользователю, но критично для всей последующей разработки. Без этого metrics-инфраструктура (questionnaire из onboarding) не может быть выделена.

2. **Затем metrics** — бизнес-ценность. EventBus → questionnaire → пайплайн → витрина. Работает на существующей модели данных, не ждёт content-management.

3. **Последним content-management** — инструменты автора. Фундаментальные изменения модели данных (basedOn, visibility, snapshot, import/export, fork). Делается последним, потому что:
   - Не блокирует метрики и UI.
   - Требует последующей UI-адаптации в одном месте (загрузка title'ов из snapshot через DS callbacks вместо чтения из contentSnapshot). Это осознанный техдолг — ~1–2 дня доп. работы против месяцев ожидания метрик.

Внутри инициативы треки выполняются последовательно, в порядке номеров.

### Релиз 5: Фундамент контента — basedOn, visibility, CRUD, snapshot

**Инициатива:** [content-management.md](./content-management.md), треки 1–2

| Трек | Содержание |
|------|-----------|
| Трек 1 | `basedOn` на всех сущностях, visibility refactor (canRead/isPublished), CRUD (update, archive каскадом, structural ops), мета-поля (`planMd`, `lessonMd`, `summaryMd`, `sourcePath`) |
| Трек 2 | `contentSnapshot` → `stream/domain/` (чистое UUID-дерево без title'ов), `resolveModuleContent`, восстановление catalog/content-path/stream-creation |

**Миграции:**
- `modules.json`, `lessons.json`, `steps.json`: добавить поля `basedOn`, `planMd`, `lessonMd`, `summaryMd`, `sourcePath`
- `streams.json`: убрать title'ы из `contentSnapshot` (оставить чистое UUID-дерево)
- `courses.json`: добавить `basedOn`

**Критерий готовности к проду:**
- Все существующие потоки работают (frozen snapshot → archived → читается по UUID)
- Студент видит свой прогресс без изменений
- Ментор видит группу без изменений

**⚠️ Техдолг, возникающий в этом релизе:**
После Трека 2 contentSnapshot становится чистым UUID-деревом — title'ы больше не хранятся в snapshot, а грузятся live по UUID через DS callbacks. UI (перенесённый в Релизах 1–2) должен быть адаптирован:
- `tree-renderer.ts` — передача колбэков `getProjectTitle`/`getLessonTitle` вместо чтения title из snapshot
- Контроллеры `streams`, `learning`, `mentor` — формирование `TreeNode[]` без вложенных title'ов
- Это **локальное изменение** (~1–2 дня), не архитектурное. Хуки те же, сигнатуры меняются аддитивно.

## Диаграмма зависимостей

```
Релиз 1 (bot-ui 1-5) ──> Релиз 2 (bot-ui 6-9) ──> Релиз 3 (metrics infra) ──> Релиз 4 (metrics pipeline)
                                                                                       │
                                                                                       ▼
                                                               Релиз 5 (content-mgmt 1-2) ──> Релиз 6 (content-mgmt 3-4)
```

**Пояснение зависимостей:**

- **Релиз 2 → Релиз 1:** тривиально (последовательные треки внутри одной инициативы).
- **Релиз 3 (metrics) → Релиз 2 (bot-ui):** блокирующая зависимость. Questionnaire выделяется из onboarding. Onboarding-контроллер физически переезжает в `apps/u7-bot` только в Релизе 2 (Трек 8). Без этого неоткуда выделять questionnaire.
- **Релиз 4 → Релиз 3:** тривиально (инфраструктура → пайплайн внутри metrics).
- **Релиз 5 → Релиз 4:** зависимость **отсутствует**. Content-management меняет domain/api слои, metrics их не использует. Можно начинать сразу после Релиза 4.
- **Релиз 6 → Релиз 5:** тривиально (последовательные треки внутри content-management).

**Почему content-management последним, а не первым:**
- Метрики — бизнес-приоритет, не должны ждать инструментов автора.
- Content-management не нужен ни UI-рефакторингу, ни metrics.
- Единственное пересечение — UI-адаптация после Трека 2 (чистое UUID-дерево), ~1–2 дня. Это осознанный техдолг, окупающийся тем, что метрики в проде на 2–3 релиза раньше.
