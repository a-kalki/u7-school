# pi-tools: Гонка edit+bash в одном parallel-блоке — коммит ловит пустой файл

- **Симптомы:** `git add <file> && git commit` фиксирует пустую версию файла (blob `e69de29b`, «N deletions» вместо ожидаемого малого диффа), хотя на диске файл корректен и `wc -c` показывает нормальный размер.
- **Причина:** `edit` и зависимая от него `bash`-команда были отправлены в одном parallel-блоке вызовов инструментов. `git add` выполнился до того, как запись `edit` стала видна, — в индекс попал промежуточный (пустой) снимок файла.
- **Решение:** Не объединять `edit` и зависимые от него команды (git add/commit, тесты, grep по этому файлу) в один parallel-блок — bash должен идти отдельным сообщением после подтверждённого edit. Если пустой коммит уже создан и является HEAD — исправить amend'ом: `git add <file> && git commit --amend --no-edit`, затем проверить `git show HEAD:<file> | wc -c`.
