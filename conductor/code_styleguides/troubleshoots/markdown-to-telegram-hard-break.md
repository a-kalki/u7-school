# markdown-to-telegram: hard break превращается в голый `\` перед переносом — fail-fast валидатор роняет рендер экрана

- **Симптомы:** `MarkdownV2ValidationError: неэкранированный '\'` в `assertDialogResponseMarkdownSafe` / `assertMarkdownV2Safe` (стек через `#render` в `bot-transport.ts`). Экран/сообщение не уходит пользователю: кнопки «молчат», `/start` не помогает — рендер того же экрана падает снова, студент застревает.
- **Причина:** `convert()` из `markdown-to-telegram` рендерит markdown hard break (два пробела или `\` в конце строки исходника) как `\` + LF. Голый `\` перед переносом — issue для `validateMarkdownV2`. Ловится в проде fail-fast ДО отправки: у 7 из 500 шагов контента (например, «Проверь имя основной ветки», p1-l2).
- **Решение:** `safeConvert` (`packages/core/src/shared/markdown.ts`) пост-обрабатывает вывод конвертера через `unescapeLineBreaks()`: линейный скан по правилам валидатора снимает экранирование только у `\`+LF вне код-сущностей. Внутри pre/inline пары `\X` копируются как есть — там `\\` легитимен (например, bash-континуация), их снятие исказило бы код. Вид не меняется: обычный `\n` Telegram рендерит тем же переносом. Регресс-тесты — `markdown.test.ts`, блок «Hard break» в `describe('safeConvert')`.
