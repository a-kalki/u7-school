# Жизненный цикл диалога bot-ui: открытые проблемы (кандидат в трек 1.1)

**Статус: РЕШЕНО треком 1.1** (`bot-ui-dialog-lifecycle_20260905`, см. его [spec.md](../archive/bot-ui-dialog-lifecycle_20260905/spec.md)). Решения владельца зафиксированы в [bot-ui-session-architecture.md](./bot-ui-session-architecture.md), §10 (дополнения трека 1.1). Ниже — исходный разбор, сохранён как история.

**Итог по решениям:**
- **Проблема 1** — решена: явное состояние «диалог не открыт» (`BotSession.dialog?`, ФР-1), единая операция входа `enterDialog` с режимами `switch`/`reopen` (ФР-2), валидация кнопок **без исключений** — alert «Наберите /start» / «Экран устарел — нажмите /start» (ФР-3).
- **Проблема 2** — решена **вариантом A**: диалог открывается только действием пользователя; `send` в контракт не возвращается. Временный легаси-мост — `ProactiveSender.invite(telegramId, { text, keyboard })` (ФР-6, замена `notifyWithButtons`): кнопки штампуются seq текущей эпохи получателя на момент отправки; получателю без диалога транспорт открывает временный диалог-якорь `app/invite` (seq = 1) — приглашение не умирает, нажатие кнопки switch-ит диалог в целевую стори. Применение к анкетам — трек 4; опция deep-link URL-кнопки — тоже там. Метод `invite` и якорь — к удалению с приходом `tasks-system`.

**Контекст контракта:** [bot-ui-session-architecture.md](./bot-ui-session-architecture.md) (И1–И3, §4–§6, §10).

## Проблема 1: нет операции «открыть диалог» — правила `seq` рассыпаны по ядру

**Как проявилось.** Фикс `47a5b05f` (трек 2): `handleWelcome` должен был инкрементировать `seq` при повторном `/start`, но `#switchDialog` — no-op при совпадении `path` («меню → меню»). Все кнопки welcome-экрана были мертвы. Фикс точечный (явный `seq + 1`) — системная причина не устранена.

**Системная суть — три рассинхронизированные истины:**
1. Транспорт лениво создаёт сессию как `{path: menuPath, seq: 0}` («диалог как бы открыт»), но штампы валидны от 1 (И2) → **любые кнопки до первого `/start` мертвы** (alert «нажмите /start»). Каскад: кнопки временного `notifyWithButtons` у получателя без сессии уходят со штампом `~0` (`apps/u7-bot/src/infra/bot-transport.ts`, `notifyWithButtons`).
2. «Открыть меню заново» моделью не выражается: `#switchDialog` (`packages/core/src/ui/bot/ui-app.ts`) игнорирует совпадение `path` — смена диалога и «остаться в диалоге» неразличимы.
3. Точки инкремента `seq` рассыпаны: `handleWelcome` (явно), `#switchDialog` (при смене `path`), delegate. Каждая новая точка входа — кандидат в тот же класс бага.

## Проблема 2: проактивный запуск диалога удалён — `fill.start` сломан в бою

**Цепочка (студент записывается на курс с пулом анкеты):**
`course-catalog.story.ts` `#handleApply` → UC `create-course-wish` (wish) → `questionnaireFacade.startStandard` → `StartUc` (`packages/questionnaire/src/api/questionnaire/start-uc.ts`) — создаёт анкету, первый вопрос, публикует событие `questionnaire:start` → подписка `FillStory.#handleStartEvent` (`apps/u7-bot/src/controllers/questionnaire/stories/fill.story.ts:56`) должна отправить вопрос и **захватить текстовый ввод** (`captureInput: {path: 'fill'}`) через `proactiveSender.send`.

**Что сейчас:** метода `send` в новом `ProactiveSender` нет (И3: проактив не пишет сессию; «проактивный запуск диалога невоспроизводим синтаксически»). В бою:
- TypeError изолируется шиной (`InProcEventBus`, console.error) — бот не падает;
- анкета создана, желание `pending`, но **вопрос не доставлен**; `#handleApply` возвращает `{}` (`course-catalog.story.ts:554`, расчёт на проактив) — студент видит «ничего»;
- восстановление — только через планировщик (`questionnaire:continue-invite`) или повторное нажатие (ветка conflict «продолжить анкету»).

**Затронуты тем же (остатки `proactiveSender.send`, все — рантайм-падения):** `invite.story.ts:47` (S01-приглашение, `questionnaire:invite` от `send-likert-invite-uc`), `fill.story.ts:99` (continue-invite, кнопки + легаси-`takeover`), `fill.story.ts:135` (abandon-warning, кнопки + `takeover`). Тесты этих сторей зелёные — они мокают `send`, бою не соответствуют.

## Варианты решения

> **Принято: вариант A** (решение владельца, сессия 2026-09-05; уточнение при ревью 2.2 — якорь `app/invite`). Варианты B/C не реализуются: потребность в сервер-инициированных диалогах позже закроет `tasks-system`.

**A. Приглашение кнопкой (И3-совместимо, без изменений ядра).**
`questionnaire:start` → `notifyWithButtons` «📋 Анкета — начать» → кнопка-мост `fill:resume:<id>` → обычный callback открывает диалог (`seq++`, `awaitInput`), дальше штатный флоу fill. Проактив только зовёт, не запускает. UX-смена: студент ткнет кнопку, чтобы начать. Закрывает и invite/continue-invite/warning. Реализуемо в рамках существующего трека 4 (анкеты).

**B. Проактивное открытие диалога как операция ядра.**
В `ProactiveSender` появляется честная операция «открыть диалог получателя» (создать/переключить, отправить экран, поставить `awaitInput`). Требует сначала проблему 1: операция открытия с ясными правилами (identity/epoch диалога, конфликт с активным вводом получателя). Ломает И3 в явной форме — но анкеты и будущий модуль задач (`system-task`, см. [tasks-system-architecture.md](./tasks-system-architecture.md)) показывают: «сервер-инициированные диалоги» — реальная потребность, а не костыль.

**C. Гибрид (рекомендация).**
B + деградейшн: если получатель в активном диалоге/вводе — поведение A (приглашение). Решается естественно, если проблема 1 решена (открытие — операция с проверкой состояния). Без трека 1.1 выродится в костыль.

**Зависимость:** проблема 1 — фундамент для B/C. Вариант A может быть применён независимо (трек 4), но тогда B/C позже всё равно потребуют ревизии анкетных уведомлений.

## Материал для генерации трека 1.1

- **Скоуп:** ядро (`packages/core/src/ui/bot/*`, транспорт `apps/u7-bot/src/infra/bot-transport.ts`, их тесты) + документация контракта (§4/§5/§10). Прикладные стори не трогать («трек уменьшает»); применение к анкетам — трек 4.
- **ФР-кандидаты:** единая операция открытия/смены диалога (identity, все точки: `/start`, delegate, мосты, проактив — по выбранному варианту); явное состояние «диалог не открыт» вместо магии `seq = 0`; инвариант-тесты: повторный `/start`, кнопка до `/start`, delegate «меню → меню», мост в свою стори, кнопки `notifyWithButtons` у получателя без сессии; документирование контракта `notifyWithButtons` (тех-долг до `system-task`).
- **Критерии:** класс сценариев покрыт тестами; документация обновлена; скоуп ядра зелёный (tsc/biome/тесты); легаси остаётся заявленно красным.
- **За рамками:** миграция сторей (треки 3–5), персистентность (трек 6), сам `system-task`.
