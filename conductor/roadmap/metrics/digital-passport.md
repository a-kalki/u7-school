# Цифровой паспорт — концепция

> v1 (2026-09-16). Бизнес-концепция модуля `passport`: зачем школе цифровой паспорт
> выпускника, что в него входит, откуда данные. Модуль реализуется **после**

> паспорта.

## Бизнес-цель

Школа выдаёт студентам подтверждение пройденного пути в двух формах:

1. **Для студента — «Сформировать рекомендацию».** По нажатию кнопки создаётся
   PDF-файл, агрегирующий всю информацию об обучении в компактном виде, с
   QR-кодом — читатель (работодатель, другое учебное заведение) может открыть
   «живую» версию по ссылке.
2. **Для компании (работодателя) — «живой» просмотр.** По QR-ссылке открывается
   веб-витрина паспорта: трек обучения — какие модули проходил студент, как
   проявлялся, какие отзывы получал.

Достоверность обеспечивается источниками: цифры и тексты приходят из доменных
систем школы, а не от студента. Студент — куратор композиции (что показать),
но не автор фактов.

## Из чего состоит паспорт

Шесть источников (оси «факты о человеке»):

| Источник | Что даёт | Модуль-поставщик |
|---|---|---|
| Системные метрики | Цифры по зафиксированным действиям: посещаемость, регулярность, скорость прохождения | `stream` |
| Анкетные метрики по мероприятиям | Баллы скилов по итогам сессий (код-ревью, парное программирование) | `questionnaire` → `dossier` |
| Отзывы по мероприятиям | Тексты отзывов участников сессий | `peer-review` |
| Анкетные метрики по окончанию модулей | Кросс-анкеты группы и ментора по завершению модуля | `peer-review` → `dossier` |
| Отзывы по модулям | Тексты отзывов одногруппников и ментора по завершению модуля | `peer-review` |
| Рекомендация по окончанию курса | Финальный отзыв ментора и студентов о выпускнике | `peer-review` (контекст «курс завершён») |

Плюс **портфолио** — результаты работ студента (проекты из модулей, артефакты
шагов; источник — контентная часть системы) и **балл вклада** — блок «член
сообщества» ([contribution-system](../contribution-system.md)).

## Структура PDF — три части

1. **Метрики** — цифры по скилам по результатам мероприятий: категории и
   подкатегории [концепции метрик](./metrics-conception.md), пороги достоверности,
   динамика по модулям.
2. **Портфолио** — результаты работ: выбранные студентом проекты, ссылки,
   описание сферы ответственности.
3. **Рекомендация** — обобщающая информация: итоговая рекомендация ментора,
   выдержки отзывов, общий рейтинг.

## Кураторские выборки студента

Студент сам собирает композицию паспорта (не факты — их состав):

- добавлять/исключать отдельные отзывы из публикации;
- указывать отдельные проекты в модулях и свою сферу ответственности в них;
- выбирать, какие части показывать в PDF (например, без метрик — только
  портфолио и рекомендация).

Кураторские выборки — состояние паспорта студента, а не изменение источников:
исключённый отзыв остаётся в peer-review, просто не попадает в витрину/PDF.

## Модуль `passport`

- Пакет `packages/passport` (будущий) + UI: кнопка «Сформировать рекомендацию»,
  экраны кураторских выборов.
- Агрегат: паспорт студента — композиция выбранных фактов (ссылки на источники +
  кураторские пометки: видимость, роль в проекте, порядок). Факты не копируются —
  читаются фасадами поставщиков при сборке витрины/PDF.
- Сборка — Ds/UC по скоупу (студент): опрос фасадов `peer-review` (отзывы,
  оценки, снапшоты участников), `dossier` (обобщённые объекты по модулям
  и досье студента), `stream`
  (системные метрики, трек модулей), `sessions` (сессии студента), контент
  (портфолио).
- Каналы рендера (канало-независимый контракт → рендереры):
  - **бот** — компактная витрина + управление выборками;
  - **PDF** — генерация файла (библиотека — при планировании трека; зафиксировать
    в [tech-stack](../../tech-stack.md) до реализации);
  - **web-витрина** — страница по публичной ссылке из QR-кода.

## Открытые вопросы

1. Публичная ссылка QR: срок жизни, отзыв, авторизация читателя (без неё?),
   хостинг web-витрины — первый веб-интерфейс школы.
2. Кто видит паспорт: только студент-владелец или также ментор/школа?
3. Формат PDF: A4, одна/несколько страниц, лимиты объёма частей.
4. Рекомендация по курсу: новый контекст кампании peer-review (`course_completed`)
   или отдельная сущность — при планировании трека отзывов о курсе.
5. Анти-манипуляции: что происходит с QR-ссылкой при исключении студентом отзыва
   (перегенерация?), контроль «снятия с публикации» задним числом.
6. Автопортрет для ушедших (`abandoned`): доступен ли паспорт и с какими частями.
