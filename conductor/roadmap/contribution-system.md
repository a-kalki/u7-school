# Система вклада — Концепция

> v1 (2026-09-15). Бизнес-концепция измерения вклада человека в школу и сообщество. Уровень документа — концепция продукта; модуль `contribution` реализуется **после** модуля метрик (зависит от `task`, `questionnaire`, `metrics`). Архитектурные детали — в spec трека при планировании.

---

## Бизнес-контекст: два измерения человека

Человек в школе проявляется в двух ролях, и профиль должен показывать обе:

| Измерение | Роль | Вопрос профиля | Источники |
|---|---|---|---|
| **Навыки** | Студент | Насколько человек развит и как применяет навыки | Анкеты: кросс-анкеты модулей, сессии ([sessions](./sessions-system.md)), инициативные отзывы |
| **Вклад** | Член сообщества | Что человек сделал для школы и сообщества | Кросс-анкеты командных задач, явные фиксации вклада |

Навыки и вклад измеряются независимо: сильный студент может не вкладываться в сообщество, а вкладчивый участник — не быть студентом текущих курсов. Итоговая витрина профиля делится на два блока (расширение §8 [концепции метрик](./metrics-conception.md)).

## Что такое вклад

**Вклад** — действие, развивающее школу и/или сообщество: менторство, создание контента, организация мероприятий, помощь новичкам, инфраструктура, модерация — поверх личного обучения.

Вклад не измеряется анкетами навыков: «качество кода» и «помог провести набор» — разные оси. Для вклада — собственные анкеты и собственные баллы (`ContributionScore`), агрегируемые модулем `metrics` в тот же профиль.

## Источники оценки вклада

### 1. Командные задачи → кросс-анкета

В системе запускается задача (модуль `task`). Если задача **командная**, по её завершении запускается кросс-анкета: каждый участник оценивает вклад остальных в достижение общей цели. Из оценок высчитывается балл вклада каждого участника.

- Триггер — событие завершения командной задачи.
- Анкета — likert (движок `questionnaire`, `likertMapping` с категорией вклада), приглашения — задачи-приглашения (механика трека 3.1 [документа 3](./metrics-pipeline-and-modules.md) — переиспользуется).
- Балл вклада в задачу агрегируется в общий балл вклада человека (формулы — по образцу §7 [концепции метрик](./metrics-conception.md), веса — при проектировании).

### 2. Явная фиксация вклада

Любой человек в любой момент может явно запустить оценку вклада, чтобы зафиксировать его:

- **кто** — субъект вклада (человек, чей вклад фиксируется);
- **место вклада** — контекст: задача, мероприятие, канал, проект (привязка к сущностям либо свободное описание);
- **что** — что именно было сделано (текст);
- **оценка** — опциональная likert-шкала «значимость вклада».

Аналог инициативного отзыва о навыках (§4 [концепции метрик](./metrics-conception.md)), но ось другая: отзыв фиксирует применённый **навык**, фиксация вклада — **действие для сообщества**. Оба используют одну механику: место + описание + likert.

## Связь с существующими и будущими модулями

| Модуль | Связь |
|---|---|
| `task` | Командные задачи — источник вклада №1; завершение задачи — триггер кросс-анкеты |
| `questionnaire` | Движок анкет вклада: новые пулы, `likertMapping` с категорией вклада |
| `metrics` | Агрегация `ContributionScore` → блок «член сообщества» в витрине профиля; порог достоверности — по образцу навыков |
| `sessions` | Сессии измеряют навыки; если сессия одновременно является вкладом (например, менторская встреча) — фиксируется отдельно (см. открытые вопросы) |

## Открытые вопросы

1. Каталог категорий вклада (менторство / контент / мероприятия / инфраструктура / ...) — нужен ли для витрины и весов?
2. Подтверждение явной фиксации: субъект принимает вклад или молчание = согласие? Анти-накрутка.
3. Веса источников: балл из командной задачи против явной фиксации — равнозначны?
4. Менторство: это вклад, навык, или обе оси одновременно?
5. Связь с геймификацией/статусами сообщества (если появятся).
