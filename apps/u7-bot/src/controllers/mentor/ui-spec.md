# Спецификация экранов Mentor (UI Spec)

Документ описывает экраны Telegram-бота модуля Mentor: мониторинг студентов, карточка студента.
Служит **отправной точкой для разработки** — что уже реализовано, что запланировано.

Условные обозначения:
- ✅ реализовано
- ❌ не реализовано
- 📋 в бэклоге / запланировано в треке

---

## S07 — Мониторинг (список студентов)

**Как попасть:** `👥 Студенты` в S02 (curious) или `👥 Студенты` в S02m (mentor).
**Кому:** **всем ролям** (прозрачность). Кнопки действий — только ментору/админу.
Веток две: публичная (`view-stream:students`, из S02 — все студенты, без фильтра
и без кнопок действий, кнопка студента → публичная карточка) и менторская
(`monitor:students`, из S02m — фильтр выбывших + кнопки действий).

**Содержание (секции в тексте):**
```
👥 Студенты потока — {Название}
Всего: N студентов, из них M активных, P выбывших
———
Метрики группы (по видимым студентам, каждая с новой строки, только ненулевые):
🏃 В процессе: N
✅ Прошли: N
↩️ Не прошли: N
🚫 Выбыли: N
Легенда:
🏃 учится   ✅ прошёл   ↩️ не прошёл   🚫 выбыл
———
Метрики по студентам:
🛑 Имя | [████░░] N/M N% | ⚡ Спринтер: N мин
...
Легенда:
🛑 критическое отставание, кандидат на снятие с учёбы
⚠️ учится, но отстаёт от группы
🏃 в норме, учится
🚫 выбыл из учёбы
↩️ завершил модуль, но пройдет заново
✅ завершил модуль, проходит дальше
```

**Фильтр выбывших (трек student-inactivity):**
- Дефолт — только активные (active/enrolled): текст, кнопки и метрики — по активным.
- Сводка «Всего: N студентов, из них M активных, P выбывших» — по всем, видна всегда.
- Режим «все» (`monitor:students-all`) — показывает всех; метрики в нём — тоже по всем.

**Кнопки (каждый студент — строка из 1-3 кнопок):**

| Текст | Код | Условие | Статус |
|-------|-----|---------|--------|
| `{Маркер} {Имя} — N%` | `monitor:detail:{id}` | видимый (активный в дефолте) | ✅ |
| `⛔` | `monitor:mark-abandoned:{id}` | status=active + canManage (в обоих режимах; enrolled — без кнопок) | ✅ |
| `✅` | `monitor:complete:{id}` | status=active + canManage (в обоих режимах) | ✅ |
| `🔄` | `monitor:complete:{id}` | advanced/not_advanced + canManage (видимы только в режиме «все») | ✅ |
| `👁 Показать выбывших` | `monitor:students-all:{streamId}` | дефолт (есть скрытые) | ✅ |
| `🙈 Скрыть выбывших` | `monitor:students:{streamId}` | режим «все» | ✅ |
| `⬅️ Назад к потоку` | `view-stream:view:{streamId}` | всегда | ✅ |

**Маркеры:** 🛑 critical / ⚠️ lagging / 🏃 on_track / ✅ advanced / ↩️ not_advanced / 🚫 abandoned.
**Сортировка:** 🛑 → ⚠️ → 🏃 (lag-приоритет) → завершённые в конец → по убыванию прогресса.
**Детализация** (прогресс-бар, категория времени) — в тексте сообщения, не в кнопках.

**Снятие с учёбы (⛔ → confirm):** «⚠️ Снять студента *{Имя}* с учёбы за бездействие?» →
`⚠️ Да, неактивен` / `❌ Отмена` → реплика «✅ Студент *{Имя}* снят с учёбы.» + возврат к списку.
**Завершение (✅/🔄):** экран выбора исхода (`✅ Прошёл` / `↩️ Не прошёл` / `🔴 Выбыл` / `❌ Отмена`)
→ confirm → реплика «✅ Студент *{Имя}* завершён.» + возврат к списку.

## S08 — Карточка студента

**Как попасть:** клик на студента в S07.
**Кому:** **всем ролям** (прозрачность). Кнопок действий в S08 нет — все в S07.

**Содержание (три секции с разделителями):**
```
👤 {Имя} | 🟢 Учится
———
Прогресс студента:
📊 Прогресс по модулю: [████░░] N/M | N%
📁 Проект: «{Название}»
📝 Урок: «{Название}»
📊 Прогресс по проекту: [████░░] N/M | N%
———
Усидчивость студента:
⏱ Типичное время на шаг: N мин.
🏃 Бегун (< 1 мин.): N шаг(ов)
⚡ Спринтер (< 5 мин.): N шаг(ов)
🐢 Вдумчивый (< 15 мин.): N шаг(ов)
📚 Исследователь (> 15 мин.): N шаг(ов)
———
Активность студента:
📅 Последняя активность: N дн. назад   (или N ч. назад, если меньше суток)
🛑 Критическое отставание: N дн.
```
(или `⚠️ Отстаёт: N дн.` / `⚠️ Отстаёт от группы` (< 4 дн.) / `✅ Идёт по расписанию`)

`StatusLabel`: `🟢 Учится` / `🚫 Выбыл` / `✅ Прошёл` / `↩️ Не прошёл`.

**Кнопка:**

| Текст | Код | Статус |
|-------|-----|--------|
| `⬅️ Назад к списку` | `monitor:students:{streamId}` | ✅ |

> Категории времени показываются **всегда** (даже с нулями). Источник: `StreamDs.computeStudentCard`.
