# Спецификация экранов Peer Review — Отзывы (UI Spec)

Документ описывает экраны Telegram-бота модуля отзывов: сбор текстовых отзывов
по окну судьбы студента потока и их просмотр. Отзывы всегда видны всем.

Служит **отправной точкой для разработки** — что уже реализовано, что запланировано.

> Обновлено 2026-09-20 под решения сессии (4-значная проекция исходов, форма
> кампании с `subjectOutcome`/`mentorId`, `direction` отзыва, тексты без
> ролей/статусов). Доменные изменения — трек `peer-review-outcomes_20260920`.

Условные обозначения:
- ✅ реализовано
- ❌ не реализовано
- 📋 в бэклоге / запланировано в треке

---

## Путь пользователя

Текущие входы:

- **По приглашению:** событие судьбы студента (`student.completed` /
  `student.abandoned`) → домен создаёт кампанию → событие
  `student-campaign.created` → **два** персонализированных приглашения (S01):
  субъекту и ментору → кнопка ведёт **сразу в кампанию** (S03).
- **Из главного меню (хаб «Отзывы»):** кнопка `💬 Отзывы` в главном меню
  (видна при наличии живых кампаний) → S02 «Мои отзывы» → кампания → S03.
- **Чтение:** «💬 Отзывы» в карточке потока (streams S02) → постраничный
  просмотр (S07).

Будущие входы (бэклог): задача в `/tasks` «Заполните отзывы по потоку {name}»
с кнопкой «Выполнено» (task-модуль); кнопка «Анкета» (likert-метрики —
отдельная от отзыва точка входа).

## Доменные основы (для контекста спека)

- `ReviewCampaign` — **окно судьбы студента (субъекта)** в потоке, контекст
  `stream_fate`, окно 7 дней (константа). Ядро: `scopeId`, `subjectId`,
  `participants` — **только id адресуемых соучеников** (без статусов и ролей),
  `createdAt`/`updatedAt`/`expiresAt`. Специфика контекста — в `payload`:
  `subjectOutcome` (исход субъекта) и `mentorId` (второй автор окна).
- Состав `participants` решает ER при создании: событие «завершил» → все
  завершившиеся и ещё учащиеся соученики (кроме субъекта); «забросил»/
  «не начал» → пустой список (адресат только ментор).
- **Проекция исходов — 4 значения** (собственный словарь модуля, сырые статусы
  студента сюда не попадают): `completed_passed` «завершил и прошел»,
  `completed_not_passed` «завершил и не прошел», `dropped` «забросил»,
  `never_started` «не начал». «Ещё учится» не хранится.
- Разрешённые адресаты: субъект → ментор + `participants` (пусто — только
  ментор); ментор → только субъект. Никогда — отзыв о себе.
- `Review`: `authorId`, `recipientId`, **`direction`** (`student_student` |
  `student_mentor` | `mentor_student`), `authorOutcome` — снапшот исхода
  автора-студента (для рендера «статуса автора» и будущих весов в досье),
  `scopeId`, `campaignId`, `text`. Один отзыв на пару (автор, адресат) в
  кампании, перезапись разрешена в пределах окна.
- **Статусы/роли в UI:** в приглашениях, кнопках и подсказках — никаких
  статусов и ролей участников; статус показывается **только у автора отзыва**
  в просмотре (S07). Исход автора используется UI скрытно — только для выбора
  текста-подсказки (S05) и текста приглашения (S01).
- Окно проверяет домен — UC не считает даты сам: живость конкретной кампании
  подтверждает агрегат (доменная ошибка «возможность закрыта»), списки живых
  кампаний отдаёт репозиторий (метод «дай активные»). Истекло → сторя рендерит
  экран-заглушку.

## S01 — Приглашение (invite) 📋

**Когда:** событие `student-campaign.created` (кампанию создал ER домена по
`student.completed` / `student.abandoned`).
**Кому:** двое — субъект кампании и ментор скоупа (по `mentorId` из события).
Одно приглашение каждому, напоминаний нет (до task-модуля).

Тексты — **без упоминания ролей и статусов**; текст субъекту выбирается по
`subjectOutcome` из события (скрыто от пользователя):

Субъекту (исход «завершил и прошел» / «завершил и не прошел» — по умолчанию
одинаковый; отдельный текст для «не прошел» — решение UI при реализации,
данные для этого в событии есть):
```
🏁 Отзывы по потоку «{StreamTitle}»

Поделитесь впечатлениями об одногруппниках и менторе — это часть
цифрового профиля каждого. Пишите только правду.
```

Субъекту (исходы «забросил» / «не начал»):
```
🏁 Отзывы по потоку «{StreamTitle}»

Поделитесь впечатлениями о менторе и учёбе — это поможет школе
и тем, кто только выбирает, учиться ли. Пишите только правду.
```

Ментору:
```
🏁 Отзывы по потоку «{StreamTitle}»

Выдайте свой отзыв для {Имя}: как он проявлялся в учёбе, что удалось,
что стоит подтянуть. Пишите только правду.
```

| Кнопка | Действие | Статус |
|--------|----------|--------|
| `💬 Отзывы` | → S03 (кампания этого субъекта) | 📋 |

> Механика invite (ФР-6): кнопка работает, даже если получатель давно не
> открывал бота; при устаревании — `/start`.

## S02 — «Мои отзывы» (хаб отзывов, список кампаний) 📋

**Как попасть:** кнопка `💬 Отзывы` в главном меню (декларативная
`menuButtons` стори, асинхронная видимость) — видна при наличии живых кампаний;
нет кампаний — нет кнопки.

**Формат:** тело сообщения — расшифровка «о ком» в расширенной форме, кнопки —
короткие (решение владельца, 2026-09-20):

```
💬 Мои отзывы — о ком можно рассказать:

1. Поток «{title}» — одногруппники и ментор. Осталось {N} дн.
2. Поток «{title}» — отзыв о {Имя}. Осталось {N} дн.
```

| Кнопка | Условие | Статус |
|--------|---------|--------|
| `🏁 Поток «{title}» · {N} дн.` | живая кампания | 📋 |
| `↩️ Главное меню` | всегда | 📋 |

> Рендер по `myRole` (из `get-my-campaigns`): субъекту — «одногруппники и
> ментор» (+ прогресс M/K — мои отзывы / доступные адресаты), ментору —
> «отзыв о {Имя}» (имя субъекта — batch-запрос пользователей).
> Из приглашения (S01) — сразу в кампанию (S03), минуя этот экран.

## S03 — Список адресатов кампании ✅

**Как попасть:** кнопка `💬 Отзывы` из приглашения (S01) или выбор кампании
в S02.

```
✍️ Поток «{title}». О ком хотите рассказать? Пишите кому хотите
и сколько хотите.
⏳ Возможность открыта ещё {N} дн.
```

*Легенда:*
✅ — если мой отзыв об адресате уже есть:

| Кнопка | Условие | Статус |
|--------|----------|--------|
| `✅ Студент: {Имя}` | адресат-студент, отзыв уже есть | ✅ |
| `Студент: {Имя}` | адресат-студент, отзыва нет | ✅ |
| `Ментор: {Имя}` / `✅ Ментор: {Имя}` | адресат-ментор | ✅ |
| `↩️ Главное меню` | всегда | ✅ |

> Состав кнопок определяет кампания: адресаты-студенты — из `participants`,
  ментор — из payload; в некоторых кампаниях доступен только ментор.
> Роли в лейблах (`Студент:` / `Ментор:`) — только надписи; в callback —
  id адресата, роли клиент не передаёт.
> ✅ — только мои отзывы. Чужие — в просмотре (S07).
> Отдельной кнопки «Закончить» нет: выход — главное меню или `/cancel`;
> кампания живёт до конца окна независимо от выхода.

## S04 — Перезапись (ввод с заменой) ✅

**Как попасть:** клик по ✅-адресату в S03. Отдельной кнопки «Перезаписать»
нет — экран сразу принимает текст.

```
✏️ Вы уже писали о {Имя}:

«{текущий текст отзыва}»

Отправьте новый текст — он заменит текущий.
Или нажмите «Назад».
```

**Ввод:** тот же контракт, что в S05 (10–3500 символов, переспросы без
потери контекста).

| Кнопка | Действие | Статус |
|--------|----------|--------|
| `❌ Назад` | → S03 без изменений | ✅ |

## S05 — Ввод отзыва ✅

**Как попасть:** клик по адресату без ✅ в S03.

Текст-подсказка выбирается по направлению «кто о ком», а для направления
«о менторе» — ещё и по исходу автора (`myOutcome` из UC; исход в UI нигде
не отображается, только выбирает текст — решение владельца, 2026-09-20):

- студент → о студенте:
  «Расскажите о {Имя}. Как бы вы описали его профессиональные, командные
  и личностные качества? Не обязательно перечислять всё — пишите только то,
  что хотите написать, и пишите правду. Если считаете, что что-то стоит
  подтянуть, — напишите и об этом.»
- ментор → о студенте:
  «Расскажите о студенте {Имя}: сильные стороны, чего удалось достичь
  за поток, что стоит подтянуть.»
- «завершил и прошел» → о менторе:
  «Поделитесь впечатлением о работе с ментором {Имя}: что помогало учиться,
  что мешало, чего не хватило. Пишите правду — это поможет и ментору,
  и школе.»
- «завершил и не прошел» → о менторе:
  «Поделитесь впечатлением о работе с ментором {Имя}: что помогало, что
  мешало, чего не хватило. Даже если итог не тот, на который рассчитывали, —
  ваша правда поможет и ментору, и школе.»
- «не начал» → о менторе:
  «Почему так и не начали учёбу? Что не совпало с ожиданиями? Ваши
  впечатления о менторе и школе помогут тем, кто только выбирает.»
- «забросил» → о менторе:
  «Почему забросили учёбу? Какие пожелания оставите школе и ментору?
  Что стоит ожидать людям, которые рассматривают возможность здесь учиться.»

**Ввод:** 10–3500 символов; короче — переспрос, длиннее — «пожалуйста,
сократите» (контекст не теряется). `/cancel` — выход из диалога отзывов.

| Кнопка | Действие | Статус |
|--------|----------|--------|
| `⏭️ Пропустить` | → S03 без сохранения | ✅ |

## S06 — Сохранение → возврат в список ✅

После сохранения — **новый экран** с обновлённым списком адресатов:

```
✅ Отзыв о {Имя} сохранён. О ком ещё рассказать?
⏳ Возможность открыта ещё {N} дн.
```

Кнопки — как в S03 (у {Имя} появился ✅).

## S07 — Просмотр отзывов (чтение, пагинация) 📋

**Как попасть:** «💬 Отзывы» в карточке потока (streams S02). Только чтение —
кнопок перехода в живую кампанию отсюда нет.

Кнопка в карточке потока видна, если есть хотя бы один отзыв по потоку.

**Формат** — группировка по адресатам; у адресата — только роль, у автора —
роль и лейбл исхода-снапшота (`authorOutcome`, из отзыва):

```
💬 Отзывы — поток «{StreamTitle}» · стр. 1/3
———
👤 {Имя} (студент):
«{текст}» — {автор} (студент · завершил и прошел)
👤 {Имя} (студент):
«{текст}» — {автор} (студент · не начал)
👤 {Имя} (ментор):
«{текст}» — {автор} (студент · завершил и не прошел)
```

> Лейблы исходов: «завершил и прошел» / «завершил и не прошел» / «забросил» /
  «не начал». Автор-ментор — без лейбла. Статус адресата не показывается.
  Роли выводятся из `direction`.

| Кнопка | Условие | Статус |
|--------|---------|--------|
| `‹ Пред` | не первая страница | 📋 |
| `След ›` | не последняя страница | 📋 |
| `⬅️ Назад к потоку` | всегда | 📋 |

> Разбиение постраничное: страница наполняется целыми отзывами до лимита
  символов (запас на шапку и клавиатуру, суммарно < 4096); отзыв не рвётся
  посередине. Имена авторов/адресатов резолвятся batch-запросом пользователей
  до нарезки страниц.

### Абстракция пагинации 📋

> Пагинатор уже готов — трек `pagination` (ядро в core `ui/pagination`,
> бот-наследник `BotPaginator` + системный кеш `DialogCache` в core `ui/bot`).
> S07 потребляет его готовым. Это не вопрос ui-spec.

## Бэклог

- 📋 **Задача `/tasks`** — при появлении кампании создаётся (или может
  создаваться) задача «Заполните отзывы по потоку {name}» с кнопкой
  «Выполнено» → кампания (S03). Требует task-модуль.
- 📋 **Метрики-анкеты (likert)** — раздельная от отзыва кнопка «Анкета».
  Паттерн интеграции: кампания запускает анкету через фасад questionnaire
  с `ownerInfo` (context/scopeId/targetId); ER peer-review на
  `questionnaire.completed` раскладывает ответы по своим местам.
- 📋 **Кампании по сессиям** (код-ревью, парное программирование — в парном
  возможно несколько смотрящих) — новый payload-тип контекста при том же
  ядре кампании. Детали — концепция `peer-review-system.md`.
- 📋 **Напоминания об окне** — с task-модулем.
- 📋 **Отзывы о курсе** — отдельный контекст.

## Снятые решения

- Видимость отзывов: всем и всегда в карточке потока; ✅-маркеры — только свои отзывы.
- Окно: 7 дней (константа); истекло — возможности нет, домен отклоняет запись.
- Длина текста: 10–3500; переполнение — просить сократить.
- Перезапись: разрешена в окне, без confirm-кнопки — ввод сразу заменяет,
  «Назад» отменяет.
- Приглашение персонализировано: кнопка ведёт сразу в кампанию (S03).
- Хаб «Отзывы»: кнопка главного меню (видна при живых кампаниях) → S02.
- Роли в кнопках: `Студент: {Имя}` / `Ментор: {Имя}`, ✅ при наличии отзыва.
- S07 — только чтение, с пагинацией.
- Анкета и отзыв — раздельные точки входа.
- **2026-09-20:** триггер приглашений — `student-campaign.created` (два
  получателя: субъект и ментор); тексты приглашений — без ролей и статусов;
  статус показывается только у автора отзыва (S07); проекция исходов —
  4 значения («завершил и прошел» / «завершил и не прошел» / «забросил» /
  «не начал»); `participants` кампании — только id адресуемых соучеников
  (без статусов; для «забросивших» — пусто), `subjectOutcome`/`mentorId` — в
  payload; отзыв хранит `direction` вместо пары ролей, `authorOutcome`
  остаётся; подсказки S05 «о менторе» — по исходу автора (4 варианта);
  S02 — расшифровка «о ком» в теле, короткие кнопки; имена — batch-запросом;
  видимость меню — асинхронная.
