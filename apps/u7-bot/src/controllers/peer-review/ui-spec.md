# Спецификация экранов Peer Review — Отзывы (UI Spec)

Документ описывает экраны Telegram-бота модуля отзывов: сбор текстовых отзывов
по окну судьбы студента потока и их просмотр. Отзывы всегда видны всем.

Служит **отправной точкой для разработки** — что уже реализовано, что запланировано.

> Обновлено 2026-09-22 по итогам живого прогона (Фаза 6 трека `peer-review-ui`):
> контекст судьбы в карточках S02/S03, метрики в мини-карточке и развёрнуто
> в S03, нумерация карточек ↔ кнопок, тон всего модуля — на «ты».
> Обновлено 2026-09-21 треком `peer-review-ui` — реализованы S01–S07 (стори
> invite / my-reviews / campaign / scope-reviews). Ранее обновлено 2026-09-20
> под решения сессии (4-значная проекция исходов, форма кампании с
> `subjectOutcome`/`mentorId`, `direction` отзыва, тексты без
> ролей/статусов). Доменные изменения — трек `peer-review-outcomes_20260920`.

Условные обозначения:
- ✅ реализовано
- ❌ не реализовано
- 📋 в бэклоге / запланировано в треке

## Путь пользователя

Текущие входы:

- **По приглашению:** событие судьбы студента (`student.completed` /
  `student.abandoned`) → домен создаёт кампанию → событие
  `student-campaign.created` → **два** персонализированных приглашения (S01):
  субъекту и ментору → кнопка ведёт **сразу в кампанию** (S03).
- **Из главного меню (хаб «Отзывы»):** кнопка `💬 Отзывы` в главном меню
  (видна при наличии живых кампаний) → S02 «Мои отзывы» → кампания → S03.
- **Чтение:** «💬 Отзывы» в карточке потока (streams S02) → постраничный
  просмотр (S07).

Будущие входы (бэклог): задача в `/tasks` «Заполните отзывы по потоку {name}»
с кнопкой «Выполнено» (task-модуль); кнопка «Анкета» (likert-метрики —
отдельная от отзыва точка входа).

**Тракт подсказок** (решение 2026-09-22): ведём пользователя от общего
к частному — S01 (событие + общая ценность) → S02 (краткий контекст судьбы) →
S03 (кому и зачем твой отзыв, по адресатам) → S05 (что именно и как:
конкретные вопросы + мягкий шаблон ответа). Ценность не повторяем на каждом
экране — каждый следующий добавляет конкретику.

## Доменные основы (для контекста спека)

- `ReviewCampaign` — **окно судьбы студента (субъекта)** в потоке, контекст
  `stream_fate`, окно 7 дней (константа). Ядро: `scopeId`, `subjectId`,
  `participants` — **только id адресуемых соучеников** (без статусов и ролей),
  `createdAt`/`updatedAt`/`expiresAt`. Специфика контекста — в `payload`:
  `subjectOutcome` (исход субъекта) и `mentorId` (второй автор окна).
- Состав `participants` решает ER при создании: событие «завершил» → все
  завершившиеся и ещё учащиеся соученики (кроме субъекта); «забросил»/
  «не начал» → пустой список (адресат только ментор).
- **Проекция исходов — 4 значения** (собственный словарь модуля, сырые статусы
  студента сюда не попадают): `completed_passed` «завершил и прошел»,
  `completed_not_passed` «завершил и не прошел», `dropped` «забросил»,
  `never_started` «не начал». «Ещё учится» не хранится.
- Разрешённые адресаты: субъект → ментор + `participants`;
  ментор → только субъект. Никогда — отзыв о себе.
- `Review`: `authorId`, `recipientId`, **`direction`** (`student_student` |
  `student_mentor` | `mentor_student`), `authorOutcome` — снапшот исхода
  автора-студента (для рендера «статуса автора» и будущих весов в досье),
  `scopeId`, `campaignId`, `text`. Один отзыв на пару (автор, адресат) в
  кампании, перезапись разрешена в пределах окна.
- **Статусы/роли в UI:** в приглашениях, кнопках и подсказках — никаких
  статусов и ролей участников. Судьба субъекта проговаривается в карточках
  S02/S03 **мягкой нейтральной формулировкой** («ты завершил обучение» /
  «ты покинул обучение» / «ты не начал обучение»), без ярлыков-проекций
  («забросил», «не прошёл»). Полный лейбл исхода (`authorOutcome`) — только
  у автора отзыва в просмотре (S07); passed/not_passed в S02/S03 не
  различаются.
- Окно проверяет домен — UC не считает даты сам: живость конкретной кампании
  подтверждает агрегат (доменная ошибка «возможность закрыта»), списки живых
  кампаний отдаёт репозиторий (метод «дай активные»). Истекло → сторя рендерит
  экран-заглушку.

## S01 — Приглашение (invite) ✅

**Когда:** событие `student-campaign.created` (кампанию создал ER домена по
`student.completed` / `student.abandoned`).
**Кому:** двое — субъект кампании и ментор скоупа (по `mentorId` из события).
Одно приглашение каждому, напоминаний нет (до task-модуля).

Тексты — **без ролей и статусов участников**; текст субъекту выбирается по
`subjectOutcome` из события (проговаривается мягко, первой строкой):

Субъекту (исход «завершил и прошел» / «завершил и не прошел» — текст один):
```
🏁 Отзывы по потоку «{StreamTitle}»

Ты завершил обучение — поделись впечатлениями об одногруппниках
и менторе: это часть цифрового профиля каждого. Пиши только правду.
```

Субъекту (исход «забросил»):
```
🏁 Отзывы по потоку «{StreamTitle}»

Ты покинул обучение — поделись впечатлениями о менторе и учёбе:
это поможет школе и тем, кто только выбирает, учиться ли.
Пиши только правду.
```

Субъекту (исход «не начал»):
```
🏁 Отзывы по потоку «{StreamTitle}»

Ты записался, но так и не начал обучение — расскажи, что остановило:
это поможет школе и будущим студентам. Пиши только правду.
```

Ментору (субъект завершил):
```
🏁 Отзывы по потоку «{StreamTitle}»

Твой подопечный {Имя} завершил обучение — выдай ему отзыв: как он
проявлялся в учёбе, что удалось, что стоит подтянуть. Пиши только правду.
```

Ментору (субъект выбыл — «забросил» / «не начал», текст один):
```
🏁 Отзывы по потоку «{StreamTitle}»

Твой подопечный {Имя} покинул обучение — поделись наблюдениями:
что удавалось, что можно было сделать иначе. Пиши только правду.
```

| Кнопка | Действие | Статус |
|--------|----------|--------|
| `💬 Отзывы` | → S03 (кампания этого субъекта) | ✅ |

> Механика invite (ФР-6): кнопка работает, даже если получатель давно не
> открывал бота; при устаревании — `/start`.

## S02 — «Мои отзывы» (хаб отзывов, список кампаний) ✅

**Как попасть:** кнопка `💬 Отзывы` в главном меню (декларативная
`menuButtons` стори, асинхронная видимость) — видна при наличии живых кампаний;
нет кампаний — нет кнопки.

```
💬 Мои отзывы

Здесь ты можешь оставить отзывы участникам своих потоков
и мероприятий. Это помогает людям расти, а школе — делать
обучение лучше.

──────────────
1. Поток «{title}»
Ты завершил обучение. Поделись впечатлениями об учёбе —
это помогает участникам расти, а также станет частью
цифрового профиля студента и ментора.
Метрики: 0/3 (6 дн.)

──────────────
2. Поток «{title}»
Ты был ментором этого потока. Твой подопечный {Имя} завершил
обучение — выдай ему отзыв: как проявлялся, что удалось,
что стоит подтянуть.
Метрики: 0/1 (6 дн.)

──────────────
3. Код-ревью «{title}»
Здесь будет текст который определится при реализации
функционала отзывов мероприятий "код-ревью".
Метрики: 0/3 (3 дн.)

──────────────
4. Парное программирование «{title}»
Здесь будет текст который определится при реализации
функционала отзывов мероприятий "Парное программирование".
Метрики: 0/1 (3 дн.)
```

**Тексты мини-карточек** — по роли и судьбе:

- я — субъект, «завершил» (passed/not_passed — текст один): «Поделись
  впечатлениями об учёбе — это помогает участникам расти, а также
  станет частью цифрового профиля студента и ментора.»
- я — субъект, «забросил»: «Ты покинул обучение. Оставь отзыв
  ментору — что помогало, что мешало: школа учтёт это, а желающие
  пройти обучение могут лучше понимать что их ожидает в обучении.»
- я — субъект, «не начал»: «Ты записался, но не начал обучение. Расскажи
  что остановило твое обучение, это будет полезно школе, ментору и
  тем кто хочет начать обучение в нашей школе.»
- я — ментор, подопечный завершил: «Ты был ментором этого потока. Твой
  подопечный {Имя} завершил обучение — выдай ему отзыв: как проявлялся,
  что удалось, что стоит подтянуть.»
- я — ментор, подопечный выбыл («забросил»/«не начал» — текст один):
  «Ты был ментором этого потока. Твой подопечный {Имя} покинул обучение —
  поделись наблюдениями: что можно было сделать иначе.»

**Метрики мини-карточки** — короткой строкой сразу после приглашения:
`Метрики: {M}/{K} ({N} дн.)`, где M — мои отзывы, K — доступные адресаты
(субъекту — ментор + участники; ментору — всегда 1), N — остаток окна.

| Кнопка | Условие | Статус |
|---------|---------|--------|
| `1. Поток «{title}»` | живая кампания, я — субъект | ⚠️ макет 2026-09-22, к доработке |
| `2. Отзыв об {Имя}` | живая кампания, я — ментор | ⚠️ макет 2026-09-22, к доработке |
| `3. Код-ревью для {Имя}` | живая кампания, я — ревьюер | запланировано |
| `4. Парн.программ. с {Имя}` | живая кампания, я — наблюдатель | запланировано |
| `↩️ Главное меню` | всегда | ✅ |

> Рендер по `myRole` (из `get-my-campaigns`); имена субъектов — batch-запрос
  пользователей. Лейбл кнопки — номер карточки + суть, без метрик.
> Из приглашения (S01) — сразу в кампанию (S03), минуя этот экран.

## S03 — Карточка кампании: список адресатов ✅

**Как попасть:** кнопка `💬 Отзывы` из приглашения (S01) или выбор кампании
в S02.

```
✍️ Отзывы — поток «{title}»

Ты завершил обучение в этом потоке. Расскажи о совместной учёбе:
что запомнилось, что было полезно, что можно улучшить. Пиши кому
хочешь и сколько хочешь.

Отзыв одногруппникам поможет увидеть, что у них хорошо получается,
а что стоит подтянуть. Если кто-то помог, с кем-то было приятно
сотрудничать — или наоборот, опыт был неприятным, — всё это полезно
и им, и тем, кто будет с ними работать.

Отзыв ментору поможет понять, что у него получается, а что нет.
А потенциальным студентам — понять, подходит ли им этот ментор.

📊 Прогресс:
• Написано отзывов: 0 из 3
• Осталось времени: 6 дн.

О ком расскажешь?
```

**Вводный абзац** — по роли и судьбе (макет выше — краткая иллюстрация;
канонические тексты здесь; структура: приглашение → кому и зачем полезен
твой отзыв):

- я — субъект, «завершил» (passed/not_passed — текст один):
  «Ты завершил обучение в этом потоке. Расскажи о совместной учёбе:
  что запомнилось, что было полезно, что можно улучшить. Пиши кому
  хочешь и сколько хочешь.

  Отзыв одногруппникам поможет увидеть, что у них хорошо получается,
  а что стоит подтянуть. Если кто-то помог, с кем-то было приятно
  сотрудничать — или наоборот, опыт был неприятным, — всё это полезно
  и им, и тем, кто будет с ними работать.

  Отзыв ментору поможет понять, что у него получается, а что нет.
  А потенциальным студентам — понять, подходит ли им этот ментор.»
- я — субъект, «забросил»:
  «Ты покинул обучение в этом потоке. Ментору и школе будет полезно
  понять, что помогало, а что мешало. Честный отзыв — лучший вклад
  в школу: тем, кто только выбирает обучение, он подскажет, чего
  от него ожидать.»
- я — субъект, «не начал»:
  «Ты записался на поток, но не начал обучение. Расскажи, что тебя
  остановило: школа это учтёт и уберёт барьеры, а тем, кто раздумывает
  начинать, твой отзыв поможет принять решение с открытыми глазами.»
- я — ментор, подопечный завершил:
  «Ты был ментором этого потока. Выдай отзыв о подопечном — {Имя}:
  как он проявлялся в учёбе, что удалось, что стоит подтянуть.
  Отзыв станет частью его цифрового профиля: следующие менторы
  и работодатели увидят, с чем он справляется.»
- я — ментор, подопечный выбыл («забросил»/«не начал» — текст один):
  «Ты был ментором этого потока. Подопечный {Имя} покинул обучение —
  поделись наблюдениями: что удавалось, что можно было сделать иначе.
  Школе это поможет лучше поддерживать студентов, а {Имя} — вернуться,
  когда будет готов.»

*Легенда:*
✅ — если мой отзыв об адресате уже есть:

| Кнопка | Условие | Статус |
|--------|----------|--------|
| `✅Ментор — {Имя}` | адресат-ментор, я — субъект | ⚠️ макет 2026-09-22, к доработке |
| `Одногруппник — {Имя}` | адресат-студент, я — субъект | ⚠️ макет 2026-09-22, к доработке |
| `Студент — {Имя}` | адресат-субъект, я — ментор | ⚠️ макет 2026-09-22, к доработке |
| `↩️ Главное меню` | всегда | ✅ |

> Состав кнопок определяет кампания: адресаты-студенты — из `participants`,
  ментор — из payload; в кампаниях «забросил»/«не начал» доступен только
  ментор (доменное правило ФР-2).
> Роль в лейбле — только надпись (взгляд автора: «Одногруппник» для субъекта,
  «Студент» для ментора); в callback — id адресата, роли клиент не передаёт.
> ✅ — только мои отзывы. Чужие — в просмотре (S07).
> Отдельной кнопки «Закончить» нет: выход — главное меню или `/cancel`;
  кампания живёт до конца окна независимо от выхода.

## S04 — Перезапись (ввод с заменой) ✅

**Как попасть:** клик по ✅-адресату в S03. Отдельной кнопки «Перезаписать»
нет — экран сразу принимает текст.

```
✏️ Ты уже писал(а) о {Имя}:

«{текущий текст отзыва}»

Отправь новый текст — он заменит текущий.
Или нажми «Назад».

Будь честен, пиши правду. Характеризуй навыки, а не людей: лучше
описать конкретную ситуацию и свои ощущения, чем повесить ярлык.
Такой отзыв приносит пользу.
```

**Ввод:** тот же контракт, что в S05 (10–3500 символов, переспросы без
потери контекста).

| Кнопка | Действие | Статус |
|--------|----------|--------|
| `❌ Назад` | → S03 без изменений | ✅ |
| `❔ Как писать отзыв` | справка S05i, без выхода из ввода | ⚠️ макет 2026-09-22 |

## S05 — Ввод отзыва ✅

**Как попасть:** клик по адресату без ✅ в S03.

Подсказка ввода — самое частное звено тракта (S01 → S02 → S03 → S05):
ценность уже рассказана в S03, здесь — только конкретика: во что вглядеться
и как структурировать ответ. Текст выбирается по паре «роль-судьба →
адресат»; поверх конкретных вопросов предлагается **мягкий шаблон ответа**
из двух секций с готовыми первыми строками (решение 2026-09-22).

**Шаблоны секций** (первая строка → пустая строка → вторая):

| Пара | Секция 1 | Секция 2 |
|------|----------|----------|
| «завершил» → об одногруппнике | `Отзыв для {Имя}:` | `Как с ним работать:` |
| «завершил» (passed/not_passed — текст один) → о менторе | `Отзыв для ментора:` | `Моя рекомендация студентам:` |
| «забросил» → о менторе | `Отзыв для ментора:` | `Следует ожидать от курса:` |
| «не начал» → о менторе | `Что остановило:` | `Моя рекомендация:` |
| ментор → о студенте | `Отзыв для {Имя}:` | `Рекомендация по развитию:` |

> Префиксы **не обязательны**: валидация прежняя — 10–3500 символов,
  шаблон только помогает структуре. Жёсткий разбор секций на поля —
  только если досье понадобятся структурированные данные (бэклог).

**Тексты-подсказки** (конкретика + шаблон):

- «завершил» → об одногруппнике:
  «Начни со строки "Отзыв для {Имя}:" — расскажи, как {Имя} проявил(а)
  себя в учёбе: профессиональные, командные и личностные качества.
  Не обязательно перечислять всё — пиши то, что считаешь важным,
  и правду. Затем через пустую строку добавь "Как с ним работать:" —
  короткую рекомендацию тем, кто будет учиться или работать рядом.»
- «завершил» (passed/not_passed — текст один) → о менторе:
  «Начни со строки "Отзыв для ментора:" — что помогало учиться,
  что мешало, чего не хватило. Затем через пустую строку добавь
  "Моя рекомендация студентам:" — кому и почему подойдёт этот ментор.
  Пиши правду.»
- «забросил» → о менторе:
  «Начни со строки "Отзыв для ментора:" — почему забросил(а) учёбу,
  что помогало, что мешало, какие пожелания школе и ментору. Затем
  через пустую строку добавь "Следует ожидать от курса:" — твою
  рекомендацию тем, кто рассматривает это обучение.»
- «не начал» → о менторе:
  «Начни со строки "Что остановило:" — почему так и не начал(а)
  учёбу, что не совпало с ожиданиями. Затем через пустую строку
  добавь "Моя рекомендация:" — что стоит знать школе и тем, кто
  выбирает обучение.»
- ментор → о студенте:
  «Начни со строки "Отзыв для {Имя}:" — как студент проявлялся
  в учёбе: сильные стороны, чего удалось достичь за поток. Затем
  через пустую строку добавь "Рекомендация по развитию:" — что стоит
  подтянуть и в каком направлении расти.»

**Принципы полезного отзыва** — общий блок-напоминание (добавление
2026-09-22, по живому прогону): завершает каждую текст-подсказку S05
и экран перезаписи S04 — в момент, когда пользователь пишет текст:

> Будь честен, пиши правду. Характеризуй навыки, а не людей: лучше
> описать конкретную ситуацию и свои ощущения, чем повесить ярлык.
> Такой отзыв приносит пользу.

В S03 и раньше блок не дублируется: там — ценность («кому и зачем»),
принципы «как писать» встречают пользователя у самого ввода.

**Ввод:** 10–3500 символов; короче — переспрос, длиннее — «пожалуйста,
сократите» (контекст не теряется). `/cancel` — выход из диалога отзывов.

| Кнопка | Действие | Статус |
|--------|----------|--------|
| `⏭️ Пропустить` | → S03 без сохранения | ✅ |
| `❔ Как писать отзыв` | справка S05i, **без выхода из ввода** (контекст сохраняется) | ⚠️ макет 2026-09-22 |

## S05i — Инструкция «Как писать отзыв» (справка) ⚠️ макет 2026-09-22

**Как попасть:** кнопка `❔ Как писать отзыв` на экранах ввода (S05, S04).
Экран справочный: ввод продолжает ждать текст, контекст и переспросы
не сбрасываются — `↩️ К вводу` возвращает подсказку.

```
❔ Как писать отзыв

Отзыв полезен, когда говорит о навыках и конкретных ситуациях —
а не о людях.

🧩 Пиши о навыках и фактах
Опирайся на наблюдаемое: что человек делал, как часто,
с каким результатом.
❌ «Андрей безответственный.»
✅ «Андрей дважды переносил дедлайн на 2–3 дня, и команде
приходилось ждать.»

💡 Пиши о ситуациях и ощущениях
Конкретный случай и как тебе было — честнее и понятнее
общих оценок.
Положительный опыт:
✅ «Когда я застрял на алгоритмах, Марина объяснила подход
на примере — за 20 минут стало ясно, куда двигаться.»
Отрицательный опыт:
✅ «Мне было тяжело ждать код-ревью по 3 дня: не успевал
исправлять до следующего шага.»

🚫 Ярлык и переход на личности
Ярлык — короткая оценка всего человека: «ленивый», «токсичный»,
«бестолковый». Переход на личности — суждение о том, какой он,
а не о том, что он делал. Такому сложно верить и невозможно
проверить.

🔄 Как превратить ярлык в полезный отзыв
1. Заметь поведение: что конкретно происходило?
2. Скажи, как это повлияло на тебя или команду.
3. Добавь пожелание, если оно есть.
«Он токсичный» → «На созвонах разговор часто уходил в споры,
из-за этого я молчал и не предлагал идеи. Было бы легче
договориться о формате заранее.»

Пиши правду — только она приносит пользу.
```

| Кнопка | Действие | Статус |
|--------|----------|--------|
| `↩️ К вводу` | → назад к подсказке ввода (S05/S04) | ⚠️ макет 2026-09-22 |

> Примеры в инструкции — обезличенные шаблоны с фиктивными именами
  (не из данных потока). Экран не зависит от роли/судьбы — один
  на все случаи.

## S07 — Просмотр отзывов (чтение, пагинация) ✅

**Как попасть:** «💬 Отзывы» в карточке потока (streams S02). Только чтение —
кнопок перехода в живую кампанию отсюда нет.

Кнопка в карточке потока видна, если есть хотя бы один отзыв по потоку.

**Формат** — группировка по адресатам; у адресата — только роль, у автора —
роль и лейбл исхода-снапшота (`authorOutcome`, из отзыва):

```
💬 Отзывы — поток «{StreamTitle}» · Стр. 1/3
———
👤 {Имя} (студент):
«{текст}» — {автор} (студент · завершил и прошел)
👤 {Имя} (студент):
«{текст}» — {автор} (студент · не начал)
👤 {Имя} (ментор):
«{текст}» — {автор} (студент · завершил и не прошел)
```

> Лейблы исходов: «завершил и прошел» / «завершил и не прошел» / «забросил» /
  «не начал». Автор-ментор — без лейбла. Статус адресата не показывается.
  Роли выводятся из `direction`.

| Кнопка | Условие | Статус |
|--------|---------|--------|
| `‹ Пред` | не первая страница | ✅ |
| `След ›` | не последняя страница | ✅ |
| `⬅️ Назад к потоку` | всегда | ✅ |

> Разбиение постраничное: страница наполняется целыми отзывами до лимита
  символов (запас на шапку и клавиатуру, суммарно < 4096); отзыв не рвётся
  посередине. Имена авторов/адресатов резолвятся batch-запросом пользователей
  до нарезки страниц.

### Абстракция пагинации ✅

> Пагинатор — трек `pagination` (ядро в core `ui/pagination`, бот-наследник
> `BotPaginator` + системный кеш `DialogCache` в core `ui/bot`); S07 потребляет
> его готовым через `pagedScreen` стори. Кнопки пагинации — одним рядом.

## Бэклог

- 📋 **Задача `/tasks`** — при появлении кампании создаётся (или может
  создаваться) задача «Заполните отзывы по потоку {name}» с кнопкой
  «Выполнено» → кампания (S03). Требует task-модуль.
- 📋 **Метрики-анкеты (likert)** — раздельная от отзыва кнопка «Анкета».
  Паттерн интеграции: кампания запускает анкету через фасад questionnaire
  с `ownerInfo` (context/scopeId/targetId); ER peer-review на
  `questionnaire.completed` раскладывает ответы по своим местам.
- 📋 **Кампании по сессиям** (код-ревью, парное программирование — в парном
  возможно несколько смотрящих) — новый payload-тип контекста при том же
  ядре кампании. Детали — концепция `peer-review-system.md`.
- 📋 **Группировка менторских кампаний потока («виртуальная кампания»)** —
  при нескольких живых менторских кампаниях одного потока (массовое
  завершение/выбытие) объединять их в S02 в одну карточку («Поток X —
  отзывы о N студентах») с общим списком адресатов в S03. Варианты:
  UI-группировка + UC «менторские кампании по потоку» или агрегат
  «виртуальной кампании». Сейчас не делаем: окно 7 дней и кампания
  уникальна по (поток, субъект) — кейс редкий. Решение 2026-09-22.
- 📋 **Напоминания об окне** — с task-модулем.
- 📋 **Отзывы о курсе** — отдельный контекст.

## Снятые решения

- Видимость отзывов: всем и всегда в карточке потока; ✅-маркеры — только свои отзывы.
- Окно: 7 дней (константа); истекло — возможности нет, домен отклоняет запись.
- Длина текста: 10–3500; переполнение — просить сократить.
- Перезапись: разрешена в окне, без confirm-кнопки — ввод сразу заменяет,
  «Назад» отменяет.
- Приглашение персонализировано: кнопка ведёт сразу в кампанию (S03).
- Хаб «Отзывы»: кнопка главного меню (видна при живых кампаниях) → S02.
- Роли в кнопках: `Студент: {Имя}` / `Ментор: {Имя}`, ✅ при наличии отзыва.
- S07 — только чтение, с пагинацией.
- Анкета и отзыв — раздельные точки входа.
- **2026-09-22 (живой прогон, Фаза 6 трека peer-review-ui):** контекст судьбы
  в S02/S03 — мягкие формулировки «покинул/завершил/не начал» без
  ярлыков-проекций; S02 — абстрактное интро + нумерованные мини-карточки
  (приглашение + краткие метрики `Метрики: M/K (N дн.)`) + кнопки внизу
  с номером карточки, без метрик; S03/S06 — развёрнутые метрики построчно;
  роли адресатов — «Ментор / Одногруппник / Студент»; тракт подсказок
  «от общего к частному» (ценность в S03, конкретика в S05); S05 — мягкий
  шаблон ответа из двух секций (префиксы не обязательны, валидация прежняя)
  и общий блок-напоминание «принципы полезного отзыва» на экранах ввода
  (S05/S04), без дублирования в S03; кнопка `❔ Как писать отзыв` на экранах
  ввода → справка S05i (навыки vs ярлыки, ситуации и ощущения, перевод
  ярлыка в полезный отзыв; без выхода из состояния ввода);
  весь модуль (S01–S06) переведён на обращение «ты».
- **2026-09-20:** триггер приглашений — `student-campaign.created` (два
  получателя: субъект и ментор); тексты приглашений — без ролей и статусов;
  статус показывается только у автора отзыва (S07); проекция исходов —
  4 значения («завершил и прошел» / «завершил и не прошел» / «забросил» /
  «не начал»); `participants` кампании — только id адресуемых соучеников
