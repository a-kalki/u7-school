# Спецификация экранов Questionnaire (UI Spec)

Документ описывает экраны Telegram-бота модуля Questionnaire: их содержимое, кнопки, условия видимости и доменную логику.
Служит **отправной точкой для разработки**.

Условные обозначения:
- ✅ реализовано
- ❌ не реализовано
- 📋 в бэклоге / запланировано в треке

---

## Путь пользователя

Два варианта входа:
- **Инициативный (Путь A):** модуль-владелец (например, onboarding) вызывает `questionnaireFacade.sendInvite(user, pool)` или `questionnaireFacade.start(user, pool)`. Система отправляет пользователю сообщение.
- **Ответный (Путь B):** пользователь нажимает кнопку в приглашении и попадает в диалог с анкетой.

### Диаграмма экранов

```
S01 (Приглашение) ──[Начать]──→ S02a/S02b/S03 (Вопрос)
                                       │
                       ┌───────────────┤
                       ▼               ▼
                   S02a (single)   S02b (multiple)
                   клик → переход   клик → toggle → [Далее] → переход
                       │               │
                       ▼               ▼
                   S02a/S02b/S03   S02a/S02b/S03  ...  → S04 (Завершение)

Любой экран ──[/cancel]──→ S05 (Отмена)
```

---

## S01 — Приглашение (📋 invite)

**Как попасть:** инициативно от системы (Путь A). Модуль-владелец вызывает `questionnaireFacade.sendInvite()`.
**Кому:** пользователю, которому предназначена анкета.
**Рендеринг:** `TelegramQuestionnaireBotFacade.sendQuestionnaireInvite()`

**Содержание:**
```
📋 *Анкета*

{текст приглашения — передаётся модулем-владельцем}

Для отмены в любой момент нажмите /cancel.
```

**Кнопки:**

| Текст | Код | Статус |
|-------|-----|--------|
| `▶️ Начать заполнение` | `questionnaire:fill:start:{questionnaireId}` | 📋 |

> Сообщение отправляется одноразово, без captureInput. Кнопка переводит пользователя в диалог (Путь B).

---

## S02a — Вопрос с одиночным выбором (🔘 single choice)

**Как попасть:** через S01 (после «Начать») или после ответа на предыдущий вопрос.
**Кому:** пользователь в процессе заполнения анкеты.
**Рендеринг:** FillStory → UC `start-by-invite` / UC `handle-action` → render response

**Содержание:**
```
*{текст вопроса}*

1. ( ) {вариант 1}
2. ( ) {вариант 2}
3. ( ) {вариант 3}
```

**Кнопки:**

| Текст | Код | Статус |
|-------|-----|--------|
| `1` | `questionnaire:fill:answer:{qId}:{answerCode1}` | 📋 |
| `2` | `questionnaire:fill:answer:{qId}:{answerCode2}` | 📋 |
| `3` | `questionnaire:fill:answer:{qId}:{answerCode3}` | 📋 |

**Логика:**
- Клик по кнопке → UC `handle-action({type:'select', value:answerCode})`
- Ответ сразу фиксируется, переход к следующему вопросу (S02a/S02b/S03) или завершению (S04)
- Предыдущий вопрос заменяется на версию с отмеченным ответом (editMessage)
- Новый вопрос отправляется отдельным сообщением (sendMessage)

---

## S02b — Вопрос с множественным выбором (☑️ multiple choice)

**Как попасть:** аналогично S02a.
**Кому:** пользователь в процессе заполнения анкеты.
**Рендеринг:** FillStory → UC `handle-action` (возвращает `WaitNextResponse`)

**Содержание:**
```
*{текст вопроса}*

1. [ ] {вариант 1}
2. [x] {вариант 2}
3. [ ] {вариант 3}
```

**Кнопки:**

| Текст | Код | Статус |
|-------|-----|--------|
| `1` | `questionnaire:fill:answer:{qId}:{answerCode1}` | 📋 |
| `2` | `questionnaire:fill:answer:{qId}:{answerCode2}` | 📋 |
| `3` | `questionnaire:fill:answer:{qId}:{answerCode3}` | 📋 |
| `▶️ Далее` | `questionnaire:fill:next:{qId}` | 📋 |

**Логика:**
- Клик по кнопке с номером → UC `handle-action` переключает (toggle) вариант
- Сообщение обновляется через editMessage — флажки [ ]/[x] меняются
- Кнопка «Далее» → UC `handle-action({type:'next-btn'})` фиксирует выбор и переходит дальше

---

## S03 — Текстовый вопрос (✏️ text)

**Как попасть:** аналогично S02a — от предыдущего вопроса.
**Кому:** пользователь в процессе заполнения анкеты.
**Рендеринг:** FillStory → UC `handle-action` возвращает `NewQuestionResponse`

**Содержание:**
```
*{текст вопроса}*

Введите ваш ответ текстом...
```

**Кнопки:** отсутствуют (нет клавиатуры)

**Логика:**
- Пользователь вводит текст как обычное сообщение
- FillStory.handleMessage → UC `handle-action({type:'text', value:messageText})`
- Ответ сохраняется в `answerText`, переход к следующему вопросу или завершению
- Если вопрос — задание с кодом (`kind: 'text'`), то код сохраняется в `answerCode` поля вопроса

---

## S04 — Завершение (✅ completed)

**Как попасть:** после последнего ответа (handle-action возвращает `CompletedResponse`).
**Кому:** пользователь завершил анкету.

**Содержание:**
```
✅ *Анкета завершена*

Спасибо! Ваша анкета принята.
```

**Кнопки:**

| Текст | Код | Статус |
|-------|-----|--------|
| `↩️ Главное меню` | `app:main-menu` | 📋 |

**Логика:**
- `releaseInput` — освобождение ввода
- `questionnaireCompleted: true` — сигнал для модуля-владельца (через события)

---

## S05 — Отмена (🚫 cancelled)

**Как попасть:** `/cancel` на любом экране анкеты.
**Кому:** пользователь прервал заполнение.

**Содержание:**
```
Анкета прервана. Вы можете начать заново, если потребуется.
```

**Кнопки:**

| Текст | Код | Статус |
|-------|-----|--------|
| `↩️ Главное меню` | `app:main-menu` | 📋 |

**Логика:**
- FillStory.handleCancel → UC `abandon({questionnaireId})`
- Статус анкеты → `abandoned`
- `releaseInput`

---

## Стори fill — обработчики

| Событие | Данные | UC | Ответ |
|---|---|---|---|
| Начало анкеты | `fill:start:{qId}` | `start-by-invite` | Render ответа + `captureInput: questionnaire/fill` |
| Выбор ответа | `fill:answer:{qId}:{aCode}` | `handle-action({type:'select', value:aCode})` | Render ответа |
| Подтверждение (multiple) | `fill:next:{qId}` | `handle-action({type:'next-btn'})` | Render ответа |
| Текстовый ввод | text message | `handle-action({type:'text', value:text})` | Render ответа |
| Отмена | `/cancel` | `abandon({questionnaireId})` | releaseInput |

## Форматирование MarkdownV2

- Вопросы: `*{текст}*` (жирный)
- Single choice: номера + `( )` / `(x)` для отмеченного
- Multiple choice: номера + `[ ]` / `[x]` для отмеченного
- Все тексты эскейпятся через `escapeMarkdown()`
