# Спецификация экранов Streams (UI Spec)

Документ описывает экраны Telegram-бота модуля Streams: каталог, карточки, программа, детали, создание потока, запись.
Служит **отправной точкой для разработки** — что уже реализовано, что запланировано.

Условные обозначения:
- ✅ реализовано
- ❌ не реализовано
- 📋 в бэклоге / запланировано в треке

---

## S01 — Каталог потоков

**Как попасть:** кнопка `📚 Потоки курсов` в главном меню.
**Кому:** всем ролям.

**Содержание:**
- Заголовок `📚 Потоки курсов`
- Легенда: `🟡 — идёт набор   🔵 — идёт обучение   🟢 — завершён   ⚫ — в архиве`
- Кнопки-потоки: `{эмодзи} {StreamTitle}` — `enrollment` и `active` по умолчанию, `completed`/`archived` — через переключатели

**Кнопки:**

| Текст | Код | Условие | Статус |
|-------|-----|---------|--------|
| `{эмодзи} {StreamTitle}` | `view-stream:view:{id}` | видимый поток | ✅ |
| `🟢 Вкл. завершённые` | `catalog:list-with-completed` | есть completed | ✅ |
| `⚫ Вкл. архивированные` | `catalog:list-with-all` | есть archived | ✅ |
| `🔵 Только активные` | `catalog:list` | показаны все | ✅ |
| `↩️ Главное меню` | `app:main-menu` | всегда | ✅ |

**Доменная логика:**
- `list-streams` → фильтр по статусу в зависимости от переключателей
- Иконки статусов едины для catalog и mentor-tools (🟡/🔵/🟢/⚫)

## S02 — Карточка потока (curious-режим)

**Как попасть:** клик на поток в S01 (ветка «Потоки курсов»).
**Кому:** всем ролям. **Только curious-функциональность, без менторских инструментов.**

**Содержание:**
```
📋 *{StreamTitle}*
_{StreamDescription}_
👤 Ментор: {MentorName}
📅 Старт: {StartDate}
🕐 Время: {HH:MM}
👥 Студентов: {N}
📌 Статус: {StatusLabel}
📚 Курс: Fullstack JS   ← ⚠️ техдолг: захардкожено
```

**Кнопки — публичные (всем ролям, включая ментора как зрителя):**

| Текст | Код | Статус потока | Статус |
|-------|-----|---------------|--------|
| `📖 Программа курса` | `view-stream:program:{id}` | любой → S03 | ✅ |
| `📋 Детали` | `view-stream:details:{id}` | любой → S04 | ✅ |
| `📊 Студенты` | `monitor:students:{id}` | любой → S07 (прозрачность) | ✅ |

**Кнопки — гостевые (только НЕ владелец потока, `canEnroll`):**

| Текст | Код | Статус потока | Статус |
|-------|-----|---------------|--------|
| `📝 Записаться` | `enroll:enroll:{id}` | `enrollment` → S10 | ✅ |
| `🔔 Уведомить о наборе` | `view-stream:notify:{id}` | `active` (гость) → заглушка | ✅ |

**Кнопка — всегда:**

| Текст | Код | Статус |
|-------|-----|--------|
| `⬅️ Назад к списку` | `catalog:list` | ✅ |

> ⚠️ В этом режиме **нет** lifecycle-кнопок ментора (`🚀 Запустить` / `✅ Завершить` / `📁 В архив`). Управление — через S02m (ветка «Инструменты ментора»).

**Доменная логика:**
- `get-stream` → карточка
- `list-stream-students` → подсчёт студентов
- `get-user` (ментор) → имя ментора

## S02m — Карточка потока (mentor-режим) (✅ реализовано)

**Как попасть:** «🛠️ Инструменты ментора» → «📋 Мои потоки» → поток (где я ментор).
**Кому:** только владелец потока / ADMIN (`StreamPolicy.canEdit`). Тот же поток, что в S02, но в режиме управления.

**Содержание** как в S02 + `📊 Сводка потока` (счёт по статусам: active/not_advanced/abandoned/enrolled; медиана/отстающие/сортировка).

**Кнопки — панель управления (внизу карточки):**

| Текст | Код | Статус потока | Статус |
|-------|-----|---------------|--------|
| `🚀 Запустить` | `activate-stream:activate:{id}` | `enrollment` | ✅ |
| `✅ Завершить` | `view-stream:complete:{id}` | `active` | ✅ |
| `📁 В архив` | `view-stream:archive:{id}` | `completed` | ✅ |
| `👥 Студенты` | `monitor:students:{id}` | любой → S07/S08 **с действиями** | ✅ |

> **Подтверждения:** `🚀 Запустить` — без подтверждения.
> `✅ Завершить` → «⚠️ Завершить поток?» → `Да, завершить` / `Отмена`.
> `📁 В архив` → «⚠️ Отправить в архив?» → `Да, в архив` / `Отмена`. **Только для завершённых потоков** (доменное правило: `StreamAr.archive()` требует `COMPLETED`).

**Кнопки — всегда (вверху):** `⬅️ Назад к моим потокам` → `mentor:my-streams`.

## S03 — Программа курса

**Как попасть:** `📖 Программа курса` в S02.
**Кому:** все.
**Формат:** дерево проектов и уроков через `renderTree` (проекты жирным, уроки с отступом
и метой `— N шагов`). Обрезка при >4000 символов.

**⚠️ Требование экранирования:** заголовки проектов и уроков (`projectTitle`, `lessonTitle`)
обязательно экранируются через `escapeMarkdown` **до** передачи в `renderTree`
(контракт `TreeNode.title` — «уже экранированный»). Реальные названия содержат
`-`, `(`, `)`, `.` (например, «Обработка ошибок: throw и try-catch») — без экранирования
отправка падает с `GrammyError 400`.

**Содержание:**
```
📖 *Программа курса*
📁 *Git, TDD и посимвольное сравнение строк*
    📝 Обработка ошибок: throw и try-catch — 2 шага
    📝 Математические операторы (+, -, *, /) — 1 шаг
📁 *Продвинутый*
    📝 Асинхронность — 1 шаг
```
Проекты — жирным (`📁 *Заголовок*`), уроки — обычным текстом с отступом
и метой `— N шагов`. Формат задаёт `renderTree` (`apps/u7-bot/src/shared/tree-renderer.ts`).

**Кнопки:**

| Текст | Код | Статус |
|-------|-----|--------|
| `⬅️ Назад к потоку` | `view-stream:view:{id}` | ✅ |

## S10 — Проверка кодового слова

**Как попасть:** `📝 Записаться` на потоке с `enrollmentKey` (S02).
**Кому:** Guest / Candidate.

**Сценарий:**
1. Бот: «Введите кодовое слово для записи на поток»
2. Пользователь вводит слово
3. Верно → вызов `enroll-student` с `enrollmentKey`
4. Неверно → «❌ Неверное слово. Осталось попыток: {N}» (всего 3)
5. 3 неудачи → «❌ Попытки исчерпаны.» → возврат в S02

**Кнопки:**

| Текст | Код | Статус |
|-------|-----|--------|
| `❌ Отмена` | `view-stream:view:{id}` | ✅ |

**Архитектура:**
- Story (UI) проверяет слово для UX и подсчёта попыток
- Use-case `enroll-student` **тоже** проверяет слово — безопасность на уровне домена

## S11 — Приглашение желающим (проактивное) (перенесено — трек user-notify)

Экрана-сторйи больше нет: приглашение — чистое уведомление без кнопок через
механизм `userFacade.notify` (Этап A, [tasks-system-implementation.md]).

**Триггер:** `stream.created` → ER `invite-wishers` (модуль wish) собирает
текст FR-6 #8 сам (поток/дата/ментор через `StreamFacade` + `UserFacade`)
и шлёт `userFacade.notify(userId, text)` → UC `notify-user` → событие
`user.notified` → сторя `notify` контроллера user (доставка, 🔔, экранирование).

Содержание (plain, до экранирования):

```
📣 Открылся набор на «{title}», который ты хотел пройти! Старт: {дд.мм.гггг}. Ментор: {имя}. Подробности: /start → 📚 Потоки курсов. Для записи нужен ключ — его выдаёт ментор. Не актуально — отмени желание: 📖 Программы курсов → карточка курса → 🗑️.
```

- Кнопок нет: запись — через S02 (карточка потока) → «Записаться».
- Профиль ментора недоступен — строка «Ментор: …» опускается; поток не
  резолвится — приглашение молчаливо пропускается.
- Событие `wish:invite` и сторя `wish-invite.story.ts` удалены.

## SIN — Уведомления о бездействии и уходе из учёбы (✅ реализовано — трек student-inactivity)

Проактивные экраны (без точки входа из меню) — сторя `inactivity.story.ts`
в streams-контроллере. Терминология трека: **«Снять с учёбы»** (не «отчислить»).

### SIN-W — Предупреждение студенту (5+ дней бездействия)

Подписка на `student.inactivity-warning` (job `inactivity-sweep`, 19:00 UTC).

```
⏳ Учёба стоит

Ты не занимаешься уже N дней.

Если бездействие продлится больше недели, ментор может снять тебя с учёбы за бездействие.
```

| Текст | Код |
|-------|-----|
| `🚪 Покинуть учёбу` | `stream:inactivity:drop-student:{studentId}` (takeover) |

Confirm: «Покинуть учёбу?» → `🚪 Да, покинуть` / `❌ Остаться`.
Выполнение: `drop-student` → «Ты покинул учёбу. Жаль, что не сложилось…».

### SIN-M — Кандидат на снятие (ментору, 7+ дней)

Подписка на `student.inactivity-remove-candidate`.

```
🛑 Кандидат на снятие с учёбы

Студент *{Имя}* из группы «{Поток}» не занимался N дней.

ℹ️ Уведомления были ранее отправлены студенту.
```

(ℹ️-строка — только если студенту слались предупреждения, `wasWarned`)

| Текст | Код |
|-------|-----|
| `⚠️ Снять с учёбы` | `stream:inactivity:mark-abandoned:{studentId}` (takeover) |

Confirm: «Снять студента с учёбы за бездействие?» → `⚠️ Да, снять с учёбы` / `❌ Отмена`.
Выполнение: `mark-abandoned` (cause=inactivity) → «✅ Студент снят с учёбы за бездействие и исключён из группы потока.».

### SIN-A — Реакции на уход (student.abandoned)

Текстовые уведомления перенесены из стори в домен (трек user-notify):
- `who=self` → ментору: UC `drop-student` шлёт `userFacade.notify`:
  «🚪 Студент {Имя} покинул учёбу с потока «{Поток}» по собственному желанию.»
- `who=mentor` → студенту: UC `mark-abandoned` шлёт `userFacade.notify`:
  «Ты снят с учёбы с потока «{Поток}» за бездействие и исключён из его группы.
  Прогресс сохранён — если захочешь вернуться, напиши ментору потока.»

Доставка обоих — событие `user.notified` → сторя `notify` контроллера user.
В `InactivityStory` от реакции на `student.abandoned` остался только мягкий
кик из Telegram-группы (ниже).

**Сопутствующие реакции (не UI-экраны):**
- ER кика `student-kick-handler` (main.ts): `banChatMember` + `unbanChatMember`
  по `stream.telegramGroupId`; нет группы/прав — запись в лог.
- `chat_member left` (group-handler): активный студент покинул группу →
  ментору notify «🚪 Студент {Имя} покинул группу «{Поток}».»; статус студента не меняется.
