# Спецификация экранов Courses (UI Spec)

Документ описывает экраны Telegram-бота модуля Courses: их содержимое, кнопки, условия видимости и доменную логику.
Служит **отправной точкой для разработки** — что уже реализовано, что запланировано.

Условные обозначения:
- ✅ реализовано
- ❌ не реализовано
- 📋 в бэклоге / запланировано в треке

---

## S00 — Каталог курсов: drill-down ✅ (трек `course-catalog-nav_20260928`)

**Как попасть:** `📖 Курсы` в главном меню.
**Кому:** всем ролям, без прогресса и статусов.
**Формат:** карточная drill-down `курс → этап → модуль → проект → урок` — общая механика в
[content-nav](./content-nav.md). Шаги на уровне урока — только заголовки, внутрь (тело шага)
заходить нельзя.

### Уровни drill-down

| Уровень | Название | Хлебные крошки (построчно с типом объекта) | Пояснение | Дочерние элементы (жирным + кнопки) | Подуровень (списком) | Навигация и возврат |
|---------|----------|--------------------------------------------|-----------|-------------------------------------|----------------------|---------------------|
| 0 | Курс | `📖 *Курсы*\n› Курс: {Курс}` | «Курс состоит из N этапов» | `🗂️ {Этап}` (кнопки `1. 🗂️ {Этап}`) | `📦 {Модуль}` | `◀️ Пред. курс` / `След. курс ▶️`, `↩️ Главное меню` |
| 1 | Этап | `📖 *Курсы*\n› Курс: {Курс}\n› Этап: {Этап}` | «Этап состоит из N модулей» | `📦 {Модуль}` (кнопки `1. 📦 {Модуль}`) | `📁 {Проект}` | `◀️ Пред. этап` / `След. этап ▶️`, `⬅️ Назад к курсу` |
| 2 | Модуль | `📖 *Курсы*\n› Курс: {Курс}\n› Этап: {Этап}\n› Модуль: {Модуль}` | «Модуль состоит из N проектов» | `📁 {Проект}` (кнопки `1. 📁 {Проект}`) | `📝 {Урок}` | `◀️ Пред. модуль` / `След. модуль ▶️`, `⬅️ Назад к этапу` |
| 3 | Проект | `📖 *Курсы*\n› Курс: {Курс}\n› Этап: {Этап}\n› Модуль: {Модуль}\n› Проект: {Проект}` | «Проект состоит из N уроков» | `📝 {Урок}` (кнопки `1. 📝 {Урок}`) | `🔹 {Шаг}` | `◀️ Пред. проект` / `След. проект ▶️`, `⬅️ Назад к модулю` |
| 4 | Урок | `📖 *Курсы*\n› Курс: {Курс}\n› Этап: {Этап}\n› Модуль: {Модуль}\n› Проект: {Проект}\n› Урок: {Урок}` | «Урок состоит из N шагов» | `🔹 {Шаг}` (только заголовки, кнопок нет) | — (одноуровневый) | `◀️ Пред. урок` / `След. урок ▶️`, `⬅️ Назад к проекту` |

> На уровне 0 отображается карточка выбранного курса. Если курсов несколько, переключение
> между ними происходит кнопками `◀️ Пред. курс` / `След. курс ▶️`.
> На уровне 4 (урок) отображаются заголовки шагов (одноуровневый список), кнопки входа в шаги отсутствуют (тела не запрашиваются).

### Кнопки навигации

| Кнопка | Условие | Статус |
|--------|---------|--------|
| `{N}. {иконка} {название}` | Дочерние элементы (уровни 0, 1, 2, 3) | ✅ |
| `◀️ Пред. …` / `След. … ▶️` | Соседние элементы в пределах родителя (уровни 0–4) | ✅ |
| `⬅️ Назад к {родителю}` | Возврат на уровень выше (уровни 1–4) | ✅ |
| `↩️ Главное меню` | Возврат в меню (уровень 0) | ✅ |

**Wish-кнопки курса:**
Размещаются на карточке курса (уровень 0) отдельным рядом после списка кнопок-этапов:
- `🎓 Хочу пройти курс` — если у пользователя нет активного желания
- `📝 Продолжить анкету` — если анкета начата (статус `pending`)
- `🗑️ Отменить желание` — если желание зафиксировано (`expressed` или `confirmed`)

### Примечания

- Кнопка «📚 Найти поток» убрана (кросс-контроллерная навигация — техдолг).
- Устаревший `pagedScreen` и ручной `tree-renderer` полностью удалены.

## Желание пройти курс (запись на курс) — ✅

Модуль `wish` фиксирует **желание пользователя пройти курс**. UI этих экранов живёт в контроллере курсов: у модуля `wish` **нет своего bot-ui-контроллера** — он вызывается через `appApi` из стори каталога курсов.

### Путь пользователя

```
Каталог курсов (S00, уровень 0) — карточка курса
  └─ кнопка «🎓 Хочу пройти курс» → фиксация желания
       ├─ курс БЕЗ анкеты → желание сразу зафиксировано → W03
       └─ курс С анкетой → «ждёт анкету» + анкета (questionnaire S01–S06)
              ├─ ✅ анкета завершена → желание подтверждено → W03
              └─ анкета прервана → желание отменено
```

### W01 — Кнопка карточки курса (✅)

**Где:** карточка курса (S00, уровень 0) — под списком кнопок-этапов.

Кнопка зависит от состояния желания пользователя на курс. Статусы всех
желаний каталога берутся **одним батч-запросом** `list-user-wishes`
(без N-запросов на курс).

| Состояние желания | Кнопка | Действие | Статус |
|-------------------|--------|----------|--------|
| активного желания нет | `🎓 Хочу пройти курс` | фиксация желания → W02/W03 | ✅ |
| `pending` (анкета начата) | `📝 Продолжить анкету` | возврат к анкете курса | ✅ |
| `expressed \| confirmed` | `🗑️ Отменить желание` | W05 (подтверждение отмены) | ✅ |
| `fulfilled` (обучение) | `🎓 Хочу пройти курс` | клик → W04 («уже обучаешься») | ✅ |

| Кнопка модуль-желания | Действие | Статус |
|--------|----------|--------|
| `➡️ Следующий модуль` / `🔁 Пройти модуль снова` | фиксирует желание пройти модуль (кнопка из сообщения о завершении; работает даже без открытого бота) | ✅ |

### W02 — Анкета желания (только если у курса есть пул анкеты) (✅)

Делегировано модулю `questionnaire` (экраны S01–S06 в `questionnaire/ui-spec.md`).

- при клике желание сразу фиксируется в статусе «ждёт анкету», затем приходит
  приглашение анкеты этого курса (questionnaire S01b) — анкета открывается
  по кнопке приглашения, сама по себе не всплывает;
- пул вопросов анкеты задаётся для курса отдельно (какой курс — какая анкета);
- анкета завершена → желание подтверждается; анкета прервана → желание отменяется;
- если у курса **нет** анкеты — шаг пропускается, желание фиксируется сразу (W03);
- при подтверждении после анкеты ER `confirm-wish` публикует `wish.confirmed`,
  а сторя `wish-confirmed` рассылает менторам курса (все, кто когда-либо вёл
  его потоки) notify-проактив: «📗 *{имя}* подтвердил желание проходить курс
  *{курс}*» — автор и менторы без telegramId пропускаются.

### W03 — Желание зафиксировано (✅)

**Как попасть:** мгновенно (курс без пула → `expressed`) или после завершения анкеты (`confirmed`).

**Что происходит:** желание пройти курс зафиксировано (сразу или после анкеты — подтверждено).

**Содержание:**

```
🎯 Твоё желание пройти курс зафиксировано!
```

| Кнопка | Статус |
|--------|--------|
| `↩️ Главное меню` | ✅ |
| `📝 Мои заявки` | 📋 бэклог |

### W04 — Желание уже есть / анкета начата (✅)

**Как попасть:** повторный клик «Хочу пройти курс» при активном желании или обучении (домен отвечает «желание уже есть» + его статус).

> Прочие ошибки (курс не найден и т.п.) — не экран: короткое
> предупреждение поверх текущего экрана.

**Содержание — ветвление по статусу:**

`pending` (анкета начата, не завершена):

```

Продолжи — и желание будет закреплено.
```

|--------|----------|
| `▶️ Продолжить анкету` | вернуться к анкете этого курса |
| `↩️ Главное меню` | главное меню |

`expressed | confirmed` (желание уже выражено) / обучение:

```

```

## Доменные замечания (для треков)

- Пока только реализация «Создание желания».
- Роль `CANDIDATE` **удаляется** — информация о желании живёт в `Wish`.
- Цель желания — `WishTarget` (дискриминированный союз: `course | module`); агрегат `Wish` не знает про курсы.
- Статусы `Wish` (полный жизненный цикл):
  - мгновенная ветка: `expressed` → `cancelled | fulfilled`;
  - анкетная ветка: `pending` → `confirmed | abandoned`, далее `confirmed` → `cancelled | fulfilled`;
  - отмена (`cancel-wish`, вариант команды по `kind`: course | module) доступна только из `expressed | confirmed`; для `pending` — только через `abandon`.
- Скоуп активности: не более одного активного желания на пару (user, target); параллельные желания на разные курсы разрешены; повторное создание после `cancelled`/`abandoned` разрешено.
- **Приглашение при открытии набора (трек wish-invite, ✅ реализовано):** при создании потока активные желающие (`expressed | confirmed`) получают приглашение — course-желающие только на поток первого модуля курса, module-желающие на поток любого модуля; историческая идентичность (форки) — через фасад курсов. ER `invite-wishers` публикует доменное событие `wish.invited` (payload: userId, telegramId, streamId, targetKind, courseId|moduleId); карточку с кнопкой отмены рендерит сторя `wish-invite` контроллера courses — экран S11 (streams/ui-spec.md), канал `invite`.
- **Реализация желания (трек C2):** при зачислении пользователя в поток — `Wish` помечается `fulfilled` (переход из `expressed | confirmed`, через ER на событие зачисления).
- **Отмена желания:** в карточке курса каталога (W01, статус `expressed | confirmed`), на экране W04 и в приглашении на поток (S11) — W05 (курс) / W05-M (модуль).
- Курс без пула анкеты — желание фиксируется **мгновенно** по клику (без questionnaire).
- Брошенная анкета (`pending` без активности): 6 часов простоя — предупреждение с кнопкой продолжения, 8 часов — автоматический abandon (трек job-scheduler).
