# Спецификация экранов Courses (UI Spec)

Документ описывает экраны Telegram-бота модуля Courses: их содержимое, кнопки, условия видимости и доменную логику.
Служит **отправной точкой для разработки** — что уже реализовано, что запланировано.

Условные обозначения:
- ✅ реализовано
- ❌ не реализовано
- 📋 в бэклоге / запланировано в треке

---

## S00 — Каталог курсов: 5-уровневый drill-down (✅ реализовано)

**Как попасть:** «📖 Программы курсов» в главном меню.
**Кому:** всем ролям.
**Формат:** как в «Моя учёба → Уроки» — каждый уровень показывает текущие объекты жирным + кнопками, подуровень — inline текстом.

### Уровни:

| Уровень | Заголовок | Жирный+кнопка | Inline (текст) | Кнопка «Назад» |
|---------|-----------|---------------|----------------|----------------|
| 0 | `📖 *Курсы*` | Курсы | Этапы (с числом модулей) | `↩️ Главное меню` |
| 1 | `📖 *Курс: {title}*` | Этапы | Модули (с проектами/уроками) | `⬅️ Назад к курсам` |
| 2 | `📖 *Этап: {title}*` | Модули | Проекты (с числом уроков) | `⬅️ Назад к курсу` |
| 3 | `📖 *Модуль: {title}*` | Проекты | Уроки (с числом шагов) | `⬅️ Назад к этапу` |
| 4 | `📖 *Проект: {title}*` | Уроки | Шаги (заголовки, без тел, макс. 3) | `⬅️ Назад к модулю` |

### Пример S00 (уровень 0):
```
📖 *Курсы*
💻 *Курс: Основы программирования*
    🗂️ Этап: Синтаксис — 1 модуль
    🗂️ Этап: Алгоритмика — 1 модуль

💼 *Курс: Бизнес-аналитика*
    🗂️ Этап: Анализ — 1 модуль
```

### Примечания:
- Карточки курса S00a нет — клик на курс сразу ведёт на уровень этапов.
- Кнопка «📚 Найти поток» убрана (кросс-контроллерная навигация — техдолг).

## Желание пройти курс (запись на курс) — 📋

Модуль `wish` фиксирует **желание пользователя пройти курс**. UI этих экранов живёт в контроллере курсов: у модуля `wish` **нет своего bot-ui-контроллера** — он вызывается через `appApi` из стори каталога курсов.

### Путь пользователя

```
Каталог курсов (S00, уровень 0) — карточка курса
  └─ кнопка «🎓 Хочу пройти курс» → UC wish:request-wish
       ├─ курс БЕЗ анкеты → желание фиксируется мгновенно → W03
       └─ курс С анкетой → анкета (questionnaire S01–S06)
              ├─ ✅ questionnaire.completed → ER wish:record-wish → W03
              └─ 🚫 отмена/отказ → желание не фиксируется
```

### W01 — Кнопка «🎓 Хочу пройти курс» (📋)

**Где:** карточка курса на уровне 0 каталога (S00) — вторая кнопка рядом с «{курс}».

| Текст | Код | Действие | Статус |
|-------|-----|----------|--------|
| `🎓 Хочу пройти курс` | `course:course-catalog:apply:{courseId}` | → UC `request-wish` | 📋 |

**Условия видимости (📋 уточнить в треке):**
- скрыть, если у пользователя уже есть желание на этот курс (→ показать статус);

### W02 — Анкета желания (только если у курса есть анкета) (📋)

Делегировано модулю `questionnaire` (экраны S01–S06 в `questionnaire/ui-spec.md`).

- при старте передаётся `ownerInfo = { courseId }` — возвращается в событии;
- пул анкеты задаёт курс (или конфигурация `wish`);
- если у курса **нет** анкеты — шаг пропускается, желание фиксируется сразу (W03).

### W03 — Желание зафиксировано (📋)

**Как попасть:** мгновенно (курс без анкеты) или после завершения анкеты (`questionnaire.completed`).

**Что происходит:** создаётся `Wish(user, course)` со статусом `expressed`.

**Содержание:**

```
🎯 Твоё желание пройти курс зафиксировано!
```

| Текст | Код |
|-------|-----|
| `↩️ Главное меню` | `app:main-menu` |
| `📝 Мои заявки` | 📋 бэклог |

### W04 — Желание уже есть / уже обучаешься (📋)

**Как попасть:** повторный клик «Хочу пройти курс» при существующем желании или обучении.

**Содержание:**

```
📝 Ты уже выразил желание пройти этот курс.
```

или

```
📚 Ты уже обучаешься на этом курсе.
```

| Текст | Код |
|-------|-----|
| `↩️ Главное меню` | `app:main-menu` |

## Доменные замечания (для треков)

- Пока только реализация "Фиксации желания".
- Роль `CANDIDATE` **удаляется** — информация о желании живёт в `Wish`.
- Статусы `Wish`: `expressed` (зафиксировано) → `fulfilled` (реализовано при зачислении) / `cancelled` (отменено).
- **Предложение о реализации:** при запуске модуля, если модуль первый для курса, то для всех желающих отправляется приглашение.
- **Реализация желания:** при зачислении пользователя в поток — `Wish` помечается `fulfilled` (через ER на событие зачисления).
- **Отмена желания:** при отправке приглашения есть кнопка об отмене приглашения.
- Курс может не иметь своей анкеты — тогда желание фиксируется **мгновенно** по клику (без questionnaire).
