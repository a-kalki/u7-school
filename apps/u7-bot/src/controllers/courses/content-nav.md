# Content-nav — общая навигация по контенту (drill-down)

**Назначение:** единый каркас пошагового просмотра иерархии учебного контента
(`ContentSnapshot`) в Telegram-боте. Используют: `learning` (`📖 Программа модуля`), `streams`
(`📖 Программа модуля`), `courses` (`📖 Курсы`).

Здесь — только общая механика. Механика прогресса и сужения шагов студента — в
[learning/ui-spec.md](../learning/ui-spec.md) (S05b). Конкретные экраны — в ui-spec контроллеров.

Реализуют треки `module-program-nav_20260928` (ядро + «Программа модуля») и
`course-catalog-nav_20260928` (каталог курсов).

---

## 1. Идея

- Иерархия проходится по лестнице уровней: `модуль/курс → проект/этап → урок → шаг`.
- Каждый уровень — **карточка одного узла**, а не плоское дерево в одном сообщении.
- Пользователь всегда понимает: где он, из чего состоит следующий уровень, куда идти
  и как листать соседей.
- Последний уровень — самый глубокий доступный (обычно урок); внутрь заходят только там,
  где это разрешено правами.

## 2. Карточка уровня

- **Шапка-крошки** — многострочный путь до узла с нумерацией и типом сущности:
  ```
  📖 Программа модуля
  › Проект 1/2: Введение в web
  › *Урок 1/3: Как устроен web*
  ```
  Промежуточные сегменты длиннее 34 символов обрезаются по границам слов (`truncateByWords`),
  текущий (последний) узел выделяется жирным.
- **Пояснение (заголовок списка)** — лаконичный курсивный заголовок: `*Этапы курса:*`,
  `*Модули этапа:*`, `*Проекты модуля:*`, `*Уроки проекта:*`, `*Шаги урока:*`.
- **Список детей:** нумерованный одноуровневый список узлов следующего уровня с мета-информацией
  в скобках (например, `(2 модуля)`, `(3 проекта)`, прогресс `(2/5)` у студента). Вложенных
  поддеревьев (подуровней с отступами) нет — карточка остаётся компактной и читаемой.
- **Кнопки** — по одной на ребёнка, с номером. Префиксы вида «Проект: », «Урок: » и эмодзи
  очищаются (`cleanChildButtonTitle`), чтобы текст кнопок был компактным и не усекался клиентом Telegram.
- **Листание** `◀️ Пред. …` / `След. … ▶️` — соседи узла **в пределах родителя**; на границе
  кнопки нет. Располагаются сразу под кнопками перехода к детям, перед дополнительными действиями
  (например, wish-кнопками) и кнопкой «Назад». Контекст может сужать список (у студента — только
  пройденные и текущий шаг, см. [learning/ui-spec.md](../learning/ui-spec.md), S05b).
- **Назад** `⬅️ Назад к {родителю}` — на уровень выше; на верхнем — выход по сценарию.
- Последний уровень — список шагов (у студента/ментора с возможностью входа в шаг, у гостя/каталога
  только заголовки). Длинные тела шагов (> 3200 символов) усекаются с пометкой
  `⚠️ _[Контент сокращён: полный текст доступен на платформе]_`.

## 3. Права: тела шагов или заголовки

Определяет `StepPolicy`: `STUDENT` / `MENTOR` / `AUTHOR` / `ADMIN` видят тела шагов;
остальные зрители — только заголовки. UI показывает то, что вернул домен, и не запрашивает
недоступное.

Дополнительное сужение для студента (тело только у пройденных и текущего шага) — это механика
прогресса, описана в [learning/ui-spec.md](../learning/ui-spec.md) (S05b).

## 4. Каркас реализации

- **Модель уровня (`NavLevel` + `NavChild`)** — единая для всех контекстов: крошки, пояснение,
  дети (`id`, `index`, `title`, `emoji`, `meta`, `status`, `enterable`, `children`),
  адреса `prev`/`next`/`back`.
- **Presenter** — чистые функции: `NavLevel` → текст MarkdownV2 + клавиатура. Доменной логики
  не содержит.
- **Резолвер контекста** — по адресу и актору отдаёт `NavLevel`: источник (поток/курс),
  доступность тел. Источник данных — существующие query-UC (`get-stream`, `get-module-snapshot`,
  `list-courses`, `get-course`, `get-step`, `get-steps-by-lessons`); новых query-UC не требуется.
- **Единый адрес уровня** — стабильные id, не индексы `phaseIdx`/`projectIdx`.
- **Рендер тела шага** — общий (`formatStepMessage`), режимы `student` / `readOnly`.
- **Права** — через `Policy`-объекты, не в presenter и не ручными проверками ролей.

**Размещение кода (вариант A):**
- `packages/core/src/ui/content-nav/` — `NavLevel`/`NavChild`, presenter (транспорт-независимо,
  `core` не знает доменов);
- `apps/u7-bot/src/` — резолверы контекста и стори.

## 5. Правила и запреты

- Не рендерить inline-поддеревья вручную; `tree-renderer` для этого не использовать.
- Не тащить `pagedScreen` в карточки (пагинация — только для длинных списков кнопок).
- Не дублировать механику в каждой стори: общее — в ядре, детали — в резолвере.
- Заголовки — через `md` (MarkdownV2-экранирование обязательно).
