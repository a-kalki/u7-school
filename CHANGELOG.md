# Changelog

Все заметные изменения проекта документируются в этом файле.
Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
версионирование — [SemVer](https://semver.org/lang/ru/).

Перед релизом: добавить секцию `## [X.Y.Z] — YYYY-MM-DD` наверх
(наличие секции проверяет `scripts/release.sh`). Группировка:
Added / Changed / Fixed / Migration.

## [0.1.12] — 2026-09-30

Доставлены проекты 3–4 модуля «HTML & CSS»: каркас портала и все
разделы с данными.

  поток документа, flexbox, grid, каркас приложения, проектный урок) и

### Changed

## [0.1.11] — 2026-09-30

Фикс падения экрана шага: одноимённые уроки в разных проектах больше не
путаются при подсчёте прогресса.

### Fixed

- `StreamDs.getStepLessonProgress` находит урок по самому шагу, а не по
  заголовку. В потоке «Алгоритмика - 7» два урока называются «Пуш ветки и
  создание Pull Request» (6 и 4 шага); поиск по названию возвращал первый
  (6-шаговый), из-за чего прогресс-бар получал `completed > total` и падал
  в `String.prototype.repeat` (`RangeError`) при открытии экрана шага.
- `formatStepMessage` берёт `completed` и `total` из одного источника
  (`getStepLessonProgress`), чтобы прогресс-бар не получал рассогласованные
  значения.

## [0.1.9] — 2026-09-27

Учебные шаги снова приходят новыми сообщениями; доставлен контент модуля
«HTML & CSS» (модуль 3) и новые проекты «Алгоритмики» (проекты 3–5).

### Added

- Единая точка чтения системных часов `now()` в `@u7-scl/core/shared`:
  `isoNow()` ходит через неё, а прод-код (UC, ER, job, repo, DS, стори)
  берёт «сейчас» только оттуда. Тесты замораживают время через
  `spyOn(Shared, 'now')` вместо реальных `new Date()`/`Date.now()`.
- Пошаговая выдача в боте: `DialogResponse.newMessage` подавляет
  edit-in-place — прежний свой экран гасится штатным retire (текст
  сохраняется, клавиатура снимается, добавляется маркер «Вы выбрали: …»),
  а новый экран уходит отдельным сообщением. `StepViewStory` доставляет так
  сам шаг, переход после завершения урока/проекта и финальный экран потока;
  просмотр пройденного шага (◀️/▶️ листание) остаётся edit-in-place.
  Возвращает прежний UX пошаговой выдачи, потерянный при перепроектировании
  bot-ui на «Диалог и Экран».
- Учебный контент «Алгоритмика»: проекты 3 «TDD и функции сравнения строк»
  (9 уроков, 35 шагов), 4 «Код-ревью в боевых условиях» (8 уроков, 21 шаг)
  и 5 «Поиск подстрок (вторая реализация, полный цикл)» (8 уроков, 24 шага).
  contentSnapshot потока «Алгоритмика - 7» обновлён.
- Учебный контент «HTML & CSS»: модуль 3 — проекты «Первые страницы:
  визитка предприятия» и «Оформление визитки: CSS и дизайн-токены»
  (10 уроков, 76 шагов), с эталонными реализациями в `reference/`.
  contentSnapshot потока обновлён.
- План модуля 4 «DOM» (`data/fullstack-js/m4-dom/module-plan.md`) —
  продолжение проекта «Портал предприятия», оживление вёрстки на чистом JS.
  Черновик, доставка контента не начата.

### Fixed

- Протухшие time-dependent тесты peer-review (`create-review-uc`,
  `get-my-campaigns-uc`, `get-campaign-recipients-uc`) и
  `StudentAr.isLaggingFromMedian`: тесты фиксируют `now()`, а не полагаются
  на реальные часы — падение по календарю (истёкшее окно кампании)
  устранено. `isLaggingFromMedian` заодно перестал терять секунды
  (было `new Date(isoNow())` — формат до минут).
- Форматирование `data/courses/*.json` и `reference/*.css` модуля
  «HTML & CSS» под текущий biome — релизный гейт `bun run check` снова зелёный.

## [0.1.0] — 2026-09-15

Первый тегированный релиз — точка отсчёта для деплоя и откатов.
До этого версии не фиксировались (деплой «push → git pull на сервере»).

В запись сведены основные изменения последних месяцев: перевод bot-ui
на контракт «Диалог и Экран», актор-объект User, персистентность сессий
бота.

### Added

- **Контракт «Диалог и Экран» для bot-ui**: единый `DialogResponse`
  (экран + клавиатура + состояние диалога) вместо разнородных ответов;
  на контракт переведены все стори — learning, questionnaire, mentor,
  community, каталоги курсов и потоков.
- **Билдеры ответов** `screen / ask / warn / note / go / kb / btn / btnUrl`
  — чистые функции сборки `DialogResponse`.
- **Персистентность сессий бота** (рестарт сервиса больше не сбрасывает
  диалоги):
  - порт `BotSessionRepo` в core — без деталей хранилища;
  - реализация `JsonBotSessionRepo` — файлы `data/bot/sessions.json` и
    `data/bot/short-ids.json` с Valibot-валидацией; битый файл — fail-fast
    на старте, без молчаливых пересозданий;
  - `restore()` до старта polling: `seq`, `ScreenState.messageId`,
    `input.context` и разворот shortId → UUID переживают рестарт;
  - синхронная запись сессии после каждого обработанного апдейта
    (command / callback / message / invite).
- **Актор-объект `User`** вместо `actorId` в UseCase/ApiModule/ApiApp
  и во всех доменах (user, wish, questionnaire, course, stream)
  и приложениях.
- Dev-фикстуры: пересев `seed:fixtures` сбрасывает сессии бота.
- **Релизный процесс**: `scripts/release.sh` (гейты, bump версии,
  аннотированный тег, пуш), `scripts/deploy.sh` на сервере (бэкап →
  checkout тега → pm2 → smoke-check), метаданные версии в каждом бэкапе
  (`data/backup/*/meta.txt`).

### Changed

- Старые типы bot-ui демонтированы: `BotCommand`, `BotResponse`,
  `SessionData`, `SendMessage`/`EditMessageDescription` и старые ассерты.
- Кнопки «Программа курса» и «Детали» ужаты в одну строку.

### Fixed

- Старые кнопки «умирали» после рестарта бота («Экран устарел») — теперь
  нажимаются и продолжают диалог с того же вопроса.
- Экран завершения потока вместо повторного рендера последнего шага.

### Migration

- Миграция данных **не требуется**: файлы `data/bot/*.json` создаются
  лениво при первом апдейте.
