# Changelog

Все заметные изменения проекта документируются в этом файле.
Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
версионирование — [SemVer](https://semver.org/lang/ru/).

Перед релизом: добавить секцию `## [X.Y.Z] — YYYY-MM-DD` наверх
(наличие секции проверяет `scripts/release.sh`). Группировка:
Added / Changed / Fixed / Migration.

## [0.1.7] — 2026-09-23

Экран «Отзывы мне» (S08) — все отзывы, адресованные пользователю.

### Added

- Хаб «Отзывы» (S02): кнопка «📥 Отзывы мне» — видна при наличии хотя бы
  одного отзыва адресату; ведёт в новый экран S08 (UC `list-my-reviews`):
  все отзывы адресату, новые наверху, карточки-отзывы разделены линией,
  пагинация целыми отзывами, возврат «↩️ Мои отзывы» в хаб.
- Кнопка меню «💬 Отзывы» видна и при одних только входящих отзывах
  (без живых кампаний) — хаб сворачивается в заглушку с кнопкой S08.
- E2E-сценарий `peer-review-reviews-for-me.e2e.test.ts`: кнопка в хабе
  (есть/нет), порядок «новые наверху», линии, лейблы ролей и исходов,
  возврат в хаб, видимость кнопки меню при отсутствии живых кампаний.

## [0.1.6] — 2026-09-23

Уведомление адресату о новом отзыве; уборка выполненных one-off скриптов.

### Added

- Уведомление адресату о новом отзыве: агрегат Review публикует
  `review.created` (только первая запись; перезапись — нет), ER

### Removed

- Одноразовые скрипты, свою работу выполнившие: `backfill-peer-review-campaigns.ts`
  и `deliver-peer-review-invites.ts` (миграция кампаний потоков до v0.1.4 —
  проведена на проде), `deliver-redesign.ts` (укладка контента «Алгоритмики» —
  черновики redesign-p1…p5 из репо удалены).

## [0.1.5] — 2026-09-23

Пагинация хаба «Отзывы» (S02) и one-off скрипты для кампаний потоков, закрытых до выката peer-review (Синтаксис-4/5/6).

### Added

- Пагинация хаба «Отзывы» (S02): опция `rowsPage` в `pagedScreen` (динамический бюджет символов), callback-навигация `hub-page:<n>`, сквозная нумерация «Стр. N/M»; чинит «message is too long» у менторов с большим числом кампаний. Страница хаба запоминается в кодах кнопок: все возвраты из кампании открывают хаб на исходной странице.
- Галочка `✅` на карточках хаба, когда все отзывы кампании написаны (M = K) — одна логика для студента и ментора.
- `scripts/backfill-peer-review-campaigns.ts`: replay событий судьбы студентов в продовый стек — кампании создаёт штатная ER (идемпотентно, без уведомлений); dry-run и фильтр по потоку.
- `scripts/deliver-peer-review-invites.ts`: доставка приглашений по существующим кампаниям напрямую через Telegram API (без кнопок, «Наберите /start → «Отзывы»»); фильтр менторских уведомлений, dry-run, ретрай на 429.

### Fixed

- Хаб S02 не открывался с «message is too long», если у ментора больше ~10 кампаний (60 рендерились одним сообщением).

## [0.1.4] — 2026-09-23

UI отзывов (peer-review S01–S07), пагинатор, dev-персоны («театр одного актёра»). Закрыт трек peer-review-ui_20260916, открыт test-worlds_20260923 (тестовые миры).

### Added

- Peer-review UI: диалог кампании (S03 список адресатов → S05 ввод/⏭️ пропуск → S06 сохранение, S04 перезапись), валидация 10–3500 без потери контекста, заглушка истёкшего окна; хаб «Мои отзывы» (S02) с рендером по роли; персонализированные приглашения (S01) по событию `student-campaign.created`; постраничный просмотр отзывов потока (S07) из карточки потока.

- Инфраструктура релизов: `scripts/release.sh` (гейты, changelog, тег, пуш), `scripts/deploy.sh` с защитой серверных коммитов.

### Changed

- Стори peer-review читают данные через `appApi` (фасад модуля удалён — клиентов не было).
- Финализация экрана ввода: новый контент — внизу чата.

### Fixed

- Dev-редирект персон покрывает все адресные вызовы API (раньше только `sendMessage` — `editMessageText` фикстурным персонам падал «400: chat not found»).
- Регресс-тесты hard break (см. [0.1.3]).

## [0.1.3] — 2026-09-23

Хотфикс: застревание студентов на шагах с hard break в контенте.

### Fixed

- `safeConvert` (core/shared): снимает экранирование перевода строки (`\` + LF → LF),
  которое `markdown-to-telegram` ставит для markdown hard break (два пробела или `\`
  в конце строки исходника). Голый `\` перед переносом ловился fail-fast валидатором
  (`assertDialogResponseMarkdownSafe`) — экран шага не уходил студенту, кнопки «молчали»,
  `/start` падал тем же рендером. Пострадали 7 из 500 шагов (например, p1-l2
  «Проверь имя основной ветки»); прогресс шагов при этом сохранялся.
- Внутри код-сущностей (` ``` ` и `` ` ``) пары `\\` не трогаются — bash-континуация
  и прочий код с обратным слешем не искажаются.

### Added

- Регресс-тесты hard break в `markdown.test.ts` (блок «Hard break» в `safeConvert`).
- Запись в базе troubleshoot: `markdown-to-telegram-hard-break`.

### Migration

- Миграция данных не требуется.

## [0.1.0] — 2026-09-15

Первый тегированный релиз — точка отсчёта для деплоя и откатов.
До этого версии не фиксировались (деплой «push → git pull на сервере»).

В запись сведены основные изменения последних месяцев: перевод bot-ui
на контракт «Диалог и Экран», актор-объект User, персистентность сессий
бота.

### Added

- **Контракт «Диалог и Экран» для bot-ui**: единый `DialogResponse`
  (экран + клавиатура + состояние диалога) вместо разнородных ответов;
  на контракт переведены все стори — learning, questionnaire, mentor,
  community, каталоги курсов и потоков.
- **Билдеры ответов** `screen / ask / warn / note / go / kb / btn / btnUrl`
  — чистые функции сборки `DialogResponse`.
- **Персистентность сессий бота** (рестарт сервиса больше не сбрасывает
  диалоги):
  - порт `BotSessionRepo` в core — без деталей хранилища;
  - реализация `JsonBotSessionRepo` — файлы `data/bot/sessions.json` и
    `data/bot/short-ids.json` с Valibot-валидацией; битый файл — fail-fast
    на старте, без молчаливых пересозданий;
  - `restore()` до старта polling: `seq`, `ScreenState.messageId`,
    `input.context` и разворот shortId → UUID переживают рестарт;
  - синхронная запись сессии после каждого обработанного апдейта
    (command / callback / message / invite).
- **Актор-объект `User`** вместо `actorId` в UseCase/ApiModule/ApiApp
  и во всех доменах (user, wish, questionnaire, course, stream)
  и приложениях.
- Dev-фикстуры: пересев `seed:fixtures` сбрасывает сессии бота.
- **Релизный процесс**: `scripts/release.sh` (гейты, bump версии,
  аннотированный тег, пуш), `scripts/deploy.sh` на сервере (бэкап →
  checkout тега → pm2 → smoke-check), метаданные версии в каждом бэкапе
  (`data/backup/*/meta.txt`).

### Changed

- Старые типы bot-ui демонтированы: `BotCommand`, `BotResponse`,
  `SessionData`, `SendMessage`/`EditMessageDescription` и старые ассерты.
- Кнопки «Программа курса» и «Детали» ужаты в одну строку.

### Fixed

- Старые кнопки «умирали» после рестарта бота («Экран устарел») — теперь
  нажимаются и продолжают диалог с того же вопроса.
- Экран завершения потока вместо повторного рендера последнего шага.

### Migration

- Миграция данных **не требуется**: файлы `data/bot/*.json` создаются
  лениво при первом апдейте.
