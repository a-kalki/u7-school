# Telegram Bot API: editMessageText без reply_markup не удаляет инлайн-клавиатуру

- **Симптомы:** пользователь жал кнопки на уже отвеченных вопросах анкеты (или других сообщениях с клавиатурой), в логах лавина `AR_INTERNAL_ERROR «Некорректный ответ на вопрос "<текущий вопрос>"»` — answerCode из кнопки старого вопроса не входит в picklist текущего. Ошибки сыплются серией (пользователь жмёт все кнопки подряд, реакции нет).
- **Причина:** в `apps/u7-bot/src/infra/bot-transport.ts` при `editMessageText` клавиатура удаляется через `reply_markup: undefined`. `JSON.stringify` выкидывает `undefined`-поля → параметр отсутствует в запросе → по Bot API **существующая инлайн-клавиатура сохраняется**. Чтобы удалить, нужно передать `reply_markup: { inline_keyboard: [] }`.
- **Решение:** при редактировании сообщения без клавиатуры явно передавать пустую инлайн-клавиатуру:

```ts
const keyboard = edit.keyboard
  ? { inline_keyboard: /* строки */ }
  : { inline_keyboard: [] }; // иначе Telegram оставит прежнюю клавиатуру
```

То же касается блока «удаление клавиатуры у предыдущего сообщения» (`reply_markup: undefined` там не работает).

**Сопутствующие баги того же инцидента:**
1. Fallback-текст `⚠️ *Произошла внутренняя ошибка*...обратитесь к администратору.` в `packages/core/src/ui/bot/bot-ui-story.ts` содержит неэкранированную `.` → `MarkdownV2ValidationError` в `assertResponseMarkdownSafe` → пользователь не получает вообще никакого ответа. В `bot-controller.ts` та же строка уже экранирована (`\\.`).
2. Ошибка валидации пользовательского ввода в `packages/questionnaire/src/domain/questionnaire/a-root.ts` (`#submitCurrentQuestion`) бросается как `throwInternal` (`kind: internal`), хотя это ожидаемая ошибка ввода — из-за этого пользователь видит «внутреннюю ошибку» вместо подсказки.
