# Telegram MarkdownV2: неэкранированные скобки вокруг ссылки ломают сообщение

- **Симптомы:** `MarkdownV2 validation failed (2 issue(s)): неэкранированный '(', неэкранированный ')'` при отправке проактивного сообщения (ProactiveSender). В бою Telegram вернул бы `Bad Request: can't parse entities`. Сообщение не доставляется (в ER — ошибка изолируется шиной, пользователь молча не получает приглашение).
- **Причина:** скобки вне Markdown-разметки (`[text](url)`) обязаны быть экранированы. Конструкция `Имя ([@nick](https://t.me/nick))` содержит внешние `(` `)` вокруг entity — для парсера MarkdownV2 это неэкранированные символы. Юнит-тесты не ловили: они проверяли подстроку текста, не прогоняя его через валидатор.
- **Решение:** экранировать внешние скобки: `Имя \([@nick](https://t.me/nick)\)` (в TS-шаблонной строке — `\\(` и `\\)`). Скобки внутри/составляющие entity (`[text](url)`) экранировать нельзя. Интеграционные/e2e тесты проактивных сообщений должны делать `assertBotResponseValid` на фактический текст — он ловит такие ошибки. Пример: `apps/u7-bot/src/controllers/streams/stories/wish-invite.story.ts` (ментор-строка S11).
