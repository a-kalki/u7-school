# Bun-test + TestBotTransport: склейка Api-записей [...edited, ...sent] даёт неверную хронологию экранов

- **Симптомы:** integration/e2e-тест, берущий код кнопки «с последнего экрана» через склейку `[...transport.api.editedMessages, ...transport.api.sentMessages].reverse()`, находит кнопку на УСТАРЕВШЕМ экране: нажатие открывает не тот уровень (например, вместо «📦 JavaScript Основы» уровня 2 — курс «Продвинутый JavaScript» с уровня 0) либо ответ пустой («Экран устарел»).
- **Причина:** транспорт рендерит ответ edit'ом, когда экран принадлежит текущей seq-эпохе диалога (внутри одной стори seq не растёт — `enterDialog(switch)` на тот же path — no-op), и send'ом при смене стори. При чередовании edit/send-рендеров простая склейка массивов (все edited, потом все sent) после `.reverse()` ставит СТАРЫЙ sent-экран НОВЕЕ свежих edited-экранов.
- **Решение:** восстанавливать хронологию по привязке edit → messageId оригинала: sent-ы по порядку, каждый edit — сразу за своим sent'ом. Готовый хелпер: `screensNewFirst` + `pressedCode` / `currentStamp` / `stampedCode` в `apps/u7-bot/tests/helpers/test-bot-transport.ts` (трек bot-ui-dialog-nav). Частный случай той же ловушки: `find` экрана по тексту должен требовать `m.keyboard` — retire-эдит («————— Вы выбрали: …») сохраняет текст экрана, но снимает клавиатуру.
